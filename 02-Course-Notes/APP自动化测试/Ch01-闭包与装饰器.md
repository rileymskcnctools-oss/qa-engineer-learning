## 一、函数引用

### 知识点 1：函数是"一等公民"，可以像变量一样赋值

【课程原话/定义】

Python 中定义的函数，可以像变量一样，把一个函数名赋值给另一个变量名。赋值后，这个变量名就成了该函数的别名，可以用来调用函数。

```python
def show():
    print("Show Run ...")

show()      # 正常调用
a = show    # 把函数名（引用）赋给 a，注意：函数名后不能加括号
a()         # 通过别名调用，等价于 show()
```

> 注意：把函数名赋给变量时，**函数名后不能加括号**——加括号是"调用函数并拿返回值"，不加括号才是"拿函数本身（引用）"。

【为什么？】

1. 在 Python 里，函数本质是一个**对象**（`function` 类型）。`show` 是"指向这个函数对象的引用"，`a = show` 只是让 `a` 也指向同一个对象，所以 `a()` 和 `show()` 调的是**同一个函数**。
2. 理解"函数名 = 引用"是理解闭包和装饰器的**唯一前提**——因为装饰器最后做的事就是"把新函数的引用赋回给旧函数名"（`show = count_time(show)`）。
3. 这也是 `sort(key=函数名)` 为什么能传函数：`key` 参数接收的是一个**函数引用**，而不是函数的调用结果。

【必须掌握】

- 函数名不带括号 = 函数引用（对象）；带括号 = 调用并取返回值
- `a = show` 后，`a()` 与 `show()` 是同一个函数
- `sort(key=...)` 传的是函数引用

【企业场景】

你在企业里写测试框架时，"传函数引用"无处不在：`pytest` 的 `parametrize`、自定义 fixture、`allure.step`、日志装饰器……本质上都是在"把一个函数交给另一个函数去执行"。看不懂这一层，后面所有"高阶函数"用法都会卡壳。

【面试考察】

面试官："Python 里函数名加括号和不加括号有什么区别？"

参考回答框架：
1. 不加括号：拿函数对象本身（引用），可以赋值、传参、放进列表。
2. 加括号：立即调用函数，得到返回值。
3. 举 `sort(key=len)` 的例子——传的是 `len` 这个函数引用，不是 `len()` 的调用结果。

【易错点】

| 误区 | 纠正 |
|------|------|
| `a = show()` | 这是"调用 show 并把返回值赋给 a"，不是函数别名；要别名应写 `a = show` |
| 以为 `a()` 复制了一份函数 | `a` 和 `show` 指向同一个函数对象，没有复制 |

【我的理解】
> （`a = show` 之后，`a` 和 `show` 是"两个名字指向同一个函数"。如果这时把 `show` 重新赋值成别的，`a` 还指向原函数吗？想一想"引用"和"值"的区别。）

## 二、闭包

### 知识点 2：闭包 = 内部函数 + 被它记住的环境变量

【课程原话/定义】

闭包（Closure）是指在一个嵌套函数内部访问其外部函数中定义的变量或函数的能力。它由两部分组成：**内部函数**和**与其相关的环境变量**。

```python
def out_func():
    out_n = 100
    def inner_func():
        print(out_n)     # 内部函数访问外部函数的变量 out_n
    return inner_func    # 返回内部函数（注意：返回的是引用，不带括号）

of1 = out_func()
of2 = out_func()
of1()   # 100
of2()   # 100
```

闭包的特点：
- 内部函数可以访问外部函数中的变量和参数，**即使外部函数已经执行完毕**。
- 闭包可以在外部函数作用域之外被调用和执行。
- 闭包可以访问并修改外部函数的局部变量，使其具有**持久性**。

【为什么？】

1. **"记住"的机制**：普通函数的局部变量在函数返回后就被回收了。但闭包里的 `inner_func` 引用了 `out_n`，Python 发现"还有函数在用它"，就不会回收 `out_n`，而是把它连同 `inner_func` 一起打包带走——这就是"记住上下文环境"。
2. **为什么 return 内部函数**：`return inner_func`（不带括号）把内部函数的引用交出去，外部代码才能在 `out_func` 已经返回之后，还能通过 `of1()` 调用它、并读到它还活着的 `out_n`。
3. **持久性**：因为环境变量没被回收，闭包能"记住上一次的状态"——这正是后面"缓存数据"应用场景的底层原因。

【必须掌握】

- 闭包两个要素：内部函数 + 被它引用的外部变量（环境变量）
- 外部函数 return 内部函数引用（不带括号）
- 外部函数返回后，内部函数仍能访问其变量（持久性）

【企业场景】

你在企业里，闭包最常见的落地是**测试框架的装饰器**（下一节）和**缓存/计数器**。比如写一个"用例执行次数统计器"：外层函数初始化 `count=0`，返回一个内部函数，每调用一次 `count+=1` 并返回当前值——这个 `count` 就靠闭包"持久化"地活着，不会被 GC 回收。

【面试考察】

面试官："闭包是什么？它为什么能'记住'外部函数的变量？"

参考回答框架：
1. 闭包 = 内部函数 + 它引用的外部变量（环境变量）。
2. 外部函数返回内部函数引用后，因为变量还被引用，Python 不会回收它。
3. 所以内部函数在外部作用域之外调用时，仍能访问/修改那个变量（持久性）。

【易错点】

| 误区 | 纠正 |
|------|------|
| `return inner_func()` | 这是"调用并返回执行结果"，会立刻执行；要返回闭包应写 `return inner_func`（不带括号） |
| 以为外部函数返回后 out_n 被回收了 | 闭包持有引用，out_n 不会被回收，这也是"持久性"的来源 |
| `of1` 和 `of2` 共享同一个 out_n | 每次 `out_func()` 都是独立的作用域，各自有独立的 out_n=100 |

【我的理解】
> （"闭包能记住变量"和"变量被回收"是矛盾的。为什么闭包里的变量不被回收？试着从"引用计数"的角度解释——谁还在引用它？）

## 三、nonlocal

### 知识点 3：闭包内要"修改"外部变量，必须用 nonlocal 声明

【课程原话/定义】

函数内不能直接修改函数外的变量。修改全局变量要用 `global`，闭包中修改外函数变量要用 `nonlocal`。

不用 nonlocal（内层赋值会新建一个同名局部变量，不影响外层）：

```python
def out_func():
    out_n = 100
    def inner_func():
        out_n = 200            # 这里其实是新建了一个 inner 自己的局部变量
        print("inner:", out_n)
    print("outer1:", out_n)    # 100
    inner_func()
    print("outer2:", out_n)    # 100（外层没变）
    return inner_func
```

用 nonlocal：

```python
def out_func():
    out_n = 100
    def inner_func():
        nonlocal out_n         # 声明：我要修改的是外层的 out_n
        out_n = 200
        print("inner:", out_n)
    print("outer1:", out_n)    # 100
    inner_func()
    print("outer2:", out_n)    # 200（外层被改了）
    return inner_func
```

【为什么？】

1. Python 的规则：**在函数内对一个变量赋值，默认就是"新建局部变量"**，而不是修改外层变量。所以 `inner_func` 里 `out_n = 200` 会新建一个 inner 自己的 `out_n`，外层的 `out_n` 纹丝不动。
2. `nonlocal out_n` 是在告诉解释器："这个 `out_n` 不是新的局部变量，去找**最近一层外层作用域**里的那个 `out_n`"。
3. 和 `global` 的分工：`global` 声明"用模块级全局变量"，`nonlocal` 声明"用外层函数（非全局）的变量"。层级不同。

【必须掌握】

- 内函数"只读"外部变量：不需要声明；"修改"外部变量：必须 `nonlocal`
- `nonlocal` 管"外层函数变量"，`global` 管"模块全局变量"
- 不声明就赋值 = 新建局部变量（外层不变）

【企业场景】

你在企业里写"重试计数器""用例执行次数统计"这类闭包时，几乎一定会踩这个坑：想 `count += 1` 却发现每次都是 1。原因就是没加 `nonlocal`，`count += 1` 被当成新建局部变量。加 `nonlocal count` 后，计数器才能真正累加。

【面试考察】

面试官："闭包内想修改外部变量，为什么要用 nonlocal？它和 global 有什么区别？"

参考回答框架：
1. 函数内赋值默认新建局部变量，不会改外层，所以要显式声明。
2. `nonlocal` 指向"最近的外层函数作用域"；`global` 指向"模块全局作用域"。
3. 只读不需要声明，只有"赋值/修改"才需要。

【易错点】

| 误区 | 纠正 |
|------|------|
| 以为 `out_n = 200` 会修改外层 | 不声明时是新建局部变量，外层不变（结果里 outer2 仍是 100） |
| nonlocal 和 global 混用 | nonlocal 管外层函数变量，global 管模块全局变量，层级不同 |
| 只读也加 nonlocal | 只读不需要声明，只有赋值才需要 |

【我的理解】
> （为什么"读"不需要声明、只有"写"才需要？想想 Python 是怎么判断一个名字是"局部变量"还是"外层变量"的——是不是看它有没有被赋值？）

## 四、装饰器

### 知识点 4：装饰器 = 不改源码、不改调用方式，却给函数加功能

【课程原话/定义】

装饰器是 Python 的**语法糖**，用 `@` + 装饰器名，在不修改原函数定义和调用方式的情况下，给函数增加额外功能。它本质上就是一个闭包函数。

功能三特点：
1. 不修改已有函数的源代码
2. 不修改已有函数的调用方式
3. 给已有函数增加额外的功能

```python
import time

def count_time(func):          # 外层函数 = 装饰器名，参数接收被装饰函数的引用
    def inner():               # 内层函数 = 真正执行的函数
        start_time = time.time()
        func()                 # 间接调用被装饰函数
        stop_time = time.time()
        print(f'函数执行时间为{stop_time - start_time}秒')
    return inner               # 返回内层函数引用

@count_time                    # 等价于 show = count_time(show)
def show():
    for i in range(3):
        print(f"第 {i+1} 次输出")
        time.sleep(1)

show()
# 第 1 次输出 / 第 2 次输出 / 第 3 次输出 / 函数执行时间为3.011...秒
```

【为什么？】

1. **装饰器的本质是"函数替换"**：`@count_time` 等价于 `show = count_time(show)`。解释器把 `show` 的引用传给 `count_time`，`count_time` 返回 `inner` 的引用，再把这个引用**赋回给 `show`**。所以从此 `show` 这个名字指向的不再是原函数，而是 `inner`。
2. **调用 `show()` 时实际跑的是 `inner`**，由 `inner` 间接调用原函数，并在前后夹带"计时"等额外逻辑——这就是"不改调用方式却加了功能"的原因。
3. **为什么用语法糖**：`@count_time` 比 `show = count_time(show)` 更简洁、可读，且装饰意图一眼可见。功能上没有新增能力，纯粹是写法更优雅。

【必须掌握】

- `@装饰器名` 等价于 `函数名 = 装饰器名(函数名)`
- 装饰器 = 闭包：外层函数收 func，内层函数包 func，返回内层引用
- 三特点：不改源码 / 不改调用方式 / 增加功能

【企业场景】

你在企业里，装饰器是测试框架的骨架。几个真实例子：`@pytest.fixture`、`@pytest.mark.parametrize`、`@allure.step`、以及你自己写的"用例失败自动截图"装饰器（见 [[Web自动化测试/Ch16-异常自动截图]] 里的 `ui_exception_record`）。它们全遵循同一套"包装函数 + 夹带逻辑"的模式。

【面试考察】

面试官："装饰器是怎么工作的？`@decorator` 背后发生了什么？"

参考回答框架：
1. `@decorator` 等价于 `func = decorator(func)`。
2. decorator 是闭包：接收原函数引用，定义 inner 包装它，返回 inner 引用。
3. 之后调用 `func()` 实际执行的是 inner，由 inner 调原函数并夹带额外逻辑。

【易错点】

| 误区 | 纠正 |
|------|------|
| 以为装饰器改了原函数源码 | 原函数一行没动，只是名字被替换成 inner 的引用 |
| `return inner()` 写成了调用 | 会立即执行并返回 None，应 `return inner`（引用） |
| 忘记 func 的返回值 | 内层若直接 `func()` 而不 return，被装饰函数的返回值就丢了（见通用装饰器） |

【我的理解】
> （`show = count_time(show)` 里，赋值号左右两边的 `show` 含义一样吗？左边是"被重新指向的名字"，右边是"原函数的引用"——想清楚这一步，装饰器就通了。）

### 知识点 5：通用装饰器（用 *args/**kwargs 和 return 兜住一切函数）

【课程原话/定义】

前面的 `count_time` 只能装饰"无参无返回值"的函数。要让装饰器能装饰任何函数，需解决参数和返回值两个问题——用可变参数接收参数，在内函数中返回被装饰函数的执行结果：

```python
def decorator(func):
    def inner(*args, **kwargs):
        # 装饰器功能代码
        result = func(*args, **kwargs)   # 透传参数 + 保存返回值
        return result                    # 返回原函数结果
    return inner
```

【为什么？】

1. `*args`（位置参数打包成元组）和 `**kwargs`（关键字参数打包成字典）能"吃掉"任意数量和形式的参数，再原样透传给 `func`——这样装饰器不关心被装饰函数长什么样。
2. 必须 `return result`：如果不返回，被装饰函数的返回值就丢了。比如装饰一个有返回值的函数（如返回页面的 `login()`），丢了返回值调用方就拿到 None。
3. 通用装饰器是"模板"，实际使用时往里填"装饰逻辑"（计时、日志、截图、重试……）。

【必须掌握】

- `inner(*args, **kwargs)` 接收任意参数并透传给 func
- `result = func(...)` 保存结果、`return result` 原样返回
- 这是所有装饰器的通用骨架

【企业场景】

你在企业里写的 `ui_exception_record` 装饰器（[[Web自动化测试/Ch16-异常自动截图]]）就是这个模板的实例：`inner(*args, **kwargs)` 里 try 执行原函数，except 时截图/存 page_source，最后把异常重新抛出。看懂这个模板，就能看懂（和写）框架里几乎所有装饰器。

【面试考察】

面试官："为什么装饰器内层要用 *args 和 **kwargs？"

参考回答框架：
1. 让装饰器通用于任意参数的函数（不限定参数个数/形式）。
2. `*args` 打包位置参数、`**kwargs` 打包关键字参数，再透传给原函数。
3. 同时用 `result = func(...); return result` 保住原函数的返回值。

【易错点】

| 误区 | 纠正 |
|------|------|
| 内层不 return result | 被装饰函数返回值丢失，调用方拿到 None |
| 只写 `*args` 不写 `**kwargs` | 带关键字参数的函数就装饰不了 |
| 把 `*args/**kwargs` 理解成"必须用" | 只是"通用"的写法，装饰无参函数时用不到 |

【我的理解】
> （通用装饰器里 `return result` 是为了"不改变被装饰函数的返回值"。这和装饰器"不改调用方式"的原则是什么关系？）

### 知识点 6：带参数装饰器（三层嵌套）

【课程原话/定义】

有些装饰器本身要接收参数（如 pytest 数据驱动的测试数据）。此时要在通用装饰器外**再套一层函数**来接收装饰器参数：

```python
def decorator_args(vars, datas):        # 最外层：接收装饰器自己的参数
    def decorator(func):                # 第二层：接收被装饰函数
        def inner(*args, **kwargs):     # 第三层：真正执行
            return func(*args, **kwargs)
        return inner
    return decorator

data = [(1,2,3),(4,5,6),(7,8,9)]
@decorator_args("a,b,c", data)          # 装饰器传参
def show(a, b, c):
    print(a, b, c)
```

【为什么？】

1. `@decorator_args("a,b,c", data)` 的解析顺序：**先执行 `decorator_args("a,b,c", data)`**，它返回 `decorator`，于是变成 `@decorator`，再按普通装饰器流程装饰 `show`。本质是**链式多次函数调用**。
2. 之所以要三层：第一层收"装饰器参数"，第二层收"被装饰函数"，第三层收"函数调用时的参数"——三层各收各的，缺一不可。
3. 最典型落地就是 pytest 的 `@pytest.mark.parametrize("a,b,c", data)`——第一层把 `("a,b,c", data)` 解析成"参数名 + 数据"，第二层拿到测试函数，第三层把每组数据解包传进去跑。

【必须掌握】

- 带参数装饰器 = 三层嵌套：外层收装饰器参数、中层收 func、内层收调用参数
- `@decorator_args(...)` 先执行最外层调用，返回真正的装饰器
- 对应 pytest 的 `parametrize`（见 [[Pytest/Ch03-Pytest参数化用例]]）

【企业场景】

你在企业里最常见的带参数装饰器就是数据驱动：`@pytest.mark.parametrize("name,age", [(...),(...)])`。理解它"三层嵌套"的结构后，你才能看懂框架源码里 parametrize 是怎么把每组数据变成一条独立用例、独立报告、独立失败的。

【面试考察】

面试官："带参数的装饰器和普通装饰器结构上差在哪？为什么多一层？"

参考回答框架：
1. 普通装饰器两层（收 func + 内层执行）；带参数装饰器三层。
2. 多出来的最外层专门接收"装饰器自身的参数"。
3. 执行时先调用最外层得到真正的装饰器，再走普通装饰流程（链式调用）。

【易错点】

| 误区 | 纠正 |
|------|------|
| 把带参数装饰器写成两层 | 少一层就没人接收装饰器参数，会报错 |
| 混淆三层的参数 | 外层收装饰器参数、中层收 func、内层收调用参数，各司其职 |
| 忘记最外层 return decorator | 不返回，`@` 后面拿不到装饰器 |

【我的理解】
> （`@decorator_args("a,b,c", data)` 里，`"a,b,c"` 和 `data` 是传给谁的？`show` 又是传给谁的？把"参数流向"画出来，三层嵌套就清楚了。）

## 今日课程总结

| 模块 | 核心内容 | 面试权重 |
|------|----------|----------|
| 函数引用 | 函数名不带括号 = 引用，可赋值/传参 | ★★★☆☆ |
| 闭包 | 内部函数 + 环境变量，外部函数返回后仍记住变量 | ★★★★☆ |
| nonlocal | 闭包内修改外部变量需 nonlocal（对比 global） | ★★★☆☆ |
| 装饰器本质 | @装饰器 = func = decorator(func)，不改源码不改调用 | ★★★★★ |
| 通用装饰器 | *args/**kwargs + return result 兜住任意函数 | ★★★★★ |
| 带参数装饰器 | 三层嵌套，链式调用（对应 parametrize） | ★★★★☆ |
