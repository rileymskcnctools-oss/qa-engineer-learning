## 一、常见操作

### 知识点 1：点击 / 坐标点击 / 输入 / 清除

【课程原话/定义】

定位到 APP 控件元素后，可以对控件进行一系列操作实现交互：

- 点击元素：`element.click()`
- 点击坐标：`driver.tap([(x, y)], 1000)`
- 元素中输入内容：`element.send_keys('appium')`
- 清除元素中内容：`element.clear()`

【为什么？】

1. click 是对元素对象操作，Appium 会自动算元素中心点去点；tap 是直接按屏幕坐标点，用于没有元素可定位、或需要点元素内部特定位置（如滑动条中心）的场景。
2. tap 第二个参数 1000 是持续时间（毫秒），控制"长按"还是"短点"——1000ms 是短按，更大是长按。
3. send_keys 输入文本（配合 unicodeKeyboard 支持中文），clear 清空输入框——登录/搜索框常用 combo。

【必须掌握】

- element.click() 点元素、driver.tap([(x,y)], ms) 点坐标
- element.send_keys() 输入、element.clear() 清除

【企业场景】

你在企业里，常规按钮用 click；遇到"滑动条、自定义控件、地图定位"这类拿不到稳定元素或要点指定位置时用 tap。输入框前先 clear 防止残留（尤其是默认值输入框），send_keys 中文记得开 unicodeKeyboard。

【面试考察】

面试官："click 和 tap 有什么区别？"

参考回答框架：click 是对已定位元素操作（Appium 自动点中心），tap 是按屏幕坐标点击、可指定持续时长（毫秒）实现短按/长按，适用于无法定位元素或需点指定位置的场景。

【易错点】

| 误区 | 纠正 |
|------|------|
| tap 第二个参数是"次数" | 它是**持续时间（毫秒）**，1000=短按，更大=长按 |
| 输入前不 clear | 输入框有默认值/残留时，send_keys 会追加，导致输入错误 |

【我的理解】

> （什么场景必须用 tap 而不是 click？tap 的持续时间参数能实现什么 click 做不到的效果？）

## 二、状态判断

### 知识点 2：is_displayed / is_enabled / is_selected

【课程原话/定义】

- 是否可见：`element.is_displayed()` 返回 True/False
- 是否可用：`element.is_enabled()` 返回 True/False
- 是否被选中：`element.is_selected()` 返回 True/False

【为什么？】

1. 这三个方法是"断言元素状态"的核心：验证元素出现了、可操作了、被勾选了。
2. is_displayed 判断可见（渲染出来了）、is_enabled 判断可交互（灰置不可点返回 False）、is_selected 判断选中（勾选框/开关）。
3. 状态判断是"自动化验证"和"演示脚本"的分水岭——不判断状态就没有断言意义。

【必须掌握】

- is_displayed / is_enabled / is_selected 三方法 + 各自判断什么

【企业场景】

你在企业里，断言"按钮是否可点"用 is_enabled，"勾选框是否勾上"用 is_selected，"元素是否出现"用 is_displayed。这比只判断 text 更贴近真实交互状态（比如灰置按钮 text 不变但 is_enabled=False）。

【面试考察】

面试官："is_enabled 和 is_displayed 的区别？"

参考回答框架：is_displayed 判断元素是否可见（渲染出来），is_enabled 判断元素是否可交互（灰置/禁用返回 False）。可见 ≠ 可用，一个灰置按钮可见但不可点。

【易错点】

| 误区 | 纠正 |
|------|------|
| is_displayed 和 is_enabled 混为一谈 | 可见和可用是两回事，灰置按钮 is_displayed=True 但 is_enabled=False |
| 只判断 text 不判断状态 | text 不变不代表状态对，要结合 is_enabled/is_selected |

【我的理解】

> （一个"灰置（不可点）的按钮"，is_displayed 和 is_enabled 分别返回什么？为什么？）

## 三、获取元素属性

### 知识点 3：get_attribute / text / location / size

【课程原话/定义】

- 获取元素属性：`element.get_attribute()`，可取 resource-id、text、class、content-desc、checkable、checked、clickable、enabled、focusable、focused 等。
- 获取元素文本：`element.text`
- 获取元素坐标：`element.location`，结果如 `{'x': 498, 'y': 19}`
- 获取元素尺寸（高和宽）：`element.size`，结果如 `{'width': 500, 'height': 22}`

【为什么？】

1. get_attribute 是通用取值接口，一个方法取任意属性；text 是语法糖（等价 get_attribute('text')），但更直观。
2. location 给左上角坐标、size 给宽高，两者组合能算出元素中心点（x + width/2, y + height/2），用于 tap 点中心。
3. 属性取值用于断言（验证文案/状态）和计算（算坐标点滑动条）。

【必须掌握】

- get_attribute() 通用取属性、element.text 取文本
- location（左上角坐标）/ size（宽高）
- 中心点 = (location.x + size.width/2, location.y + size.height/2)

【企业场景】

你在企业里，断言文案用 element.text；断言元素是否可点用 get_attribute('clickable')；需要点滑动条/进度条指定位置时，用 location + size 算中心坐标再 tap。这些是"精确控制"的基础。

【面试考察】

面试官："怎么获取一个元素的中心点坐标？"

参考回答框架：location 取左上角坐标 (x, y)，size 取宽高 (width, height)，中心点 = (x + width/2, y + height/2)。

【易错点】

| 误区 | 纠正 |
|------|------|
| 原文 location 结果写 `{'y': 19,'x: 498}` | 正确是 `{'x': 498, 'y': 19}`（x 键少了闭合引号，原文笔误） |
| 以为 location 是中心点 | location 是**左上角**坐标，中心点要自己加 width/2、height/2 |

【我的理解】

> （element.location 和 element.size 合起来能算出什么？为什么 tap 滑动条中心要先算坐标而不是直接 click？）

## 四、完整示例

### 知识点 4：状态判断 + 属性获取 + 坐标点击

【课程原话/定义】

Python 示例（点击 Animation → Seeking → 查看 RUN/滑动条状态 → 获取属性 → 点滑动条中心）：

```python
# 点击 Animation
self.driver.find_element(AppiumBy.ACCESSIBILITY_ID, "Animation").click()
# 点击 Seeking
self.driver.find_element(AppiumBy.ACCESSIBILITY_ID, "Seeking").click()

# 查看 RUN 按钮状态
run_btn_ele = self.driver.find_element(AppiumBy.ID, "io.appium.android.apis:id/startButton")
print(f"RUN 按钮是否显示 {run_btn_ele.is_displayed()}")
print(f"RUN 按钮是否可用 {run_btn_ele.is_enabled()}")
print(f"RUN 按钮是否可点击 {run_btn_ele.get_attribute('clickable')}")

# 查看滑动条状态与属性
seek_bar_ele = self.driver.find_element(AppiumBy.ID, "io.appium.android.apis:id/seekBar")
print(f"滑动条是否显示 {seek_bar_ele.is_displayed()}")
print(f"滑动条是否可点击 {seek_bar_ele.get_attribute('clickable')}")
print(f"滑动条 resource-id {seek_bar_ele.get_attribute('resource-id')}")

# 获取长度与坐标，算中心点
seek_bar_ele_width = seek_bar_ele.size.get('width')
seek_bar_ele_start = seek_bar_ele.location
seek_bar_center_x = seek_bar_ele_start.get("x") + seek_bar_ele_width / 2
seek_bar_center_y = seek_bar_ele_start.get("y")
seek_bar_center = (seek_bar_center_x, seek_bar_center_y)

# 点击滑动条中心
self.driver.tap([seek_bar_center], 1000)
```

【为什么？】

1. 这是"操作 + 状态判断 + 属性获取 + 坐标计算 + 坐标点击"的全链路示范，把本章前面三个知识点串起来。
2. 滑动条（SeekBar）不能直接 click 到指定进度，要靠算中心点坐标再 tap。
3. is_displayed / is_enabled / get_attribute 组合判断，展示"验证状态"的正确姿势。

【必须掌握】

- 能看懂并复现"点滑动条中心"的完整流程
- 状态判断 + 属性获取 + 坐标计算的组合运用

【企业场景】

你在企业里，测试自定义控件（进度条、滑动条、图表）时，经常要"先算坐标再 tap"，因为这类控件没有可点元素。这套 location + size + tap 的组合是处理自定义控件的通用套路。

【面试考察】

面试官："如何测试一个 SeekBar（滑动条）的点击？"

参考回答框架：定位到 SeekBar 元素，用 size 取宽、location 取左上角坐标，算出中心点 (x+width/2, y)，再用 driver.tap([(x,y)], 时长) 点中心完成操作。

【易错点】

| 误区 | 纠正 |
|------|------|
| 直接 click 滑动条 | 滑动条要按指定位置（中心）点击，需算坐标 + tap，click 只点元素默认中心点 |
| 中心点只加 width 不加 height | 中心点 x、y 都要算：x + width/2、y + height/2（此例 y 方向中心即起点） |

【我的理解】

> （为什么 SeekBar 不能直接 click？"算中心坐标 + tap"这套思路还能用在哪些自定义控件上？）
