## 一、什么是测试体系与测试方案

### 【课程定义】

> 测试体系（Testing Framework）和测试方案设计（Test Plan Design）共同构成了有效的软件测试过程。前者是框架和结构，后者是具体执行方案。

### 【为什么两者要一起学？】

测试体系 = 你的武器库（有什么工具、什么能力）。测试方案 = 你针对具体项目的作战计划。

没有体系 → 不知道能做什么。没有方案 → 知道能做什么但不知道怎么落地。

### 【为什么测试要理解系统架构？】

面试和工作中经常被问："你们系统的架构是什么样的？"

不理解架构的测试 = 只能黑盒点点点。理解架构的测试 = 知道数据怎么流转、请求经过哪些服务、瓶颈在哪、哪层最可能出Bug。

### 【必须掌握】五大价值

| 价值 | 对你意味着什么 |
|------|--------------|
| 提高软件质量 | 架构级测试覆盖 > 功能级测试 |
| 降低开发成本 | 架构阶段发现一个问题 = 避免后期100个Bug |
| 增强测试效率 | 知道数据经过哪几层 → 精准定位问题 |
| 促进团队协作 | 和开发讨论架构 = 同一种语言 |

## 二、系统架构三视图

> 测试看架构，不是让你画架构图，而是能从三个角度理解系统。

### 【必须掌握】三种架构视角

| 架构类型 | 看什么 | 测试关注什么 |
|---------|--------|------------|
| 业务架构 | 业务流程、功能模块 | 哪些功能是核心链路？业务逻辑怎么走？ |
| 技术架构 | 技术组件、通信协议 | 用了什么框架？服务间怎么通信？ |
| 数据架构 | 数据模型、存储引擎 | 数据存在哪？怎么流转？缓存和DB怎么同步？ |

#### 【面试考察】

> 面试官："你们项目的技术架构是什么样的？"

**参考回答框架：** 不用从底层讲到顶层。抓住三层：接入层（Nginx/网关）→ 服务层（Spring Boot微服务）→ 数据层（MySQL + Redis + 消息队列）。再补一句：测试重点在服务层的接口测试和数据层的数据一致性校验。

## 四、经典技术栈全景图

> 这张图是面试时回答"你们项目用了什么技术"的参考框架。不需要全精通，但要知道每层有什么。

### 【必须掌握】分层技术栈

| 层级      | 技术组件                              | 测试对应做什么                |
| ------- | --------------------------------- | ---------------------- |
| 网关      | Nginx, Apache Httpd               | 接口转发、限流测试              |
| Web前端   | Vue.js, React                     | UI自动化（Selenium）        |
| 移动端     | Android, iOS, RN, Flutter         | App自动化（Appium）         |
| 后端应用    | Java (Spring Boot)                | 接口测试（Postman/Requests） |
| 底层引擎    | C/C++, Go, Rust                   | 了解即可                   |
| 消息管道    | Kafka, RabbitMQ                   | 消息丢失、重复消费测试            |
| 缓存系统    | Redis, MemCached                  | 缓存穿透、缓存一致性问题           |
| 数据监控    | Logstash + ElasticSearch + Kibana | 日志检索、问题定位              |
| 性能监控    | Prometheus + Grafana              | 性能基线、告警阈值              |
| 大数据     | Hadoop, Spark, Flink              | 数据准确性测试                |
| AI/深度学习 | TensorFlow, PyTorch               | 模型效果验证                 |

#### 【面试考察】

> 面试官："你们项目用了哪些中间件？你在测试中怎么关注这些中间件？"

**参考回答框架：** 我们用了Redis做缓存、Kafka做消息队列。测试重点：Redis方面关注缓存和DB的数据一致性——修改了DB但缓存没失效导致脏数据；Kafka方面关注消息重复消费和消息丢失——模拟网络抖动看消息是否能正常重试。

## 七、测试能力框架

> ![[02-Course-Notes/软件测试基础/images/Pasted image 20260702152122.png]]

### 【必须掌握】三大核心能力

| 能力               | 做什么                 | 为什么重要          |
| ---------------- | ------------------- | -------------- |
| **精准测试**         | 保证测试的充分性——只测该测的、不遗漏 | 解决"不知道测够了没有"   |
| **CI/CD/DevOps** | 提高测试效率——自动构建+自动测试   | 解决"手工重复劳动"     |
| **测试平台**         | 保证测试高效+降低沟通成本       | 解决"用例散落、进度不透明" |

#### 【面试考察】

> 面试官："你觉得一个优秀的测试工程师需要具备哪些能力？"

**参考回答框架：** 三个层次。基础层：功能测试能力（用例设计、Bug管理）。进阶层：自动化能力（接口自动化、UI自动化）+ 专项能力（性能、安全）。高阶层：架构理解（能看懂技术架构图）+ 平台思维（能把重复劳动变成平台能力）。再加上跨部门沟通能力——能推动Bug修复、能参与需求评审。
