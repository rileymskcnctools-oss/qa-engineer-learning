## 一、这一章在讲什么

前面 [[Ch18-测试框架体系（TDD-BDD-ATDD-DDT-MBT）]]、[[Ch19-持续交付与DevOps体系]]、[[Ch20-测试左移体系]]、[[Ch21-测试右移体系]]、[[Ch22-精准测试体系]] 是**一个个垂直专题**。这一章把它们收拢成一张"**测试开发工程师的能力全景图**"——回答一个根本问题：

> 一名测试开发工程师，到底要掌握哪些技术？这些技术之间是什么关系？

## 二、测试开发技术体系（四大板块）

### 【必须掌握】全景框架

测试开发的技术能力，按"被测对象 + 交付环节"分成四大板块：

```
测试开发技术体系
├── ① 用户端测试（前端）
│   ├── Web / App 测试
│   ├── Web / App 自动化测试
│   ├── 用户端专项测试
│   └── 用户端安全测试
├── ② 服务端测试（后端）
│   ├── 接口协议与 Mock
│   ├── 接口自动化测试
│   ├── 服务端性能测试
│   └── 服务端安全测试
├── ③ 持续交付（工程化）
│   ├── 容器技术 Docker
│   ├── 自动化系统 Jenkins
│   ├── 持续集成 CI
│   └── 持续交付 CD
└── ④ 测试开发（质量工程化）
    ├── 持续部署 DevOps
    ├── 测试框架 / 测试平台
    ├── 测试左移 · 精准测试
    └── 测试右移 · 质量监控
```

### 【为什么分"用户端 + 服务端 + 持续交付 + 测试开发"四块？】

用户端、服务端是**被测对象**（测什么），持续交付是**交付方式**（怎么更快地测和上线），测试开发是**能力放大器**（左移右移、框架平台，让测试更聪明）。四块合起来就是"测什么 × 怎么测 × 怎么交付 × 怎么提升"的完整闭环。

### 【我的理解】

> 思考：如果只做"用户端测试 + 服务端测试"，不做"持续交付 + 测试开发"，会卡在哪一步？反过来，只做工程化（CI/CD、框架）却不懂被测对象，又会出现什么问题？

## 三、测试开发工程师的进阶路线

### 【必须掌握】四阶段进阶

| 阶段    | 定位        | 核心能力                  | 对应板块        |
| ----- | --------- | --------------------- | ----------- |
| 手工测试  | 验证功能对不对   | 用例设计、缺陷报告             | 用户端/服务端测试   |
| 自动化测试 | 把重复验证自动化  | pytest/Selenium/接口自动化 | 用户端/服务端自动化  |
| 测试开发  | 用代码提升测试效率 | 框架/平台、工具二次开发          | 测试开发        |
| 质量工程  | 全流程质量保障   | CI/CD、左移右移、精准测试、监控    | 持续交付 + 测试开发 |

### 【为什么是这条路线？】

进阶的本质是"**从执行者变成工程化建设者**"：手工测试是在"用"测试，自动化是在"写"测试，测试开发是在"造工具让所有人测得更快"，质量工程是在"把测试嵌入研发交付全流程"。越往上，工程化能力占比越高，也越稀缺。

### 【我的理解】

> 思考：你现在处于哪个阶段？要往下一阶段走，最该补的"工程化能力"是四大板块里的哪一块？为什么？

## 四、腾讯与阿里的质量保证服务参考

### 【必须掌握】两大厂的质量能力全景

| 厂商 | 平台 | 定位 | 能力覆盖 |
|------|------|------|---------|

| 腾讯 | WeTest（测试能力全景图） | 终端/服务端质量平台 | 兼容性、性能、安全、自动化、真机云测 |

### 【为什么看大厂的质量平台？】

大厂的质量平台 = 测试开发技术体系的**产品化落地**。云效、WeTest 不是凭空来的，它们就是四大板块（用户端/服务端/持续交付/测试开发）打包成平台对外服务。看懂这些平台的功能分类，等于用真实产品验证了你学的"全景图"。

### 【企业场景】

> 你面试一家公司，面试官问"你觉得我们团队还缺什么测试能力"。你可以用全景图对照：先看他们用户端/服务端自动化做到什么程度，再看 CI/CD 有没有接入、左移右移有没有落地（精准测试、质量监控），最后指出缺口。这就是"体系化视角"的价值——不是凭感觉提建议，而是有框架地诊断。

### 【我的理解】

> 思考：把"阿里云效"和"腾讯 WeTest"的功能，分别归入四大板块的哪一块？它们各自最擅长的是哪一块？这说明大厂平台的护城河在哪？

## 五、测试能力架构图（整理笔记）

### 【必须掌握】一张图收拢全文

```
                    测试开发工程师能力架构
┌────────────────────────────────────────────────────────┐
│                    被测对象（测什么）                      │
│   ┌───────────────┐          ┌───────────────┐         │
│   │   用户端测试    │          │   服务端测试    │         │
│   │ Web/App 功能   │          │ 接口/Mock/性能  │         │
│   │ 自动化/专项/安全 │          │ 自动化/安全     │         │
│   └───────────────┘          └───────────────┘         │
├────────────────────────────────────────────────────────┤
│                  交付方式（怎么更快交付）                    │
│   Docker ──> Jenkins ──> 持续集成 CI ──> 持续交付 CD      │
├────────────────────────────────────────────────────────┤
│              能力放大器（怎么测得更聪明）                    │
│   测试框架/平台 ── 持续部署 DevOps                          │
│   测试左移·精准测试  ──  测试右移·质量监控                    │
└────────────────────────────────────────────────────────┘
```

### 【面试考察】

> 面试官："说说你对测试开发技术体系的理解。"

**参考回答框架：** 用"四块 + 一条主线"来答。四块是：用户端测试、服务端测试、持续交付、测试开发。一条主线是：前两块是被测对象（测什么），持续交付是工程化交付（Docker/Jenkins/CI/CD），测试开发是能力放大器（测试框架平台、左移精准测试、右移质量监控）。合起来就是"从测功能，到自动测，再到把测试嵌入研发交付全流程、用数据提升质量"的进阶过程。

### 【我的理解】

> 思考：把你目前学过的所有课程（软件测试基础、功能测试、测试用例、Bug定位、Python、Pytest、接口测试、SQL、Linux、Git、Docker、AI大模型）分别放进这张架构图的哪个位置？有没有哪块是"完全空白"、需要后续补的？
