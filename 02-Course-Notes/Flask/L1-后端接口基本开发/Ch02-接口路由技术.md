## 一、路由的基本概念

### 知识点 1：路由 = URL 与视图函数的映射

【课程原话/定义】
路由是将 URL 地址与应用程序中的函数相映射的过程。当用户在浏览器输入特定 URL 时，Flask 调用与该地址匹配的函数并返回结果。

在 Flask 中用 @app.route() 装饰器定义路由：
```python
from flask import Flask
app = Flask(__name__)

@app.route("/")
def index():
    return "Home Page"

@app.route("/about")
def about():
    return "About Page"
```
- @app.route('/') 访问 http://127.0.0.1:5000/
- @app.route('/about') 访问 http://127.0.0.1:5000/about

【为什么？】
为什么路由是 Web 开发的核心？因为 Web 应用的本质就是"用户通过 URL 访问不同的内容"。路由把"URL"和"处理函数"绑定起来，决定了"输入什么 URL、看到什么结果"。没有路由，Flask 就不知道 /、/about、/user/xxx 这些地址该返回什么。理解了路由，就理解了 Web 应用"URL → 内容"的响应机制——这也是测试平台后端开发里，每个接口/页面入口的定义方式。

【必须掌握】
- 路由 = URL 与函数映射，@app.route() 装饰器定义
- 基本路由：@app.route('/路径') + 视图函数
- 视图函数：处理请求并返回响应的函数
- URL 与返回内容的对应关系

【企业场景】
你在公司做测试平台后端，每个功能页面/接口都要定义一个路由。比如 /case/list 返回用例列表、/case/detail 返回用例详情。用户（或前端）访问不同 URL，Flask 调用不同函数返回不同内容。路由设计决定了平台的 URL 结构是否清晰、可访问性好坏。

【面试考察】
面试官：「Flask 里路由是什么？怎么定义？」

参考回答框架：
1. 路由 = URL 与视图函数的映射
2. 用 @app.route() 装饰器定义
3. 基本路由指定固定路径，视图函数返回内容
4. 访问 URL 时 Flask 调用匹配的函数

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 忘写 @app.route() 装饰器 | 没有装饰器，Flask 不知道这个 URL 该调用哪个函数 |
| 视图函数名和 URL 混淆 | 函数名是 Python 标识，URL 是路由路径，两者独立 |
| 忘 return | 视图函数必须返回响应，否则报错 |

【我的理解】
> （"路由 = URL 与函数映射"，这里的"映射"具体是怎么发生的？Flask 内部靠什么机制，让访问 /about 时能自动找到 about 这个函数？）

## 二、三种路由类型

### 知识点 2：基本路由、动态路由、限定类型

【课程原话/定义】
| 路由类型 | 实现方式 | 说明 |
|----------|----------|------|
| 基本路由 | @app.route('/') | 固定路径 |
| 动态路由 | @app.route('/user/<username>') | URL 中有可变部分 |
| 限定类型 | @app.route('/post/<int:post_id>') | 限制动态字段类型 |

动态路由（尖括号 <> 实现，动态部分作为参数传入函数）：
```python
@app.route("/user/<username>")
def user_info(username):
    return f"User {username} is select info."
```
访问 /user/Ron → username 参数为 "Ron"，返回 "User Ron is select info."

限定类型（<类型:变量名>，支持 int、float、string、path）：
```python
@app.route("/user/<int:user_id>")      # user_id 必须是整数
def user_id(user_id):
    return f"User ID is {user_id}"

@app.route('/path/<path:sub_path>')    # path 可包含斜杠
def show_subpath(sub_path):
    return f'Subpath is {sub_path}'
```
类型不匹配时 Flask 自动返回 404。

【为什么？】
为什么要区分基本路由和动态路由？因为现实中很多 URL 不是固定的——比如用户详情页 /user/Harry、/user/Ron 是"同一类页面、不同参数"。如果给每个用户写一个路由（/user/Harry、/user/Ron...）不可能也不现实。动态路由用 <username> 一个路由就搞定所有用户，把可变部分作为参数传给函数。而"限定类型"解决的是"参数类型安全"——/post/<int:post_id> 保证 post_id 是整数，非法输入（如 /post/abc）直接 404，不用函数里再写类型校验。这三层（基本→动态→限定）是从"固定"到"灵活"再到"类型安全"的递进。

【必须掌握】
- 基本路由：固定路径
- 动态路由：<变量名>，动态部分作为参数传入函数
- 限定类型：<int:变量名> 等，支持 int/float/string/path
- path 类型可包含斜杠
- 类型不匹配自动 404

【企业场景】
你在公司做测试平台，用户详情接口用动态路由 /user/<user_id>（限定 int），列表接口用基本路由 /user/list。动态路由让你一个函数处理所有用户，限定类型防止传入非法 ID。这是后端开发最常用的路由写法。

【面试考察】
面试官：「Flask 有哪几种路由？动态路由怎么实现？」

参考回答框架：
1. 三种：基本路由、动态路由、限定类型
2. 动态路由用 <变量名>，作为参数传入函数
3. 限定类型用 <int:变量名> 限制参数类型
4. 支持 int/float/string/path，类型不匹配返回 404

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 动态路由函数忘写同名参数 | <username> 必须对应函数参数 username |
| 限定类型写错格式 | 是 <int:user_id>，不是 <user_id:int> |
| path 和 string 混淆 | path 可包含斜杠，string 不能 |

【我的理解】
> （动态路由 <username> 是怎么把 URL 里的 "Ron" 变成函数参数 username="Ron" 的？限定类型 <int:user_id> 传了非整数为什么会 404 而不是报错？）

## 三、路由规则（尾部斜杠）

### 知识点 3：URL 尾部斜杠的重定向规则

【课程原话/定义】
Flask 的 URL 规则基于 Werkzeug 路由模块，保证 URL 唯一。

- 路由尾部带 /（如 @app.route('/hogwarts/')）：是"规范 URL"，访问时输入 / 或不输入 / 效果一样，Flask 会自动重定向补上斜杠。
- 路由尾部不带 /（如 @app.route('/about')）：访问时加 / 会产生 "Not Found" 错误。

【为什么？】
为什么要理解"尾部斜杠"规则？因为这直接关系到用户访问会不会 404。如果路由定义成 /about（无斜杠），用户手滑输入 /about/（有斜杠）就会 404；而定义成 /about/（有斜杠），Flask 会自动把 /about 重定向到 /about/。这个规则来自 Werkzeug 对"唯一 URL"的约定，理解了就能在设计路由时规避"用户多打一个斜杠就报错"的问题。实践中常采用"带斜杠"让 URL 更宽容。

【必须掌握】
- 尾部带 /：Flask 自动重定向，带不带斜杠都能访问
- 尾部不带 /：加斜杠会 404
- 规则来自 Werkzeug 路由模块的"唯一 URL"约定
- 实践建议：路由末尾统一加 /，避免用户输入斜杠导致 404

【企业场景】
你在公司定义接口 /api/users/（带斜杠），前端有时调用 /api/users（不带斜杠），Flask 自动重定向不报错。如果定义成 /api/users（不带斜杠），前端多带一个斜杠就 404，联调时容易踩坑。所以规范是路由末尾统一加斜杠。

【面试考察】
面试官：「Flask 路由末尾的斜杠有区别吗？」

参考回答框架：
1. 带斜杠：规范 URL，自动重定向，带不带都能访问
2. 不带斜杠：加斜杠会 404
3. 来自 Werkzeug 的唯一 URL 约定
4. 实践：末尾统一加斜杠

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 以为带不带斜杠都一样 | 不带斜杠的路由，用户加斜杠会 404 |
| 路由定义不一致 | 有的带 / 有的不带，导致访问行为不一致 |
| 不知道重定向机制 | 带 / 的路由会自动重定向补斜杠 |

【我的理解】
> （为什么"带斜杠"的路由会自动重定向、"不带斜杠"的不会？从"URL 唯一性"的角度，Werkzeug 为什么要设计成这种不对称的行为？）
