## 一、Web 开发技术栈

### 知识点 1：前端 / 后端 / 数据库三大技术栈

【课程原话/定义】
Web 开发分前端和后端两大部分，加上数据库，构成三大技术栈：

**前端**（用户交互）：HTML（结构）、CSS（样式）、JavaScript（交互）；框架 Vue.js / React / Angular。

**后端**（业务逻辑和数据）：Web 框架 Flask / Django / Express.js / Spring Boot。

**数据库**（持久化）：关系型 MySQL；NoSQL Redis（缓存）；ORM 工具 SQLAlchemy。

【为什么？】
为什么要先学 Web 开发基础？因为 Flask 是"后端 Web 框架"，学它之前要理解"Web 应用的整体图景"——前端负责展示、后端负责逻辑、数据库负责存储，三者配合才是一个完整应用。理解了前端/后端/数据库的分工，才知道 Flask 在整个 Web 应用里"扮演什么角色"（后端框架），以及测试平台后端开发要处理的是"业务逻辑 + 数据存储"这一层。这是学 Flask 的"地图"，先看全貌再学细节。

【必须掌握】
- 前端：HTML/CSS/JS + Vue/React/Angular
- 后端：Flask/Django/Express/Spring Boot
- 数据库：MySQL（关系型）、Redis（缓存）、SQLAlchemy（ORM）
- Flask 属于后端 Web 框架，负责业务逻辑和数据

【企业场景】
你在公司测试平台后端开发，前端（Vue）负责页面展示，后端（Flask）负责接口和业务逻辑，数据库（MySQL + SQLAlchemy）负责存储测试数据。理解这三层分工，就知道"接口"是前端和后端的桥梁，也是测试的重点。

【面试考察】
面试官：「说说 Web 开发的前端、后端、数据库技术栈分别是什么？」

参考回答框架：
1. 前端：HTML/CSS/JS + Vue/React/Angular
2. 后端：Flask/Django/Express/Spring Boot
3. 数据库：MySQL/Redis + SQLAlchemy ORM
4. 三者分工：展示 / 逻辑 / 存储

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 认为 Flask 管前端 | Flask 是后端框架，前端是 HTML/CSS/JS |
| 混淆 Redis 和 MySQL | Redis 是内存缓存（NoSQL），MySQL 是关系型 |
| 不理解三者配合 | 前端展示 → 后端逻辑 → 数据库存储，三层配合 |

【我的理解】

## 二、Web 架构与 HTTP 协议

### 知识点 2：四层架构 + HTTP 请求/响应

【课程原话/定义】
Web 产品四层架构：
- **客户端（前端）**：浏览器/移动应用，展示数据、处理输入
- **Web 服务器**：Nginx/Apache，接收请求转发给应用
- **应用层（后端）**：处理请求、执行业务逻辑、与数据库交互
- **数据层（数据库）**：MySQL/PostgreSQL/MongoDB 存储数据

HTTP 协议：
- **请求**：请求行（方法 GET/POST/PUT/DELETE + URL + 版本）、请求头、请求体
- **响应**：响应行（版本 + 状态码 + 状态消息）、响应头、响应体
- **状态码**：200 成功、301 永久重定向、404 未找到、500 服务器错误

【为什么？】
为什么要理解四层架构和 HTTP 协议？因为这是"接口测试"和"后端开发"的共同基础。四层架构让你知道"一个请求是怎么从浏览器走到数据库的"（客户端 → Web 服务器 → 应用层 → 数据层），而 HTTP 协议让你知道"请求和响应的结构"（请求行/头/体、状态码）。接口测试的本质就是"构造 HTTP 请求、校验 HTTP 响应"，理解 HTTP 的请求方法（GET/POST/PUT/DELETE）和状态码（200/404/500），是接口测试的"语言基础"。

【必须掌握】
- 四层：客户端 → Web 服务器 → 应用层 → 数据层
- HTTP 请求：请求行（方法+URL+版本）、请求头、请求体
- HTTP 响应：响应行（版本+状态码）、响应头、响应体
- 方法：GET 查 / POST 增 / PUT 改 / DELETE 删
- 状态码：200 / 301 / 404 / 500

【企业场景】
你在公司做接口测试，每天打交道的就是 HTTP 请求和响应——构造 GET/POST 请求、看状态码（200 成功、404 没找到、500 服务器错）、解析响应体（JSON）。理解 HTTP 协议，就知道"测接口到底在测什么"。

【面试考察】
面试官：「HTTP 请求和响应由哪几部分组成？常见状态码？」

参考回答框架：
1. 请求：请求行（方法/URL/版本）+ 请求头 + 请求体
2. 响应：响应行（版本/状态码）+ 响应头 + 响应体
3. 方法：GET/POST/PUT/DELETE
4. 状态码：200 成功、301 重定向、404 未找到、500 服务器错

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| GET 和 POST 用途混淆 | GET 查（参数在 URL），POST 增（数据在请求体） |
| 404 和 500 分不清 | 404 客户端（资源不存在），500 服务端（内部错误） |
| 请求头和请求体混淆 | 头是元信息（格式等），体是数据本体 |

【我的理解】
