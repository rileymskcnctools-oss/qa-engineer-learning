## 一、多对多关系的建立

### 知识点 1：中间表 + relationship(secondary)

【课程原话/定义】
多对多：多个数据行与多个其他数据行相关联（如学生和老师，一个学生有多个老师，一个老师教多个学生）。关系型数据库不允许两表直接多对多，需通过"中间表"拆成两个一对多。

建立步骤：
1. 定义三张表（两个主表 + 一个中间表）
2. 中间表包含两个主表的外键
3. 用 relationship() 关联（secondary 指向中间表）

```python
# 中间表
teacher_student_rel = Table(
    "teacher_student", Base.metadata,
    Column("id", Integer, primary_key=True),
    Column("teacher_id", Integer, ForeignKey("teacher.id")),
    Column("student_id", Integer, ForeignKey("student.id"))
)

class Teacher(Base):
    __tablename__ = "teacher"
    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False, unique=True)
    students = relationship("Student", secondary=teacher_student_rel, backref="teachers")

class Student(Base):
    __tablename__ = "student"
    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False, unique=True)
```

建立关联：
```python
tea1.students = [stu1, stu2]   # 老师1 关联 学生1、学生2
db_session.commit()
```

【为什么？】
为什么多对多要中间表？因为关系型数据库的表是"平面"的，无法直接表示"多对多"的网状关联。中间表把"多对多"拆成"两个一对多"（老师—中间表—学生），这是关系型数据库表达多对多的标准范式。而 relationship(secondary=中间表) 让开发者不用手动操作中间表，直接 tea1.students = [stu1, stu2] 就能建立关联，SQLAlchemy 自动维护中间表。理解"中间表 + secondary"，是理解"复杂数据关系"的关键。

【必须掌握】
- 多对多需中间表（包含两个主表的外键）
- 中间表用 Table() 定义（不是 class）
- relationship("类名", secondary=中间表, backref='反向')
- 建立关联：tea1.students = [stu1, stu2]
- 查询：stu1.teachers、tea1.students

【企业场景】
你在公司测试平台，"用户"和"项目"是多对多（一个用户参与多个项目，一个项目有多个用户）。建一个 user_project 中间表，用 relationship(secondary) 关联，就能优雅地"查用户参与的所有项目"或"查项目的所有成员"。

【面试考察】
面试官：「SQLAlchemy 怎么建立多对多关系？」

参考回答框架：
1. 多对多要中间表（含两个主表外键）
2. 中间表用 Table() 定义
3. relationship(secondary=中间表, backref=反向)
4. 直接给 relationship 属性赋值建立关联

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 想直接两表建多对多 | 必须加中间表，拆成两个一对多 |
| 中间表用 class 定义 | 中间表用 Table()，不是继承 Base 的 class |
| 忘 secondary 参数 | relationship 要 secondary 指向中间表 |
