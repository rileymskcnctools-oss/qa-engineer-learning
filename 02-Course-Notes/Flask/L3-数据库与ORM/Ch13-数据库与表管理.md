## 一、表的创建与删除

### 知识点 1：create_all / drop_all

【课程原话/定义】
有了数据库配置后，可对表进行操作：
- 创建表：Base.metadata.create_all(engine)
- 删除表：Base.metadata.drop_all(engine)

定义表结构：
```python
class User(Base):
    __tablename__ = "user"
    id = Column(Integer, primary_key=True)
    username = Column(String(20))
    password = Column(String(20))

if __name__ == '__main__':
    Base.metadata.create_all(engine)   # 创建表
    # Base.metadata.drop_all(engine)   # 删除表
```

创建表的注意事项：
1. 必须继承 Base 基类对象
2. 表类和创建表代码在同一文件
3. 必须执行 create_all(engine)

【为什么？】
为什么要用 create_all 而不是手写 CREATE TABLE SQL？因为 ORM 已经把"类定义"和"表结构"绑定了——你定义好 User 类（字段、类型、约束），create_all 就能自动生成对应的建表 SQL。这体现了 ORM 的核心价值：表结构只定义一次（在类里），建表、删表、增删改查都复用这个定义。而注意事项（继承 Base、同文件）是 create_all 能"扫描到类定义"的前提。

【必须掌握】
- Base.metadata.create_all(engine)：创建所有表
- Base.metadata.drop_all(engine)：删除所有表
- 表类必须继承 Base、__tablename__ 指定表名
- create_all 基于类定义自动建表

【企业场景】
你在公司测试平台，定义好所有模型类（TestCase、User、Report 等）后，跑一次 create_all(engine) 就把所有表建好了，不用手写一堆 CREATE TABLE。模型类就是"表的唯一定义来源"。

【面试考察】
面试官：「SQLAlchemy 怎么建表？有哪些注意事项？」

参考回答框架：
1. Base.metadata.create_all(engine)
2. 表类继承 Base，__tablename__ 指定表名
3. 删除用 drop_all
4. 类定义 = 表结构定义，建表删表都基于它

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 表类不继承 Base | create_all 扫描不到，建不出表 |
| 忘执行 create_all | 类定义了但没执行建表，数据库里没表 |
| 表类和建表代码不同文件 | create_all 要在能 import 到类的地方执行 |

【我的理解】
> （create_all(engine) 是怎么"自动"生成建表 SQL 的？它从哪里读到的表名、字段、类型这些信息？）
