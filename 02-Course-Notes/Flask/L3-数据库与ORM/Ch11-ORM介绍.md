## 一、ORM 与持久化

### 知识点 1：对象关系映射解决什么问题

【课程原话/定义】
ORM（Object Relational Mapping，对象关系映射）：将数据库表与面向对象语言中的类建立对应关系，通过描述对象与表之间的映射，自动将对象持久化到关系型数据库表中。

持久化（Persistence）：把内存中的对象保存到可永久保存的存储设备（如磁盘）。因为程序中断/断电后内存数据消失，需要持久化才能保留。

ORM 的三层映射关系：
- 类 ↔ 表（每张表对应一个类）
- 对象 ↔ 记录（每条记录对应一个实例）
- 类的属性 ↔ 表的字段

【为什么？】
为什么要 ORM？因为传统数据库操作要写复杂 SQL（连接、游标、执行、取结果、关连接），而数据库的表、字段和实体类之间没有一一对应。ORM 的解法是：让"类=表、对象=记录、属性=字段"一一对应，用面向对象的方式（操作对象）代替手写 SQL。后端工程师就不用为每个操作写 SQL，代码更简洁、更贴近业务逻辑。这也是测试平台后端开发里，操作数据库的标准方式。

【必须掌握】
- ORM = 对象关系映射，类↔表、对象↔记录、属性↔字段
- 持久化 = 内存对象保存到磁盘（防断电丢失）
- ORM 替代手写 SQL，用对象操作数据库
- ORM 对比 SQL：代码更简洁，抽象数据访问层

【企业场景】
你在公司测试平台后端，要存取测试用例数据。用 ORM 后，定义一个 TestCase 类（对应 test_case 表），新增用例就是实例化 TestCase 对象 + add + commit，不用写 INSERT 语句。表结构和字段变了，只改类定义，业务代码不受影响。

【面试考察】
面试官：「什么是 ORM？为什么要用 ORM？」

参考回答框架：
1. ORM 对象关系映射，类↔表、对象↔记录、属性↔字段
2. 用面向对象方式操作数据库，替代手写 SQL
3. 优点：开发效率高、数据库无关、减少 SQL 注入
4. 持久化解决内存数据断电丢失

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 以为 ORM 完全不用懂 SQL | 复杂查询仍需理解 SQL，ORM 是封装不是替代 |
| ORM 只有优点 | 有性能开销、复杂查询性能下降 |
| 映射关系记混 | 类↔表、对象↔记录、属性↔字段，一一对应 |
