## 一、用类定义表结构

### 知识点 1：Column 定义字段、数据类型与列选项

【课程原话/定义】
类名相当于表名（驼峰转下划线，如 class UserInfo → user_info），可用 __tablename__ 自定义。

字段定义：`name = Column(数据类型, 列选项...)`
```python
class User(Base):
    __tablename__ = "user"
    id = Column(Integer, primary_key=True, comment="用户ID")
    username = Column(String(80), unique=True, nullable=False, comment="用户名")
    email = Column(String(120), unique=True, nullable=False, comment="邮箱")
    gender = Column(String(3), comment="性别")
```

常用数据类型：Integer、SmallInteger、BigInteger、Float、Numeric、String、Text、JSON、Boolean、Date、Time、LargeBinary

常用列选项：
| 选项 | 说明 |
|------|------|
| primary_key | 是否主键 |
| unique | 是否唯一 |
| nullable | 是否允许空 |
| default | 默认值 |
| index | 是否建索引（提高查询效率） |
| comment | 注释 |

【为什么？】
为什么要理解"用类定义表结构"？因为这是 ORM 的"数据建模"环节——类的每个属性（Column）对应表的一个字段，数据类型和列选项（主键/唯一/非空/索引/注释）定义了字段的约束。这一层决定了"数据库表长什么样、数据受什么约束"。写对了，后续 CRUD、关联查询、数据完整性都有保障；写错了（比如漏了 unique、忘了 nullable=False），数据就会脏、查询就会错。这是测试平台后端"数据层"的地基。

【必须掌握】
- Column(类型, 选项) 定义字段
- 常用类型：Integer、String(长度)、JSON、DateTime、Boolean
- 列选项：primary_key、unique、nullable、default、index、comment
- __tablename__ 自定义表名，否则驼峰转下划线
- __repr__ 自定义对象输出（调试友好）

【企业场景】
你在公司定义 TestCase 模型：id 主键、name 唯一非空、detail 可空有默认值、create_time 时间。字段约束（unique 防重复、nullable 防空值）就是数据质量的保障。定义好模型后，建表、增删改查都基于这个定义。

【面试考察】
面试官：「SQLAlchemy 怎么定义一个表模型？字段有哪些列选项？」

参考回答框架：
1. 类继承 Base，__tablename__ 指定表名
2. 属性 = Column(类型, 选项) 定义字段
3. 常用类型：Integer/String/JSON/DateTime
4. 列选项：primary_key/unique/nullable/default/index/comment

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 漏了 unique=True | 用户名等字段应唯一，否则数据重复 |
| nullable 和 default 混淆 | nullable 控制是否允许空，default 是默认值 |
| String 不写长度 | String(80) 要指定最大长度 |

【我的理解】
