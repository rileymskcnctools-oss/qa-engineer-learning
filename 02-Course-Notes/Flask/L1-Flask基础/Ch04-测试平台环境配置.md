## 一、监听主机与端口

### 知识点 1：app.run() 的 host 和 port 参数

【课程原话/定义】
app.run() 方法运行应用并设置监听的主机和端口，默认监听 127.0.0.1（localhost）和端口 5000。

**host 参数**：
- 127.0.0.1：只能本机访问（默认）
- 0.0.0.0：服务发布到局域网（监听所有网络接口）

```python
app.run(host="0.0.0.0")
```
设 host="0.0.0.0" 后，可通过 http://<本机IP>:5000 访问（如 http://192.168.1.100:5000/）。

**port 参数**（默认 5000）：
```python
app.run(host="0.0.0.0", port=5050)
```

【为什么？】
为什么要配置 host 和 port？因为默认 127.0.0.1 只能本机访问——你在电脑 A 起服务，电脑 B 访问不了。测试平台是给团队用的，必须让局域网内其他人（前端、其他测试、领导演示）也能访问，所以要 host="0.0.0.0"。而 port 配置是为了避开端口冲突——5000 可能被占用，或需要多个服务并行跑不同端口。理解 host 和 port，是"把 Flask 应用真正发布出去给团队用"的前提。

【必须掌握】
- app.run() 默认 host=127.0.0.1、port=5000
- host="0.0.0.0" 让局域网可访问（监听所有接口）
- port 参数改端口（默认 5000）
- 0.0.0.0 后访问地址：http://本机IP:端口

【企业场景】
你在公司本地开发测试平台，自己访问用默认 127.0.0.1 就行。但要给前端联调、给领导演示，必须 host="0.0.0.0"，让他们用你的 IP 访问。如果 5000 被其他服务占了，就 port 改成 5050。这些是"把本地服务变成团队可用的服务"的基本操作。

【面试考察】
面试官：「Flask 怎么让局域网内其他机器访问你的应用？」

参考回答框架：
1. app.run(host="0.0.0.0")
2. 0.0.0.0 监听所有网络接口，127.0.0.1 只能本机
3. 其他机器通过 http://本机IP:5000 访问
4. port 参数改端口

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 默认 127.0.0.1 想让别人访问 | 必须 host="0.0.0.0" 才能局域网访问 |
| host 和 port 写反 | host 是主机地址，port 是端口号 |
| 0.0.0.0 理解成某个具体 IP | 0.0.0.0 是"所有接口"，不是具体地址 |

## 二、Debug 调试模式

### 知识点 2：debug=True 的三大作用 + 生产环境禁用

【课程原话/定义】
app.run() 设置 debug=True（默认 production）。

Debug 模式三大作用：
1. **显示详细错误信息**：出错时显示完整错误堆栈，方便定位
2. **自动重新加载代码**：修改代码后 Flask 自动重载，无需手动重启
3. **支持实时调试器**：浏览器里显示源码、支持断点调试和变量查看

```python
app.run(host="0.0.0.0", port=5050, debug=True)
```

**注意**：生产环境必须禁用 debug，因为它会暴露应用详细信息 + 自动重载代码有安全/性能风险。

【为什么？】
为什么 debug 模式是开发必备、生产禁用？因为开发阶段要快速迭代——改代码不用手动重启（自动重载）、出错能看到完整堆栈（快速定位）、能断点调试（实时调试器），这三个能力让开发效率大增。但 debug 的这些能力在生产环境是"危险品"：详细错误信息会暴露代码结构和敏感信息给攻击者，自动重载可能带来安全风险。所以 debug 是"开发期利器、生产期禁药"，这个边界必须清楚。

【必须掌握】
- debug=True 三大作用：详细错误 / 自动重载 / 实时调试器
- 默认 debug=False（production）
- 生产环境必须禁用 debug（安全 + 性能）
- 开启方式：app.run(debug=True)

【企业场景】
你在公司开发测试平台，开发阶段 debug=True——改代码自动生效、报错看堆栈，效率高。上线前一定要 debug=False，否则线上报错会暴露代码路径、数据库信息等，是严重安全漏洞。这是"开发/生产配置分离"的典型例子。

【面试考察】
面试官（高频）：「Flask 的 debug 模式有什么用？生产环境能用吗？」

参考回答框架：
1. 三大作用：详细错误信息、自动重载代码、实时调试器
2. 开发阶段用，加速开发调试
3. 生产环境禁用：暴露信息 + 安全风险
4. 通过 app.run(debug=True) 开启

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 生产环境开 debug | 暴露代码/敏感信息，严重安全漏洞 |
| 以为 debug 只影响报错显示 | 还有自动重载、实时调试器两个作用 |
| 默认以为 debug 是开的 | 默认 debug=False（production） |

【扩展知识】
debug 模式只是 Flask 配置的冰山一角。真实的测试平台还会配置 SECRET_KEY（会话加密）、数据库连接、日志级别等。这些配置在生产环境通常通过环境变量或配置文件注入（如 config.py + FLASK_ENV），而不是硬编码。理解 debug 的"开发/生产分离"，是理解"配置管理"的第一课。
