## 一、同源策略与跨域

### 知识点 1：跨域的本质是浏览器的同源策略

【课程原话/定义】
前后端联调常见的报错：
```
Access to XMLHttpRequest at 'http://127.0.0.1:5000/login' from origin
'http://localhost:8080' has been blocked by CORS policy: No
'Access-Control-Allow-Origin' header is present on the requested resource.
```

**同源策略**：浏览器最核心的安全功能，阻止一个域的 JS 脚本和另一个域的内容交互。所谓"同源"指两个页面协议、主机、端口号三者都相同。

**跨域**：请求 URL 的协议、域名、端口三者中任意一个与当前页面 URL 不同即为跨域。如前端 http://localhost:8080 请求 API http://127.0.0.1:5000 就跨域（域名不同）。

【为什么？】
为什么浏览器要"限制"跨域？因为如果没有同源策略，恶意网站 A 的 JS 就能随意读取你在网站 B 的登录态、数据，发起 XSS/CSRF 攻击。同源策略是浏览器保护用户安全的基本防线。但它也带来麻烦：前后端分离开发时，前端（8080）调后端（5000）就是跨域，会被浏览器拦截。所以理解"跨域是浏览器端的安全限制（不是服务端限制）"，是解决跨域问题的前提——服务端要主动声明"允许哪些源访问我"（CORS 头）。

【必须掌握】
- 同源 = 协议 + 主机 + 端口三者都相同
- 跨域 = 三者任一不同
- 跨域限制发生在浏览器端（不是服务端）
- 同源策略防 XSS/CSRF 攻击
- 解决：服务端返回 Access-Control-Allow-Origin 头（CORS）

【企业场景】
你在公司前后端分离开发：前端跑在 localhost:8080，后端 Flask 跑在 127.0.0.1:5000，前端一调接口就报 CORS 错。根因是浏览器拦了跨域请求。你要在后端 Flask 加 CORS 支持，允许 8080 这个源访问。这是前后端分离项目的"第一道坎"。

【面试考察】
面试官：「什么是跨域？为什么会跨域？怎么解决？」

参考回答框架：
1. 同源策略：协议+主机+端口三者相同才是同源
2. 跨域 = 三者任一不同
3. 浏览器端安全限制（防 XSS/CSRF）
4. 解决：后端加 CORS 头（Access-Control-Allow-Origin）

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 以为是后端拒绝了请求 | 跨域是浏览器拦截的，请求可能已到后端但响应被拦 |
| 前端加 header 解决 | CORS 头要后端返回，前端加不了 |
| 端口不同不算跨域 | 端口不同也算跨域（协议+主机+端口都算） |

【我的理解】

## 二、flask-cors 解决跨域

### 知识点 2：全局 CORS 与局部 cross_origin

【课程原话/定义】
安装 flask-cors：pip install flask-cors

两种解决方式：
```python
from flask import Flask
from flask_cors import CORS, cross_origin
app = Flask(__name__)

# 方式一：全局解决（对所有 API 开跨域）
CORS(app, supports_credentials=True)

@app.route('/hello')
def hello():
    return "hello world"
```
方式二：局部解决（只对特定 API 开跨域）：
```python
@app.route('/hello')
@cross_origin(supports_credentials=True)
def hello():
    return "hello world"
```

也可结合蓝图使用（CORS 全局 + 蓝图路由上 @cross_origin 局部）。

【为什么？】
为什么要区分"全局"和"局部"？因为安全。全局 CORS(app) 会让所有接口都允许跨域，方便但扩大了暴露面；局部 @cross_origin 只对需要跨域的几个接口开放，更精细、更安全。真实项目里，通常"能局部就局部"，只有整个服务都面向跨域调用时才全局开。supports_credentials=True 是允许携带 Cookie 等凭证跨域（登录态场景需要）。理解这两种粒度，是"安全与便利的平衡"。

【必须掌握】
- pip install flask-cors
- 全局：CORS(app, supports_credentials=True)
- 局部：@cross_origin(supports_credentials=True)
- supports_credentials 允许携带凭证（Cookie）
- 结合蓝图：全局 CORS + 蓝图路由上局部 @cross_origin

【企业场景】
你在公司测试平台，只有登录接口和几个查询接口需要被前端（跨域）调用，其他接口是内部调用。就用局部 @cross_origin 只给这几个接口开跨域，而不是全局 CORS 把整个平台暴露。这是更安全的做法。

【面试考察】
面试官：「Flask 怎么解决跨域？全局和局部有什么区别？」

参考回答框架：
1. 用 flask-cors 扩展
2. 全局：CORS(app)，所有接口开跨域
3. 局部：@cross_origin()，只对特定接口开
4. 局部更安全，按需开放

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 忘装 flask-cors | pip install flask-cors，不是 Flask 自带 |
| 需要带 Cookie 但没 supports_credentials | 跨域携带凭证要 supports_credentials=True |
| 全局 CORS 滥用 | 扩大暴露面，能局部就局部 |

【我的理解】
> （CORS 的 Access-Control-Allow-Origin 头是谁加的？为什么"跨域限制在浏览器端"，但"解决跨域要在服务端"？）
