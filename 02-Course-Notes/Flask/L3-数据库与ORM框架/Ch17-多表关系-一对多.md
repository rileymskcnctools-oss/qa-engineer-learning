## 一、一对多关系的建立与查询

### 知识点 1：ForeignKey + relationship + backref

【课程原话/定义】
一对多（One-to-Many）：一个表的记录对应另一个表的多个记录。如一个班级（ClassInfo）有多个学生（StudentInfo），每个学生只属于一个班级。

建立方式：在"多"的一方引入外键（ForeignKey 指向"一"的一方主键），再用 relationship 建立关联。

```python
class ClassInfo(Base):
    __tablename__ = "class_info"
    id = Column(Integer, primary_key=True)
    name = Column(String(30))

class StudentInfo(Base):
    __tablename__ = 'student_info'
    id = Column(Integer, primary_key=True)
    name = Column(String(30))
    class_id = Column(Integer, ForeignKey("class_info.id"))   # 外键
    class_info = relationship("ClassInfo", backref='student_info')  # 关联关系
```

查询：
```python
# 多查一：id=3 的学生对应的班级
stu_info = db_session.query(StudentInfo).filter_by(id=3).first()
print(stu_info.class_info.name)   # 通过 relationship 反向拿到班级

# 一查多：id=1 的班级里所有学生
my_class = db_session.query(ClassInfo).filter_by(id=1).first()
print(my_class.student_info)      # 通过 backref 拿到学生列表
```

【为什么？】
为什么要 relationship？因为只用 ForeignKey，只能拿到"学生的 class_id"这个数字，想拿班级名称还得再查一次。relationship + backref 让关联查询变得优雅：学生对象直接 .class_info 拿到班级对象、班级对象直接 .student_info 拿到学生列表，不用手写 JOIN。这本质是把"SQL 的 JOIN 关联"封装成了"对象的属性访问"——用面向对象的方式表达表之间的关联。

【必须掌握】
- 一对多：在"多"的一方加 ForeignKey("一表.主键")
- relationship("类名", backref='反射名') 建立关联
- 多查一：对象.relationship属性 拿到"一"的对象
- 一查多：对象.backref名 拿到"多"的列表
- 修改：由一改多（班级改学生）、由多改一（学生改班级）

【企业场景】
你在公司测试平台，一个"项目"（Project）有多个"用例"（TestCase）。定义 TestCase 加 project_id 外键 + relationship，就能优雅地"查项目下的所有用例"或"查用例属于哪个项目"，不用写 JOIN SQL。

【面试考察】
面试官：「SQLAlchemy 怎么建立一对多关系？」

参考回答框架：
1. "多"的一方加 ForeignKey 外键指向"一"的主键
2. relationship("类名", backref='反射名') 建立关联
3. 多查一：对象.relationship 拿"一"的对象
4. 一查多：对象.backref 拿"多"的列表

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 只加 ForeignKey 不加 relationship | 只能拿外键数字，不能优雅地关联查对象 |
| backref 方向搞反 | backref 是"反向引用"，定义在 relationship 一侧 |
| relationship 参数写错 | 第一个参数是关联类名（字符串），backref 是反向属性名 |
