## 一、完整的 CRUD 接口开发

### 知识点 1：Flask + SQLAlchemy + pydantic 三层配合

【课程原话/定义】
用 MySQL + SQLAlchemy + Flask 完成课程管理的增删改查后端。

**接口设计**：
| 功能 | 请求 URL | 方法 |
|------|----------|------|
| 课程新增 | /course | POST |
| 课程删除 | /course | DELETE |
| 课程修改 | /course | PUT |
| 获取课程 | /course/<id> | GET |
| 课程列表 | /course/list | GET |

**三层配合**：
1. SQLAlchemy 定义 ORM 模型（Course 类）
2. pydantic 定义数据校验模型（CourseModel，验证请求体）
3. Flask 蓝图定义接口（route + 增删改查逻辑）

```python
# pydantic 数据校验
class CourseModel(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    name: constr(max_length=30)
    detail: Optional[constr(max_length=255)] = ""

# 新增课程
@course_manager.post("")
def create_course():
    course_json = request.get_json()
    try:
        CourseModel.model_validate(course_json)   # 校验请求体
    except ValidationError as e:
        return {"errcode": 10002, "errmsg": repr(e.errors())}
    db_session.add(Course(**course_json))         # 入库
    db_session.commit()
    db_session.close()
    return {"errcode": 0, "errmsg": "创建课程成功！"}
```

【为什么？】
为什么这个实战要引入 pydantic？因为之前的 CRUD 是"直接操作数据库"，但真实接口要处理"外部传来的数据"——外部数据不可信，必须校验（字段类型对不对、长度超不超、必填有没有）。pydantic 就是干这个的：CourseModel.model_validate() 校验请求体，不合规就返回错误码 10002，合规才入库。这套"pydantic 校验 → SQLAlchemy 入库 → 统一错误码返回"是测试平台后端的标准范式，把"数据校验"和"数据存储"解耦了。

【必须掌握】
- 接口设计：RESTful 风格（POST/PUT/DELETE/GET）
- pydantic：model_validate 校验请求体，model_dump 转字典
- SQLAlchemy：ORM 模型 + CRUD
- Flask 蓝图：Blueprint + url_prefix 管理路由
- 统一错误码：errcode=0 成功，10001 不存在，10002 参数错误

【企业场景】
你在公司开发测试平台的用例管理模块，就是这套范式：pydantic 定义用例的数据模型（校验前端传参）、SQLAlchemy 定义用例表（存储）、Flask 蓝图定义增删改查接口（/case POST/PUT/DELETE/GET）。错误统一返回 errcode，前端根据 errcode 提示用户。

【面试考察】
面试官：「说说你怎么开发一个后端增删改查模块？」

参考回答框架：
1. 需求分析 + 接口设计（RESTful）
2. SQLAlchemy 定义 ORM 模型
3. pydantic 定义数据校验模型
4. Flask 蓝图实现增删改查接口
5. 统一错误码返回

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 不校验请求体直接入库 | 外部数据不可信，要 pydantic 校验 |
| 忘 commit / close | 增删改要 commit，用完 close |
| 错误码不统一 | 用 errcode 统一（0 成功 / 10001 不存在 / 10002 参数错） |

【扩展知识】
pydantic 的 model_validate（校验 + 解析）和 model_dump（对象转字典）是两个核心方法：前者把"外部 JSON"校验成可信对象，后者把"ORM 对象"转成可返回的字典。这正好是"输入校验"和"输出序列化"两个方向，理解它们就理解了"数据在接口边界的进出"。
