## 一、电脑端证书配置

### 知识点 1：电脑证书安装（Mac / Windows）

【课程原话/定义】
Charles 开始使用前需要完成一系列设置。电脑证书配置：`Help → SSL Proxying → Install Charles Root Certificate`。
- **Mac**：安装证书 → 进入钥匙串 → 信任证书（注意选择"始终信任"）
- **Windows**：进入证书导入向导 → 点击安装证书 → 选择本地计算机 → 将证书放入"受信任的根证书颁发机构" → 一直下一步 → 安全警告点"是" → 导入成功

【为什么？】
为什么要装证书？因为 HTTPS 的流量是加密的，Charles 作为中间人要解密，就必须让系统"信任"它自己的根证书。装了根证书后，系统会把 Charles 当作可信的"证书颁发机构"，Charles 才能对每个域名签发临时证书、完成"冒充服务器"的过程。**不装证书 = 只能看到 `CONNECT xxx:443` 的握手，看不到明文**。Mac 上"始终信任"是关键——只安装不信任，系统仍然不认。

【必须掌握】
- 安装入口：Help → SSL Proxying → Install Charles Root Certificate
- Mac：钥匙串里找到证书，改为"始终信任"
- Windows：证书导入到"受信任的根证书颁发机构"（不是"个人"存储）
- 装证书的目的：让系统信任 Charles 的根证书，才能解密 HTTPS

【企业场景】
你在公司第一次用 Charles 抓 https 接口，发现只能看到一堆 `CONNECT` 请求、看不到接口明文。排查顺序：① 证书装了吗；② 钥匙串里是不是"始终信任"（Mac）；③ Proxy 里 SSL Proxying 开了吗。三步都对了，HTTPS 明文才会出来。

【面试考察】
面试官："为什么 Charles 抓 HTTPS 必须装证书？装在哪里？"

参考回答框架：
1. HTTPS 是加密的，Charles 要解密必须做中间人
2. 它需要系统信任自己的根证书，才能签发临时证书冒充服务器
3. Windows 装在"受信任的根证书颁发机构"，Mac 在钥匙串里"始终信任"
4. 不装证书，只能看到握手，看不到明文

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 只安装证书不信任 | Mac 必须在钥匙串里选"始终信任"，否则系统不认 |
| Windows 证书装到"个人"存储 | 应装到"受信任的根证书颁发机构" |
| 装了证书就能抓 https | 还要在 Charles 里开启 SSL Proxying（见知识点 2） |

【我的理解】
> （为什么"装证书"和"信任证书"是两回事？Mac 上如果只安装、不设"始终信任"，抓 https 时会发生什么？）

### 知识点 2：Charles 端开启 SSL 代理

【课程原话/定义】
Charles 端设置 SSL：`Proxy → SSL Proxying Settings`，在这里配置要抓取 https 的域名。

【为什么？】
为什么"装了证书"还不够，还要在 Charles 里配置 SSL Proxying？因为 Charles 默认**不代理任何 HTTPS 流量**——它只对你在 SSL Proxying Settings 里配置了 Host 的域名才做解密转发。这样设计是为了效率和安全（避免无差别解密所有流量）。所以即使证书装好了，没配 SSL Proxying，https 接口照样只显示 `CONNECT`。

【必须掌握】
- 开启路径：Proxy → SSL Proxying Settings
- 需要添加要抓取的 Host（域名），可加通配符如 `*.*`
- 配置后，匹配的域名才会被解密显示明文
- 抓 https 的完整前提：装证书（信任）+ 开启 SSL Proxying + 配置 Host

【企业场景】
你在公司抓某个 https 接口，证书都装好了还是看不到明文，十有八九是 SSL Proxying Settings 里没加这个域名。加一条 Host（如 `*.hogwarts.ceshiren.com`），重新请求，明文就出来了。

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 认为装了证书就自动抓 https | 还要开 SSL Proxying 并配置 Host |
| SSL Proxying 配了所有域名导致混乱 | 建议只配置要测的域名，减少无关流量 |
| 只看到 CONNECT 请求以为抓包失败 | 是 https 未被解密的表现，补 SSL Proxying 配置即可 |

【我的理解】
> （"装证书"和"开 SSL Proxying"分别解决的是什么问题？为什么两个都要做？）

## 二、移动端代理配置

### 知识点 3：移动端代理配置（模拟器 / 真机）

【课程原话/定义】
移动端代理配置：
- 设备和电脑处于**同一 WIFI**（模拟器不需要配置）
- 进入 `Proxy → Proxy Setting`，勾选 **Enable transparent HTTP proxying**（可抓移动设备的数据包），查看代理 IP 地址与端口
- **模拟器（mumu）**：进入 mumu 网络设置 → 长按连接的网络 → 修改网络 → 设置代理 → 保存
- **安装证书**：系统浏览器输入 `chls.pro/ssl`，自动下载 Charles 证书并安装
- **允许远程代理**：Charles 弹窗点 allow

iOS 系统配置代理：
- 设置 → 网络 → 配置代理 → 手动，服务器填电脑 IP，端口填 Charles 监听端口（默认 8888）
- 下载证书：浏览器输入 `chls.pro/ssl`
- 安装证书：通用 → VPN 与设备管理 → 选择 Charles Proxy CA → 安装
- 信任证书：通用 → 关于本机 → 证书信任设置 → 打开 Charles Proxy CA 开关

【为什么？】
为什么要让手机和电脑同一 WIFI？因为代理是"手机把流量发给电脑上的 Charles"，手机必须能访问到电脑的 IP。手机设置代理（电脑 IP + 端口 8888）后，手机的流量就会先到 Charles 再出去，Charles 就能抓手机的包。`chls.pro/ssl` 是 Charles 官方的证书下载地址——手机浏览器访问它会自动下载根证书，装到手机上才能解密手机侧的 https。最后弹窗点 allow 是授权"允许这个设备连入代理"。

【必须掌握】
- 手机和电脑同一网络（同一 WIFI），模拟器天然同机无需配
- 手机代理：电脑 IP + Charles 端口（默认 8888）
- 手机证书：浏览器访问 `chls.pro/ssl` 下载安装
- iOS 额外要"信任证书"（证书信任设置打开开关）
- 首次连接需在 Charles 弹窗点 allow 授权

【企业场景】
你在公司抓 App 的 https 接口：电脑开 Charles → 手机连同一 WIFI → 手机设代理（电脑 IP:8888）→ 手机浏览器装 `chls.pro/ssl` 证书 →（iOS 再去信任证书）→ 手机操作 App → Charles 弹窗点 allow → 就能看到 App 的 https 请求明文。这套"代理 + 证书"流程是移动端抓包的标准动作。

【面试考察】
面试官："手机上怎么配置才能用 Charles 抓 App 的 https 包？"

参考回答框架：
1. 手机与电脑连同一 WIFI
2. 手机设置代理：电脑 IP + 端口（默认 8888）
3. 手机浏览器访问 chls.pro/ssl 下载安装 Charles 证书
4. iOS 需在"证书信任设置"里打开信任开关
5. Charles 弹窗点 allow，即可抓 App 的 https 明文

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 手机和电脑不连同一网络 | 手机访问不到电脑 IP，代理失效 |
| iOS 只装证书不信任 | iOS 10+ 必须在"证书信任设置"里打开开关 |
| 忘记在 Charles 弹窗点 allow | 设备连入被拒绝，抓不到包 |

【我的理解】
> （为什么手机抓包要同时做"设代理"和"装证书"两件事？它们分别解决什么问题？）

### 知识点 4：注意事项（Android 6+ / iOS 10+ 证书信任）

【课程原话/定义】
注意事项：
- **Android 6** 以上系统 App 默认不信任抓包证书，需要开发修改代码（大部分测试 App 安装包默认打开状态）
- **iPhone 10** 以上需要在 设置 → 通用 → 关于本机 → 证书信任设置 中打开信任开关

【为什么？】
为什么 Android 6+ 会"默认不信任抓包证书"？因为 Android 7（Nougat）开始，系统默认只信任**系统级 CA 证书**，而 Charles 装的是**用户级 CA 证书**，App 默认不认——除非 App 在配置里显式声明信任用户证书（`networkSecurityConfig`）。很多测试包为了能抓包会默认打开这个开关，但线上包通常是关的。iOS 则是"证书装了还要手动信任"，两步缺一不可。

【必须掌握】
- Android 6+/7+：App 默认不信任用户级证书（Charles 装的是用户级）
- 解决办法：App 声明信任用户证书（测试包通常已打开，需开发配合）
- iOS 10+：装了证书还要在"证书信任设置"打开开关
- 抓不到 https 时，先排查"证书是否被系统/App 信任"

【企业场景】
你在公司抓一个线上 App 的 https 包，证书都配好了却还是抓不到明文，大概率是这个 App 的 `networkSecurityConfig` 没信任用户证书（线上包常见）。这时要么让开发出一个"可抓包的测试包"，要么用其他手段（如脱壳/改包）。iOS 则检查"证书信任设置"开关有没有打开。

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 认为装证书就能抓所有 App | Android 7+ 默认不信任用户证书，线上包常抓不到 |
| iOS 装证书后不信任就抓包 | 必须在"证书信任设置"打开开关 |
| 抓不到 https 就反复重装证书 | 先排查 App 是否信任用户证书、SSL Proxying 是否配了 |

【扩展知识】
Android 7.0 起引入 `networkSecurityConfig`：App 可通过 XML 配置 `trust-anchors` 指定是否信任用户证书。测试包通常配置 `<certificates src="user" />` 以便抓包，线上包为安全起见不信任。这也是"为什么测试包能抓、线上包不能抓"的根因。
