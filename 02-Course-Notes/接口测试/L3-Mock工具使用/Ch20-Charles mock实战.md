## 一、Rewrite 重写

### 知识点 1：Rewrite 重写（原理 + 实战）

【课程原话/定义】
**Rewrite** 就是接口重写。Charles 的 Rewrite 功能非常强大，可以重写接口所有元素的内容：header、host、url、path、query param、response status、body——请求和响应都可以修改。

**原理**：客户端请求先发到 Charles → Charles 按 rewrite 规则修改请求 → 再发到服务端；服务端响应先到 Charles → Charles 按规则修改响应 → 再发给客户端。

**实战场景**：修改雪球行情页面的股票名称、股票价格。
设置：`Tools → Rewrite` → 勾选 `Enable Rewrite` → `Add` 新建规则 → 右侧编辑 → `ok` 生效。

【为什么？**
Rewrite 是 Mock 工具里"改数据"最灵活的一种——它不用把整个响应替换成文件，而是"按规则改其中的某几个字段"。原理上，Rewrite 在请求和响应两个方向都能改（改请求参数 = 模拟不同输入，改响应 = 模拟不同返回）。理解"Rewrite 是双向拦截 + 按规则改"，你就掌握了 Mock 的核心能力。提示：Rewrite 适合**小范围数据篡改**。

【必须掌握】
- Rewrite = 接口重写，可改请求和响应的任意字段（header/url/body/status）
- 原理：请求和响应都经过 Charles，按规则修改后再转发
- 入口：Tools → Rewrite → Enable Rewrite → Add 规则
- 适合小范围数据篡改（改某几个字段）
- 实战：改雪球股票名称/价格

【企业场景】
你在公司测 App 时，想验证"股票价格为 0"或"名称为超长字符串"时页面怎么显示，不用改后端，直接用 Charles 的 Rewrite 把行情接口响应里的价格字段改成 0、名称改成超长串，再刷新页面看效果。这就是 Rewrite 的典型用法——"按规则改字段，模拟各种数据场景"。

【面试考察】
面试官："Charles 的 Rewrite 是干什么的？原理是什么？"

参考回答框架：
1. Rewrite 是接口重写，可修改请求和响应的任意字段
2. 原理：请求/响应经过 Charles 时按规则修改再转发
3. 适合小范围数据篡改（改某几个字段，如股票名/价格）
4. 对比 MapLocal（整个响应替换）更灵活

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| Rewrite 只能改响应 | 请求和响应都能改（header/body/参数） |
| Rewrite 和 MapLocal 一样 | Rewrite 改字段，MapLocal 整个响应替换成本地文件 |
| 忘了勾 Enable Rewrite | 规则不生效 |

【我的理解】
> （Rewrite 和 MapLocal 都"改数据"，它们的区别是什么？如果要改"响应里的一个字段"用哪个，要"整个替换成文件"用哪个？）

## 二、MapLocal 与 MapRemote

### 知识点 2：MapLocal 本地映射（原理 + 实战）

【课程原话/定义】
**Map Local** 就是使用本地数据代替线上数据，方便改变接口返回、模拟不同场景。原理：Charles **根本不把请求发到服务器**，直接返回本地文件的数据。

操作：准备本地接口响应数据 → 右键接口选 Map Local 进入设置 → `Map From` 填接口信息、`Map To` 选本地文件 → 修改配置 `Tools → Map Local`。实战：修改雪球行情页面的股票名称/价格。

【为什么？**
MapLocal 和 Rewrite 的核心区别：Rewrite 是"改字段"，MapLocal 是"整个响应用本地文件顶替"（请求根本不发到服务器）。这带来两个好处：① 完全可控（本地文件想写成什么样就什么样）；② 不依赖后端（后端挂了也能测）。提示：**只想修改响应体中的数据时使用 MapLocal**。理解这个区别，就能选对工具。

【必须掌握】
- MapLocal = 用本地文件数据替代线上返回，请求不发到服务器
- 原理：Charles 直接返回本地文件，不访问真实服务
- 入口：右键接口 → Map Local（Map From 填接口，Map To 选本地文件）
- 适合"整个响应体用本地数据顶替"的场景

【企业场景】
你在公司测一个"商品详情"页面，想验证"商品名称超长""价格为空"等展示效果。你把接口响应保存下来，改成本地文件（改名称/价格），配 MapLocal，之后请求该接口 Charles 直接返回本地文件，后端根本不参与。这样能反复、稳定地测试各种数据展示场景，不受后端数据限制。

【面试考察】
面试官："MapLocal 和 Rewrite 有什么区别？"

参考回答框架：
1. MapLocal：整个响应用本地文件替代，请求不发到服务器
2. Rewrite：按规则修改请求/响应的某些字段，请求仍到服务器
3. MapLocal 适合"整体替换响应体"，Rewrite 适合"改局部字段"
4. MapLocal 完全脱离后端，Rewrite 仍依赖后端返回

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 以为 MapLocal 还是访问了服务器 | MapLocal 请求根本不发到服务器，直接返回本地文件 |
| Map From / Map To 填反 | Map From 是原接口信息，Map To 是本地文件 |
| 想改一个字段却用 MapLocal | 改局部字段用 Rewrite 更合适 |

【我的理解】
> （MapLocal 的"请求不发到服务器"有什么好处？在什么测试场景下这个特性特别有用？）

### 知识点 3：MapRemote 远程映射（原理 + 实战）

【课程原话/定义】
**Map Remote** 是将指定的网络请求重定向到另一个服务器。测试中常在多个环境（测试环境 → 预发布 → 线上）切换，用 MapRemote 可轻松切换环境。

原理：MapRemote 把请求重定向到另一个网址/服务器。操作：右键接口选 Map Remote → 设置重定向接口信息 → ok 生效（修改设置 `Tools → Map Remote`）。实战：访问百度转发至豆瓣；访问开发环境转发至测试环境。

【为什么？**
MapRemote 解决的是"**环境切换**"问题——同一套前端代码，后端有开发/测试/预发布/线上多个环境。手动改每个接口的地址又慢又易错，MapRemote 一条规则就把"某个域名的请求"整体转发到"另一个域名/环境"。这和 Rewrite/MapLocal 的"改数据"不同，MapRemote 是"改目的地"，用于环境切换和请求转发。

【必须掌握】
- MapRemote = 把请求重定向到另一个服务器/网址
- 用途：环境切换（开发→测试→预发布→线上）
- 入口：右键接口 → Map Remote → 设置重定向信息
- 与 Rewrite/MapLocal 区别：它改"目的地"，不改"数据"

【企业场景】
你在公司前端代码指向开发环境，现在要在测试环境验证。不用改代码或改接口地址，用 Charles 配一条 MapRemote：把 `dev.xxx.com` 的请求转发到 `test.xxx.com`。切回开发环境时关掉规则即可。这就是 MapRemote 做"多环境切换"的实战价值。

【面试考察】
面试官："MapRemote 是干什么的？和 MapLocal 有什么区别？"

参考回答框架：
1. MapRemote 把请求重定向到另一个服务器/网址
2. 用途：环境切换（dev→test→线上）
3. MapLocal 是"返回本地文件"，MapRemote 是"转发到另一个服务器"
4. 一个改数据源、一个改目的地

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| MapRemote 和 MapLocal 混淆 | Remote=转发到另一服务器，Local=返回本地文件 |
| 环境切换改代码/改接口地址 | 用 MapRemote 一条规则即可切换 |
| 忘了 MapRemote 只改目的地不改数据 | 数据仍来自目标服务器，不会凭空变 |

【扩展知识】
三种 Mock 手段对比（面试高频）：

| 手段 | 改什么 | 请求去向 | 适用 |
|------|--------|----------|------|
| Rewrite | 局部字段 | 仍到服务器 | 小范围篡改 |
| MapLocal | 整个响应 | 不到服务器 | 本地数据顶替 |
| MapRemote | 目的地 | 到另一服务器 | 环境切换 |
