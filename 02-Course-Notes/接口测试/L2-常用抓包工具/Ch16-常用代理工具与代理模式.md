## 一、代理模式

### 知识点 1：四种代理模式

【课程原话/定义】
代理模式分为：**常规代理、透明代理、反向代理、上游代理**。
代理工具（Charles、BurpSuite、Fiddler、mitmproxy）在接口测试中帮助构造各种测试场景、更好地完成测试工作。

【为什么？】
为什么要理解"代理模式"？因为不同的代理模式对应不同的数据流向和用途：
- **常规代理（正向代理）**：客户端主动把请求交给代理，代理代表客户端访问服务器。Charles/Fiddler 抓包就是这种——客户端 → 代理 → 服务器。
- **透明代理**：客户端无感知，网络层把流量劫持到代理（如公司网关）。客户端"以为"自己在直连服务器。
- **反向代理**：代理站在服务器一侧，客户端访问代理，代理转发到后端多台服务器（如 Nginx）。客户端"以为"代理就是服务器。
- **上游代理**：代理自己不直接访问服务器，而是把请求转交给另一个代理（链式代理）。

理解这四种，你就能说清"抓包工具是哪种代理"（正向代理），以及"为什么 Nginx 和 Charles 都是代理但作用不同"（反向 vs 正向）。

【必须掌握】
- 正向代理（常规代理）：代表客户端，抓包工具属于这一类
- 透明代理：客户端无感知的流量劫持
- 反向代理：代表服务器，Nginx 是典型
- 上游代理：代理链，请求转交给另一个代理

【企业场景】
你在公司做接口测试，Charles/Fiddler 是"正向代理"（你主动把流量交给它）。而线上服务的 Nginx 是"反向代理"（客户端访问 Nginx，它转发到后端集群）。理解这个区别，面试被问"正向代理和反向代理的区别"时能答清楚，排查问题时也知道流量经过了几层。

【面试考察】
面试官："正向代理和反向代理有什么区别？"

参考回答框架：
1. 正向代理代表客户端，客户端主动设置；反向代理代表服务器，对客户端透明
2. 正向代理的典型：Charles/Fiddler 抓包、翻墙代理
3. 反向代理的典型：Nginx 负载均衡、网关
4. 用途不同：正向代理做"访问控制/抓包"，反向代理做"负载均衡/安全防护"

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 抓包工具是"反向代理" | 抓包工具是正向代理（代表客户端） |
| Nginx 和 Charles 是一类 | Nginx 是反向代理（服务器侧），Charles 是正向代理（客户端侧） |
| 透明代理需要客户端配置 | 恰恰相反，透明代理对客户端无感知 |

### 知识点 2：代理工具清单

【课程原话/定义】
代理工具分类：
- **代理工具**：Charles、BurpSuite、Fiddler、mitmproxy
- **高性能代理服务器**：Squid、dante
- **反向代理**：Nginx
- **流量转发与复制**：em-proxy、gor、iptable、Nginx
- **SOCKS5 代理**：`ssh -d` 参数

【为什么？】
为什么会有这么多代理工具？因为它们解决不同层面的问题：Charles/Fiddler/mitmproxy 是"调试抓包"用（人看的界面）；Squid/dante 是"高性能代理服务器"（扛流量）；Nginx 是"反向代理/负载均衡"（服务器侧）；gor/em-proxy 是"流量复制"（把线上流量复制到测试环境回放）；`ssh -d` 是最简单的 SOCKS5 隧道。测试人员日常用的是前一类（调试抓包），但要认识后几类，才能选对工具、看懂架构。

【必须掌握】
- 调试抓包：Charles（全平台）、Fiddler（仅 Windows）、mitmproxy（可编程）、BurpSuite（安全）
- 高性能代理：Squid、dante
- 反向代理/负载均衡：Nginx
- 流量复制/回放：gor、em-proxy（常用于流量回放测试）
- SOCKS5 隧道：`ssh -d`

【企业场景】
你在公司做流量回放测试（把线上流量复制下来，在测试环境重放验证），会用到 gor 这类工具；做安全测试用 BurpSuite；日常接口抓包用 Charles/Fiddler；要写自动化抓包脚本用 mitmproxy（Python 可编程）。这些工具各有分工，不是一个工具打天下。

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 只认识 Charles/Fiddler | 还有 mitmproxy（可编程）、BurpSuite（安全）、gor（流量回放） |
| 把 Nginx 当抓包工具 | Nginx 是反向代理/负载均衡，不是调试抓包工具 |
| mitmproxy 和 Charles 完全一样 | mitmproxy 是命令行 + Python 编程，适合自动化，无 GUI |

### 知识点 3：优秀代理工具必备特性

【课程原话/定义】
优秀代理工具必备特性：
- **代理功能**：HTTP/HTTPS、SOCKS5
- **请求模拟工具**：拼装请求、重放请求、重复请求
- **网络环境模拟**：限速、超时、返回异常
- **Mock**：请求修改、响应修改
- **Fake**：用测试环境替代真实环境

【为什么？】
这五条是"评判一个代理工具好不好"的标准，也是"抓包工具能帮测试做什么"的完整能力清单。换个角度看，这五条就是接口测试对代理工具的五大需求：能代理（基本盘）、能造请求（Composer/重放）、能模拟网络（弱网/超时）、能改数据（mock）、能隔离环境（fake）。理解了这五条，你就不只是"会点 Charles 按钮"，而是知道一个成熟的抓包工具应该具备哪些能力。

【必须掌握】
- 五大必备特性：代理 / 请求模拟 / 网络模拟 / Mock / Fake
- 请求模拟：拼装 + 重放 + 重复（Composer/Repeat）
- 网络模拟：限速、超时、返回异常（Throttle/断点）
- Mock：改请求 + 改响应（Rewrite/MapLocal/MapRemote）
- Fake：用测试环境替代真实环境（MapRemote 切环境）

【企业场景】
你在公司选型抓包工具时，就按这五条对照：Charles 有 GUI + 弱网 + mock（适合手工）；mitmproxy 有 Python 编程 + 可进自动化（适合测试开发）；Fiddler 有 FiddlerScript（Windows 专用）。这五条能力，分别对应后续章节：网络模拟→Ch17 弱网，Mock→Ch18-Ch20，请求模拟→Ch21 curl。

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 把 Mock 和 Fake 混为一谈 | Mock 是改数据，Fake 是用假实现/测试环境替代真实环境 |
| 抓包工具只能"看" | 完整能力还包括造请求、模拟网络、改数据、隔离环境 |
| 选工具只看界面好不好看 | 要看五条能力是否满足，尤其"可编程"对自动化重要 |
