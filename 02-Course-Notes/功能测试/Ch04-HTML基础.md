## 一、HTML 是什么

### 【课程定义】

> HTML（Hyper Text Markup Language，超文本标记语言）是描述网页的语言。网页是由前端工程师使用 HTML 编写而成的文件，包含文字、图片、超链接、声音、视频等内容。

### 【为什么？】

HTML 是 Web 页面的骨架。测试工程师不懂 HTML，就像医生看不懂 X 光片：

```
一个网页由三件套组成：
  HTML  →  骨架（结构）
  CSS   →  皮肤（样式）
  JS    →  肌肉（行为）
```

测试中最常见的场景：页面元素找不到？先看 HTML 结构。自动化定位元素？靠 HTML 标签和属性。所以 HTML 不是"前端才需要学"，它是测试的基本功。

### 【必须掌握】

- HTML 是标记语言，不是编程语言
- HTML 负责结构，CSS 负责样式，JS 负责交互
- HTML5 是当前主流标准

### 【HTML 发展简史】

| 阶段        | 特点                      |
| --------- | ----------------------- |
| HTML 1.0  | 只能传输简单文字                |
| XHTML 1.0 | 过渡版本，语法更严格              |
| XHTML 2.0 | 被放弃                     |
| HTML5     | 当前标准，支持音视频/Canvas/本地存储等 |

### 【面试考察】

> 面试官：HTML 是什么？HTML5 相比之前有什么新特性？

参考回答框架：
1. 定义：超文本标记语言，描述网页结构
2. HTML5 新特性：语义化标签（header/footer/article）、音视频（video/audio）、Canvas、本地存储、WebSocket
3. 测试相关：HTML5 带来了新的测试场景（离线应用、音视频播放等）

## 二、HTML 基本结构

### 【课程定义】

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Title</title>
</head>
<body>

</body>
</html>
```

### 【为什么？】

这个骨架模板里，每一行测试时都会用到：

| 标签                       | 作用                    | 测试场景                |
| ------------------------ | --------------------- | ------------------- |
| `<!DOCTYPE html>`        | 声明文档类型为 HTML5         | 缺少时浏览器进入怪异模式，页面渲染异常 |
| `<html lang="en">`       | 根标签，lang 影响屏幕阅读器和搜索引擎 | 国际化测试关注点            |
| `<head>`                 | 元信息（编码、标题、样式引用）       | charset 错了→中文乱码     |
| `<meta charset="UTF-8">` | 字符编码                  | 编码问题导致页面显示问号和乱码     |
| `<title>`                | 浏览器标签页标题              | 每个页面标题是否正确的检查项      |
| `<body>`                 | 页面可见内容                | 所有测试的主体范围           |

### 【必须掌握】

- 能默写 HTML5 基本骨架
- 理解 head 和 body 的分工
- 知道 DOCTYPE 的作用

### 【易错点】

| 误区 | 正解 |
|------|------|
| head 里的内容用户看不到所以不重要 | title 影响 SEO 和用户体验，meta 影响编码和移动端适配 |
| DOCTYPE 只是一行注释 | 它决定了浏览器用标准模式还是怪异模式渲染 |

## 三、标签与属性

### 【课程定义】

> **双标签**：`<标签名>内容</标签名>` — 有开始有结束
> **单标签**：`<标签名 />` — 自闭合
> **属性**：`<标签名 属性1="值1" 属性2="值2">` — 提供额外信息

### 【为什么？】

属性和标签是自动化测试中定位元素的核心手段。Selenium、Playwright 等都靠标签名+属性来找到你要操作的元素。

### 【属性规则】（必须记住）

1. 属性写在开始标签中，位于标签名后面
2. 多个属性用空格隔开，不区分顺序
3. 任何属性都有默认值，省略即用默认
4. 属性值建议用双引号包裹

### 【必须掌握】

- 双标签和单标签的区别
- 属性的 5 条基本规则
- 能识别标签名和属性名

## 四、HTML 全局属性

### 【课程定义】

| 属性      | 作用         | 测试关注点          |
| ------- | ---------- | -------------- |
| `class` | 元素类名       | 自动化定位最常用属性之一   |
| `id`    | 元素唯一标识     | 自动化定位首选（唯一且稳定） |
| `lang`  | 内容语言代码     | 国际化测试          |
| `style` | 行内样式       | 测试中较少直接关注      |
| `title` | 额外信息（悬停提示） | tooltip 功能测试   |

### 【为什么？】

**id 和 class 是自动化测试的生命线。** 一个好测的页面，关键元素都有唯一 id 或语义化 class；一个难测的页面，全是 `<div>` 没有任何标识，自动化脚本根本没法写。

### 【企业场景】

> 你写自动化脚本时发现元素定位不到，打开 F12 一看，开发写的全是 `<div class="box">`，10 个 div 都叫 box。你只能找开发加 id 或改 class 名。如果开发一开始就有"可测试性设计"意识，会给关键元素加上 `data-testid` 属性，自动化定位准确率直接 100%。

### 【面试考察】

> 面试官：自动测试中用什么定位元素？id 和 class 有什么区别？

参考回答框架：
1. id 是唯一的，class 可以多个元素共用
2. 定位优先级：id > name > class > tag > xpath/css selector
3. id 最稳定，但如果开发频繁改 id 就不行了
4. 最佳实践：用 `data-testid` 专门给测试用

## 五、HTML 事件属性

### 【课程定义】

事件属性让 HTML 可以响应用户操作，触发 JavaScript。

### 【事件分类速查表】

| 类别  | 事件                     | 触发时机      | 测试场景            |
| --- | ---------------------- | --------- | --------------- |
| 窗口  | onload                 | 页面加载完成    | 验证页面完全加载后才执行的逻辑 |
| 窗口  | onblur/onfocus         | 窗口失去/获得焦点 | 多窗口交互测试         |
| 表单  | onchange               | 元素值改变     | 下拉框联动、输入校验      |
| 表单  | onsubmit               | 表单提交      | 提交前校验、防重复提交     |
| 键盘  | onkeydown/onkeyup      | 按下/松开键    | 快捷键、搜索框回车键      |
| 鼠标  | onclick                | 单击        | 最常用，按钮点击        |
| 鼠标  | onmouseover/onmouseout | 鼠标移入/移出   | 悬停菜单、tooltip    |
| 多媒体 | onabort                | 媒体加载中止    | 视频/音频异常处理       |

### 【为什么？】

事件 = 用户行为触发器。测试的本质上就是验证"用户做了什么操作 → 系统给出什么反应"。**每个事件属性都对应一种需要测试的交互场景。**

### 【必须掌握】

- 5 类事件：窗口、表单、键盘、鼠标、多媒体
- onclick 是最常用的
- onsubmit 和 onchange 是表单测试的关键

### 【企业场景】

> 你测一个注册表单，需求说"用户名输入框失去焦点时校验是否已被注册"。你怎么测？Tab 切走（onblur）、点其他地方（onblur）、提交表单（onsubmit）——每个触发方式都要覆盖。只测一种路径 = 漏测。

## 六、基础标签速查

> 以下标签是测试日常中最常遇到的，按使用频率排列。不需要背，但需要知道每个是干什么的，看到能认出来。

### 6.1 文本类

| 标签            | 作用        | 示例                  | 测试关注点                |
| ------------- | --------- | ------------------- | -------------------- |
| `<h1>`~`<h6>` | 标题，h1 最重要 | `<h1>首页标题</h1>`     | 层级是否合理（h1 一个页面通常只一个） |
| `<p>`         | 段落        | `<p>这是一段文字</p>`     | 段落间距/折行              |
| `<span>`      | 行内容器，不换行  | `<span>高亮文字</span>` | 常用于局部样式，不改变布局        |
| `<div>`       | 块级容器，会换行  | `<div>一个区块</div>`   | 最常用的布局元素             |
| `<!-- -->`    | 注释        | `<!-- 这是注释 -->`     | 不显示但存在于源码中           |

### 6.2 div 和 span 的区别（必考）

| 对比  | `<div>`  | `<span>` |
| --- | -------- | -------- |
| 类型  | 块级元素     | 行内元素     |
| 换行  | 独占一行     | 不换行      |
| 用途  | 页面布局、大区块 | 文字局部修饰   |
| 类比  | 一个盒子，占整行 | 一句话里的高亮词 |

### 6.3 链接与图片

| 标签      | 关键属性                 | 测试关注点                        |
| ------- | -------------------- | ---------------------------- |
| `<a>`   | href（目标URL）          | 链接是否可点击、跳转是否正确、是否新窗口打开       |
| `<img>` | src（图片URL）、alt（替代文本） | 图片是否加载、alt 在图片失效时是否显示、尺寸是否正确 |

**img 的 alt 属性为什么必须？**
- 图片加载失败时显示替代文字
- 屏幕阅读器读给视障用户（无障碍测试）
- SEO 依赖 alt 识别图片内容

### 6.4 列表

| 标签 | 作用 |
|------|------|
| `<ul>` + `<li>` | 无序列表（圆点） |
| `<ol>` + `<li>` | 有序列表（数字） |

### 6.5 表格

```html
<table border="1">
  <tr>          ← 行
    <td>A1</td> ← 单元格
    <td>B1</td>
  </tr>
</table>
```

| 标签 | 作用 | 测试关注点 |
|------|------|-----------|
| `<table>` | 表格容器 | border 属性控制边框 |
| `<tr>` | 表格行 | 数据行数是否正确 |
| `<td>` | 表格单元格 | 数据内容是否正确 |

### 6.6 表单类（重点）

**form 标签：**

```html
<form action="/api/login" method="POST" name="loginForm">
```

| 属性     | 作用          | 测试关注点                        |
| ------ | ----------- | ---------------------------- |
| action | 提交到的服务器 URL | 接口地址是否正确                     |
| method | GET 或 POST  | GET 参数在 URL 可见，POST 在 body 中 |
| name   | 表单名称        | JS 操作表单时用到                   |

**input 标签 — type 属性决定一切：**

| type 值 | 效果 | 测试关注点 |
|---------|------|-----------|
| text | 文本输入框 | 最大长度、特殊字符、XSS 注入 |
| password | 密码框（掩码显示） | 是否掩码、复制粘贴限制 |
| radio | 单选按钮 | name 相同的为一组，默认选中项 |
| checkbox | 复选框 | 多选、全选/取消全选 |
| button | 普通按钮 | 点击后的行为 |
| submit | 提交按钮 | 点击后触发表单提交 |
| reset | 重置按钮 | 点击后清空所有输入 |
| file | 文件上传 | 文件类型限制、大小限制、多文件 |

**其他 input 属性：**

| 属性          | 作用         | 测试关注点                |
| ----------- | ---------- | -------------------- |
| name        | 控件名称，同名为一组 | radio 必须 name 相同才能互斥 |
| value       | 控件的值       | 提交时传给后端的值            |
| checked     | 默认选中       | radio/checkbox 初始状态  |
| maxlength   | 最大字符数      | 边界值测试                |
| placeholder | 输入提示       | 提示文字是否在输入后消失         |

**textarea（多行文本）：**

| 属性          | 作用   |
| ----------- | ---- |
| rows        | 可见行数 |
| cols        | 可见宽度 |
| readonly    | 只读   |
| placeholder | 提示文字 |

**select（下拉菜单）：**

```html
<select name="city">
  <option value="bj">北京</option>
  <option value="sh">上海</option>
</select>
```

| 属性 | 作用 | 测试关注点 |
|------|------|-----------|
| multiple | 多选 | 多选时按住 Ctrl |
| disabled | 禁用 | 灰色不可点击 |
| size | 可见选项数 | 大于 1 时变为列表而非下拉 |

### 【企业场景】

> 你测一个用户注册页，包含 10+ 个表单字段：text × 5、password × 2、radio × 1、checkbox × 1、select × 2、file × 1。你需要确保：每个 input 类型正确、name 属性不冲突、必填项有校验、maxlength 生效、radio 互斥正确、select 默认值合理、file 只接受允许的文件类型。这就是 HTML 表单测试的日常。

### 【面试考察】

> 面试官：form 表单中 GET 和 POST 有什么区别？

参考回答框架：
1. GET 参数在 URL 中，POST 在请求体中
2. GET 有长度限制（URL 最大约 2KB），POST 没有
3. GET 可被缓存/收藏，POST 不行
4. 安全角度：POST 比 GET 略安全（参数不暴露在 URL）
5. 测试角度：GET 请求可以直接改 URL 测试，POST 需要工具（Postman/F12）
