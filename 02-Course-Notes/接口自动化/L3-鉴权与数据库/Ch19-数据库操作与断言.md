## 一、数据库辅助验证

### 知识点 1：查询数据库做辅助断言 + 脏数据处理

【课程原话/定义】
接口自动化除了用接口响应值验证，通常还用查询数据库的方式做辅助验证（如接口"写"了数据，查库确认数据真的落库了）。

脏数据处理的两种方案：
1. 通过对应的 Delete 接口删除
2. 自动化测试用干净环境，每次执行前后做数据还原

为什么**不建议**直接删库清理脏数据：
- 公司权限管理严格，删数据是敏感操作，不放给测试
- 数据表关联关系复杂，漏删一点就产生 Bug

实现方案分两步：连接与配置（封装数据库配置 + 封装 sql 查询 + 调用执行）→ 查询数据与断言（加查询条件 + 断言结果不为 None）。

Python 用 pymysql：
```python
import pymysql
def get_conn():
    conn = pymysql.connect(host="litemall.hogwarts.ceshiren.com", port=13306,
                           user="test", password="test123456",
                           database="litemall", charset="utf8mb4")
    return conn
def execute_sql(sql):
    connect = get_conn()
    cursor = connect.cursor()
    cursor.execute(sql)
    return cursor.fetchone()   # 查询记录

sql_res = execute_sql("select * from litemall_cart where user_id=1 and deleted=0 and goods_name='hogwarts1'")
assert sql_res   # 断言查询结果不为空
```

【为什么？】
为什么要查数据库做断言？因为接口响应只能反映"接口这一层"，而很多操作的真实结果是"数据落库"——比如"加入购物车"接口返回成功，但数据到底写进购物车表没有，接口响应看不出来，必须查库确认。数据库断言是接口断言的"纵深补充"：响应告诉你"接口说它成功了"，数据库告诉你"数据真的变了"。而脏数据要谨慎处理（优先走 Delete 接口或数据还原，而非直接删库），则是权限和安全的现实约束。

【必须掌握】
- 数据库断言 = 接口响应的纵深补充（确认数据真的落库）
- 脏数据处理：Delete 接口 / 数据还原，不直接删库
- 不直接删库的原因：权限敏感 + 表关联复杂
- Python：pymysql（connect + cursor + execute + fetchone）
- 断言：查询结果不为 None（assert sql_res）

【企业场景】
你在公司测"添加购物车"接口，接口返回成功，但你还要查购物车表确认"user_id=1 的购物车里真的有 goods_name='hogwarts1' 这条记录"。接口响应和数据库双重验证，才敢说这个接口真的没问题。清理测试数据时，优先调 Delete 接口而不是直接 delete 数据库——因为公司不给测试删库权限，且表关联复杂容易漏删。

【面试考察】
面试官："接口测试为什么要查数据库？脏数据怎么清理？"

参考回答框架：
1. 接口响应只反映接口层，数据是否真正落库需查库确认
2. 数据库断言是接口断言的纵深补充
3. 脏数据清理：优先 Delete 接口 / 数据还原
4. 不直接删库：权限敏感 + 表关联复杂易漏删

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 只信接口响应不查库 | 响应说成功≠数据落库，要查库确认 |
| 直接 delete 删脏数据 | 优先 Delete 接口/数据还原，避免权限和关联问题 |
| fetchone 结果当布尔值判断错误 | 有记录返回元组（真），无记录返回 None（假） |

【我的理解】
> （为什么"接口返回成功"不等于"数据真的落库了"？举一个"接口成功但数据没写进去"的可能场景，说明查库断言的必要性。）
