## 一、接口参数与携带方式

### 知识点 1：请求参数是什么、怎么拼进 URL

【课程原话/定义】
接口参数是调用接口时传递给接口的数据，用于指定操作的详细信息、请求内容、过滤条件等。参数在路径之后用 `?` 引导，`key=value` 形式拼接，多个参数用 `&` 分隔。例如：`https://ceshiren.com/search?expanded=true&q=requests`。

两种携带方式：
1. 直接拼接在 URL：`?username=Hogwarts&id=666`
2. 通过 params 参数传递：`requests.get(url, params)`

【为什么？】
为什么要区分"直接拼 URL"和"用 params 参数"两种方式？因为直接拼 URL 适合参数固定、少的情况（一眼能看懂）；而 params 传 dict 适合参数多、动态的情况——代码里维护一个 dict 比手动拼一长串 URL 字符串清晰得多，也不容易漏 `&` 或转义问题。本质是"可读性"和"可维护性"的取舍。

【必须掌握】
- 参数格式：`?key1=value1&key2=value2`
- 两种携带方式：URL 直接拼接 / params 参数传 dict
- 多参数、动态参数优先用 params（dict 形式）

【企业场景】
你在公司查一个搜索接口，参数只有 keyword 一个，直接拼 URL 也行；但如果参数有七八个（分页 page/limit、排序 sort、过滤 categoryId、token 等），你肯定用 params 传一个 dict——改参数、加参数都只动 dict，不用重拼 URL 字符串。

【面试考察】
面试官："GET 请求的参数怎么传？有哪几种方式？"

参考回答框架：
1. 直接拼 URL：`?key=value&key2=value2`
2. 用 params 参数传 dict：`requests.get(url, params={"key":"value"})`
3. 两者效果一样，params 更适合多参数、动态场景

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 多个参数用 `;` 或空格分隔 | 用 `&` 分隔 |
| 忘记参数前的 `?` | 第一个参数前必须用 `?` 引导 |
| 参数含特殊字符不转义 | URL 参数要 URL 编码，requests 的 params 会自动处理 |

【我的理解】
> （用 params 传 dict 和直接拼 URL 字符串，结果一样。为什么说 params 更"可维护"？当参数从 1 个变成 10 个时，哪种写法更不容易出错？）

## 二、Python 携带 params 参数

### 知识点 2：Python 用 params 传 GET/POST 参数

【课程原话/定义】
Python 携带 params 的两种写法等价：

```python
import requests

# 方式一：params 传 dict
def get_by_params():
    url = "https://httpbin.ceshiren.com/get"
    params = {"get_key": "get_value"}
    r = requests.get(url, params=params)
    print(r.json())

# 方式二：直接拼 URL
def get_by_url():
    url = "https://httpbin.ceshiren.com/get?get_key=get_value"
    r = requests.get(url)
    print(r.json())
```

POST 也可携带 params（作为 URL 查询参数，而非请求体）：
```python
def post_by_params():
    url = "https://httpbin.ceshiren.com/post"
    params = {"post_key": "post_value"}
    r = requests.post(url, params=params)
    print(r.json())
```

【为什么？】
为什么 GET 和 POST 都能带 params？因为 params 是拼在 URL 上的"查询参数"，跟方法无关——不管 GET 还是 POST，只要 URL 后面有 `?key=value`，params 都能传。要区分的是：GET 的参数通常全在 URL（params），而 POST 的"请求体数据"要用 data/json，params 只是 POST 附带在 URL 上的查询串。这是接口测试里最常见的混淆点。

【必须掌握】
- GET 带参数：requests.get(url, params=dict)
- POST 带 URL 查询参数：requests.post(url, params=dict)
- POST 的"请求体"数据用 data/json，不是 params
- r.json() 把响应解析成 Python 对象

【企业场景】
你在公司测一个"分页查询"接口 `GET /goods/list?page=1&limit=10`，用 `requests.get(url, params={"page":1, "limit":10})`；而"下单"接口 `POST /order` 的订单数据在请求体里，用 `requests.post(url, json={...})`。分清"查询参数在 URL（params）"和"业务数据在请求体（data/json）"，是接口测试的基本功。

【面试考察】
面试官："POST 请求能不能用 params？params 和 data/json 有什么区别？"

参考回答框架：
1. POST 也能用 params，但它是拼在 URL 上的查询参数
2. params 是 URL 查询串（?key=value），GET/POST 都能用
3. data/json 是 POST 的请求体（body），这才是 POST 提交数据的地方
4. 判断依据：看数据是"URL 里"还是"body 里"

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| POST 提交数据用 params | params 拼 URL，POST 的请求体数据用 data/json |
| 认为 params 只能 GET 用 | params 是查询参数，GET/POST 都能带 |
| 把请求体和查询参数混为一谈 | 查询参数在 URL，请求体在 body，位置不同 |

【我的理解】
> （同一个 POST 请求，`params` 和 `json` 传的数据，服务器分别从哪读到？用 httpbin 的回显结果，你能从响应里哪个字段看出区别？）

## 三、Java 携带请求参数

### 知识点 3：Java queryParam / queryParams

【课程原话/定义】
Java（REST-assured）携带参数两种方式：
1. 直接拼 URL：`.get(".../get?name=ad&scholl=hogwarts")`
2. 通过 queryParam 传递：
   - `queryParam("key", "value")`：单个 URL 参数
   - `queryParams(map)`：批量传多个参数（用 HashMap）

```java
// 单个参数
given().queryParam("name", "ad").when().get(url)...
// 批量参数（HashMap）
HashMap<String, Object> query = new HashMap<>();
query.put("name", "ad");
query.put("school", "hogwarts");
given().queryParams(query).when().get(url)...
```

【为什么？】
为什么 REST-assured 要提供 queryParam/queryParams 两个方法？因为它们对应两种场景：queryParam 是链式写法，加一两个参数直观；queryParams 接受一个 Map，适合参数多、或需要"动态构造参数"的场景（比如从数据库/配置文件读出来的参数集合，直接塞进 Map）。这和 Python 里"直接拼 URL vs 传 dict"是同一个思路，只是 Java 用方法表达了。

【必须掌握】
- queryParam("key","value")：单个参数
- queryParams(map)：批量参数（HashMap）
- Java 里参数同样可拼 URL 或走方法
- given().queryParam()...when().get()...then() 是 REST-assured 链式写法

【企业场景】
你在一个 Java 技术栈的公司做测试，接口参数从配置文件里读出来是一个 Map，你直接 `given().queryParams(paramMap)` 一次性传进去，比一个个 `.queryParam()` 链式调用干净得多。参数多、动态生成时用 queryParams 是标准做法。

【面试考察】
面试官："REST-assured 里 queryParam 和 queryParams 有什么区别？"

参考回答框架：
1. queryParam：传单个参数，链式调用
2. queryParams：传多个参数，接受一个 Map（HashMap）
3. 参数多或动态构造时用 queryParams

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| queryParam 和 queryParams 混用 | 单数=单个，复数=批量（Map） |
| 把请求体参数也塞 queryParam | queryParam 是 URL 查询参数，请求体要用 body() |
| HashMap 泛型写错 | 参数值是 Object，用 HashMap<String, Object> |

【我的理解】
> （Java 的 queryParams(Map) 和 Python 的 params=dict，本质是不是同一件事？它们各自帮你解决了"拼 URL"里的什么麻烦？）
