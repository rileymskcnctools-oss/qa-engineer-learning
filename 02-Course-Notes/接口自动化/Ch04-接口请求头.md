## 一、请求头概念与常见头信息

### 知识点 1：请求头是什么、有哪些常见字段

【课程原话/定义】
请求头是 HTTP 请求消息中包含的元数据信息，用于描述请求或响应的一些属性和特征。常见头信息：

| 头信息 | 含义 |
|--------|------|
| Authorization | 客户端请求的身份验证信息 |
| Cookie | 客户端状态信息，通常用于身份验证和会话管理 |
| Content-Type | 请求消息体的 MIME 类型 |
| User-Agent | 发送请求的客户端软件信息 |

【为什么？】
为什么 HTTP 要带一堆"头信息"？因为 URL 和方法只表达了"去哪、干什么"，但"你是谁、你用什么格式发数据、你是浏览器还是脚本"这些信息，URL 装不下，就得靠请求头传递。对接口测试来说，最关键的三个头是：**Authorization**（证明身份，没它常 401）、**Content-Type**（告诉服务器请求体是什么格式，没对服务器解析不了）、**Cookie**（维持会话状态）。

【必须掌握】
- 请求头 = HTTP 消息里的元数据（描述请求属性）
- 四个高频头：Authorization（身份）、Cookie（会话）、Content-Type（格式）、User-Agent（客户端标识）
- 请求头是 key-value 形式

【企业场景】
你在公司调一个接口总是 401（未授权），八成是 Authorization 头没带或 token 不对；调一个 JSON 接口服务器报"解析失败"，八成是 Content-Type 没设成 application/json。这两个头是接口测试里"请求发不出去/发出去被拒"的两大元凶。

【面试考察】
面试官："常见的请求头有哪些？Authorization 和 Cookie 分别干什么用？"

参考回答框架：
1. Authorization：身份验证信息（如 token），证明"你是谁"
2. Cookie：会话状态，维持登录态
3. Content-Type：请求体的格式（json/form 等）
4. User-Agent：客户端标识（浏览器/脚本）

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| Authorization 和 Cookie 混为一谈 | Authorization 是显式身份凭证（token），Cookie 是会话状态，机制不同 |
| Content-Type 设错 | 传 JSON 必须设 application/json，否则服务器解析不了 |
| 请求头和请求参数分不清 | 头在 header（元数据），参数在 URL/body（业务数据） |

【我的理解】
> （Authorization（token）和 Cookie 都是"证明身份"，它们的工作方式有什么本质区别？为什么现代 API 更倾向用 Authorization + token？）

## 二、头部信息的获取与使用场景

### 知识点 2：从哪获取头部信息 + 两个核心使用场景

【课程原话/定义】
头部信息获取的三个地方：
1. 浏览器右键检查（F12）→ Network 里查看
2. Postman 运行接口后从 headers 里查看
3. 接口文档（有的文档没写头信息，就需用前两种方法获取）

两个核心使用场景：
- **Authorization**：根据用户身份凭证生成权限，如用登录接口返回的 token 证明身份
- **Content-Type**：定义网络文件的类型和编码，决定接收方以什么形式读取

【为什么？】
为什么要学"从哪获取头信息"？因为接口文档经常不全——文档可能漏了某个必需的 header，或者压根没写。这时最靠谱的办法是"抓真实请求"：浏览器 F12 或 Postman 里跑一遍，看真实请求带了哪些头，照抄即可。这跟 Ch01 里"抓包摸清接口"是同一个思路：**真实流量比文档更权威**。

【必须掌握】
- 获取头的三途径：F12 Network、Postman headers、接口文档
- Authorization 场景：带 token 证明身份（登录态接口必用）
- Content-Type 场景：声明请求体格式（json/form）
- 文档不全时，以真实请求（抓包）为准

【企业场景】
你在公司接手一个老接口，文档只写了 URL 和参数，没写需要哪些头。你直接 F12 抓浏览器里前端调这个接口的请求，看到它带了 `X-Token`、`Content-Type: application/json`、`User-Agent` 三个头，照抄进你的脚本，请求就通了。这就是"文档不全靠抓包"的实战价值。

【面试考察】
面试官："接口文档没写请求头，你怎么知道要传哪些？"

参考回答框架：
1. 用浏览器 F12 抓前端真实请求，看带了哪些头
2. 或 Postman 跑一次接口，看 headers
3. 以真实请求为准（比文档权威）
4. 重点确认 Authorization（身份）和 Content-Type（格式）

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 只信文档、文档没写就不传头 | 文档可能不全，抓真实请求确认 |
| 抓包时把响应头当请求头 | 请求头是"发出去"的，响应头是"返回"的，方向不同 |
| 头信息一股脑全抄 | 只传必要的头，多余的反而可能干扰 |

【我的理解】
> （为什么"抓真实请求"比"看接口文档"更可靠？文档和真实请求不一致时，你应该信哪个、为什么？）

## 三、构造头信息

### 知识点 3：Python 与 Java 构造 headers

【课程原话/定义】
请求头用 headers 参数传入，通常字典格式：`headers={"Content-Type":"需要传入的格式"}`。

Python：
```python
import requests
def test_get():
    url = "https://httpbin.ceshiren.com/get"
    headers = {'user-agent': 'my-app/0.0.1'}
    r = requests.get(url, headers=headers)
    print(r.headers)  # 打印响应的头信息
test_get()
```

Java（REST-assured）两种方式：
1. 直接传参：`.headers("Authorization", "verifyMessage")`
2. 用 HashMap：`.headers(headerMap)`

```java
HashMap<String, String> headerMap = new HashMap<>();
headerMap.put("Authorization", "verifyMessage");
headerMap.put("name", "ad");
given().headers(headerMap).when().get(url)...
```

【为什么？】
为什么头信息要单独用 headers 参数传、而不是塞进 params？因为头和参数的位置根本不同——头在 HTTP 消息的 header 区，参数在 URL 或 body。requests 用 `headers=` 这个独立参数，就是让你明确"这是元数据，不是业务数据"。Java 的 headers() 方法同理。理解"头 ≠ 参数"，是避免接口测试里传错位置的关键。

【必须掌握】
- Python：requests.get(url, headers=dict)
- Java：given().headers(k,v) 或 .headers(HashMap)
- 头是 key-value，用字典/Map 承载
- r.headers 拿的是"响应头"，别和"请求头"混淆

【企业场景】
你在公司写登录后的接口调用，用 `headers={"Authorization": "Bearer " + token}` 带上 token；再设 `headers={"Content-Type": "application/json"}` 发 JSON 请求体。headers 是几乎所有真实接口请求的"标配"，几乎没有一个企业接口是不带头的。

【面试考察】
面试官："Requests 里怎么传请求头？headers 和 params 有什么区别？"

参考回答框架：
1. requests.get(url, headers={"key":"value"})
2. headers 是 HTTP 元数据（身份/格式/客户端信息），在消息 header 区
3. params 是业务参数，拼在 URL 或放 body
4. 两者位置和用途都不同，不能混用

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 把 token 当 params 传 | token 是身份凭证，应放 headers 的 Authorization |
| r.headers 当成请求头 | r.headers 是响应头，请求头是你自己传的 |
| headers 键名大小写随意 | HTTP 头键名大小写不敏感，但值要注意格式 |

【我的理解】
> （同样是一个 key-value，凭什么"token"要放 headers 的 Authorization，而"分页参数 page"要放 params？它们最本质的区别是什么？）
