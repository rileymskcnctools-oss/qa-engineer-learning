## 一、代理配置与抓包定位

### 知识点 1：proxies 参数 + 结合抓包工具定位请求错误

【课程原话/定义】
调试接口用例时，若响应结果和预期不一致，需检查请求信息。通过代理获取请求对应的响应信息，与正常请求对比，更直观地排查错误——相当于编写代码时的 debug 功能。

Python 用 proxies 参数（字典，分别设 http 和 https 代理）：
```python
proxy = {
    "http": "http://127.0.0.1:8000",
    "https": "http://127.0.0.1:8888"
}
requests.post(url="https://httpbin.ceshiren.com", proxies=proxy, verify=False)
```
verify 是证书验证：默认 True 会验证 SSL 证书，设 False 则忽略验证（抓包/自签名场景常用）。

【为什么？】
为什么要配代理？因为脚本里发的请求"看不见"——你写了 `requests.post(...)`，但实际发出去的数据对不对、header 对不对，肉眼看不到。配了代理（指向 Charles/Fiddler 等抓包工具），脚本的每个请求都经过抓包工具，你就能看到"脚本真实发出的请求"长什么样，和"正常请求"一对比，差异立现。这跟浏览器 F12 抓包是同一个思路，只是对象从"浏览器"变成了"自动化脚本"。

【必须掌握】
- proxies 参数配代理（字典，http/https 分开）
- verify=False 跳过 SSL 证书验证（抓包场景）
- 代理 + 抓包工具 = 脚本请求的"debug"
- 用抓包对比"脚本请求"和"正常请求"的差异，定位问题

【企业场景】
你在公司写脚本调接口失败，响应不对但不知道脚本发了什么。你给脚本配 `proxies={"http":"http://127.0.0.1:8888"}` 指向 Charles，再跑脚本，Charles 里就能看到脚本发出的完整请求（URL、header、body）。和正常请求一对比，发现是 header 少传了 token 或 body 参数写错了，立马定位。这就是"给脚本加 debug"。

【面试考察】
面试官："脚本请求结果不对，怎么排查脚本实际发了什么？"

参考回答框架：
1. 配代理（proxies 参数），指向抓包工具
2. 跑脚本，抓包工具里看脚本发出的完整请求
3. 和正常请求对比，找差异（header/参数/body）
4. verify=False 跳过证书校验

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 抓包时报 SSL 证书错误 | 设 verify=False 跳过证书校验 |
| http 和 https 代理都配一个 | 分别配置，https 走 8888、http 走 8000 等 |
| 只抓包不看差异 | 抓包目的是"对比正常请求找差异"，不是看热闹 |

【扩展知识】
代理配置的价值不止"抓包"——还能用于：① 访问内网（走公司代理）；② 调试移动端（手机设代理指向电脑）；③ 拦截/篡改请求（mock）。它是接口测试里"让流量可见、可控"的基础能力，配合抓包工具（见 [[接口测试/README|接口测试]] 的 Ch11-Ch16 抓包章节）能发挥更大价值。
