## 一、定位策略概述

### 知识点 1：定位策略的定义与价值

【课程原话/定义】
Web 自动化测试定位策略是指在自动化测试脚本中用于准确定位和操作 Web 页面元素的方法和规则。选择正确的定位策略对于成功执行自动化测试非常重要，因为它直接影响到测试脚本的**稳定性**和**可维护性**。

【为什么？】
本章和 Ch06 的分工要看清——Ch06 讲"八种定位方式**怎么写**"（how），本章讲"面对一个元素**选哪种策略**"（which + why）：

```
Ch06 八大定位方式  → 方法层：每种写法长什么样、边界在哪
Ch09 定位策略      → 策略层：选型原则（7 条）+ 特殊场景（alert/日期/上传）
```

为什么要单独拔高一层"策略"？因为"会写八种"不等于"选得对"。定位策略 = **方法 + 规则**：方法解决"能不能找到"，规则解决"下次改版还能不能找到、改起来贵不贵"。定位器选错，最贵的代价不是报错，而是**静默点错元素**（Ch06 讲过）和**改版后大面积失效**。

【必须掌握】
- 定位策略 = 方法 + 规则；两个关键词：稳定性、可维护性
- 与 Ch06 分工：Ch06 = 八种方法，Ch09 = 选型原则 + 特殊场景
- 选错策略的代价：静默点错、改版后失效、维护成本飙升

【企业场景】
你在团队里做自动化框架选型，会先定一份"定位器规范"（就是本章的"通用原则"），新人照着写，而不是每个人按自己的习惯乱选。规范的价值在于：出了问题（前端改版）时，所有人都知道去哪儿改、按什么优先级重建定位。

【面试考察】
面试官："你怎么看待'定位策略'？它和'定位方式'是一回事吗？"

参考回答框架：
1. 定位方式是"八种写法"，定位策略是"选型方法 + 规则"
2. 策略回答两个问题：选哪种（优先级）、遇到特殊场景怎么办（alert/日期/上传）
3. 评判标准始终是稳定性和可维护性，不是"能不能找到"
4. 落地：定位器规范 + PO 层集中管理 + 推动前端契约化

【易错点】

| 误区 | 纠正 |
|------|------|
| 以为"会八种定位方式"= 掌握定位 | 方法只是基础，选型策略和特殊场景才是进阶 |
| 定位策略只追求"能找到" | 还要"改版后还能找到、且维护成本低" |

【我的理解】
> （"定位方式"和"定位策略"的区别是什么？为什么一个只会写 XPath 的人，可能不如一个会选策略的人定位得稳？）

## 三、选择定位器通用原则（本章核心）

### 知识点 3：七条选型原则

【课程原话/定义】
1. **与研发约定的属性优先**（如约定 `class` 属性、`[name='locate']`）：在与开发团队约定的属性上定位，确保一致性和可维护性
2. **身份属性 id、name**：通常是唯一的，是首选定位方法
3. **复杂场景使用组合定位**：用 xpath 和 css 选择器处理复杂定位需求
4. **处理属性动态变化**：通过 xpath
5. **重复元素属性**（id、text、class）：处理重复元素
6. **父子定位**：先定位父元素，再在其内部查找子元素
7. **js 定位**：使用 js 注入来定位元素，特别适用于动态或特殊交互的元素

【为什么？】
这七条不是并列的"七个技巧"，而是一条**从理想兜底的选型路径**。把它们按"优先→兜底"排成一张决策表：

| 优先级 | 原则 | 何时用 | 落地写法 |
|--------|------|--------|----------|
| 0️⃣ 契约优先 | 与研发约定专用定位属性 | 前端愿意配合（最理想） | `[data-test-id='submit']`、`[name='locate']` |
| 1️⃣ 身份属性 | id / name | 元素有语义化 id 或表单 name | `By.ID, "login-btn"` / `By.NAME, "username"` |
| 2️⃣ 组合定位 | css / xpath 组合 | 无 id/name，但属性可组合 | `#order-form input[type='password']` |
| 3️⃣ 动态属性处理 | 用 xpath 部分匹配 | 属性值带动态后缀 | `//div[contains(@id, 'react-select')]` |
| 4️⃣ 重复元素处理 | 加限定、取第 N 个 | 多个元素属性相同 | `(//button[text()='删除'])[2]` 或父级限定 |
| 5️⃣ 父子定位 | 先定位父再找子 | 元素自身无特征、父级有语义 | `driver.find_element(By.ID,"order-form").find_element(By.TAG_NAME,"button")` |
| 6️⃣ js 定位兜底 | JS 注入直接定位/操作 | 特殊交互、组件内部状态 | `driver.execute_script("return document.querySelector(...)")` |

第 0 条（契约优先）是 Ch06 里 `data-test-id` 思路的**原则化**：与其每次猜前端怎么改，不如和研发**约一个专用定位属性**，把定位变成前后端契约——这是"治根"。

第 4、5 条解决同一个问题：**重复**。一个页面几十个相同 class/文本，直接定位会静默命中错误元素。父子定位和"取第 N 个"都是把定位**范围缩小到唯一**。

第 6 条（js 定位）是最后的兜底：某些元素（日期控件、富文本、阴影 DOM、特殊组件）常规定位器搞不定，直接 `execute_script` 用 JS 找到并操作——这已经跨进了下一节"特殊场景"。

【必须掌握】
- 七条原则能按"优先→兜底"顺序背下来
- 契约优先（data-test-id / 约定属性）是治根手段
- 父子定位：`父元素.find_element(...)` 在父级作用域内再查
- 动态属性：xpath 的 `contains()` / `starts-with()` 部分匹配
- js 定位：`execute_script` 是特殊/动态元素的兜底

【企业场景】
你在写一个后台列表的"删除"按钮定位，页面有 20 条数据、每条都有一个 `class="del-btn"`。直接用 class 会点到第一条。你有两条路：
- 父子定位：先定位"第 5 行"这个语义化的父容器，再在其内部找 `.del-btn`
- XPath 取第 N 个：`(//button[@class='del-btn'])[5]`

更稳的做法是推动研发给每行加 `data-row-id`，然后 `//tr[@data-row-id='10086']//button[@class='del-btn']`——契约 + 父子定位结合，一次到位。

【面试考察】
面试官："说说你选择定位器的通用原则？"

参考回答框架：
1. 契约优先：与研发约定专用属性（data-test-id），最稳
2. 身份属性：语义化 id > name
3. 复杂/动态：css 组合、xpath 部分匹配（contains）
4. 重复元素：父子定位缩小作用域，或 xpath 取第 N 个
5. 特殊元素：js 注入兜底
6. 收尾：定位器集中放 PO 层，推动前端契约化

【易错点】

| 误区 | 纠正 |
|------|------|
| 七条原则平等看待 | 有优先级：契约 > id/name > 组合 > 动态处理 > 重复处理 > 父子 > js |
| 重复元素靠"试到哪个是哪个" | 用父子定位或取第 N 个，把范围缩到唯一 |
| 动态属性硬编码 | 用 xpath `contains()` 部分匹配稳定前缀 |
| 一上来就用 js 定位 | js 是兜底不是首选，能常规定位就常规定位（可读性、维护性更好） |

【扩展知识】
父子定位是 PO 模式"链式定位"的基础，Ch06 知识点 4 的 PO 雏形（定位器常量）和后续 PO 专章会用到。动态属性匹配的 xpath 函数：`contains(@id, 'x')`、`starts-with(@id, 'x')`、`ends-with()`（注意 xpath 1.0 无 ends-with，需 `substring` 模拟）。

【我的理解】
> （七条原则里，为什么"契约优先"排在"身份属性"之前？如果研发愿意配合，它比 id/name 好在哪？）

## 四、特殊定位场景

### 知识点 4：弹框 alert() 处理

【课程原话/定义】
场景：web 页面 alert 弹框。
解决：`driver.switchTo().alert()`（Java 写法）。

【为什么？】
alert 弹框是**浏览器原生对话框**，不是页面 DOM 元素，所以 `find_element` 永远找不到它。必须先把"焦点"切换到弹框，再操作：

```python
# Python（Selenium 4 写法）
alert = driver.switch_to.alert
print(alert.text)          # 取弹框文本
alert.accept()             # 点"确定"
# alert.dismiss()          # 点"取消"
```

| 操作 | Python | Java | 含义 |
|------|--------|------|------|
| 切换到弹框 | `driver.switch_to.alert` | `driver.switchTo().alert()` | 焦点切到 alert |
| 确定 | `alert.accept()` | `alert.accept()` | 点确定 |
| 取消 | `alert.dismiss()` | `alert.dismiss()` | 点取消 |
| 取文本 | `alert.text` | `alert.getText()` | 读取弹框文字（可断言） |
| 输入（prompt） | `alert.send_keys("x")` | `alert.sendKeys("x")` | 对 prompt 弹框输入 |

关键：alert 是**模态**的——不处理掉，页面后续操作会卡住（`UnhandledAlertException`）。所以遇到会弹 alert 的用例，要么提前 `accept`/`dismiss`，要么设置 `driver.switch_to.alert` 处理后再继续。

【必须掌握】
- alert 是浏览器原生弹框，`find_element` 找不到，必须 `switch_to.alert` 切换
- 三个动作：`accept` 确定 / `dismiss` 取消 / `text` 取文本
- alert 模态，不处理会抛 `UnhandledAlertException`

【企业场景】
你测一个"删除"功能，点删除会弹 `confirm` 确认框"确定删除吗？"。用例必须 `alert.accept()` 才能继续断言删除结果；反过来测"取消删除"就用 `alert.dismiss()`。还可以断言 `alert.text == "确定删除吗？"` 验证文案正确。

【面试考察】
面试官："遇到 alert 弹框怎么处理？为什么 find_element 找不到它？"

参考回答框架：
1. alert 是浏览器原生对话框，不属于 DOM，`find_element` 找不到
2. 用 `driver.switch_to.alert` 切换焦点，再 `accept()`/`dismiss()`/`text`
3. alert 是模态的，不处理后续操作会抛 `UnhandledAlertException`

【易错点】

| 误区 | 纠正 |
|------|------|
| 用 `find_element` 找 alert | 找不到，它不是 DOM 元素 |
| 老教程的 `switch_to_alert()` | 已废弃，Selenium 4 用 `switch_to.alert` |
| 不处理 alert 就继续点页面 | 抛 `UnhandledAlertException` |

【我的理解】
> （为什么 alert 不能用 `find_element` 定位？它和普通页面元素在"存在位置"上有什么本质区别？）

### 知识点 5：日期控件与 JS 注入定位

【课程原话/定义】
场景：`<input>` 标签组合的下拉框无法定位、`<input>` 标签组合的日期控件无法定位。
解决：面对这些元素，引入 **JS 注入技术**来解决问题。

【为什么？】
这类控件（日期选择器、下拉组合框、第三方组件）的"值"往往存在**组件内部状态**里，而不是原生 `<input>` 的 value 属性里——你点开是一个浮层日历，选完日期它把结果写回一个隐藏状态。常规定位要么找不到、要么改了 value 不生效。JS 注入绕过组件，直接对 DOM 动手：

```python
# 1. 直接改 value（最快，但可能不触发前端双向绑定）
element = driver.find_element(By.CSS_SELECTOR, "input.date-picker")
driver.execute_script("arguments[0].value = '2026-08-28';", element)

# 2. 移除 readonly 后正常 send_keys（更贴近真实用户输入）
driver.execute_script("arguments[0].removeAttribute('readonly');", element)
element.send_keys("2026-08-28")

# 3. 用 JS 直接定位并返回元素（连定位一起交给 JS）
el = driver.execute_script("return document.querySelector('input.date-picker');")
```

注意坑：只改 `value` 可能不触发前端框架（Vue/React）的**双向绑定**——页面上看着填了，点提交却拿到空值。更稳的做法是移除 readonly 后 `send_keys`（模拟真实输入），或改完 value 再手动派发 `input`/`change` 事件。

【必须掌握】
- 日期控件/组合下拉框值在组件内部状态，常规定位+send_keys 可能失效
- JS 注入三招：改 value、removeAttribute('readonly') 后 send_keys、JS 直接定位
- 只改 value 可能不触发框架双向绑定 → 补发 input/change 事件或改用 removeAttribute + send_keys

【企业场景】
你测一个下单页面，日期选择器是 Element UI 的 `el-date-picker`，`<input>` 是 readonly 的、点开才出日历。直接 `send_keys` 会失败（readonly 拦住了）。你的解法：先 `removeAttribute('readonly')` 再 `send_keys("2026-08-28")`，或者用 JS 改 value 后 `dispatchEvent(new Event('input'))` 通知框架。这类"组件型控件"的处理是 UI 自动化里常见的硬骨头。

【面试考察】
面试官："日期控件没法用 send_keys 输入怎么办？"

参考回答框架：
1. 先判断原因：readonly？组件内部状态？shadow DOM？
2. `removeAttribute('readonly')` 后 `send_keys`（贴近真实输入）
3. 或 JS 注入直接改 `value`，但要注意触发 `input`/`change` 事件同步框架状态
4. 顺带提：这些属于"特殊定位场景"，能用 JS 兜底，但要控制在 PO 层封装好

【易错点】

| 误区 | 纠正 |
|------|------|
| 只改 value 不触发事件 | Vue/React 拿不到值 → 改完派发 `input`/`change` 事件 |
| 对 readonly 输入框直接 send_keys | 被拦 → 先 `removeAttribute('readonly')` |
| 以为 JS 注入万能 | 阴影 DOM 内的元素要穿透 shadowRoot，比普通 JS 复杂 |

【我的理解】
> （为什么"只改 value"有时候没用？这和 Ch08 里 `clear()` 失效是同一个根因吗？）

### 知识点 6：文件上传

【课程原话/定义】
场景：input 标签文件上传。
解决：input 标签直接使用 `send_keys()` 方法。

【为什么？】
`<input type="file">` 点击后会弹**操作系统的文件选择对话框**，这是 OS 原生窗口，Selenium 控制不了（它只能操作浏览器）。所以不能"点按钮 → 选文件"，而是**绕过对话框**，直接给 input 塞文件路径：

```python
# input 型上传：直接传绝对路径，绕过系统对话框
driver.find_element(By.CSS_SELECTOR, "input[type='file']").send_keys(r"C:\Users\riley\test_upload.txt")
```

| 上传类型 | 能否用 send_keys | 原因 |
|----------|-----------------|------|
| `<input type="file">` | ✅ 能 | 原生 input，send_keys 直接赋值 |
| div 模拟的上传按钮 | ❌ 不能 | 值不在 input 里，send_keys 无效 |

易错点：
1. **路径必须用绝对路径**（相对路径会因工作目录不同而找不到）
2. **路径含中文/空格**：Windows 下注意转义或用原始字符串 `r"..."`
3. **非 input 型上传**（div/js 模拟的）`send_keys` 无效，要用 AutoIt / pyautogui 操作系统对话框，或找隐藏的 `<input type="file">` 元素（很多组件其实是"好看的按钮 + 隐藏 input"）

【必须掌握】
- `<input type="file">` 用 `send_keys(绝对路径)` 上传，绕过系统对话框
- 为什么不能 click 后选文件：系统对话框是 OS 原生，Selenium 控制不了
- 非 input 型上传 send_keys 无效，需 AutoIt/pyautogui 或定位隐藏 input

【企业场景】
你测一个"上传头像"功能，页面是个漂亮的"上传"按钮，F12 一看它背后其实有个 `display:none` 的 `<input type="file">`。你直接对这个隐藏 input `send_keys(绝对路径)` 就完成了上传，不用去点那个按钮。这就是"好看的按钮 + 隐藏 input"的常见套路。

【面试考察】
面试官："文件上传怎么自动化？"

参考回答框架：
1. `<input type="file">` 直接 `send_keys(绝对路径)`，绕过系统对话框
2. 原理：系统文件对话框是 OS 原生，Selenium 控制不了，只能直接赋值
3. 非 input 型：找隐藏的 input，或用 AutoIt/pyautogui 操作系统窗口
4. 注意：绝对路径、路径转义、多个文件上传用逗号分隔

【易错点】

| 误区 | 纠正 |
|------|------|
| click 上传按钮后想选文件 | 系统对话框 Selenium 控制不了，会卡住 |
| 用相对路径 send_keys | 工作目录不同会找不到 → 用绝对路径 |
| 对 div 模拟上传按钮 send_keys | 无效，找背后的隐藏 `<input type="file">` |
