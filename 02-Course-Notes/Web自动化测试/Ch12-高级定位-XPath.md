## 一、XPath 定位概述

### 知识点 1：XPath 是什么、与 CSS 如何互补

【课程原话/定义】
XPath 是一种用于在 XML 文档中检索信息的语言，通过**路径表达式**导航文档。XPath 的灵活性和强大功能使其成为在 XML 结构中准确定位和提取数据的重要工具。

XPath 使用场景：①Web 自动化测试（通过层次结构、属性、文本内容精准定位）②App 自动化测试（原生 + 混合 Hybrid App 中跨平台一致定位）。

示例：

```javascript
// 复制的绝对定位
$x('//*[@id="ember75"]/td[1]/span/a')
// 编写的相对定位
$x("//*[text()='技术分享 | SeleniumIDE用例录制']")
```

【为什么？】
XPath 和 CSS（Ch11）是**互补**的，各自补对方的短板：

| 能力 | CSS | XPath |
|------|-----|-------|
| 按 id/class/属性定位 | ✅ | ✅ |
| **按元素文本定位**（`text()`） | ❌ 不能 | ✅ 能 |
| **向上找父级/祖先**（`..`、轴） | ❌ 不能 | ✅ 能 |
| 找兄弟、按位置 | 部分（`~`/`+` 弱） | ✅ 完整（轴） |
| 写法简洁、执行快 | ✅ 更优 | 略冗长 |

所以规范是"**CSS 为主、XPath 补位**"：常规元素用 CSS（简洁快），需要按文本、找父级、复杂层级时才用 XPath。

相对定位（`//*[text()='...']`）vs 绝对定位（`//*[@id='ember75']/td[1]/span/a`）的差别与 Ch11 的 CSS 一样：**相对定位锚定稳定条件（文本/属性），绝对定位写死结构路径**——结构一变绝对定位就废。

【必须掌握】
- XPath 是路径表达式语言，能按层次/属性/文本定位
- 与 CSS 互补：XPath 能按文本、能向上找父级（CSS 不能）
- 规范：CSS 为主、XPath 补位
- 相对定位（锚定文本/属性）优于绝对定位（写死结构）

【企业场景】
你要定位一个按钮，它没有任何 id/class，只有一个文本"提交订单"。CSS 拿它没办法（不能按文本），但 XPath 一行 `//button[text()='提交订单']` 搞定。反过来，能拿到 id 时你会优先用 CSS 的 `#submit`——这就是"CSS 为主、XPath 补位"的日常。

【面试考察】
面试官："CSS 和 XPath 定位有什么区别？什么时候必须用 XPath？"

参考回答框架：
1. 都能按 id/class/属性定位，CSS 更简洁、执行略快
2. XPath 独有能力：按文本（`text()`）、向上找父级（`..`）、完整轴（兄弟/祖先）
3. 必须用 XPath 的场景：要按元素文本定位、要从元素回溯到父级/祖先
4. 规范：CSS 为主、XPath 补位

【易错点】

| 误区 | 纠正 |
|------|------|
| 认为 XPath 万能所以全用 XPath | CSS 更简洁，能 CSS 就 CSS，XPath 留给文本/父级场景 |
| 从 F12 "Copy full XPath" 粘贴 | 绝对路径，结构一变就废 |

【我的理解】

## 二、XPath 基础语法

### 知识点 2：六种基础符号

【课程原话/定义】

| 表达式 | 结果 |
|--------|------|
| `/` | 从该节点的子元素选取 |
| `//` | 从该节点的子孙元素选取 |
| `*` | 通配符 |
| `nodename` | 选取此节点的所有子节点 |
| `..` | 选取当前节点的父节点 |
| `@` | 选取属性 |

```javascript
$x("/")                             // 整个页面（根）
$x("/*")                            // 根下的第一层元素
$x("//*")                           // 页面所有元素
$x("//div")                         // 所有 div 节点
$x('//*[@id="site-logo"]')          // id 为 site-logo 的节点
$x('//*[@id="site-logo"]/..')       // 它的父节点（用 .. 向上）
```

【为什么？】
六个符号里最需要分清的是 `/` 和 `//`：

| 符号 | 含义 | 例子 |
|------|------|------|
| `/` | **直接子**（下一层） | `/html/body/div` 只取直接子 |
| `//` | **任意后代**（任意深度） | `//div` 取页面所有 div |

这和 Ch11 的 CSS `>`（父子）vs 空格（后代）是**完全对应的概念**——`/` ≈ `>`，`//` ≈ 空格。`..` 是 XPath 独有的"向上取父节点"，CSS 没有对应物，这是 XPath 补 CSS 短板的第一个体现。

`@` 取属性：`//*[@id="site-logo"]` 就是"id 属性等于 site-logo 的任意元素"。

【必须掌握】
- `/` 直接子 vs `//` 任意后代（对应 CSS 的 `>` 和空格）
- `..` 向上取父节点（CSS 没有）
- `@` 取属性，`*` 通配符

【企业场景】
你定位到一个输入框后，想断言它所在的那一行（`<tr>`）的某个状态，CSS 只能往下找，XPath 用 `//input[@id='x']/../..` 向上回溯两层的父节点。这种"从元素反推父级"是 XPath 的独门用法。

【面试考察】
面试官："XPath 里 `/` 和 `//` 有什么区别？`..` 是干嘛的？"

参考回答框架：
1. `/` 选直接子节点，`//` 选任意深度的后代
2. `..` 选当前节点的父节点（向上回溯）
3. 类比 CSS：`/` ≈ `>`，`//` ≈ 空格；`..` 是 CSS 没有的能力

【易错点】

| 误区 | 纠正 |
|------|------|
| `/` 和 `//` 不分 | `/` 只下一层，`//` 任意深度 |
| 以为 CSS 也能向上找父级 | CSS 不能，向上回溯必须用 XPath 的 `..` |

【我的理解】
> （把 XPath 的 `/`、`//`、`..` 和 CSS 的 `>`、空格做一一对应，哪个 XPath 符号在 CSS 里没有对应物？）

## 三、XPath 顺序关系（索引）

### 知识点 3：索引 [n] 的坑

【课程原话/定义】
XPath 通过索引直接获取对应元素：

```javascript
$x("//*[@id='ember21']//li")       // 该节点下所有的 li
$x("//*[@id='ember21']//li[1]")    // 该节点下【所有节点中】的第一个 li
```

【为什么？】
这里藏着一个**面试爱考、极易翻车**的坑：`//li[1]` 不是"全局第一个 li"，而是"**每个父节点下各自的第一 li**"。

```javascript
$x("//*[@id='ember21']//li[1]")   // 每个父 ul 下各取第一个 li → 可能返回多个！
$x("(//*[@id='ember21']//li)[1]") // 加括号：全局真正的第一个 li → 只返回一个
```

原因：XPath 的 `[1]` 是**位置谓词**，作用在"它前面那段路径匹配出的每一个结果集"上。`//li[1]` 对每个父节点都取第 1 个；要"全局第一个"，必须先用括号 `(...)` 把整个结果集包起来，再 `[1]`。

同理，`last()` 也要配括号：`(//div)[last()]` 才是全局最后一个 div。

【必须掌握】
- `//li[1]` = 每个父节点下的第一个（不是全局第一个）——高频陷阱
- 全局第一个：`(//li)[1]`；全局最后一个：`(//div)[last()]`
- 位置谓词 `[n]` 作用在"前面路径的每个结果集"上

【企业场景】
你定位"列表页第一行"，写了 `//tr[1]`，结果发现匹配到了**每个表格里的第一行**（页面有多个表格），而不是整个页面的第一行。改成 `(//tr)[1]` 才拿到真正想要的那一行。这个坑在"页面里有多个同类结构"时必踩。

【面试考察】
面试官："`//li[1]` 和 `(//li)[1]` 有什么区别？"

参考回答框架：
1. `//li[1]` 是"每个父节点下的第一个 li"，可能返回多个
2. `(//li)[1]` 是"整个文档第一个 li"，只返回一个
3. 原因：`[n]` 是位置谓词，作用在每一步的结果集上
4. 要"全局第 n 个"，用括号 `(...)` 包住再 `[n]`

【易错点】

| 误区 | 纠正 |
|------|------|
| 以为 `//li[1]` 是全局第一个 | 是"每个父下的第一个"，可能多个 |
| 全局第一个写成 `//li[1]` | 要 `(//li)[1]` |
| `last()` 不配括号 | `//div[last()]` 是"每个父下最后一个"，全局用 `(//div)[last()]` |

【我的理解】
> （页面里有两个 `<ul>`，各含 3 个 `<li>`。`//li[1]` 返回几个元素？`(//li)[1]` 返回几个？）

## 四、XPath 高级用法

### 知识点 4：last / 与 / 或 / 文本

【课程原话/定义】

| 语法 | 含义 |
|------|------|
| `[last()]` | 选取最后一个 |
| `[@属性名='值' and @属性名='值']` | 与关系 |
| `[@属性名='值' or @属性名='值']` | 或关系 |
| `[text()='文本信息']` | 根据文本信息定位 |
| `[contains(text(),'文本信息')]` | 根据文本信息包含定位 |

注意：所有的表达式都需要和 `[]` 结合。

```javascript
$x("(//div)[last()]")                                        // 全局最后一个 div
$x("//*[@class='nav-item_new new ember-view' and @id='ember24']")  // 与：两个属性都满足
$x("//*[@id='ember23' or @id='ember24']")                   // 或：满足其一
$x('//*[text()="所有类别"]')                                  // 文本精确匹配
$x('//*[contains(text(),"Python测试开发")]')                  // 文本包含匹配
```

【为什么？】
这五个是 XPath 的"组合拳"，核心价值在**按文本定位**——这是 CSS 完全做不到的（Ch11 讲的短板）：

| 需求 | 写法 | 注意 |
|------|------|------|
| 文本精确 | `[text()='所有类别']` | 文本必须**完全一致**（含空格） |
| 文本包含 | `[contains(text(),'Python')]` | 更稳，抗文案微调 |
| 多属性与 | `[@a='x' and @b='y']` | 两个条件都满足 |
| 多属性或 | `[@a='x' or @b='y']` | 满足其一 |

文本定位的两个坑：①`text()` 是**精确匹配**，文案带空格/换行就匹配不上，此时用 `contains` 更稳；②`contains` 只匹配文本内容，不匹配属性（匹配属性用 `contains(@class, 'x')`）。

`last()` 用于"取最新/最后一个"，常见于"列表最新一条数据"的场景（配合括号 `(//x)[last()]`）。

【必须掌握】
- 按文本定位：`[text()='...']` 精确、`[contains(text(),'...')]` 包含
- 多属性：`and`（交集）、`or`（并集）
- `[last()]` 取最后一个（配括号）
- 所有谓词都要和 `[]` 结合

【企业场景】
你断言"最新发布的帖子标题包含关键字"，定位"最新一条"用 `(//div[@class='topic-title'])[last()]`，再 `.text` 断言。按文本定位在"按钮/菜单没有 id/class"时是唯一解：`//button[text()='提交']`。

【面试考察】
面试官："XPath 怎么按文本定位？`text()` 和 `contains` 有什么区别？"

参考回答框架：
1. `[text()='x']` 精确匹配整个文本；`[contains(text(),'x')]` 包含匹配
2. 文案带空格/换行/前后缀时 `text()` 精确匹配会失败 → 用 contains 更稳
3. `contains` 也用于属性：`contains(@class, 'x')`
4. 按文本定位是 XPath 相对 CSS 的核心优势

【易错点】

| 误区 | 纠正 |
|------|------|
| `text()` 当包含匹配用 | `text()` 是精确匹配，包含用 `contains` |
| `contains` 匹配属性 | 匹配属性要 `contains(@属性, 'x')` |
| `last()` 不配括号 | 全局最后一个要 `(...)[last()]` |

【我的理解】
> （`[text()='所有类别']` 和 `[contains(text(),'类别')]` 谁的匹配更稳？为什么？）

## 五、XPath 定位实战

### 知识点 5：实战 + 调试方法

【课程原话/定义】
测试步骤：打开测试人社区（https://ceshiren.com/）→ 用 XPath 高级定位进入【类别】页面 → 获取文本断言。

Python 实现：

```python
from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.common.by import By


class Test():
    def setup(self):
        service = Service()
        options = webdriver.ChromeOptions()
        self.driver = webdriver.Chrome(service=service, options=options)
        self.driver.implicitly_wait(10)

    def teardown(self):
        self.driver.quit()

    def test_xpath(self):
        self.driver.get("https://www.ceshiren.com")
        self.driver.find_element(By.XPATH, "//*[text()='类别']").click()   # 按文本定位并点击
        text = self.driver.find_element(By.XPATH, "//*[text()='提问区']").text  # 按文本定位取值
        assert text == '提问区'                                            # 断言
```

【为什么？】
这条实战的核心看点：**两个定位都用 `text()`**——因为"类别"、"提问区"是纯文本元素，没有稳定 id/class，这正是 XPath 的用武之地（CSS 做不到按文本定位）。

调试方法（和 Ch11 的 CSS 对照）：

| 调试方式 | 操作 | 用途 |
|----------|------|------|
| Console `$x("xpath")` | 输入 XPath 直接看匹配结果 | 快速验证 XPath |
| Elements 面板 Ctrl+F | 粘贴 XPath（或 CSS）看"1 of N" | 验证匹配数 |

写 XPath 前先在 Console 里 `$x()` 跑一遍、确认匹配数是 1，再写进代码——和 Ch11 的 CSS 是同一个习惯。

【必须掌握】
- XPath 实战：按文本定位（`text()`）→ 点击/取值 → 断言
- 调试：Console `$x()` / Elements Ctrl+F
- 文本元素没有 id/class 时，`text()` 是首选

【企业场景】
你在维护一个"老项目"，页面元素几乎都没有 id/class，只有中文文本。CSS 定位几乎无从下手，XPath 的 `text()` 定位成了救命稻草。你总结出一条团队经验：**"CSS 吃属性，XPath 吃文本"**——属性丰富用 CSS，纯文本元素用 XPath。

【面试考察】
面试官："XPath 定位怎么调试、怎么验证？"

参考回答框架：
1. Console 输入 `$x("xpath 表达式")` 看匹配结果
2. Elements 面板 Ctrl+F 粘贴表达式看"1 of N"
3. 匹配数必须为 1（或明确取第几个），避免点错元素
4. 先验证再写进代码，省去反复失败

【易错点】

| 误区 | 纠正 |
|------|------|
| 文本元素硬套 CSS | CSS 不能按文本，用 XPath `text()` |
| 写完 XPath 直接跑 | 先 `$x()` / Ctrl+F 验证匹配数为 1 |
| `text()='提问区'` 文案带空格 | 精确匹配失败 → 换 `contains(text(),...)` |

【扩展知识】
XPath 的"轴"（Axis）是更进阶的能力：`parent::`、`following-sibling::`、`ancestor::` 等，能沿文档树任意方向导航。日常用 `..`（父）和 `text()` 已覆盖 90% 场景，轴留给"从某元素回溯到特定祖先/兄弟"的复杂场景。面试提一句"了解轴（axis）"即可加分。

【我的理解】
> （综合 Ch11 + Ch12：一个元素有稳定 id，一个元素只有文本。分别用 CSS 还是 XPath？写出两个定位表达式。）
