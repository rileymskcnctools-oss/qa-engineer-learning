## 一、控件交互概览

### 知识点 1：元素操作 vs 属性获取

【课程原话/定义】
常见的控件交互包含两部分：
1. **元素操作**——对页面元素可以做什么，比如点击、输入、清空等
2. **元素属性获取**——找到元素之后获取它的信息，比如获取元素的文本、获取元素的属性、获取元素的坐标等

【为什么？】
定位只是"找到"元素，交互才是"用它"。一条完整用例的三段式是：

```
定位（Ch06）→ 操作/取值（本章）→ 断言（Ch04）
```

- **元素操作**对应"步骤"：模拟用户在页面上的动作
- **属性获取**对应"断言/调试"：拿到真实结果，和预期比对，或打印出来排查问题

所以本章是连接"定位"和"断言"的中间一环——不会操作，定位到了也白搭；不会取值，操作完了也验证不了。

【必须掌握】
- 控件交互 = 元素操作（动作）+ 属性获取（数据）
- 操作服务于"步骤"，取值服务于"断言/调试"
- 完整链路：定位 → 操作 → 取值 → 断言

【企业场景】
你写一条登录用例，`find_element` 找到了用户名框，但如果不知道 `send_keys` 怎么输入、`click` 怎么点按钮、`.text` 怎么取回错误提示，这条用例永远写不出来。控件交互是写任何一条 UI 用例的"基本动作库"。

【面试考察】
面试官："定位到一个元素之后，你能对它做哪些事？"

参考回答框架：
1. 两类：操作（动作）和取值（数据）
2. 操作：`click` 点击、`send_keys` 输入、`clear` 清空（还有 submit、拖拽等进阶）
3. 取值：`.text` 文本、`get_attribute("...")` 属性值、`location/size` 坐标尺寸
4. 用途：操作用于走流程，取值用于断言和调试

【易错点】

| 误区 | 纠正 |
|------|------|
| 认为定位到就完事了 | 定位只是起点，操作/取值才是目的 |
| 把"操作"和"断言"混在一起 | 操作是步骤，断言是验证，两者要分开写 |

【我的理解】
> （"定位 → 操作 → 取值 → 断言"这条链路里，如果缺了"取值"会怎样？想想 Ch04 讲的"没有断言的脚本不是测试"。）

## 二、元素操作

### 知识点 2：输入 send_keys / 清空 clear / 点击 click

【课程原话/定义】
场景：输入"霍格沃兹测试开发" → 清空搜索框 → 点击搜索按钮。演练地址 https://www.sogou.com/ 。

Python 版本：

```python
from selenium import webdriver
from selenium.webdriver.common.by import By


class TestInteractions:
    def setup_method(self):
        self.driver = webdriver.Chrome()
        self.driver.implicitly_wait(10)

    def teardown_method(self):
        self.driver.quit()

    def test_interaction_demo(self, driver):
        driver.get("https://www.sogou.com/")
        search_box = driver.find_element(By.ID, "query")
        search_box.send_keys("霍格沃兹测试开发")   # 输入
        search_box.clear()                         # 清空
        search_button = driver.find_element(By.ID, "stb")
        search_button.click()                      # 点击
```

Java 版本：

```java
@Test
void interactionDemo(){
    driver.get("https://www.sogou.com/");
    driver.findElement(By.id("query")).sendKeys("霍格沃兹测试开发");  // 输入
    driver.findElement(By.id("query")).clear();                       // 清空
    driver.findElement(By.id("stb")).click();                         // 点击
}
```

【为什么？】
这三个方法是"鼠标键盘动作的语义化封装"——Selenium 把底层的 W3C WebDriver 协议动作翻译成人类可读的动词：

| 方法 | 模拟的动作 | 本质 |
|------|-----------|------|
| `send_keys("文本")` | 键盘逐字输入 | 还能传 `Keys.ENTER` / `Keys.TAB` 等特殊键 |
| `clear()` | 清空输入框 | 相当于"删光现有内容"，为重新输入做准备 |
| `click()` | 鼠标左键单击 | 触发元素的 click 事件（可能是按钮/链接/复选等） |

注意它们都是**元素实例的方法**：先 `find_element` 拿到元素对象，再调 `元素.方法()`，不是 driver 直接调。

【必须掌握】
- `元素.send_keys("文本")` 输入；可传 `Keys.ENTER` 模拟回车
- `元素.clear()` 清空输入框
- `元素.click()` 点击
- 三者的调用对象是**定位返回的元素**，不是 driver

【企业场景】
你在写搜索用例：输入关键词 → 清空（验证 clear 后输入框确实空了，用 `get_attribute("value")` 断言空串）→ 输入新词 → 点搜索。`clear()` 在企业里有个真实坑：某些输入框（`type=number`、日期选择器、第三方 autocomplete 组件）`clear()` 清不掉，因为它们的值存在组件内部状态而非原生 input value。这时要么用三键清空 `Ctrl+A` + `Delete`，要么用 JS 直接改 value。

【面试考察】
面试官："`send_keys` 和 `click` 有什么区别？`clear` 什么情况下会失效？"

参考回答框架：
1. `send_keys` 模拟键盘输入（可传字符串或 `Keys` 特殊键），`click` 模拟鼠标单击
2. `clear` 清空原生 input 的 value，但对 number/date/第三方组件可能失效（值在组件状态里）
3. 失效时的兜底：`send_keys(Keys.CONTROL + "a")` 全选 + `send_keys(Keys.DELETE)` 删除，或 JS `execute_script` 直接改
4. 加分：`send_keys` 不需要先 `click` 聚焦，它会自动聚焦（Ch04 讲过）

【易错点】

| 误区 | 事实 | 纠正 |
|------|------|------|
| 课程 Python 示例 `test_interaction_demo(self, driver)` 用了 `driver` 参数 | 类里没有 `driver` fixture，`setup_method` 建的是 `self.driver`；直接跑 pytest 会报 `fixture 'driver' not found` | 改为 `self.driver`（对照课程第二个示例 `test_interaction_demo2(self)` 的写法） |
| 以为 `clear()` 能清空所有输入框 | number/date/自定义组件可能清不掉 | 兜底用 `Keys.CONTROL+"a"` + `Keys.DELETE` 或 JS |
| `send_keys` 前先 `click` 一下 | 多余动作（Ch04 录制脚本讲过） | `send_keys` 会自动聚焦，除非有遮罩才需处理 |
| 课程 Java 示例 `setUpAll` 注释写"显式等待"却调用 `implicitlyWait` | copy-paste 笔误（Ch07 同款） | 隐式等待就是 `implicitlyWait`，真正的显式等待是 `new WebDriverWait(...).until(...)` |

【我的理解】
> （课程第一个 Python 示例的 `test_interaction_demo(self, driver)` 和第二个 `test_interaction_demo2(self)` 有什么不同？哪一个能正常跑？你判断的依据是什么？）

## 三、获取元素属性信息

### 知识点 3：获取元素文本 .text

【课程原话/定义】
原因：定位到元素后，获取元素的文本信息、属性信息等。
目的：根据这些信息进行断言或者调试。

获取元素文本（Python）：`self.driver.find_element(By.ID, "frame").text`
Java：`driver.findElement(By.id("frame")).getText()`

【为什么？】
`.text` 取的是浏览器**渲染后的可见文本**——也就是用户眼睛真正看到的内容。所以它最贴近"用户视角"，是断言文本时最常用的取值方式。

一个关键细节（Ch04 已讲，这里再强调）：`.text` 对**不可见元素返回空串**。所以如果发现取回来是空字符串，先怀疑"元素是不是被 CSS 藏起来了（display:none / 被遮挡）"，而不是"定位错了"。

【必须掌握】
- `.text`（Java `getText()`）取渲染后可见文本，是断言文本的首选
- 不可见元素 `.text` 返回空串
- 用途：断言提示语、标题、结果文本

【企业场景】
你断言登录失败的提示"用户名或密码错误"时，用 `error_msg.text` 取值。但有个坑：如果提示框是"闪现后隐藏"的 toast，`.text` 可能已经取到空串。这时要么用显式等待等到提示可见再取，要么用 `get_attribute("textContent")` 兜底。

【面试考察】
面试官："`.text` 取不到值，可能是什么原因？"

参考回答框架：
1. 元素不可见（display:none / 被遮挡 / 还没渲染完）→ `.text` 返回空串
2. 定位器匹配到了多个元素，取到了错的那个
3. 取错对象：输入框的内容不能用 `.text`，要用 `get_attribute("value")`
4. 解法：显式等待可见后再取；隐藏元素用 `get_attribute("textContent")`

【易错点】

| 误区 | 纠正 |
|------|------|
| 用 `.text` 取输入框内容 | input 的值在 value 属性里，`.text` 永远空 → 用 `get_attribute("value")` |
| `.text` 空就断定定位错 | 先排查元素是否可见/是否被遮挡 |
| 页面还在加载就取 `.text` | 加显式等待，等元素可见再取 |

【我的理解】
> （同一个元素，`.text` 和 `get_attribute("textContent")` 什么时候结果一样、什么时候不一样？提示：一个只管"可见"，一个包含"隐藏"。）

### 知识点 4：获取元素属性 get_attribute

【课程原话/定义】
获取元素的属性（HTML 的属性值）（Python）：

```python
text2 = self.driver.find_element(By.ID, "locate_id").get_attribute("name")
```

Java：`driver.findElement(By.id("locate_id")).getAttribute("name")`

演练地址 https://vip.ceshiren.com/#/ui_study （`frame` 元素取 `.text`，`locate_id` 元素取 `name` 属性）。

【为什么？】
`get_attribute("属性名")` 是"万金油"取值法——HTML 元素上**任意一个属性**都能取：

| 想取什么 | 写法 |
|----------|------|
| name 属性 | `get_attribute("name")` |
| id / class | `get_attribute("id")` / `get_attribute("class")` |
| 链接地址 | `get_attribute("href")` |
| 输入框当前值 | `get_attribute("value")` |
| 自定义数据 | `get_attribute("data-test-id")` |
| 完整文本（含隐藏） | `get_attribute("textContent")` |

它和 `.text` 的关系（Ch04 知识点 4 已详细对比）：`.text` 只能取"可见文本"，`get_attribute` 能取任意属性值——二者是"取内容"和"取元数据"的分工。断言输入框内容、链接跳转地址、元素自定义标记时，都必须靠 `get_attribute`。

【必须掌握】
- `get_attribute("属性名")` 取任意 HTML 属性值（name/id/class/href/value/data-*…）
- 输入框当前值 → `get_attribute("value")`（`.text` 取不到）
- 隐藏文本 → `get_attribute("textContent")`
- 用途：断言属性值（链接、输入框值、自定义标记）、调试

【企业场景】
你断言"点击后跳转到指定 URL"，不是等页面标题，而是直接 `link.get_attribute("href")` 拿 href 和预期比对——快且不依赖新页面渲染。再比如前端加了 `data-test-id="login-btn"`，你的定位器和断言都能用 `get_attribute("data-test-id")` 做契约校验，这就是 Ch06 讲的"定位契约化"的延伸。

【面试考察】
面试官："`.text` 和 `get_attribute` 有什么区别？输入框的值用什么取？"

参考回答框架：
1. `.text` 取渲染后可见文本（不可见返回空串）；`get_attribute` 取 HTML 任意属性值
2. 输入框当前值用 `get_attribute("value")`（`.text` 对 input 取不到）
3. 隐藏内容用 `get_attribute("textContent")`，可见文本用 `.text`
4. 加分：`get_attribute` 还能取 href、data-* 等元数据，是断言链接/自定义标记的手段

【易错点】

| 误区 | 纠正 |
|------|------|
| 用 `.text` 断言输入框内容 | 永远空串 → `get_attribute("value")` |
| 以为 `get_attribute` 只能取标准属性 | 任意属性（含 data-*）都能取 |
| 取 `<a>` 链接文本用 `get_attribute("text")` | 更通用的是 `.text`（`get_attribute("text")` 是特定标签的兼容用法） |

【扩展知识】
坐标与尺寸（课程简介里提到"获取元素的坐标"，未展开）：`element.location` / `element.size` / `element.rect` 返回元素的位置和宽高。企业里用于截图定位、判断元素是否在可视区、或者用 `ActionChains` 精确拖拽到某坐标。了解即可，属进阶。

【我的理解】
> （输入框里已经输入了"霍格沃兹测试开发"，现在要断言它确实在框里——用 `.text` 还是 `get_attribute("value")`？为什么另一个取不到？）

## 今日课程总结

| 模块 | 方法 | 作用 |
|------|------|------|
| 点击 | `click()` | 模拟鼠标左键单击 |
| 输入 | `send_keys("文本")` | 模拟键盘输入（可传 `Keys`） |
| 清空 | `clear()` | 清空输入框内容 |
| 获取元素属性信息 | `.text` / `get_attribute("属性名")` | 取文本/属性值，用于断言或调试 |

> 完整链路：**定位（Ch06）→ 操作/取值（本章）→ 断言（Ch04）**。
