## 一、测试执行顺序与控制

### 知识点 1：默认顺序 + --lf / --ff

【课程原话/定义】
测试用例调度 = pytest 如何发现、加载、排序并执行测试。

默认执行顺序：
- 按文件名字母顺序收集测试文件
- 每个文件内按函数定义顺序执行
- 类内按方法定义顺序执行

控制执行顺序：
- pytest-order 插件：显式控制顺序（见 Ch28）
- --lf（--last-failed）：只重新运行上次失败的用例
- --ff（--failed-first）：先运行上次失败的用例，再运行其余

```bash
pytest test_double.py --lf    # 只跑上次失败的
pytest test_double.py --ff    # 失败优先
```

【为什么？】
为什么要理解执行顺序和控制？因为调试时"只跑失败的用例"能大幅提效——修复一个 bug 后，不想全量跑，只想重跑那几条失败的。--lf 就是干这个的（只重跑失败），--ff 是"失败优先"（先跑失败再跑其余，快速看失败是否修复）。理解默认顺序（文件名字母序 + 定义顺序）也有助于理解"为什么用例按这个顺序跑"，以及为什么需要 pytest-order 插件来显式控制顺序。

【必须掌握】
- 默认顺序：文件名字母序 + 文件内定义顺序
- --lf：只重跑上次失败（调试高效）
- --ff：失败优先执行
- pytest-order 插件：显式控制顺序
- 修复成功后 --lf 会跑全部（因为没失败了）

【企业场景】
你在公司修好一个 bug 后，用 pytest --lf 只重跑之前失败的用例，几十秒验证修复，不用全量跑几千条用例。这是调试的高频操作。

【面试考察】
面试官：「pytest 用例默认按什么顺序执行？怎么控制顺序？」

参考回答框架：
1. 默认：文件名字母序 + 文件内定义顺序
2. --lf 只跑失败、--ff 失败优先
3. pytest-order 插件显式控制
4. 目的：调试时精准重跑失败

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 以为用例按编写时间跑 | 默认是文件名字母序 + 定义顺序 |
| --lf 和 --ff 混淆 | --lf 只跑失败，--ff 失败优先（还跑其余） |
| 依赖固定顺序写用例 | 用例应独立，别依赖执行顺序（可配 order 插件） |
