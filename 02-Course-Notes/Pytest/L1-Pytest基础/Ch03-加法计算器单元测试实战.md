## 一、用 setup/teardown 组织测试

### 知识点 1：setup_method / teardown_method / teardown_class

【课程原话/定义】
被测产品是一个加法计算器 add(a, b)，需求：用 Pytest 编写测试用例，每个测试函数前打印【开始计算】、后打印【结束计算】，全部用例结束打印【结束测试】。

实现（用测试类 + 测试装置）：
```python
class TestAdd:
    def setup_method(self):          # 每个测试方法前
        print("开始计算")
    def teardown_method(self):       # 每个测试方法后
        print("结束计算")
    def teardown_class(self):        # 整个测试类结束后
        print("结束测试")

    def test_add(self):
        result = add(1, 1)
        assert 2 == result
```

【为什么？】
为什么要用 setup/teardown 组织测试？因为单元测试常有"前后置"需求——测试前准备、测试后清理、全部结束后收尾。setup_method/teardown_method 是"方法级"（每个测试方法前后各执行一次），teardown_class 是"类级"（整个测试类结束后执行一次）。这套装置让"重复的前后置逻辑"集中管理，不用在每个用例里重复写。这是 Pytest 测试框架结构（模块级/函数级/类级/方法级装置）的落地应用。

【必须掌握】
- setup_method：每个测试方法前执行（准备）
- teardown_method：每个测试方法后执行（清理）
- teardown_class：整个测试类结束后执行（收尾）
- 测试装置（fixture 的前身）集中管理前后置逻辑
- 用例：准备数据 → 调用被测函数 → assert 断言

【企业场景】
你在公司写单元测试，测试类里每个用例前要连数据库、每个用例后要清理数据，全部结束要关闭连接。用 setup_method/teardown_method/teardown_class 集中管理，比在每个用例里重复写要干净得多。

【面试考察】
面试官：「Pytest 有哪些测试装置？作用域是什么？」

参考回答框架：
1. setup_method/teardown_method：方法级（每个测试方法前后）
2. setup_class/teardown_class：类级（整个测试类前后）
3. setup_module/teardown_module：模块级
4. 用测试类 + 装置组织用例

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 装置方法名写错 | 必须用固定名 setup_method/teardown_method 等 |
| teardown_class 忘写 classmethod | 类级装置要用 @classmethod |
| 装置里写业务逻辑 | 装置只做前后置，断言在测试方法里 |
