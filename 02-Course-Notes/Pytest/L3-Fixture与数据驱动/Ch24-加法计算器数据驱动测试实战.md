## 一、yaml + fixture + conftest 组合实战

### 知识点 1：数据外置 + fixture 前后置 + 数据驱动

【课程原话/定义】
综合运用 yaml 数据驱动 + fixture 前后置 + conftest 共享：

```python
# utils/util.py —— 读取 yaml 工具
import yaml
def get_yaml_data(filepath):
    with open(filepath, encoding="utf-8") as f:
        return yaml.safe_load(f)

# test_add_prac.py
def get_add_data(level):
    yaml_data = get_yaml_data("../data/add.yaml")
    return yaml_data.get(level)

@pytest.fixture(autouse=True)              # 方法级自动生效
def method_info():
    print("开始计算")
    yield
    print("结束计算")

@pytest.fixture(scope="class", autouse=True)  # 类级自动生效
def class_info():
    yield
    print("结束测试")

class TestAdd:
    @pytest.mark.P0
    @pytest.mark.parametrize("a, b, expect", get_add_data("P0"))
    def test_add_P0(self, a, b, expect):
        result = add(a, b)
        assert result == expect
```

yaml 数据（add.yaml，按优先级分组）：
```yaml
P0:
- [ 1, 1, 2 ]
- [ -0.01, 0.02, 0.01 ]
P1:
- [ 98.99, 99, 197.99 ]
special:
- [ "*&", 0.2, "a参数为非数字" ]
```

【为什么？】
为什么这个实战是 L3 的收尾？因为它把 L3 的知识点"串"起来：yaml 数据驱动（数据外置）、fixture 前后置（autouse 自动生效）、作用域（function/class）、conftest 共享。相比 Ch12（参数化实战，数据硬编码在 parametrize 里），这里数据外置到 yaml，前后置改用 fixture（autouse 自动生效），更接近"工程化"的真实形态。核心演进：从"数据硬编码"到"数据外置 + fixture 自动前后置"，这是 L3 相比 L2 的进阶。

【必须掌握】
- yaml.safe_load 读取数据，get(level) 按级别取数据
- fixture autouse=True 自动生效（无需显式传参）
- 作用域：function 级（每用例）vs class 级（每类）
- 数据按优先级/类型分组管理（P0/P1/special 等）
- conftest.py 管理共享 fixture

【企业场景】
你在公司接口自动化框架，测试数据放 yaml（按模块/优先级分组），前后置用 autouse fixture 自动执行，公共 fixture 放 conftest 共享。这套"数据外置 + fixture 自动前后置 + conftest 共享"是接口自动化框架的标准形态。

【面试考察】
面试官：「说说你的数据驱动 + fixture 怎么配合的？」

参考回答框架：
1. 数据外置到 yaml，按级别分组
2. 读取工具 get_yaml_data 统一读取
3. fixture autouse=True 自动前后置
4. conftest 共享公共 fixture
5. parametrize 接收 yaml 数据驱动

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 数据硬编码在 parametrize | 数据量大应外置到 yaml |
| autouse fixture 忘 autouse=True | 不设 autouse 要显式传参才生效 |
| yaml 数据格式和 parametrize 不匹配 | get(level) 返回 [[]] 格式 |

【扩展知识】
这个实战体现了 pytest 数据驱动的完整演进：Ch12 参数化实战（数据硬编码）→ Ch24 数据驱动实战（数据外置 yaml + fixture 自动前后置 + conftest 共享）。理解了这条演进，就理解了"测试框架工程化"的方向：数据、前后置、配置都从代码里"抽离"出来，代码只留测试逻辑。
