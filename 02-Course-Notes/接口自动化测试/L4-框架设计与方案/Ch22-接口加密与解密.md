## 一、Base64 与加密响应处理

### 知识点 1：base64 编码 + 加密接口的三种解法

【课程原话/定义】
Base64 是用 64 个字符表示二进制数据的编码方式：
- 标准 base64 有 64 个字符（大小写字母、数字、+、/）+ 后缀等号
- 3 个字节 → 4 个可打印字符，编码后长度一定能被 4 整除（不算等号）
- 等号作后缀，数目只能是 0、1、2 个（原文长度不被 3 整除时补 \0）

加密接口的三种解法：
1. **通用加密算法**：了解算法（如 base64），用通用解密算法解密
2. **研发提供加解密 lib**：不了解算法，让研发提供 lib 包
3. **提供远程解析服务**：既非通用算法、研发也无法提供 lib，由加密方提供远程解析服务

Python 演示（base64 加解密）：
```python
import requests, base64
secret_msg = base64.b64encode("霍格沃兹".encode('utf-8'))   # 加密
res = requests.post(url, data={"msg": secret_msg})
msg = res.json()["form"]["msg"]                              # 取加密响应
encoded_str = base64.b64decode(msg).decode('utf-8')          # 解密
assert encoded_str == "霍格沃兹"
```

【为什么？】
为什么要专门讲"接口加密与解密"？因为不是所有接口都明文传输——金融、政务、安全敏感的系统会加密请求/响应数据。测试时，加密的响应是一堆看不懂的字符，不解密就没法断言。而 base64 是"入门级加密"（严格说是编码），理解它的原理（3 字节变 4 字符、等号补位）能帮你识别"这串东西是不是 base64"。三种解法（通用算法/lib 包/远程服务）则覆盖了"你会解 / 研发给工具 / 别人帮你解"三种现实情况。

【必须掌握】
- Base64：64 字符 + 等号后缀，3 字节 → 4 字符，是可逆的"编码"而非"加密"
- 加密接口三解法：通用算法解密 / 研发提供 lib / 远程解析服务
- Python：base64.b64encode 加密、b64decode 解密
- 加解密后做断言（解密后的数据 == 预期）

【企业场景】
你在公司测一个加密接口，响应是一串 base64 密文。你用 `base64.b64decode()` 解密后再断言字段值。如果遇到公司自研的加密算法（不是 base64），你搞不定，就找研发要加解密 lib 包，或让加密方提供远程解析服务。这三种解法对应"简单、中等、复杂"三种加密场景。

【面试考察】
面试官：「接口返回的数据是加密的，你怎么测试？」

参考回答框架：
1. 先判断加密类型（如 base64 是编码，可直接解）
2. 通用算法：用对应解密算法（base64.b64decode）
3. 自研算法：找研发要加解密 lib 包
4. 都不行：让加密方提供远程解析服务
5. 解密后再断言

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 认为 base64 是加密 | base64 是可逆的"编码"，任何人拿到都能解，不算加密 |
| 解密后忘 decode | b64decode 返回 bytes，要 .decode('utf-8') 转字符串 |
| 自研算法硬要自己破解 | 找研发要 lib 或远程服务，别浪费时间逆向 |
