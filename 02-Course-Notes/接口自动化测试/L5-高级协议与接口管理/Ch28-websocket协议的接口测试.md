## 一、WebSocket 协议测试

### 知识点 1：WebSocket 与 HTTP 的区别 + 测试四步

【课程原话/定义】
WebSocket 特点：
- 服务器可以主动向客户端推送信息，客户端也可主动发信息（双向通信）
- 数据格式轻量、性能开销小、通信高效
- 可发送文本或二进制数据
- 协议标识符是 ws（加密为 wss），服务器网址就是 URL

环境：演示连接 ws://websocket.hogwarts.ceshiren.com

WebSocket 测试四步：链接服务 → 发送信息 → 获取响应值 → 断言响应信息。

【为什么？】
为什么要区分 WebSocket 和 HTTP？因为它们的通信模型根本不同：HTTP 是"请求-响应"（客户端问一次，服务器答一次），WebSocket 是"长连接双向"（连接建立后，服务器能主动推消息）。这决定了测试方式不同——HTTP 测"发请求收响应"，WebSocket 测"建立连接后双向收发消息"。理解这个区别，才知道什么场景该用 WebSocket 测试（如实时聊天、股票行情推送、在线游戏）。

【必须掌握】
- WebSocket = 长连接双向通信（服务器可主动推送），HTTP = 请求-响应
- 协议标识：ws（明文）/ wss（加密）
- 测试四步：链接 → 发送 → 获取响应 → 断言
- 场景：实时推送（聊天、行情、通知）

【企业场景】
你在公司测一个"实时行情推送"功能，用的是 WebSocket 而非 HTTP——因为行情要服务器主动推给客户端，HTTP 做不到"主动推"。测试时建立 WebSocket 连接，发送订阅消息，验证服务器推回来的数据对不对。

【面试考察】
面试官：「WebSocket 和 HTTP 有什么区别？WebSocket 怎么测试？」

参考回答框架：
1. HTTP 请求-响应（一问一答），WebSocket 长连接双向（服务器可主动推）
2. 协议 ws/wss，适合实时场景
3. 测试：建立连接 → 发消息 → 收消息 → 断言
4. 场景：聊天、行情推送、通知

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 用 HTTP 方式测 WebSocket | WebSocket 是长连接双向，不是请求-响应 |
| 混淆 ws 和 wss | ws 明文、wss 加密（对应 http/https） |
| 认为 WebSocket 能替代 HTTP | 各有用途：WebSocket 实时推送，HTTP 普通请求 |

【我的理解】
> （为什么 HTTP 做不到"服务器主动推送"，而 WebSocket 可以？从"请求-响应"和"长连接"的机制区别来解释。）
