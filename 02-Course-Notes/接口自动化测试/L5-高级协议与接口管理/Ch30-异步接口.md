## 一、异步接口测试

### 知识点 1：异步接口的特点、挑战与四种测试方法

【课程原话/定义】
异步接口是非阻塞的通信方式，客户端发起请求后无需等待返回，可继续处理其他任务。特点：非实时返回（回调/轮询获取结果）、高并发、测试需模拟异步逻辑。

典型场景：消息队列（Kafka/RabbitMQ）、通知服务（短信/邮件/推送）、文件处理（上传后异步生成缩略图）、支付服务（异步通知交易结果）。

测试挑战：时间不确定性、状态管理复杂、多种通信方式、高并发。

四种测试方法：
1. **回调验证**：模拟客户端监听，验证服务端回调（Mock Server、Postman）
2. **轮询检查**：定期检查状态判断任务完成（Requests + 时间控制）
3. **消息队列验证**：拦截队列消息（Kafka-console-consumer、RabbitMQ 工具）
4. **日志验证**：查服务端日志确认任务完成（ELK、Graylog）

轮询示例：
```python
def poll_async_status(task_id):
    url = f"https://api.example.com/status/{task_id}"
    for _ in range(10):   # 最多轮询 10 次
        response = requests.get(url)
        if response.json().get("status") == "completed":
            return True
        time.sleep(2)      # 等待 2 秒再查
    return False
```

【为什么？】
为什么异步接口难测？因为"发请求"和"出结果"分离了——同步接口发完就能拿到响应断言，异步接口发完只能拿到"任务已提交"，真正结果要过一会儿才能通过回调/轮询/消息队列拿到。这带来"时间不确定性"（不知道结果什么时候好）和"状态管理复杂"（要验证中间态到终态的转换）。理解四种测试方法（回调/轮询/队列/日志），本质是理解"异步结果的四种获取途径"。

【必须掌握】
- 异步接口：非阻塞，发请求不等待结果，通过回调/轮询获取
- 典型场景：消息队列、通知、文件处理、支付
- 四种测试方法：回调验证、轮询检查、消息队列验证、日志验证
- 轮询：定时查状态，completed 即完成，超时判失败

【企业场景】
你在公司测"支付回调"接口：发起支付后，结果不是立即返回，而是支付宝异步回调通知你的系统。测试时用 Mock Server 模拟回调、验证你的系统是否正确处理；或者轮询订单状态，看它从"待支付"变成"已支付"。这就是异步接口测试的真实场景。

【面试考察】
面试官：「异步接口怎么测试？和同步接口有什么不同？」

参考回答框架：
1. 异步接口发请求不等待结果，结果通过回调/轮询/消息队列获取
2. 同步接口发完直接断言响应，异步接口要处理"时间不确定性"
3. 四种方法：回调验证、轮询检查、消息队列验证、日志验证
4. 挑战：时间不确定、状态管理复杂、需模拟异步逻辑

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 发完请求直接断言结果 | 异步结果延迟返回，要轮询/回调等结果 |
| 轮询不设超时 | 任务卡住会无限轮询，要设最大次数/超时 |
| 只测终态不测中间态 | 异步要验证状态转换（如待支付→已支付） |

【我的理解】
> （同步接口"发完就能断言"，异步接口为什么不行？从"非阻塞、结果延迟返回"的角度，说明异步测试为什么需要轮询或回调。）
