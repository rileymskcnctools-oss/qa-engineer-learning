## 一、多环境切换的三层优化

### 知识点 1：从硬编码到 env 配置到 yaml 文件

【课程原话/定义】
敏捷迭代项目有多个环境（测试环境、预发环境等）。一套脚本通过切换域名配置实现多环境测试。

三层优化演进：
1. **硬编码**：每个环境各写一套用例（URL 写死）——用例变了每条都要改
2. **env 字典**：域名统一放 env 配置，用 default 字段指定默认环境
   ```python
   envs = {"default": "ceshiren", "org": "http://httpbin.org/get", "ceshiren": "http://httpbin.ceshiren.com/get"}
   res = requests.get(url=envs[envs['default']])
   ```
   缺点：多脚本文件都要重复设置 envs，切换环境逐个改，维护成本高
3. **yaml 文件**：envs 配置存到 envs.yaml，脚本里读取
   ```python
   import yaml
   def get_envs():
       with open('envs.yaml', 'r') as file:
           return yaml.safe_load(file)
   envs = get_envs()
   res = requests.get(url=envs[envs['default']] + "/get")
   ```
   切换环境只需改 envs.yaml 里的 default 字段值。

【为什么？】
为什么要"多环境配置"？因为测试环境 → 预发环境 → 生产环境，接口的域名/地址是不同的。如果 URL 写死在每个用例里，切环境就要改几百个用例的 URL，又累又易错。三层优化体现的是"配置与代码分离"的思想：URL 是"配置"（会随环境变），不该写死在"代码"里。从硬编码 → env 字典 → yaml 文件，本质是把"可变的环境地址"一步步抽离成"可集中管理的配置"，最终做到"切环境只改一个 default 字段"。

【必须掌握】
- 多环境：URL 抽成配置，default 字段切换
- 三层：硬编码（URL 写死）→ env 字典 → yaml 文件
- 核心思想：配置与代码分离
- 最终方案：envs.yaml 存配置，脚本读取，切环境改 default

【企业场景】
你在公司写接口自动化，脚本在测试环境跑通后要上预发环境。如果 URL 写死，你得把几百个用例的 `http://test.xxx.com` 全改成 `http://pre.xxx.com`。用了 envs.yaml 后，只改 `default: test` → `default: pre`，一行搞定。这套"环境配置抽离"是接口自动化能"一套脚本多环境复用"的基础。

【面试考察】
面试官：「接口自动化怎么支持多套环境切换？」

参考回答框架：
1. 把环境域名抽成配置，不写死在用例里
2. 用 default 字段指定当前环境
3. 配置存 yaml 文件，脚本读取
4. 切环境只改 default，不改用例代码

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| URL 写死在每个用例里 | 切环境要改几百处，用 env 配置集中管理 |
| env 字典重复定义在每个脚本 | 抽到 yaml 文件，统一读取 |
| 切换环境改代码而非配置 | 改 default 字段即可，别动代码 |

【扩展知识】
这套"环境配置抽离"的思路，和 pytest 的 fixture、conftest.py、以及更高级的"环境变量 + 命令行参数"是一脉相承的。进一步可以把环境配置做成"pytest 插件 + 命令行 --env=pre 传参"，实现不碰代码、不改文件，跑命令时指定环境。这是接口自动化框架走向"工程化"的标志之一。
