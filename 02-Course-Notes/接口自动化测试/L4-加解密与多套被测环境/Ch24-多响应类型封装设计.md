## 一、统一响应类型

### 知识点 1：把 json/xml 响应统一转成结构化数据

【课程原话/定义】
工作中可能遇到不同协议类型的响应（有的是 json、有的是 xml），造成响应值不统一、断言困难。解决方案：把获得的响应全部转换为结构化数据（dict）再处理。

Python 用 xmltodict（`pip install xmltodict`）：
```python
import xmltodict
def response_to_dict(response):
    res_text = response.text
    if res_text.startswith("<?xml"):
        final_res = xmltodict.parse(res_text)   # xml 转 dict
    else:
        final_res = response.json()             # json 直接转 dict
    return final_res
```

【为什么？】
为什么要"统一响应类型"？因为断言逻辑是"从结构化数据里取字段"，而 json 和 xml 的解析方式完全不同（json 用 r.json()，xml 要用 XML 解析器）。如果一套脚本里同时有 json 和 xml 接口，断言代码就得写两套。统一封装后，不管响应是 json 还是 xml，都先转成 dict，后续断言用同一套"取字段"逻辑——这就是"适配器"思想：把不同的格式适配成统一的中间结构，下游代码就简单了。

【必须掌握】
- 多响应类型的问题：json/xml 解析方式不同，断言困难
- 解决方案：统一转成 dict（结构化数据）
- Python：xmltodict.parse 转 xml，response.json() 转 json
- 判断依据：响应是否以 "<?xml" 开头
- 统一后，断言用同一套取字段逻辑

【企业场景】
你在公司测的接口，90% 返回 json，10% 是老系统的 xml。你写一个 `response_to_dict()` 封装，根据响应内容自动判断格式（xml 开头用 xmltodict，否则用 json），统一转成 dict。这样所有断言都从 dict 取字段，不用为 xml 接口单独写一套断言逻辑。这个封装在真实项目里很实用。

【面试考察】
面试官：「接口响应有 json 也有 xml，怎么统一处理断言？」

参考回答框架：
1. 问题：json/xml 解析方式不同，断言逻辑要写两套
2. 方案：统一转成 dict（结构化数据）
3. json 用 response.json()，xml 用 xmltodict.parse()
4. 封装成 response_to_dict()，断言用同一套取字段逻辑

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| json 和 xml 各写一套断言 | 统一转 dict，用一套断言逻辑 |
| xml 响应直接 r.json() | 会报错，xml 要用 xmltodict 解析 |
| 判断格式的依据不明确 | 用响应是否 "<?xml" 开头判断 |
