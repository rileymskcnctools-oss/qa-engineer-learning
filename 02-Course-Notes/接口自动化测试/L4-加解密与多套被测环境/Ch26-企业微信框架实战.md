## 一、完整框架实战（串联 L1-L4 知识点）

### 知识点 1：从需求到方案的全流程落地

【课程原话/定义】
企业微信部门管理接口自动化测试实战，把 L1-L4 的知识点串成一个完整框架：

1. **需求分析**：企业微信 API（gettoken 获取 token，corpid + corpsecret）
2. **请求发送**：requests 发请求
3. **接口鉴权**：token 处理
4. **断言处理**：
   - 字段嵌套深 → json 响应体断言（jsonpath）
   - 字段量大 → 整体结构响应断言（jsonschema）
   - 结合数据库 → 数据库操作与断言
5. **用例独立性**：用例之间无耦合（add 不依赖 get 顺序）
6. **用例执行**：mark 标签区分环境/冒烟（@pytest.mark.P1、@pytest.mark.smoke）
7. **结果报告**：allure（step=一个接口、title=一条用例）
8. **测试数据管理**：用例结束后清理（软删除，调接口方式）
9. **环境管理**：环境变量切换（os.getenv("env")）

```python
@allure.title("添加部门测试")
def test_add_department(self):
    with allure.step("添加部门"):
        ...
    with allure.step("获取子部门ID列表"):
        ...
    with allure.step("删除操作"):
        ...
```

【为什么？】
为什么这一课是 L4 的收尾？因为它把前面所有知识点"串"成一个完整框架：Ch01-Ch08 的请求发送、Ch07/Ch16 的 jsonpath 断言、Ch18 的 jsonschema 整体结构断言、Ch19 的数据库断言、Ch20 的鉴权、Ch25 的方案设计（pytest + allure + 数据管理 + 环境管理）。单独学每个知识点是一回事，把它们组合成一个"能落地的企业级接口自动化框架"是另一回事——这一课就是那个"组合"的过程。理解了它，你就知道"接口自动化框架"不是一个抽象概念，而是这些具体知识点按方案组合起来的工程。

【必须掌握】
- 完整框架 = 请求发送 + 鉴权 + 断言 + 用例独立性 + 报告 + 数据管理 + 环境管理
- 断言分层：jsonpath（嵌套深）、jsonschema（字段多）、数据库（结合断言）
- 用例独立性：用例之间无耦合
- allure：step=接口、title=用例
- 数据管理：软删除清理（调接口）
- 环境管理：环境变量切换

【企业场景】
你在公司搭接口自动化框架，就是这样组合：requests 发请求、token 鉴权、jsonpath/jsonschema 断言、pytest mark 标签管理用例、allure 出报告、用例结束软删除清理数据、环境变量切换环境。这套组合就是"企业级接口自动化框架"的标准形态。

【面试考察】
面试官（高频）：「说说你的接口自动化框架怎么设计的？」

参考回答框架：
1. 请求发送：requests
2. 鉴权：token 处理
3. 断言：jsonpath（嵌套）/ jsonschema（字段多）/ 数据库（结合）
4. 用例管理：pytest mark 标签
5. 报告：allure
6. 数据管理：软删除清理，环境管理：环境变量切换

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 用例之间互相依赖 | 用例要独立，任意顺序可执行 |
| 测试数据不清理 | 用例结束软删除清理，避免脏数据 |
| 断言只用一种 | 按场景选：嵌套深用 jsonpath，字段多用 jsonschema |

【扩展知识】
这一课呼应了 Ch25（接口自动化测试方案）——把"技术选型表"落地成"企业微信部门管理"的真实用例。它是接口自动化课程 L1-L4 的"综合验收"：能不能独立搭出一个完整框架，就看能不能把请求、鉴权、断言、报告、数据、环境这几块拼起来。
