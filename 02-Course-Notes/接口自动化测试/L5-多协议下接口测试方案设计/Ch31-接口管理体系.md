## 一、接口管理体系

### 知识点 1：解决前后端联调依赖的整体方案

【课程原话/定义】
接口管理体系是解决接口管理过程中各种问题的整体解决方案（如 Swagger、ApiFox、YAPI）。

它要解决的痛点（KickOff 会议常见）：
- 前端等后端联调环境，后端还没开发完
- 测试写用例也等后端接口调通

接口生命周期各阶段的交付：

| 阶段 | 交付 |
|------|------|
| 设计阶段 | 设计工具和规范 |
| 研发阶段 | stub 环境联调 + 客户端 sdk + 基础测试用例 |
| 测试阶段 | 测试脚本 + 联调环境 |
| 交付阶段 | 接口文档 + 客户端 sdk |

接口管理工具需具备：接口文档规范、根据文档生成 stub/mock 服务、自动生成测试脚本、持续维护文档。相关工具：Swagger、YAPI、ApiFox。

【为什么？】
为什么要"接口管理体系"而不是"一份接口文档"？因为接口开发是跨角色协作（前端/后端/测试），且各角色在接口的不同生命周期有不同的依赖。核心矛盾是"后端没开发完，前端和测试就没法干活"。接口管理体系的解法是：用"接口文档"作为契约，提前生成 stub/mock 服务（让前端联调、测试写用例），后端按契约开发，最后对接真实服务。这本质是"契约先行、并行开发"——用文档定义接口，让各方并行工作，而不是串行等待。

【必须掌握】
- 接口管理体系 = 解决接口协作问题的整体方案
- 核心痛点：前端/测试依赖后端，后端 delay 就阻塞
- 生命周期交付：设计规范 → stub/sdk → 测试脚本 → 文档
- 工具：Swagger、YAPI、ApiFox
- 核心思想：文档契约先行，各方并行开发

【企业场景】
你在公司做测试，后端接口还没开发完，但你不能干等。接口管理体系让后端先定好接口文档（Swagger），你用文档生成 mock 服务、提前写测试用例，等后端开发完再切到真实服务。这就是"契约先行"——测试不再被后端阻塞。

【面试考察】
面试官：「接口管理体系解决什么问题？核心思想是什么？」

参考回答框架：
1. 解决前后端/测试对后端接口的串行依赖
2. 接口文档作为契约，提前生成 stub/mock 服务
3. 各方并行开发，不被后端阻塞
4. 工具：Swagger/YAPI/ApiFox

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 认为接口管理体系只是"文档工具" | 是"文档 + mock/stub + 测试脚本 + 维护"的整体方案 |
| 接口文档和 mock 服务混为一谈 | 文档是契约，mock/stub 是契约的产物（联调用） |
| 只关注自己角色的环节 | 要理解全生命周期各阶段的交付 |

【我的理解】
> （为什么"后端 delay 会阻塞前端和测试"？接口管理体系用"文档契约 + mock"怎么打破这种串行依赖？）
