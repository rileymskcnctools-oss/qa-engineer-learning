## 一、Diff 方法论

### 知识点 1：用 diff 对比新旧响应做断言

【课程原话/定义】
Diff 测试的价值：
- 了解应用变更（新版本相比旧版本改了什么）
- 对被测结果做细粒度断言
- 无须显式断言（不写期望值，对比新旧响应差异即可）
- web app service 都可应用

通用 diff 工具 **deepdiff**（Python）：对比两个文件/数据的深层差异，支持 csv/tsv/json/yaml/toml。

自定义 XML diff：
```python
from deepdiff import DeepDiff
class XMLDiff:
    def diff(self, old, new):
        old_object = self.xml2dict(old)
        new_object = self.xml2dict(new)
        return DeepDiff(old_object, new_object).to_dict()
```

【为什么？】
为什么要用 diff 测试？因为传统断言要"预先知道期望值"，但很多场景期望值难维护（比如接口大改版、响应结构复杂）。diff 测试的思路是"对比新旧版本的响应，差异就是变化"——不用写死期望值，只要对比"改版前"和"改版后"的响应，差异处就是要关注的变更。这在回归测试、线上变更监控里特别有用：新版本上线后，对比新旧响应，diff 出来的就是"这次改动影响了什么"。

【必须掌握】
- diff 测试价值：了解变更、细粒度断言、无需显式断言
- deepdiff 工具：对比深层数据差异
- 思路：对比新旧响应，差异即变化
- 适用：回归测试、变更监控

【企业场景】
你在公司做接口回归，新版本上线前，把同一批请求发给旧版和新版服务，用 diffy/deepdiff 对比响应，diff 出的差异就是"新版本改了什么"，重点检查这些差异是否符合预期。不用为每个接口手写断言，diff 自动暴露变化。

【面试考察】
面试官：「接口回归怎么做 diff 测试？有什么价值？」

参考回答框架：
1. 对比新旧版本的响应，差异即变化
2. 价值：了解变更、无需显式断言
3. 工具：diffy、deepdiff
4. 适用回归测试、变更监控

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| diff 测试当唯一断言 | diff 暴露变化，但变化是否符合预期仍需人工判断 |
| 只 diff 不关注差异 | 要重点分析 diff 出的差异是否合理 |
| 认为 diff 不需要工具 | deepdiff/diffy 能处理深层结构差异 |

【我的理解】
> （为什么"diff 测试"能"无须显式断言"？它用"对比新旧响应"替代了"写死期望值"，这背后是什么思路？）
