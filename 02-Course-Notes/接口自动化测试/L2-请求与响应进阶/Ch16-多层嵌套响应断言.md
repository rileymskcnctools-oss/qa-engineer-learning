## 一、多层嵌套结构与 JSONPath

### 知识点 1：完整 JSONPath 语法

【课程原话/定义】
JSON 响应常含多层嵌套（对象嵌套对象、数组嵌套对象、对象嵌套数组）。手写字典路径（`res["extattr"]["external_profile"]["external_attr"][1]["web"]["title"]`）又长又易错。JSONPath 是定位提取 JSON 的查询语言，更灵活。

完整 JSONPath 语法：

| 符号 | 描述 |
|------|------|
| `$` | 查询的根节点对象 |
| `@` | 过滤器处理的当前节点对象 |
| `*` | 通配符 |
| `.` | 获取子节点 |
| `..` | 递归搜索，筛选所有符合条件节点 |
| `?()` | 过滤器表达式，筛选操作 |
| `[start:end]` | 数组片段，区间 [start,end)，不含 end |
| `[A]` 或 `[A,B]` | 迭代器下标，一个或多个数组下标 |

语法示例（练习环境 jsonpath.hogwarts.ceshiren.com）：

| 需求 | JSONPath |
|------|----------|
| 所有书籍的作者 | `$.store.book[*].author` |
| 所有作者 | `$..author` |
| store 下所有内容 | `$.store.*` |
| 所有价格 | `$.store..price` |
| 第三本书 | `$..book[2]` |
| 所有含 isbn 的书 | `$..book[?(@.isbn)]` |
| 价格小于 10 的书 | `$.store.book[?(@.price < 10)]` |
| 所有书籍数量 | `$..book.length` |

【为什么？】
为什么 Ch07 讲过 JSONPath，这里还要再讲一次"多层嵌套响应断言"？因为 Ch07 是入门（认识 JSONPath），这里是进阶——面对真实接口那种"五层嵌套、数组套数组"的响应，手写路径已经不可维护，必须系统掌握完整语法。重点新增的是 **`@`（过滤器当前节点）** 和 **`?()` 过滤器**——它们让 JSONPath 从"取字段"升级到"按条件筛选"，这是处理动态数组（如"找出价格小于 10 的书"）的关键能力。

【必须掌握】
- 完整语法：$、@、*、.、..、?()、[start:end]、[A,B]
- `$..字段` 递归查找，`$..book[?(@.price<10)]` 条件筛选
- 练习环境 jsonpath.hogwarts.ceshiren.com（在线验证表达式）
- 深层嵌套 + 动态数组，是 JSONPath 发挥价值的典型场景

【企业场景】
你在公司测一个返回员工详情的接口，响应有 5 层嵌套，要断言"所有部门里名为 X 的员工"。手写路径不可维护，用 `$..name` 递归拿所有 name，或用 `$..book[?(@.price<10)]` 筛选条件。响应结构再复杂，JSONPath 一行搞定。练习环境 jsonpath 在线工具能帮你先验证表达式对不对，再写进代码。

【面试考察】
面试官："JSONPath 的 `..` 和 `[?()]` 分别是什么意思？举个组合使用的例子。"

参考回答框架：
1. `..` 递归搜索，匹配所有符合条件的节点
2. `[?()]` 过滤器，@ 是当前节点，做条件筛选
3. 组合：`$..book[?(@.price<10)]` = 所有价格小于 10 的书
4. 解决"深层嵌套 + 动态数组"的提取断言问题

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| `$..字段` 和 `$.字段` 混淆 | `..` 递归全量，`.` 只取直接子节点 |
| 过滤器忘 @ | `[?(@.price<10)]`，@ 表示当前元素 |
| 数组切片 end 含边界 | `[start:end]` 不含 end |
| 与 Ch07 的 JSONPath 混淆 | Ch07 是入门（$ / . / ..），本章是完整版（@ / ?() / 切片） |

【我的理解】
> （`$..book[?(@.price<10)]` 这条表达式，`..`、`?()`、`@` 分别解决什么问题？如果不用过滤器，用 Python 手写要几行代码才能拿到"价格小于 10 的书"？）

## 二、JSONPath 与代码结合

### 知识点 2：Python jsonpath 库与 Java JsonPath

【课程原话/定义】
Python（`pip install jsonpath`）：
```python
import jsonpath
jsonpath.jsonpath(源数据对象, jsonpath表达式)
# 例：jsonpath.jsonpath(r.json(), "$..id")
```

Java 用 com.jayway.jsonpath（依赖 json-path 2.8.0）：
```java
DocumentContext context = JsonPath.parse(res);
ArrayList<String> codeList = context.read("$..code");
// 或：JsonPath.read(res, "$..code")
```

【为什么？】
为什么要学"JSONPath 和代码结合"？因为表达式写得再对，最终还是要写进测试脚本里做断言。Python 用 jsonpath 库（`jsonpath.jsonpath(obj, expr)` 返回 list），Java 用 Jayway JsonPath（`JsonPath.parse()` + `read()`）。两者 API 不同但思想一致：喂一个对象 + 一个表达式，返回匹配结果列表。掌握"表达式 → 库调用 → 断言 list"这个链路，JSONPath 才算真正落地。

【必须掌握】
- Python：jsonpath.jsonpath(obj, "表达式") 返回 list
- Java：JsonPath.parse(res).read("表达式") 或 JsonPath.read(res, expr)
- 提取结果通常是 list，断言针对 list（in / == / 长度）
- 与 Ch07 的分工：Ch07 用 jsonpath 做简单断言，本章用于多层嵌套的复杂断言

【企业场景】
你在公司做宠物管理接口的断言，用 `jsonpath.jsonpath(r.json(), "$..id")` 一次提取响应里所有 id，然后 `assert pet_id in ids` 判断新增的宠物在不在。Java 技术栈则用 Jayway JsonPath 的 `JsonPath.parse(body).read("$..id")`。两种语言同一套 JSONPath 表达式，跨语言通用。

【面试考察】
面试官："Python 和 Java 分别怎么用 JSONPath 做断言？"

参考回答框架：
1. Python：pip install jsonpath，jsonpath.jsonpath(obj, "$..字段")
2. Java：com.jayway.jsonpath，JsonPath.parse(res).read("$..字段")
3. 返回 list，针对 list 做断言（in/==/长度）
4. 表达式跨语言通用，是 JSONPath 的价值

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| jsonpath 返回单个值当标量 | 返回 list，要 [0] 或直接对 list 断言 |
| Java 忘加 json-path 依赖 | pom.xml 加 com.jayway.jsonpath:json-path |
| 表达式没验证就写进代码 | 先用 jsonpath 在线练习环境验证表达式 |

【我的理解】
> （Python 的 `jsonpath.jsonpath(obj, expr)` 和 Java 的 `JsonPath.parse(res).read(expr)` 本质是不是同一件事？为什么 JSONPath 表达式能跨语言通用，而解析库不能？）
