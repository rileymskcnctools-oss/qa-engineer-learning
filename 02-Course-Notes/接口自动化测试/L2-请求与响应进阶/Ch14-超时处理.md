## 一、请求超时

### 知识点 1：timeout 参数控制超时，防止用例堵塞

【课程原话/定义】
请求超时：A 发请求等 B 响应，同时开始超时计时，超时时间内收到响应则成功，超过超时时间没收到响应则宣告失败。

使用场景：网络延迟、服务器负载高时，接口可能超时报错。用 timeout 参数控制请求时间，否则用例会堵塞——没设超时的用例遇到服务端阻塞，会一直等待，后面的用例都不执行。

Python 用 timeout 参数，并用异常捕获处理超时：
```python
import requests
def test_two(self):
    try:
        r = requests.post("https://github.com/post", timeout=5)  # 5 秒超时
        assert r.status_code == 200
    except requests.exceptions.Timeout:
        print("请求超时")
        return
```

【为什么？】
为什么要专门设超时？因为接口测试脚本是"批量、自动"跑的，一旦某个接口卡住（服务器阻塞、网络抖动），没设 timeout 的脚本会无限等下去，导致整个回归挂起。设了 timeout，卡住的请求会在指定时间后抛异常，配合 try/except 捕获，脚本能跳过这条、继续跑后面的用例。这是自动化脚本"健壮性"的底线——一个接口卡住不能拖垮整个测试。

【必须掌握】
- timeout 参数设置超时时间（秒）
- 没设 timeout 的用例会无限等待，堵塞后续用例
- 超时抛 requests.exceptions.Timeout，用 try/except 捕获
- 生产环境接口测试必设 timeout

【企业场景】
你在公司跑接口回归，某天一个依赖的外部接口变慢卡住了。如果你没设 timeout，整个回归脚本就挂在那不动；设了 timeout=10 并 try/except 捕获，脚本 10 秒后跳过这条、标记超时、继续跑剩下的用例，最后报告里能看到"这条超时了"，而不是"整个回归都卡死了"。

【面试考察】
面试官："接口自动化里为什么要设 timeout？不设会怎样？"

参考回答框架：
1. timeout 控制请求超时时间，防止脚本无限等待
2. 不设 timeout，接口卡住时用例会一直等待，堵塞后续用例
3. 超时抛异常（requests.exceptions.Timeout），用 try/except 捕获
4. 保证单个接口失败不影响整体回归

【易错点】

| 常见错误 | 正确理解 |
|----------|----------|
| 不设 timeout | 接口卡住时脚本无限等，后续用例不执行 |
| 超时异常不捕获 | 异常向上抛，用例直接失败终止 |
| timeout 设太小 | 正常慢接口也被误判超时，要设合理值 |
