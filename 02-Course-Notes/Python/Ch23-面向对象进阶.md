## 一、构造方法 `__init__(self)`

### 前置：动态绑定的问题

【课程原话/定义】
Python 中的属性变量使用**动态绑定**方式绑定到实例对象上。格式：`实例对象名.属性名 = 值`

```python
class Student:
    pass

s1 = Student()
s2 = Student()

# 为 s1 动态绑定属性
s1.name = "Tom"
s1.age = 22

print(s1.name)   # Tom
print(s1.age)    # 22

# s2 没有绑定——报错！
print(s2.name)   # AttributeError: 'Student' object has no attribute 'name'
print(s2.age)    # AttributeError: 'Student' object has no attribute 'age'
```

给哪个实例绑定的属性，哪个实例才有——没绑定的没有。这显然不符合面向对象思想：同一个类的对象，结构应该一致。

> 💡 **思考**：上面代码中 `print(s2.name)` 和 `print(s2.age)` 分别输出什么？为什么？

正常的实例属性应该通过构造方法 `__init__` 统一定义——保证同一个类的所有对象拥有相同的属性结构。这就引出了下一节的内容。

【为什么？】
动态绑定暴露了原始问题：没有构造方法的类像一张白纸——每次创建对象后要手写一堆 `obj.xxx = yyy`，容易漏、容易写错、每个对象的属性还不统一。

这是"面向过程的 Python"和"面向对象的 Python"的分界线：
- `obj.xxx = value` → 面向过程：事后手动添加
- `__init__` 里 `self.xxx = value` → 面向对象：创建时自动装配

### 知识点 1：为什么需要构造方法

【课程原话/定义】
构造方法 `__init__(self)` 在实例对象时**自动调用**，在对象创建的同时完成属性初始化，解决了动态绑定的痛点。

```python
class Student:
    def __init__(self):
        print("Init Run ...")
        self.name = "Tom"
        self.age = 22

s1 = Student()  # 输出: Init Run ...
s2 = Student()  # 输出: Init Run ...
# s1 和 s2 都有 name 和 age——结构一致！
```

【为什么？】
`__init__` 的本质：把"实例化后手动绑定属性"的时机提前到"实例化的那一刻自动执行"。

不用构造方法 → 三步：创建对象 → 手动加 name → 手动加 age（可能忘）
用构造方法 → 一步：创建对象时自动完成所有初始化

类比：买手机。不用构造方法 = 买个空壳手机，然后自己装电池、插 SIM 卡、装系统。用构造方法 = 开箱即用。

注意：`__init__` 里直接写 `name = "Tom"` 是局部变量，不是属性。必须 `self.name = "Tom"` 才是绑定到实例上。

【必须掌握】
- `__init__(self)` 在实例化时自动调用，不需要手动调用
- `self.参数名 = 值` 才是为实例对象绑定属性
- 不用 `self.` 前缀的变量只是方法内的局部变量，方法结束就消失

【企业场景】
你在写自动化测试时，每个用例都需要 driver：

```python
class TestLogin:
    def __init__(self):
        self.driver = webdriver.Chrome()   # 每个用例创建时自动准备好 driver
        self.base_url = "https://test.com"
```

这样 new 一个用例对象时 driver 已经就绪，不用每次都手动 `driver = webdriver.Chrome()`。

【面试考察】
面试官："`__init__` 方法什么时候被调用？它和普通方法有什么区别？"

参考回答框架：
1. `__init__` 是构造方法，在 `类名()` 实例化对象时由 Python 解释器自动调用
2. 普通方法需要显式 `对象.方法名()` 调用，构造方法自动触发
3. `__init__` 的作用是为实例对象初始化属性
4. 不能有返回值（或者说只能返回 None）

【易错点】

| 常见错误                         | 错误原因          | 正确做法                    |
| ---------------------------- | ------------- | ----------------------- |
| `__init__` 里写 `name = "Tom"` | 以为是属性，实际是局部变量 | 必须写 `self.name = "Tom"` |
| 手动调用 `s1.__init__()`         | 不理解它是自动调用的    | 构造方法只通过 `类名()` 触发       |
| `__init__` 写了 `return` 返回值   | 不知道构造方法不能返回值  | 去掉 return               |

【我的理解】
> （为什么 `__init__` 里的变量必须加 `self.` 前缀才是属性？不加 `self.` 的变量生命周期是怎样的？用自己的话解释）
> 
> `self` 指向当前实例对象。使用 `self.变量名` 定义的是对象属性，会保存在实例中，只要对象存在，就可以通过 `对象.属性` 访问；而不加 `self.` 定义的是 `__init__` 方法内的局部变量，只在该方法执行期间存在，方法执行结束后就会被销毁，无法通过对象访问。

### 知识点 2：带参构造方法

【课程原话/定义】
无参构造方法让所有对象属性值都一样，不符合现实需求。带参构造方法通过参数传入不同的初始值：

```python
class Student:
    def __init__(self, name, age):
        self.name = name    # 左边的 self.name 是属性名，右边的 name 是参数
        self.age = age

s1 = Student("Tom", 22)
s2 = Student("Jack", 23)

print(s1.name)  # Tom
print(s2.name)  # Jack
```

此时才真正实现了"不同对象，不同属性值"。

【为什么？】
带参构造方法是面向对象的"真正形态"。无参构造创建的所有对象像克隆人——长一样。带参构造让每个对象有自己的"个性"。

`self.name = name` 这句是初学者最容易晕的地方：
- 左边 `self.name`：给实例对象绑定一个叫 name 的属性
- 右边 `name`：引用构造方法的参数 name

它们恰好同名（这是常见做法），但不是同一个东西。你也可以写成 `self.xxx = name`，只是这样属性名叫 xxx，用起来很奇怪。

【必须掌握】
- `__init__(self, 参数1, 参数2)` 定义带参构造方法
- 实例化时传入实参：`对象 = 类名(实参1, 实参2)`
- `self.属性名 = 参数名` 完成属性初始化
- self 参数不需要手动传，Python 自动处理

【企业场景】
测试用例参数化——同一个测试逻辑，不同数据：

```python
class TestCase:
    def __init__(self, case_id, title, input_data, expected):
        self.case_id = case_id
        self.title = title
        self.input_data = input_data
        self.expected = expected

# 从 Excel 读取数据，每行创建一个用例对象
case1 = TestCase("TC001", "正常登录", {"user": "admin", "pwd": "123"}, "success")
case2 = TestCase("TC002", "密码错误", {"user": "admin", "pwd": "wrong"}, "fail")
```

【面试考察】
面试官："`self.name = name` 中，两个 name 分别是什么？为什么可以同名？"

参考回答框架：
1. 左边 `self.name` 是实例属性，绑定到当前对象上
2. 右边 `name` 是构造方法的参数
3. 它们可以同名因为作用域不同——左边是实例命名空间，右边是函数局部命名空间
4. 同名是 Python 惯例，提高可读性

【易错点】

| 常见错误                 | 错误原因         | 正确做法                                     |
| -------------------- | ------------ | ---------------------------------------- |
| 混淆 self.name 和 name  | 不理解 self 的作用 | self.xxx = 给对象加属性；不加 self = 局部变量         |
| 实例化时忘记传参：`Student()` | 构造方法定义了参数    | `Student("Tom", 22)`                     |
| 参数顺序搞反               | 传参时没按定义顺序    | 按位置传，或用关键字：`Student(age=22, name="Tom")` |

【我的理解】
> （写一个自己的类，用带参构造方法创建 3 个不同属性值的对象。解释 `self.xxx = xxx` 中两边的 xxx 各自是什么）

### 知识点 2+：实例方法进阶

【课程原话/定义】
实例方法用来定义对象的行为，本质上就是定义在类中的函数。默认携带 `self` 参数，由解释器自动传入调用该方法的实例对象。通过 `self`，可以在方法中访问/修改实例属性，也可以调用其他实例方法。

最简格式：

```python
def 方法名(self):
    pass

# 或带参数
def 方法名(self, args...):
    pass
```

`self` 不是 Python 关键字，是约定俗成的命名——但强烈不建议改成别的名字。

下面是一个完整示例：

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age
        self.courses = []           # 每个学生有自己的选课列表

    def __str__(self):
        return f"Name: {self.name} -- Age: {self.age}"

    def select_course(self, courseName):
        self.courses.append(courseName)    # 通过 self 修改实例属性

    def all_course(self):
        print(f"{self.name} 本学期选课如下：")
        for idx, c in enumerate(self.courses):
            print(f"第{idx+1}门课：{c}")

s1 = Student("Tom", 22)
s1.select_course("Python")
s1.select_course("Java")
s1.select_course("Pytest框架")
s1.all_course()
# Tom 本学期选课如下：
# 第1门课：Python
# 第2门课：Java
# 第3门课：Pytest框架
```

【为什么？】
这个例子展现了实例方法的完整形态：

1. **构造方法**（`__init__`）：初始化了基础属性 `name`、`age` 和一个空列表 `courses`
2. **修改器方法**（`select_course`）：通过 `self.courses.append()` 修改实例的内部状态
3. **展示方法**（`all_course`）：遍历 `self.courses` 并格式化输出
4. **魔法方法**（`__str__`）：让 `print(对象)` 显示有意义的信息

关键洞察：`s1` 和 `s2` 各有各的 `courses` 列表——这是实例属性的独立性。s1 选了 Python 不影响 s2 的选课。

这比 Ch22 的 Plane 例子更进一步：Plane 只是打印，这里的方法真正在**维护对象的内部状态**——这才是面向对象的核心用途。

【必须掌握】
- 实例方法第一个参数永远是 `self`
- 通过 `self.属性` 访问和修改实例数据
- 通过 `self.方法()` 调用其他实例方法
- 每个实例的属性相互独立（`s1.courses` ≠ `s2.courses`）
- 实例方法可以维护可变状态（列表、字典等）

【企业场景】
测试用例对象维护自己的执行状态：

```python
class TestCase:
    def __init__(self, name):
        self.name = name
        self.status = "NOT_RUN"
        self.steps = []
        self.errors = []

    def add_step(self, description):
        self.steps.append({"desc": description, "result": None})

    def step_pass(self, step_index):
        self.steps[step_index]["result"] = "PASS"

    def step_fail(self, step_index, error):
        self.steps[step_index]["result"] = "FAIL"
        self.errors.append(error)
        self.status = "FAIL"

    def finish(self):
        if self.status != "FAIL":
            self.status = "PASS"
```

每个测试用例对象独立跟踪自己的步骤、错误和最终状态——所有方法都通过 `self` 操作自己的数据。

【面试考察】
面试官："实例方法中的 `self` 参数是什么？它是关键字吗？可以不叫 self 吗？"

参考回答框架：
1. `self` 指向调用该方法的实例对象
2. `self` 不是 Python 关键字，是约定名（可以改，但强烈不建议）
3. Python 自动传递：`s1.select_course("Python")` 实际调用 `Student.select_course(s1, "Python")`
4. 通过 self 才能区分不同对象的属性——这是面向对象的核心机制

【易错点】

| 常见错误                       | 错误原因             | 正确做法                       |
| -------------------------- | ---------------- | -------------------------- |
| 方法里修改 `courses` 没用 `self.` | 变成局部变量，方法结束就丢    | `self.courses.append(...)` |
| 在方法中直接 `courses = []`      | 创建了局部变量，不是修改实例属性 | `self.courses = []`        |
| 调用其他方法时不写 `self.`          | 以为是普通函数调用        | `self.method_name()`       |

【我的理解】
> （定义一个自己的类，带构造方法和 2 个以上的实例方法，一个负责添加数据，一个负责展示数据。用两个不同对象验证实例数据的独立性。）
> 注意：类内部使用 `self` 是为了让同一套代码可以作用于不同实例对象。由于类不清楚类外部的对象名称，不推荐类内部通过对象名.属性/方法进行操作。

## 二、`__str__(self)` 方法

### 知识点 3：让对象打印有意义的信息

【课程原话/定义】
直接 `print(对象)` 输出的是类型和内存地址，比如 `<__main__.Student object at 0x000001>`。实现 `__str__(self)` 方法可以自定义打印格式：

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"Name: {self.name} -- Age: {self.age}"

s1 = Student("Tom", 22)
print(s1)  # Name: Tom -- Age: 22
```

要求：只接收 self 参数，必须返回一个字符串。

【为什么？】
`__str__` 是面向对象中的"自我介绍"方法。调试时 `print(对象)` 看到地址 → 一头雾水；`print(对象)` 看到 "Name: Tom, Age: 22" → 立刻知道这个对象的状态。

类比：你去派出所查一个人，系统返回"公民编号 42010619900101..."——这是地址版；返回"张三，男，30 岁"——这是 `__str__` 版。显然后者有用 100 倍。

测试中经常要打印用例执行结果，定义了 `__str__` 后一行 `print(case)` 就能看到所有关键信息。

【必须掌握】
- `__str__(self)` 只接收 self，返回一个字符串
- `print(对象)` 或 `str(对象)` 时自动调用
- 调试利器：一眼看到对象的关键属性

【企业场景】
测试结果报告：

```python
class TestResult:
    def __init__(self, case_name, status, duration):
        self.case_name = case_name
        self.status = status
        self.duration = duration

    def __str__(self):
        return f"[{self.status}] {self.case_name} ({self.duration}s)"

result = TestResult("test_login", "PASS", 1.5)
print(result)  # [PASS] test_login (1.5s)
```

生成测试报告时遍历结果列表，一行 print 一个结果——简洁、可读、不需要拼字符串。

【面试考察】
面试官："`__str__` 和 `__init__` 有什么区别？各自的触发时机？"

参考回答框架：
1. `__init__`：实例化时自动调用，负责初始化属性，不返回（或返回 None）
2. `__str__`：`print()` 或 `str()` 时自动调用，负责返回对象的字符串表示，必须返回 str
3. 时机：`__init__` 在对象"出生"时，`__str__` 在对象被"展示"时

【易错点】

| 常见错误                                | 错误原因         | 正确做法                 |
| ----------------------------------- | ------------ | -------------------- |
| `__str__` 写了 `print()` 而不是 `return` | 以为打印就是 print | 必须 `return` 字符串      |
| `__str__` 返回了非字符串类型                 | 不了解返回类型要求    | 返回 `str` 类型          |
| 把 `__str__` 当成构造方法写属性初始化            | 混淆两个方法的作用    | `__str__` 只管展示，不管初始化 |

【我的理解】
> （给自己之前定义的类加上 `__str__` 方法，打印 3 个不同对象，验证输出是否正确。为什么调试时 `__str__` 比直接 `print(obj.name, obj.age)` 更好？）
> 
在调试过程中，如果直接打印对象，只能看到对象类型和地址信息，无法快速了解对象当前保存的数据。通过重写 `__str__` 方法，可以自定义对象的可读信息，快速查看关键属性，提高排查效率。

## 三、类属性

### 知识点 4：类属性 vs 实例属性

【课程原话/定义】
在类中直接定义的变量（不加 `self.`）是**类属性**，被所有实例对象共享。带 `self.` 前缀的是**实例属性**，每个对象各自独立。

```python
class WaterDispenser:
    surplus_water = 1500        # 类属性：所有实例共享

    def water_outlet(self, n):
        WaterDispenser.surplus_water -= n       # 通过类名访问/修改
        print("剩余水量：", WaterDispenser.surplus_water)

wd1 = WaterDispenser()
wd2 = WaterDispenser()

wd1.water_outlet(100)   # 剩余水量：1400
wd2.water_outlet(200)   # 剩余水量：1200  ← wd2 看到的是 wd1 修改后的值
```

【为什么？】
类属性 = 饮水机里的桶装水——所有接水口（实例）共享同一桶水，谁接了都会减少。
实例属性 = 每个人自己的水杯——各喝各的，互不影响。

为什么要区分？测试中最典型的场景：
- `base_url = "https://test.com"` → 类属性，所有用例共享
- `self.username`、`self.password` → 实例属性，每个用例不同

【必须掌握】
- 类属性：直接在 class 下定义，不用 self 前缀
- 访问类属性：`类名.属性名` 或 `self.__class__.属性名`
- 所有实例共享同一个类属性
- 实例对象可以读类属性，但不能直接修改（修改会变成创建实例属性）
- 修改类属性必须通过 `类名.属性名 = 新值` 或方法内修改

【企业场景】
测试配置共享：

```python
class TestConfig:
    base_url = "https://api.test.com"   # 所有用例共享
    timeout = 30                         # 全局超时
    retry_times = 3                      # 全局重试次数

class TestLogin:
    def __init__(self, username, password):
        self.username = username          # 实例属性：每个用例不同
        self.password = password

    def run(self):
        url = f"{TestConfig.base_url}/login"   # 通过类名访问类属性
        # ... 发送请求
```

改一个 `TestConfig.base_url`，所有用例的请求地址全切换——改一处，处处生效。

【面试考察】
面试官："类属性和实例属性有什么区别？通过实例对象能修改类属性吗？"

参考回答框架：
1. 类属性在类中直接定义，实例属性通过 `self.xxx` 定义
2. 类属性所有对象共享一份，实例属性每个对象独立一份
3. 通过实例对象读取类属性可以，但赋值（`obj.attr = xxx`）会创建同名的实例属性，遮住类属性
4. 修改类属性必须通过 `类名.属性名 = 新值`

【易错点】

| 常见错误                               | 错误原因              | 正确做法                                    |
| ---------------------------------- | ----------------- | --------------------------------------- |
| `wd1.surplus_water = 2000` 以为改了类属性 | 赋值操作在实例上创建了同名实例属性 | 用 `WaterDispenser.surplus_water = 2000` |
| 在 `__init__` 外写 `self.xxx`         | self 只能在方法内使用     | 类属性不加 self，直接写变量名                       |
| 类方法里用 `self.类属性` 修改                | 容易意外创建实例属性        | 用 `类名.类属性` 或 `cls.类属性`                  |

【我的理解】
> （设计一个 Counter 类，用类属性统计一共创建了多少个实例对象。提示：在 `__init__` 里每创建一个实例，类属性 +1）

## 四、类方法 `@classmethod`

### 知识点 5：类方法的本质

【课程原话/定义】
类方法用 `@classmethod` 装饰器修饰，默认参数是 `cls`（代表类对象本身，不是实例对象）。通过类名直接调用，不需要实例化。

```python
import datetime

class Utils:
    now = datetime.datetime.now()

    @classmethod
    def current_date_time(cls):
        return cls.now

    @classmethod
    def current_date(cls):
        return cls.now.strftime("%Y-%m-%d")

print(Utils.current_date())        # 不需要实例化，直接类名调用
print(Utils.current_date_time())
```

【为什么？】
有些功能跟具体的实例对象无关，属于"这个类整体"的能力。

类比：银行 ATM 类。查询余额 → 实例方法（需要知道是谁的账户）。汇率查询 → 类方法（跟具体账户无关，属于银行系统）。

`cls` 和 `self` 的区别：
- `self` → 指向调用方法的实例对象
- `cls` → 指向类对象本身（即 `Utils` 这个类）

【必须掌握】
- `@classmethod` 装饰器定义类方法
- 第一个参数是 `cls`，代表类对象（约定名，同 self 一样不是关键字）
- 通过 `类名.方法()` 调用，不需要实例化
- 类方法内可以访问类属性（`cls.属性名`）
- 类方法内**不能**访问实例属性（因为调用时可能没有实例存在）

【企业场景】
测试环境的配置切换：

```python
class TestEnv:
    env = "staging"
    configs = {
        "dev": {"url": "https://dev.test.com", "db": "dev_db"},
        "staging": {"url": "https://staging.test.com", "db": "staging_db"},
        "prod": {"url": "https://prod.test.com", "db": "prod_db"},
    }

    @classmethod
    def set_env(cls, env_name):
        cls.env = env_name

    @classmethod
    def get_config(cls):
        return cls.configs[cls.env]

# 一键切换环境
TestEnv.set_env("prod")
print(TestEnv.get_config())  # 所有测试用例自动使用 prod 配置
```

【面试考察】
面试官："类方法和实例方法有什么区别？什么时候用类方法？"

参考回答框架：
1. 实例方法：默认参数 self，操作实例属性，需要先创建对象
2. 类方法：默认参数 cls，操作类属性，类名直接调用
3. 使用时机：功能跟具体实例无关、只需要操作类属性、封装工具方法

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 类方法里用了 `self.xxx` | 类方法没有 self，只有 cls | 用 `cls.xxx` 访问类属性 |
| 类方法中访问实例属性 | 调用时可能没有实例对象 | 类方法只操作类属性 |
| 忘记写 `@classmethod` | 以为是普通实例方法 | 必须加装饰器，否则 cls 被当成普通参数 |

## 五、静态方法 `@staticmethod`

### 知识点 6：类中的普通函数

【课程原话/定义】
静态方法用 `@staticmethod` 装饰器修饰，**没有默认参数**（没有 self，没有 cls）。本质上就是放在类里的普通函数。

```python
class Calc:
    @staticmethod
    def add(n1, n2):
        return n1 + n2

    @staticmethod
    def sub(n1, n2):
        return n1 - n2

print(Calc.add(10, 20))   # 30
print(Calc.sub(10, 20))   # -10
```

【为什么？】
静态方法就是普通函数，那为什么不直接放类外面？——**组织性**。

把相关的工具函数放在同一个类里，代码结构更清晰：
- `Calc.add()` 比 `add()` 更清楚表达"这是计算器类的加法"
- 避免全局函数满天飞
- IDE 自动补全时，`Calc.` 就能看到所有计算相关方法

类方法 vs 静态方法的区别：
- 类方法：需要访问/修改类属性 → 有 `cls`
- 静态方法：完全独立的工具函数 → 无默认参数

【必须掌握】
- `@staticmethod` 装饰器定义静态方法
- 没有 self，没有 cls——就是个普通函数
- 通过 `类名.方法()` 调用
- 可以在静态方法中通过 `类名.属性` 访问类属性（但不建议）
- 核心作用：逻辑上属于这个类，但不需要访问类和实例的数据

【企业场景】
测试断言辅助方法：

```python
class AssertHelper:
    @staticmethod
    def is_json(response_str):
        """判断响应是否是 JSON 格式"""
        try:
            import json
            json.loads(response_str)
            return True
        except:
            return False

    @staticmethod
    def status_in(response, valid_codes):
        """判断状态码是否在有效范围内"""
        return response.status_code in valid_codes

# 测试用例中使用
if AssertHelper.is_json(response.text):
    data = response.json()
```

这些方法不需要类属性，不需要实例属性——只是逻辑上属于"断言辅助"这个分类。

【面试考察】
面试官："`@classmethod` 和 `@staticmethod` 有什么区别？各适合什么场景？"

参考回答框架：
1. 类方法有 `cls` 参数，可以访问/修改类属性；静态方法没有默认参数
2. 类方法适合操作类级别数据（配置切换、工厂方法）
3. 静态方法适合纯工具函数（不依赖类和实例的状态）
4. 简单判断：需要读/写类属性 → `@classmethod`；完全独立 → `@staticmethod`

【易错点】

| 常见错误                | 错误原因             | 正确做法              |
| ------------------- | ---------------- | ----------------- |
| 静态方法里写了 `self`      | 混淆了静态方法和实例方法     | 去掉 self           |
| 用实例对象调用静态方法         | 虽然能跑但不规范         | 用 `类名.静态方法()`     |
| 把操作实例属性的方法标成 static | 不理解 static 的使用场景 | 需要访问 self → 用实例方法 |
