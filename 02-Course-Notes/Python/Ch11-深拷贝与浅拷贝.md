## 一、先搞清：赋值 vs 拷贝

### 知识点 1：什么是拷贝

【课程原话/定义】
拷贝是指使用一个已存在的对象，生成一个新的对象，两个对象在内存中具有独立的存储空间。

【为什么？】
拷贝和"="赋值的区别是整个话题的起点。"="不是拷贝——它只是让两个变量指向同一个对象。拷贝才会创建新对象。很多 Bug 的根源就是以为"b = a"是拷贝，结果改了 b 把 a 也改了。

【必须掌握】
- `b = a` → 不是拷贝，是引用传递（两个变量指向同一个对象）
- 拷贝 → 创建新对象，`a is b` → False

【企业场景】
> 你写测试用例：`case2 = case1`，然后修改 `case2["input"] = new_value`——结果 `case1` 的 input 也被改了，两个测试用例变成了一样的数据。这就是把赋值当拷贝的经典 Bug。

【易错点】

| 操作                     | 是否创建新对象 | `a is b` | 修改 a 影响 b？  |
| ---------------------- | ------- | -------- | ----------- |
| `b = a`                | ❌       | True     | ✅ 影响（同一个对象） |
| `b = a.copy()`         | ✅       | False    | ⚠️ 看情况（浅拷贝） |
| `b = copy.deepcopy(a)` | ✅       | False    | ❌ 不影响（完全独立） |

## 二、浅拷贝

### 知识点 2：什么是浅拷贝

【课程原话/定义】
浅拷贝是指创建一个新的对象时，只拷贝内容是原始对象的引用，而不是创建原始对象的副本数据。浅拷贝不具有数据独立性。

【为什么？】
浅拷贝只复制"外层容器"，内层的嵌套对象还是共享引用——这就是"浅"的含义。Python 设计浅拷贝为默认行为是因为：①大多数场景不需要完全独立的嵌套数据；②深拷贝成本高（递归复制所有嵌套对象）；③很多场景下共享嵌套引用反而是期望的行为（比如多个视图共享同一份数据源）。

打个比方：浅拷贝像是复印了文件夹的目录页，但里面的文件还是原来的——你改了文件内容，所有看到这个文件的人都受影响。

【必须掌握】
- 浅拷贝：新外壳 + 旧内容引用
- 4 种浅拷贝方式：`.copy()`、`list()`、`[:]`、`copy.copy()`
- 修改嵌套元素 → 所有浅拷贝对象都受影响

【企业场景】
> 你有一份基准测试数据 `base_data = [{"name": "test1", "params": [1,2]}, ...]`。用 `case1 = base_data.copy()` 准备一个新的测试用例，修改 `case1[0]["params"][0] = 999`——结果 `base_data` 中对应的 params 也被改了，后续所有用例都用到了被污染的数据。

【面试考察】
> 面试官："说说你知道的浅拷贝方式，各举一例。"
> 参考回答：① `l.copy()` — 列表的 copy 方法；② `list(l)` — 工厂方法；③ `l[:]` — 切片；④ `import copy; copy.copy(l)` — copy 模块。四种效果相同，都是浅拷贝。

【易错点】

```python
import copy

origin = [[1,2], {"name": "Tom", "chars": ["A","B"]}]

c1 = origin.copy()       # 浅拷贝
c2 = list(origin)        # 浅拷贝
c3 = origin[:]           # 浅拷贝
c4 = copy.copy(origin)   # 浅拷贝

# 这四种方式效果一样——都是浅拷贝
# 验证：修改嵌套元素，所有对象都受影响
c3[1]["chars"][1] = "BBB"

print(origin[1]["chars"])  # ['A', 'BBB'] ← 原对象也被改了！
print(c1[1]["chars"])      # ['A', 'BBB']
print(c2[1]["chars"])      # ['A', 'BBB']
print(c4[1]["chars"])      # ['A', 'BBB']
```

【我的理解】
浅拷贝：外面复制，里面共享。

## 三、深拷贝

### 知识点 3：什么是深拷贝

【课程原话/定义】
深拷贝是指创建一个新的对象，并递归地复制原始对象及其所有嵌套对象的内容，而不仅仅是复制它们的引用。深拷贝具有数据独立性。使用 `copy` 模块中的 `deepcopy()` 方法实现。

【为什么？】
深拷贝递归地走完整个对象图，把每一层嵌套对象都真正复制一份——相当于把整栋楼拆了重建，不是只换门牌号。代价是时间和内存，但在需要完全隔离数据时必须用。Python 的 `deepcopy()` 会自动处理循环引用（用 memo dict 记录已复制过的对象，遇到第二次直接复用），避免无限递归。

【必须掌握】
- `import copy; copy.deepcopy(obj)` 是 Python 中唯一的深拷贝方式
- 深拷贝 = 完全独立的副本，修改任何层级都不影响原对象
- 深拷贝会处理循环引用

【企业场景】
> 数据驱动测试：你有 100 个测试用例，每个基于同一份模板数据 `template` 但需要各自修改——`case = copy.deepcopy(template)` 确保每个用例互不影响。如果用浅拷贝，第 50 个用例改了嵌套参数，前 49 个用例的断言可能全部失效——因为它们在共享同一个被改坏的嵌套对象。

【面试考察】
> 面试官："`deepcopy()` 怎么处理循环引用？"
> 参考回答：`deepcopy()` 内部维护一个 memo 字典，记录 `{id(原始对象): 新对象}`。遇到已复制过的对象直接返回之前的副本，避免无限递归和重复复制。这是生产级代码才有的细节——自己写递归拷贝很容易在这个点上崩溃。

```python
import copy

origin = [[1,2], {"name": "Tom", "chars": ["A","B"]}]
deep = copy.deepcopy(origin)

# 验证独立性
origin[1]["chars"][1] = "BBB"

print(origin[1]["chars"])  # ['A', 'BBB'] ← 原对象变了
print(deep[1]["chars"])    # ['A', 'B']   ← 深拷贝不受影响
```

【我的理解】
深拷贝：里里外外全部复制，互不影响

## 四、对比与场景选择

### 知识点 4：浅拷贝 vs 深拷贝 vs 赋值 决策表

【课程原话/定义】
程序的大部分场景都使用浅拷贝。浅拷贝、深拷贝特指容器类型保存的复杂结构，对于基本类型的数据，都是引用指向。

【为什么？】
基本类型（int、str、bool 等）是不可变的——"修改"实际上是创建新对象并重新绑定变量名，所以不存在"共享修改"的问题。拷贝的话题只对容器类型有意义。大部分场景用浅拷贝就够，因为通常只需要"不同的列表外壳"来增删元素，嵌套对象共享反而是设计意图。

【必须掌握】

| 操作                     | 创建新容器 | 嵌套对象独立 | 适用场景      |
| ---------------------- | ----- | ------ | --------- |
| `b = a`                | ❌     | ❌      | 不需要独立数据   |
| `b = a.copy()`         | ✅     | ❌      | 只需增删外层元素  |
| `b = copy.deepcopy(a)` | ✅     | ✅      | 需要完全独立的数据 |

【企业场景】
> 测试中的典型选择逻辑：
> - `b = a`：同一个测试用例对象，只是换个变量名引用——几乎不用。
> - `b = a.copy()`：用例列表需要增删（加参数、删字段），但嵌套的用户对象共享没毛病——用浅拷贝。
> - `b = copy.deepcopy(a)`：每个用例需要独立的数据副本，各自修改互不干扰——用深拷贝。

【面试考察】
> 面试官："`sorted()` 返回新列表，它是深拷贝还是浅拷贝？为什么？"
> 参考回答：是浅拷贝——内部元素还是原对象的引用。这符合"大部分场景用浅拷贝"的原则。排序只改变元素顺序，不需要复制元素本身。如果真的需要深拷贝版本，自己包一层：`copy.deepcopy(sorted(original))`。

【易错点】

| 数据类型 | `b = a` 后修改 b | `b = a.copy()` 后修改 b 的外层 | `b = a.copy()` 后修改 b 的嵌套层 |
|----------|-----------------|---------------------------|--------------------------------|
| `a = [1,2,3]` | 影响 a | 不影响 a（1,2,3 是不可变对象，无所谓嵌套） | 无嵌套层 |
| `a = [[1,2], [3,4]]` | 影响 a | 不影响 a | 影响 a |
| `a = {"k": [1,2]}` | 影响 a | 不影响 a | 影响 a |

```python
# 关键验证：为什么基本类型"看起来"不受浅拷贝影响？
a = [1, 2, 3]
b = a.copy()
b[0] = 999
print(a)  # [1, 2, 3] — 没变？
print(b)  # [999, 2, 3]

# 真相：不是浅拷贝保护了数据，而是 int 不可变——
# b[0] = 999 不是"修改 int 对象"，而是"让 b[0] 指向新的 int 对象 999"
# a[0] 依然指向原来的 1。如果是嵌套列表 b[0][0] = 999，问题就暴露了。
```

【我的理解】

## 五、测试中的实战场景

### 知识点 5：测试工程师怎么用拷贝

【课程原话/定义】
程序的大部分场景都使用浅拷贝。`sorted()` 这种返回新列表的场景可考虑深拷贝以避免原列表被修改。

【为什么？】
测试中数据隔离是最核心的需求之一——每个测试用例必须独立运行，不能因为用例 A 改了数据导致用例 B 失败（这叫测试间耦合，是自动化测试的癌症）。拷贝就是实现数据隔离的基本工具。

【企业场景】

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 每个测试用例需要独立的数据副本 | `deepcopy()` | 嵌套字段互不干扰 |
| 构建用例列表，只需增删外层元素 | `copy()` | 嵌套对象共享没问题 |
| 函数接收列表参数，不想修改原数据 | `l[:]` 或 `l.copy()` | 只保护外层够用 |
| 缓存接口返回的原始响应做对比 | `deepcopy()` | 防止后续处理修改原始数据 |
| Pytest 参数化时每个参数组隔离 | 框架自动处理 | 但手动构建参数列表时需注意 |

【面试考察】
> 面试官："在写自动化测试时，你遇到过因为浅拷贝导致的 Bug 吗？怎么解决的？"
> 参考回答：遇到过——准备测试数据时用 `case = template.copy()`，然后修改嵌套字段，结果 template 也被污染，后续用例全部用错数据。解决：改用 `copy.deepcopy(template)`，确保每个用例获得完全独立的副本。

【我的理解】
