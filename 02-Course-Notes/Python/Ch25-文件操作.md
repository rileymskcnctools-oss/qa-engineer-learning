## 一、为什么测试工程师必须会文件操作

### 知识点 1：文件操作在测试工作中的三大用途

【课程原话/定义】
文件操作是每一门编程语言中都必不可少的一项语法。通过文件可以实现**数据持久化存储**、**测试数据驱动文件的处理**、**程序配置文件的处理**。

在程序中操作文件和用图形界面操作文件的过程基本一致：找到文件位置 → 打开文件 → 读写文件 → 关闭文件。

【为什么？】
程序运行时所有变量都在内存里，进程一结束内存就被回收。测试工作中有大量数据**必须活得比进程更久**：

| 数据 | 如果只存内存会怎样 | 所以必须落文件 |
|------|-----------------|--------------|
| 测试用例数据（100 组账号密码） | 每次改数据都要改代码 | 存 csv/yaml/json，代码不动只换数据 |
| 环境配置（测试/预发/生产 URL） | 换环境要改代码再提交一次 | 存 config 文件，切环境只改一行 |
| 测试结果 / 日志 | 程序退出后什么都不剩，出问题无法复盘 | 写 log/report 文件，可归档可追溯 |

一句话：**文件是测试代码和测试数据之间的解耦层**。后面 Pytest 的数据驱动（yaml/csv 参数化）、Allure 报告、conftest 读配置，底层全是这一章的 `open()`。

【必须掌握】
- 文件操作四步：打开 → 读/写 → （处理）→ 关闭
- 测试场景三大用途：数据持久化、数据驱动、配置管理

【企业场景】
你接手一个接口自动化项目，需要用 200 个账号跑登录用例。你不会把 200 个账号写死在 Python 代码里，而是：`accounts.csv` 存数据 → 代码 `open()` 读出来 → `@pytest.mark.parametrize` 参数化跑。测试同学要加账号时改 csv 就行，不需要碰代码，也不需要你重新 review。

【面试考察】
面试官："你们的测试数据是怎么管理的？"

参考回答框架：
1. 不写死在代码里 → 数据与代码分离
2. 小数据量用 yaml/json/csv 文件，大数据量或需要共享时进数据库
3. 读取方式：Python 文件操作 / PyYAML / csv 模块 → 交给 pytest 参数化
4. 收益：改数据不改代码、非开发同学也能维护、同一套用例跑多环境

【易错点】

| 误区 | 问题 | 正确做法 |
|------|------|---------|
| 测试数据写死在 .py 里 | 改数据 = 改代码 = 重新提交 + review | 数据外置到文件 |
| 账号密码明文提交到 Git | 敏感信息泄露 | 敏感配置进 `.env`，`.gitignore` 排除 |
| 用 print 代替日志文件 | 控制台一关什么都不剩 | 结果写文件，CI 里可归档 |

【我的理解】
> （回想一下你做过的手工测试：哪些重复填写的数据，如果外置成文件就能自动跑？）

## 二、打开文件 open()

### 知识点 2：open() 的三个核心参数

【课程原话/定义】
Python 使用 `open` 方法打开一个文件并返回**文件对象**，如果该文件无法被打开，会抛出 `OSError`。

完整格式：

```python
open(file, mode='r', buffering=-1, encoding=None, errors=None,
     newline=None, closefd=True, opener=None)
```

简化格式（实际工作只用这三个参数）：

```python
open(file, mode='r', encoding=None)
```

- `file`：必选，文件的**相对路径或绝对路径**
- `mode`：可选，打开模式，默认 `r` 只读
- `encoding`：一般使用 `utf8`

```python
# 以写入方式打开 index.html 文件
file = open("index.html", "w")
```

【为什么？】
`open()` 返回的不是文件内容，而是一个**文件对象（file object）**，它内部维护一个"文件指针"——记录当前读到/写到哪个位置。理解指针是理解 `read()`、`readline()` 行为的关键：读过的内容指针就走过去了，不会重复读。

`encoding` 为什么必须显式写 `utf8`？因为不指定时 Python 用**操作系统默认编码**：Linux/macOS 是 UTF-8，而中文 Windows 是 GBK。同一份代码在你的 Windows 上能读，跑到 CI 的 Linux 容器上就 `UnicodeDecodeError`。这是中文环境下最高频的"我这里明明能跑"事故。

【必须掌握】
- `open()` 返回文件对象，不是内容
- 文件对象内部有**文件指针**
- 打开失败抛 `OSError`（子类 `FileNotFoundError`、`PermissionError`）
- 涉及中文一律显式 `encoding="utf8"`

【企业场景】
你在本地写好读取 `case.csv` 的脚本跑得很好，推到 Jenkins 后报 `UnicodeDecodeError: 'gbk' codec can't decode byte`。排查发现本地 Windows 默认 GBK 恰好能读，Linux 容器默认 UTF-8。修法一行：`open("case.csv", encoding="utf8")`。以后所有 `open()` 都带上 encoding，是一条团队规约。

【面试考察】
面试官："open() 的 encoding 参数不写会有什么问题？"

参考回答框架：
1. 不写就用系统默认编码，Windows 常是 GBK、Linux 是 UTF-8
2. 导致同一份代码换机器/换 CI 就 UnicodeDecodeError
3. 结论：跨平台代码必须显式 `encoding="utf8"`
4. 补充：二进制模式 `rb/wb` 不能传 encoding（字节流没有编码概念）

【易错点】

| 写法 | 结果 | 说明 |
|------|------|------|
| `open("data.txt")` | 只读打开，编码看系统 | 有中文时跨平台会炸 |
| `open("data.txt", "rb", encoding="utf8")` | ValueError | 二进制模式不能带 encoding |
| `open("C:\Users\new.txt")` | 路径错乱 | `\n` 被当转义符，用 `r"C:\Users\new.txt"` 或 `/` |
| 相对路径当成"相对于 .py 文件" | 找不到文件 | 相对路径是相对**运行时的工作目录** |

【我的理解】
> （在 PyCharm 里 Run 一个脚本和在项目根目录用命令行运行同一个脚本，相对路径 `data.txt` 指向的是同一个文件吗？动手验证一下）

### 知识点 3：mode 打开模式

【课程原话/定义】

| 字符 | 含义 |
|------|------|
| `r` | 以只读方式打开文件。文件指针放在文件开头。**这是默认模式** |
| `w` | 以只写方式打开。文件已存在则**覆盖**，不存在则创建新文件 |
| `a` | 以追加写入方式打开。文件存在则在**末尾追加**，不存在则创建新文件 |
| `b` | 二进制模式 |
| `t` | 文本模式（默认） |

【为什么？】
`w` 和 `a` 的区别是新手最容易踩的坑，而且踩了**没有报错**——数据被静默清空。`w` 打开的瞬间（还没 write）文件就已经被清空了。

为什么要设计得这么"危险"？因为 `w` 表达的语义是"这个文件我全权负责，内容由我决定"（比如每次重新生成的报告），而 `a` 表达的是"我只往后加，不动历史"（比如日志）。选错模式 = 语义搞错。

`b` 和 `t` 是**修饰符**，要和 r/w/a 组合：`rb`、`wb`、`ab`。文本模式读出来是 `str`，二进制模式读出来是 `bytes`。

【必须掌握】
- `r` 只读（默认）、`w` 覆盖写、`a` 追加写
- `w` 在打开瞬间就清空文件，不是 write 的时候
- 组合模式：`r+`（读写）、`rb`/`wb`（二进制）、`w+`（清空后可读写）
- 文件不存在时：`r` 报 `FileNotFoundError`，`w`/`a` 自动创建

【企业场景】
你写一个把失败用例记录到 `failed_cases.txt` 的 hook。用 `w` 打开，跑第二条失败用例时把第一条覆盖掉了，最后文件里永远只有最后一个失败用例。改成 `a` 追加才对。反过来，生成 `report.html` 必须用 `w`——否则第二次运行会把两份 HTML 拼在一起，报告直接打不开。

结论：**日志/累积型 → `a`；报告/快照型 → `w`。**

【面试考察】
面试官："w 和 a 的区别？如果我要往一个已有文件里加一行，用哪个？"

参考回答框架：
1. `w` = 覆盖（打开即清空），`a` = 追加（指针在末尾）
2. 加一行用 `a`
3. 两者都在文件不存在时自动创建
4. 补充坑：`w` 的清空发生在 open 时刻，即使后面没 write 也已经清空了

【易错点】

| 场景 | 错误模式 | 正确模式 | 后果 |
|------|---------|---------|------|
| 追加日志 | `w` | `a` | 历史日志被清空 |
| 重新生成报告 | `a` | `w` | 报告内容越来越长、格式错乱 |
| 读取测试数据 | `w` | `r` | **数据文件被清空**（最惨的一种） |
| 读图片/Excel | `r` | `rb` | UnicodeDecodeError |

【扩展知识】
`+` 系列模式的区别（面试偶尔追问）：

| 模式 | 可读 | 可写 | 文件不存在 | 是否清空 | 初始指针 |
|------|------|------|-----------|---------|---------|
| `r+` | ✅ | ✅ | 报错 | 否 | 开头 |
| `w+` | ✅ | ✅ | 创建 | **是** | 开头 |
| `a+` | ✅ | ✅ | 创建 | 否 | 末尾 |

【我的理解】
> （做个实验：先往 data.txt 写三行，然后用 `open("data.txt","w")` 打开后**立刻 close 什么都不写**，再看文件里还有什么？这说明了什么？）

## 三、关闭文件 close()

### 知识点 4：close() 与 with 上下文管理器

【课程原话/定义】
文件操作完以后需要关闭，`close()` 方法用于关闭一个已打开的文件。关闭后的文件不能再进行读写操作，否则会触发 `ValueError`。`close()` 允许调用多次。使用 `close()` 关闭文件是一个好的习惯。

格式：`fileObject.close()`

```python
file = open("index.html", "w")
file.close()
```

【为什么？】
不关闭文件有三个真实后果：

1. **数据丢失**：写入先进操作系统缓冲区，`close()` 才强制刷盘（flush）。程序异常退出时缓冲区内容没落盘，文件是空的或截断的——"我明明 write 了，文件里啥也没有"。
2. **文件句柄泄漏**：每个进程能打开的文件数有上限（Linux 默认 1024）。循环里打开 1 万个文件不关，报 `OSError: Too many open files`。
3. **文件被锁**：Windows 上没关闭的文件可能无法被删除/重命名，CI 清理工作区时失败。

那为什么工作中几乎看不到 `close()`？因为 `with` 更好：**只要出了 with 代码块，无论正常结束还是抛异常，文件一定被关闭**。手写 `close()` 在异常时会被跳过（除非配 try/finally）。

```python
# 课程写法：手动关闭
file = open("data.txt", "r", encoding="utf8")
content = file.read()
file.close()

# 企业写法：with 自动关闭（推荐）
with open("data.txt", "r", encoding="utf8") as file:
    content = file.read()
# 出了缩进块，file 已自动关闭
```

【必须掌握】
- `close()` 的真正作用是**刷缓冲 + 释放句柄**，不只是"礼貌"
- 关闭后再读写 → `ValueError: I/O operation on closed file`
- `close()` 可重复调用，不报错
- 实际工作统一用 `with open(...) as f:`，等价于 try/finally 版 close

【企业场景】
你的自动化脚本每条用例都 `open()` 一个截图文件写入但忘了关闭，跑 500 条用例后报 `Too many open files`，整个夜间构建挂掉。这类问题的特征是"跑少量用例正常，跑全量就崩"——句柄泄漏的典型症状。改成 `with` 之后彻底消失。

【面试考察】
面试官："为什么推荐用 with open 而不是 open + close？"

参考回答框架：
1. `with` 是上下文管理器，退出代码块自动调用 `close()`
2. **即使块内抛异常也保证关闭**，等价于 try/finally 但更简洁
3. 不关闭的危害：缓冲区数据没落盘、文件句柄泄漏、Windows 文件被占用
4. 补充：`with` 依赖 `__enter__`/`__exit__` 协议，自己写的类也能支持（关联 [[Ch23-面向对象进阶]]）

【易错点】

| 写法 | 问题 |
|------|------|
| `open()` 后中间抛异常 | close 被跳过，文件句柄泄漏 |
| close 之后再 `f.read()` | ValueError: I/O operation on closed file |
| 循环里 open 不 close | Too many open files |
| `with` 块外面用 `f.read()` | 文件已关闭，同样 ValueError |

【扩展知识】
一个 `with` 可以同时管理多个文件（读一个写一个，做数据清洗时很常用）：

```python
with open("raw.txt", encoding="utf8") as src, \
     open("clean.txt", "w", encoding="utf8") as dst:
    for line in src:
        dst.write(line.strip() + "\n")
```

【我的理解】
> （`with open()` 在块内抛异常时文件会被关闭吗？先猜结论，再用 `1/0` 制造异常在 finally 里打印 `file.closed` 验证）

## 四、写入文件

### 知识点 5：write() 写字符串

【课程原话/定义】
`write()` 方法用于向文件中写入指定字符串。如果文件打开模式为 `b`，则要将字符串转换成 bytes 类型的二进制字符串。**函数返回成功写入数据的长度。**

格式：`fileObject.write([str])`

```python
file = open("index.html", "w")
file.write("<h1>文件写入标题</h1>")
file.write("\n")
file.write("<p>文件写入内容。。。。。。</p>")
file.close()
```

【为什么？】
`write()` **不会自动加换行**——这是和 `print()` 最大的区别。`print()` 默认 `end="\n"`，`write()` 默认什么都不加。所以课程示例中要单独 `file.write("\n")`。

为什么设计成不自动换行？因为文件写入需要**精确控制字节**：写 JSON、写 CSV、写二进制协议包时多一个换行就是格式错误。Python 把"要不要换行"的决定权交给你。

返回值是写入的字符数，可用于校验，但工作中很少用——真正靠得住的校验是写完读回来比对。

【必须掌握】
- `write()` 只接受**字符串**，写数字要先 `str()` 转换
- `write()` 不自动换行，需要手动 `\n`
- 返回值 = 写入的字符数
- `wb` 模式下必须写 `bytes`：`f.write("abc".encode("utf8"))`

【企业场景】
你写一个把 pytest 失败用例名落盘的小工具：

```python
def save_failed(case_name, reason):
    with open("failed_cases.txt", "a", encoding="utf8") as f:
        f.write(f"{case_name}\t{reason}\n")   # 制表符分隔 + 换行，方便后续解析
```

用 `a` 追加保证多条不覆盖，用 `\t` 分隔保证之后能 split 出结构化数据，用 `\n` 保证一条一行。三个细节全在这一个 write 里。

【面试考察】
面试官："write() 和 print() 有什么区别？"

参考回答框架：
1. print 输出到标准输出（控制台），write 输出到文件对象
2. print 自动加换行和空格分隔，write 一个字节都不多加
3. print 能接任意类型（内部 str() 转换），write 只接字符串/bytes
4. 补充：`print("x", file=f)` 也能写文件，等价于 write + 换行

【易错点】

| 错误写法 | 报错/后果 | 正确写法 |
|---------|----------|---------|
| `f.write(100)` | TypeError: must be str | `f.write(str(100))` |
| 多次 write 但没写 `\n` | 所有内容挤成一行 | 每条末尾补 `\n` |
| `wb` 模式 `f.write("中文")` | TypeError: bytes-like required | `f.write("中文".encode("utf8"))` |
| 用 `w` 在循环里写 | 只剩最后一条 | 循环外 open 一次，或用 `a` |

【我的理解】
> （为什么 `f.write(100)` 会报错，而 `print(100)` 不会？从"谁负责类型转换"的角度解释）

### 知识点 6：writelines() 写序列

【课程原话/定义】
`writelines()` 方法用于向文件中写入一序列的字符串。这一序列字符串可以是由迭代对象产生的，如一个字符串列表。

**注意：不要被方法名所迷惑，如果每个元素独占一行，需要在数据后指定换行符 `\n`。**

格式：`fileObject.writelines(seq)`

```python
datas = ["AAAAAAAAAAAA\n", "BBBBBBBBBBBB\n", "CCCCCCCCCCCC\n", "DDDDDDDDDDDD\n"]
file = open('data.txt', "w")
file.writelines(datas)
file.close()
```

【为什么？】
名字里有 `lines` 却不加换行，是 Python 标准库里最著名的"误导性命名"之一。它真实的语义是"把序列里每个元素依次 write 一遍"，等价于：

```python
for line in datas:
    file.write(line)
```

那为什么还要 `writelines()`？因为它在 C 层循环，比 Python 层 for 循环快，且和 `readlines()` 对称——`readlines()` 读出来的每行**自带 `\n`**，直接 `writelines()` 写回去格式不变。这两个方法是设计成配对使用的。

【必须掌握】
- `writelines()` **不自动加换行**，要自己在元素里带 `\n`
- 参数是任意可迭代对象（list/tuple/生成器）
- 元素必须都是字符串，有数字要先转换
- 与 `readlines()` 配对：读出来能原样写回去

【企业场景】
你要从 1000 条测试数据里筛出手机号用例另存一份：

```python
with open("all_cases.txt", encoding="utf8") as src:
    lines = src.readlines()                      # 每行自带 \n

phone_cases = [l for l in lines if "phone" in l]  # 列表推导筛选（Ch17）

with open("phone_cases.txt", "w", encoding="utf8") as dst:
    dst.writelines(phone_cases)                   # 原样写回，格式不变
```

readlines + 推导式 + writelines，是最常见的"文件级数据清洗"三件套。

【面试考察】
面试官："writelines 会自动换行吗？"

参考回答框架：
1. 不会。它只是把序列里每个元素依次 write
2. 想每行一条必须自己在元素末尾加 `\n`
3. 与 readlines 对称：readlines 保留 `\n`，所以能原样 writelines 回去
4. 追问优势：C 层循环比 Python for 快，代码也更短

【易错点】

| 错误 | 结果 | 修正 |
|------|------|------|
| `f.writelines(["a","b","c"])` | 写出 `abc` 挤一行 | 元素带 `\n`，或 `f.write("\n".join(lst))` |
| `f.writelines([1,2,3])` | TypeError | 先 `[str(i) for i in lst]` |
| 以为 writelines 会覆盖判断 | 覆盖与否由 mode 决定 | `w` 覆盖 / `a` 追加 |

【扩展知识】
不带 `\n` 的列表想每行一条，用 `join` 更干净：

```python
f.write("\n".join(["case1", "case2", "case3"]))   # 行间换行，末尾无多余空行
```

【我的理解】
> （`writelines` 和 `write("\n".join(lst))` 写出来的文件有什么细微差别？想想最后一行有没有换行符）

## 五、读取文件

### 知识点 7：read() 读指定字符数

【课程原话/定义】
`read()` 方法用于从文件读取指定的字节数，如果未给定或为负则读取所有。

格式：`fileObject.read([size=-1])`

```python
file = open('data.txt', "r")
content = file.read(10)   # 读取 10 个字符
print(content)
content = file.read()     # 读取剩余所有内容（不是全部！）
print(content)
file.close()
```

【为什么？】
注意课程示例里的隐藏考点：第二次 `read()` 读到的**不是整个文件**，而是"第 11 个字符到结尾"。因为第一次 `read(10)` 已经把文件指针推到了第 10 个字符处，指针不会自动回头。

想重新从头读，要么 `f.seek(0)` 把指针拨回开头，要么重新 open。这个"指针只前进"的模型是所有读方法的共同前提。

`read()` 不带参数一次性把整个文件读进内存——小文件很方便，几百 MB 的日志会直接把内存吃满。

【必须掌握】
- `read()` 读全部，`read(n)` 读 n 个字符（文本模式下是字符，二进制模式下是字节）
- 读操作会**推进文件指针**，不会自动复位
- `f.seek(0)` 把指针拨回开头
- 读到文件末尾返回空字符串 `""`（不是 None，也不报错）
- 大文件禁用 `read()`，改用逐行迭代

【企业场景】
你要断言接口返回的报告文件里包含某个关键字，文件只有几 KB：

```python
with open("report.json", encoding="utf8") as f:
    content = f.read()
assert "\"status\": \"pass\"" in content
```

小文件一次读完做断言最简单。但如果是 2GB 的 Jenkins 构建日志找 ERROR，`read()` 会让容器 OOM，必须逐行遍历：

```python
with open("build.log", encoding="utf8") as f:
    for line in f:                 # 迭代文件对象，一次只驻留一行
        if "ERROR" in line:
            print(line.strip())
```

【面试考察】
面试官："几个 G 的日志文件，怎么用 Python 找出所有含 ERROR 的行？"

参考回答框架：
1. 不能用 `read()` / `readlines()`——会把整个文件load进内存导致 OOM
2. 直接 `for line in f:` 迭代文件对象，内存里只有当前行
3. 命中就处理（打印/写另一个文件），全程内存恒定
4. 加分：也可 `f.read(1024*1024)` 分块读；生产上更常见的是 `grep` / 日志平台

【易错点】

| 误区 | 真实行为 |
|------|---------|
| 第二次 `read()` 还能读到全部 | 只读到剩余部分（指针已前移） |
| 以为读完会报错 | 读到末尾返回 `""`，静默为空 |
| 用 `read()` 处理大文件 | 内存被打满 / OOM |
| `read(10)` 在二进制模式也是 10 个字符 | `rb` 模式是 10 个**字节**，中文一个字 3 字节 |

【我的理解】
> （`read()` 两次连续调用，第二次为什么是空的？用"文件指针"这个词解释给自己听）

### 知识点 8：readline() 读一行

【课程原话/定义】
`readline()` 方法用于从文件读取整行，**包括 `\n` 字符**。如果指定了一个非负数的参数，则返回指定大小的字节数，包括 `\n` 字符。

格式：`fileObject.readline(size=-1)`

```python
file = open('data.txt', "r")
content = file.readline(10)   # 读取 10 个字符
print(content)
content = file.readline()     # 读取文件指针所在行剩余所有内容
print(content)
file.close()
```

【为什么？】
`readline()` 的返回值**带着行尾的 `\n`**，所以拿来做比较时必须先 `strip()`：

```python
line = f.readline()          # "admin\n"
if line == "admin":          # False！因为实际是 "admin\n"
    ...
if line.strip() == "admin":  # True ✅
    ...
```

这是文件读取里最高频的"看起来相等却不相等"事故。同理，`readline(10)` 如果这行不足 10 个字符，它读到 `\n` 就停——不会跨行去凑够 10 个。

如何判断读完了？`readline()` 在文件末尾返回 `""`（空字符串）；而空行返回的是 `"\n"`，长度为 1。用 `while line:` 判断结束是安全的，用 `while line != "\n"` 是错的。

【必须掌握】
- `readline()` 返回值**含 `\n`**，比较前先 `.strip()`
- 每次调用读下一行（指针推进）
- 文件末尾返回 `""`；空行返回 `"\n"`
- `readline(n)` 最多读 n 个字符，遇 `\n` 提前停

【企业场景】
你要从一个大的账号文件里只读第一行做冒烟测试：

```python
with open("accounts.txt", encoding="utf8") as f:
    first = f.readline().strip()      # 只读一行，大文件也不吃内存
username, password = first.split(",")
```

只需要一行时用 `readline()` 而不是 `readlines()[0]`——后者会把整个文件读进内存再取第一个，浪费得离谱。

【面试考察】
面试官："readline 读出来的内容为什么和你比较的字符串不相等？"

参考回答框架：
1. `readline()` 保留行尾换行符 `\n`
2. `"admin\n" != "admin"`，所以断言失败
3. 修法：`.strip()` 去掉首尾空白（换行、空格、\r）
4. 加分：Windows 换行是 `\r\n`，跨平台文件读出来可能带 `\r`，`strip()` 一并解决

【易错点】

| 误区 | 后果 | 正确做法 |
|------|------|---------|
| 直接比较 `readline()` 结果 | 永远不相等（多了 `\n`） | `.strip()` 后比较 |
| 用 `readline()` 循环但忘了终止条件 | 死循环 | `while line:` （空串即结束） |
| 认为空行会返回 `""` | 空行是 `"\n"`，被误判成结束 | 只有 `""` 才是 EOF |
| `readline(5)` 以为一定返回 5 个字符 | 行短时提前返回 | 它以行为边界 |

【我的理解】
> （文件里有一个空行，`readline()` 返回什么？和文件读完时的返回值怎么区分？）

### 知识点 9：readlines() 读所有行成列表

【课程原话/定义】
`readlines()` 方法用于读取所有行（直到结束符 EOF）并返回**列表**。

格式：`fileObject.readlines()`

```python
file = open('data.txt', "r")
contents = file.readlines()    # 以行为单位读取文件所有内容
print(contents)
file.close()
```

输出形如：`['AAAA\n', 'BBBB\n', 'CCCC\n', 'DDDD\n']`

【为什么？】
`readlines()` 是**文件 → 列表**的桥梁：一旦变成列表，Ch09（列表）、Ch17（推导式）的全部技能就能用上——筛选、切片、排序、去重。这也是它在测试数据处理里最常见的用法：

```python
with open("cases.txt", encoding="utf8") as f:
    cases = [line.strip() for line in f.readlines() if line.strip()]  # 去空行 + 去换行
```

注意每个元素**都带 `\n`**（除了最后一行可能没有），所以基本都要配 `strip()`。

它的代价和 `read()` 一样：整个文件进内存。所以有个铁律：**能用 `for line in f` 的地方就别用 `readlines()`**——前者是惰性迭代，后者是一次性加载。只有需要"列表能力"（切片、多次遍历、统计行数）时才值得 readlines。

【必须掌握】
- `readlines()` → 列表，每个元素是一行且**含 `\n`**
- 常配列表推导式做 `strip()` + 过滤
- 与 `writelines()` 对称，可原样写回
- 大文件不用它，改用 `for line in f:`

【企业场景】
测试数据文件常带表头，要跳过第一行：

```python
with open("users.csv", encoding="utf8") as f:
    lines = f.readlines()

header = lines[0].strip().split(",")     # ['username','password','expect']
data = [l.strip().split(",") for l in lines[1:] if l.strip()]   # 切片跳表头
# data → [['admin','123456','pass'], ['guest','','fail']]
# 直接丢给 @pytest.mark.parametrize
```

"切片跳表头"这个动作用 `readlines()` 最自然，逐行迭代反而要额外计数器。

【面试考察】
面试官："read、readline、readlines 三个怎么选？"

参考回答框架：
1. `read()` → 整个文件成一个字符串：小文件全文匹配/断言
2. `readline()` → 一行：只要头几行、或想省内存
3. `readlines()` → 行列表：需要按行筛选/切片/统计
4. 大文件三个都不用，直接 `for line in f:` 惰性迭代
5. 共同坑：readline/readlines 都保留 `\n`，要 strip

【易错点】

| 误区 | 说明 |
|------|------|
| 以为 readlines 会去掉 `\n` | 保留，必须 strip |
| 用 readlines 读大文件 | 全部进内存，OOM |
| `readlines()` 后再 `read()` | 指针已到末尾，返回 `""` |
| 忘记过滤末尾空行 | 最后多出一个 `''` 元素，参数化时多跑一条空用例 |

【扩展知识】
三种读法与 `for line in f` 的内存/适用对比：

| 方式 | 返回 | 内存 | 适合 |
|------|------|------|------|
| `read()` | str（全文） | 全文件 | 小文件全文断言 |
| `read(n)` | str（n 字符） | n | 分块处理二进制/大文件 |
| `readline()` | str（一行，含 `\n`） | 一行 | 只取头部若干行 |
| `readlines()` | list[str] | 全文件 | 需要列表操作（切片/统计） |
| `for line in f` | 逐行 str | 一行 | **大文件首选** |

【我的理解】
> （用 readlines 读一个 100 行的用例文件并跳过表头，再想想同样的事用 `for line in f` 要怎么写，哪个更清楚？）
