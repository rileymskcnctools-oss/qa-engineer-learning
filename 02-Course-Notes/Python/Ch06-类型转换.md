## 一、为什么需要类型转换

### 【课程原话/定义】

> Python 是动态类型语言，不需要像 Java/C 一样在使用变量前声明类型。但有时仍然需要用到类型转换。

### 【为什么？】

Python 虽然自动推断类型，但"自动推断"不等于"自动适配"。当你用 `input()` 拿到用户输入时，返回的永远是字符串——你想做加法？对不起，`"123" + 456` 直接报错。类型转换的本质是：**告诉 Python "我知道这个数据看起来像 A 类型，但请把它当 B 类型来用"**。没有这个能力，你连用户输入的两个数字都加不了。

### 【必须掌握】

- 隐式转换（自动）vs 显式转换（强制）的区别
- 6 个核心转换函数：`int()` `float()` `str()` `bool()` `complex()` `chr()`
- 哪些值转 `bool` 是 `False`（链接 Ch05 假值体系）

### 【企业场景】

> 你写自动化脚本，从 Excel 读取测试数据——所有数字都被 pandas 读成了字符串 `"200"`。断言 `assert response.status_code == expected_code` 时发现 `expected_code` 是字符串 `"200"`，永远不会等于整数 `200`，测试白白失败。类型转换是自动化测试里每天都要写的东西。

### 【面试考察】

> "Python 中字符串 '123' 和整数 456 能直接相加吗？如果不能，怎么办？"

> 参考回答：不能，会报 `TypeError`。需要先转换——`int("123") + 456` 或 `"123" + str(456)`，取决于想要的结果是整数还是字符串。

### 【易错点】

| 易混淆概念               | 区别                                                              |
| ------------------- | --------------------------------------------------------------- |
| 隐式转换 vs 显式转换        | 隐式 = Python 自动做（`10 + 3.14 → 13.14`）；显式 = 你主动调用函数（`int("123")`） |
| 类型转换 vs 类型推断        | 推断是 Python 自动猜变量类型（`x = 5 → int`）；转换是你手动改类型（`str(5) → "5"`）     |
| `int("3.14")` 为什么报错 | `int()` 不能直接从浮点字符串转整数——得先 `float("3.14")` 再 `int()`             |

## 二、自动转换（隐式类型转换）

### 【课程原话/定义】

> 程序在执行过程中自动完成，将数据精度低的类型转换为数据精度高的类型。

### 【为什么？】

Python 的设计哲学是"别让用户为小事烦心"。整数和浮点数做运算，自动把整数升级为浮点数——因为浮点数的值域更大，不会丢失信息。反过来（浮点自动降级为整数）会丢小数部分，Python 不做这种"安全的反方向"。

### 【必须掌握】

隐式转换规则：`int + float → float`，`bool + int → int`（因为 `True=1, False=0`）

### 【企业场景】

> 接口返回的 JSON 里 `"count": 0`，你写 `if response["count"] == False` 居然走通了——因为 `0 == False` 在 Python 里是 `True`。这就是隐式转换的陷阱：布尔是 int 的子类，`True==1, False==0` 在数值比较时成立但 `is` 比较时不成立。

### 【面试考察】

> "`True + 1` 的结果是什么？为什么？"

> 参考回答：结果是 `2`。因为 `bool` 是 `int` 的子类，`True` 等价于 `1`，`False` 等价于 `0`。但注意 `True is 1` 返回 `False`——值相等不代表是同一个对象。

### 【易错点】

| 代码            | 结果              | 为什么                               |
| ------------- | --------------- | --------------------------------- |
| `10 + 3.14`   | `13.14` (float) | int 自动升级为 float                   |
| `False + 1`   | `1`             | `False == 0`                      |
| `True + 3.5`  | `4.5`           | `True → 1`，然后 `1 + 3.5` → `float` |
| `"abc" + 123` | `TypeError`     | 隐式转换不会跨"数字/字符串"边界                 |

## 三、强制转换（显式类型转换）

### 【课程原话/定义】

> 强制转换需要在代码中使用类型函数来转换。

### 【为什么？】

隐式转换只覆盖了 Python 认为"安全"的场景。当你需要"不安全"但"你确定是对的"的转换时——比如把用户输入的字符串当数字用——必须显式告诉 Python："我知道风险，执行吧"。这也是 Python "我们都是成年人"哲学的体现：不阻止你做任何事，但要求你明确表达意图。

### 【必须掌握】

6 个类型转换函数的使用和边界条件。

### 【企业场景】

> 写接口自动化，测试数据写在 YAML 文件里，读出来全是字符串。`"200"` 不能和 `response.status_code`（int）直接比较。你写了个工具函数 `safe_int(s)`，转换失败时打印警告而不是直接炸掉整个测试套件。

### 【面试考察】

> "`int('abc')` 会怎么样？你如何处理这种异常？"

> 参考回答：抛出 `ValueError: invalid literal for int() with base 10: 'abc'`。实际项目中用 `try/except` 包裹，或先用 `.isdigit()` 检查再转换。测试框架中通常是测试数据问题，需要明确报错而不是静默吞掉。

### 【易错点】

| 易错 | 正解 |
|------|------|
| `int("3.14")` → ❌ ValueError | 浮点字符串不能直接转 int，应 `int(float("3.14"))` |
| `int(3.14)` → `3`（截断，非四舍五入） | int() 对浮点数直接截断，要四舍五入用 `round(3.14)` |
| `bool("False")` → `True` | 非空字符串都是 `True`，只有空字符串 `""` 才是 `False` |
| `str(True)` → `"True"` 不是 `"1"` | str(布尔) 保留字面量，不是转数字字符串 |

## 四、六大转换函数速查

| 函数 | 用途 | 示例 | 失败条件 |
|------|------|------|----------|
| `int(x)` | 转整数 | `int("123")` → `123` | x 是无效整数字符串 |
| `float(x)` | 转浮点数 | `float("3.14")` → `3.14` | x 是无效浮点字符串 |
| `str(x)` | 转字符串 | `str(123)` → `"123"` | 基本不会失败 |
| `bool(x)` | 转布尔 | `bool(0)` → `False` | 基本不会失败 |
| `complex(x)` | 转复数 | `complex("1+2j")` → `(1+2j)` | x 格式不对 |
| `chr(x)` | 整数→字符 | `chr(65)` → `'A'` | x 超出 Unicode 范围 |
