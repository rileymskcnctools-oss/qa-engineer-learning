## 一、什么是运算符

### 【课程原话/定义】

> 运算符是用于进行各种运算操作的符号或关键词。Python 提供算术、比较、赋值、逻辑、成员、身份运算符等。

### 【为什么？】

程序 = 数据 + 运算。数据靠变量存（Ch05），运算靠运算符来做（Ch07）。没有运算符，变量只是一堆"静止的数据"——你没法比较两个接口返回的状态码是否相等，没法计算分页的总页数，没法判断"用户登录了吗"和"订单支付了吗"同时成立。**运算符是让数据"动起来"的东西。**

### 【必须掌握】

- 算术运算符 7 个：`+` `-` `*` `/` `%` `**` `//`
- 赋值运算符 8 个（含复合赋值）
- 逻辑运算符 3 个：`and` `or` `not`
- 运算符优先级：括号 > 算术 > 比较 > 逻辑 > 赋值
- 短路特性

### 【企业场景】

> 接口自动化里，分页断言是最常见的运算场景：`total_pages = (total_count + page_size - 1) // page_size`——这是整除的经典用法。再比如 `assert response.status_code == 200 and "token" in response.json()`——and 连接两个条件，一个假全盘假。

### 【面试考察】

> "Python 中 `//` 和 `/` 的区别？`%` 有什么用？"

> 参考回答：`/` 返回浮点数（`5/2 → 2.5`），`//` 返回向下取整的整数商（`5//2 → 2`）。`%` 取余数，常见场景：判断奇偶（`n%2`）、分页计算、循环索引。

### 【易错点】

| 易混淆概念 | 区别 |
|-----------|------|
| `/` vs `//` | `/` 总是返回 float；`//` 返回向下取整的 int |
| `=` vs `==` | `=` 是赋值；`==` 是比较——if 条件里写 `=` 会报错/产生意外 |
| `and` vs `&` | `and` 是逻辑与（短路）；`&` 是位与（不短路，两边都执行） |
| `**` vs `^` | Python 中 `**` 是幂运算；`^` 是位异或，不是乘方 |

## 二、算术运算符

### 【课程原话/定义】

> 算术运算符用于基本的数学计算：`+ - * / % ** //`

### 【为什么？】

算术运算符是所有编程语言的基础——测试工作中，验证接口返回数据的数值正确性、分页计算、超时重试次数计数，全是算术。

### 【必须掌握】

| 运算符 | 名称 | 示例 | 结果 | 注意 |
|--------|------|------|------|------|
| `+` | 加 | `10 + 3` | `13` | 字符串用 `+` 是拼接 |
| `-` | 减 | `10 - 3` | `7` | — |
| `*` | 乘 | `10 * 3` | `30` | 字符串 `"a" * 3` → `"aaa"` |
| `/` | 除 | `10 / 3` | `3.333...` | 永远是 float |
| `%` | 取模 | `10 % 3` | `1` | 余数，除数为 0 抛异常 |
| `**` | 幂 | `2 ** 10` | `1024` | `x ** y` = x 的 y 次方 |
| `//` | 整除 | `10 // 3` | `3` | 向下取整，除数为 0 抛异常 |

### 【企业场景】

> 接口返回 `{"total": 103, "page_size": 20}`，你要验证总页数：`total_pages = (103 + 20 - 1) // 20` → `6`。这就是整除在测试断言里的日常用法。另外 `%` 在循环中用于"每 N 次执行一次"——比如大批量接口测试，每 50 条报告一次进度：`if i % 50 == 0: print(f"已完成 {i} 条")`。

### 【面试考察】

> "`/` 和 `//` 的区别是什么？什么场景用哪个？"

> 参考回答：`/` 返回浮点数，用于需要精度的计算；`//` 返回整数商（向下取整），用于分页、索引计算等必须整数的场景。测试里分页断言用 `//`，数据校验算比例用 `/`。

### 【易错点】

| 代码 | 结果 | 解读 |
|------|------|------|
| `5 / 2` | `2.5` | float，不是 `2` |
| `5 // 2` | `2` | 不是四舍五入，是向下取整 |
| `-5 // 2` | `-3` | 向下取整（更小）：`-2.5 → -3` |
| `5 / 0` | `ZeroDivisionError` | `/` `%` `//` 除数为 0 都报错 |

## 三、赋值运算符

### 【课程原话/定义】

> 赋值运算符将右侧数据保存到左侧变量中。复合赋值运算符（`+=` `-=` 等）是算术运算+赋值的组合。

### 【为什么？】

`a = a + 1` 这种"自操作"模式太常见了——计数器、累加、步进——于是 Python 提供了 `a += 1` 的简写。但注意：**复合赋值不是简单的展开**——`n *= 3 + 4` 展开后是 `n = n * (3 + 4)` 而非 `n = n * 3 + 4`。

### 【必须掌握】

| 运算符   | 等价于          | 测试中的用途               |
| ----- | ------------ | -------------------- |
| `=`   | 赋值           | 基础                   |
| `+=`  | `a = a + x`  | 计数器累加（`passed += 1`） |
| `-=`  | `a = a - x`  | 倒计时、剩余重试次数           |
| `*=`  | `a = a * x`  | 倍数计算                 |
| `/=`  | `a = a / x`  | 比例调整                 |
| `//=` | `a = a // x` | 整数步进                 |
| `%=`  | `a = a % x`  | 循环索引                 |
| `**=` | `a = a ** x` | 指数增长                 |

### 【企业场景】

> 跑完一轮自动化，统计结果：`passed = 0; failed = 0`，每个用例结束后 `passed += 1` 或 `failed += 1`。最后打印 `print(f"通过率：{passed}/{passed+failed}")`。这就是赋值运算符最朴素的用途。

### 【面试考察】

> "`a += b` 和 `a = a + b` 完全等价吗？"

> 参考回答：对不可变类型（int、str）行为一样；对可变类型（list），`+=` 是原地修改（调用 `__iadd__`），`a = a + b` 会创建新对象——`id` 不同。另外 `n *= 3 + 4` 不能简单展开为 `n = n * 3 + 4`。

### 【易错点】

| 代码                           | 结果        | 为什么                         |
| ---------------------------- | --------- | --------------------------- |
| `n = 2; n *= 3 + 4`          | `14`      | 先算右边 `3+4=7`，再 `n = 2*7`    |
| `n = 2; n = n * 3 + 4`       | `10`      | 不是等价展开！正确展开：`n = n * (3+4)` |
| `a = [1,2]; b = a; a += [3]` | a 和 b 都变了 | `+=` 对 list 是原地修改           |

## 四、逻辑运算符

### 【课程原话/定义】

> 逻辑运算符用于组合多个关系条件，运算结果为布尔值。包含 `and`（与）、`or`（或）、`not`（非）。

### 【为什么？】

测试断言很少是单一条件。你需要判断"状态码=200 **并且** 返回体包含token **并且** token不是空字符串"——三个条件同时成立。逻辑运算符就是把"多个小判断"组合成"一个综合判断"的胶水。

### 【必须掌握】

| 运算符 | 真值表 | 一句话 |
|--------|--------|--------|
| `x and y` | 两个都真→真 | "并且"——一个假全盘假 |
| `x or y` | 至少一个真→真 | "或者"——一个真全盘真 |
| `not x` | 真→假，假→真 | 取反 |

### 【短路特性（重点）】

#### 【课程原话/定义】

> 如果自左向右计算已经能确定整个表达式的结果，后面的表达式不再计算。

#### 【为什么？】

短路不是 bug，是 Python 的性能优化 + 安全机制。`False and 1/0` 不会报除零错误——因为 Python 看到 `False` 就确定结果了，根本不执行 `1/0`。利用短路可以写出优雅的"安全取值"模式：`result = data and data.get("key")`——data 为空时不会调用 `.get()`。

#### 【必须掌握】

| 表达式 | 结果 | 是否短路 | 原因 |
|--------|------|----------|------|
| `False and 1/0` | `False` | ✅ 短路 | False 已确定 and 结果 |
| `True or 1/0` | `True` | ✅ 短路 | True 已确定 or 结果 |
| `True and print("hi")` | 执行 print | ❌ 不短路 | True 不能确定，继续算右边 |

#### 【企业场景】

> 你写测试断言：`assert response and response.status_code == 200`——如果 `response` 是 `None`（接口挂了），短路机制让你不会尝试访问 `None.status_code`（那样会抛 AttributeError）。这是防御性编程的好习惯。

#### 【面试考察】

> "解释 Python 逻辑运算符的短路特性，你测试中怎么利用它？"

> 参考回答：`and` 左边为假时右边不执行，`or` 左边为真时右边不执行。测试中用于安全取值——先判空再访问属性/方法，避免 `NoneType` 异常。这是 Python 惯用法，面试官期待的工程直觉。

#### 【易错点】

| 误区                          | 正解                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------- |
| 以为 `and`/`or` 返回 True/False | Python 的 `and`/`or` 返回的是**参与运算的对象本身**（如 `0 and 3` → `0`，`"a" or "b"` → `"a"`），不一定是布尔值 |
| `and`/`or` 和 `&`/`\|` 混用    | `and`/`or` 是逻辑运算符（短路）；`&`/`\|` 是位运算符（不短路、两边都执行）                                       |

### 【我的理解】

>print和return区别 
>print: - 输出内容 - 返回None - 用于调试查看 
>return: - 返回数据 - 自动化测试中用于传递结果 测试场景: 
>login()应该return True/False 不能只print("登录成功")

## 五、运算符优先级

### 【课程原话/定义】

> 不同的运算符具有不同的优先级别，决定表达式中运算的执行顺序。

### 【为什么？】

`2 + 3 * 4` 是 `14` 还是 `20`？如果没有优先级规则，每种写法都得加括号，代码会变得臃肿。优先级是"不用写括号时的默认约定"——但你记不住所有优先级时，**加括号永远是最安全的做法**。

### 【必须掌握】

优先级从高到低（记住核心即可）：

```
() 括号                  ← 最高
** 幂
* / // %                 ← 算术
+ -
< <= > >= == != in is    ← 比较
not                      ← 逻辑非
and                      ← 逻辑与
or                       ← 逻辑或
= += -= ...              ← 赋值（最低）
```

### 【企业场景】

> 写测试时，`assert a == b and c == d` 没问题（比较优先级高于 and）。但 `assert a == b or c == d and e == f` 就容易迷惑——`and` 优先级高于 `or`，实际是 `a == b or (c == d and e == f)`。不确定时加括号：`assert (a == b) or (c == d and e == f)`，意图明确，不会坑自己。

### 【面试考察】

> "`print(2 + 3 * 4)` 输出多少？如果想让结果是 20 怎么写？"

> 参考回答：`14`（先乘后加）。要得 20：`print((2+3)*4)`。面试官考的不是记忆力，是"不确定时你会不会主动加括号"的工程习惯。

### 【易错点】

| 表达式                           | 你以为             | 实际                              | 原因              |
| ----------------------------- | --------------- | ------------------------------- | --------------- |
| `2 + 3 * 4`                   | 20              | 14                              | `*` 优先于 `+`     |
| `not a and b`                 | `not (a and b)` | `(not a) and b`                 | `not` 优先于 `and` |
| `a == b or c == d and e == f` | 从左到右            | `a == b or (c == d and e == f)` | `and` 优先于 `or`  |
| `x = y = z = 1`               | 从左到右赋值          | 从右到左：`z=1, y=z, x=y`            | 赋值是右结合          |
