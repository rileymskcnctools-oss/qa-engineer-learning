## 一、函数设计思想：高内聚低耦合

### 知识点 1：高内聚

【课程原话/定义】
高内聚指函数内部的代码逻辑和功能彼此相关，只完成一个明确的任务，内部各部分密切配合。

【为什么？】
高内聚不是让你把函数写短，而是让你把函数写"专一"。如果一个函数既读文件、又算统计、又画图表，它的内聚性就低——因为你改"怎么画图表"时可能不小心破坏了"怎么算统计"。

判断一个函数是否高内聚，问自己一个问题：**能不能用一句话描述这个函数做什么？** 如果能，通常是高内聚的。如果需要"并且"来连接，说明该拆了。

【必须掌握】
- 一个函数只做一件事
- 判断标准：函数名能否准确描述全部功能
- 高内聚 = 容易测试、容易修改、不容易出 bug

【企业场景】
你在写测试框架时，把"登录"拆成两个函数而不是写在一个函数里：
```python
# 高内聚：两个函数各干一件事
def get_login_token(username, password):
    """只负责获取 token"""
    resp = requests.post("/api/login", json={"user": username, "pwd": password})
    return resp.json()["token"]

def call_api_with_auth(token, endpoint, data):
    """只负责带 token 发请求"""
    headers = {"Authorization": f"Bearer {token}"}
    return requests.post(endpoint, json=data, headers=headers)
```
如果"获取 token"的逻辑变了，你只改 `get_login_token`，`call_api_with_auth` 完全不受影响。

【面试考察】
面试官："什么叫高内聚？怎么检查自己的代码是否高内聚？"

参考回答框架：
1. 高内聚 = 一个函数只做一件事，内部代码紧密相关
2. 检查方法：能否用一句话描述函数功能，不需要"并且"
3. 好处：易测试、易修改、不容易牵一发动全身

【易错点】

| 常见错误           | 错误原因          | 正确做法                 |
| -------------- | ------------- | -------------------- |
| 一个函数干 N 件事     | 图省事，把流程全塞一起   | 拆成独立函数，每个函数名能说明其职责   |
| 为了"高内聚"把函数拆得太碎 | 过度拆分，每个函数只有一行 | 平衡：一个合理的"原子操作"就是一个函数 |

### 知识点 2：低耦合

【课程原话/定义】
低耦合指函数之间依赖关系弱，相对独立。通过参数传递和返回值进行数据交互，而不是共享全局变量或直接修改其他函数的内部数据。

【为什么？】
耦合 = 函数 A 改了，函数 B 会不会坏。耦合度高的时候，改一个函数像拆炸弹——你不知道会炸到谁。

全局变量是耦合的元凶。因为任何一个函数都能读写全局变量，出问题时你根本不知道是谁改的。参数传递 + 返回值是最安全的通信方式——数据流是可追踪的。

【必须掌握】
- 减少全局变量的使用
- 函数间通过参数和返回值通信
- 低耦合 = 改 A 不影响 B、C、D

【企业场景】
对比两种测试函数的设计：
```python
# 高耦合：依赖全局变量
current_user = None

def login():
    global current_user
    current_user = "admin"

def check_permission():
    global current_user
    if current_user != "admin":
        raise PermissionError()

# 低耦合：参数传递
def login(username):
    return username

def check_permission(user):
    if user != "admin":
        raise PermissionError()

user = login("admin")
check_permission(user)
```
低耦合版本：`login` 和 `check_permission` 互不依赖，可以独立测试。高耦合版本：必须先调 login 再调 check_permission，测试时两个必须一起测。

【面试考察】
面试官："全局变量有什么问题？怎么降低函数间的耦合？"

参考回答框架：
1. 全局变量让函数间隐式依赖，改了值不知道影响谁
2. 降低耦合：用参数传数据，用 return 返回结果
3. 测试优势：低耦合函数可以单独 mock 和断言

【易错点】

| 常见错误            | 错误原因        | 正确做法               |
| --------------- | ----------- | ------------------ |
| 用 global 到处传状态  | 图方便         | 用参数和返回值            |
| 函数内直接修改传入的列表/字典 | 理解错"低耦合"的含义 | 需要修改时明确文档说明，或返回新对象 |

## 二、函数返回值

### 知识点 3：return 的作用

【课程原话/定义】
Python 用 `return` 将函数处理结果返回给调用者。`return` 同时具有**结束函数执行**的作用——执行到 return 时函数立即退出，返回到调用处继续执行。

真正完整的函数应通过 return 返回结果，而不是 `print()` 输出。

```python
# return 结束函数
def show():
    print("循环前输出内容")
    for i in range(10):
        print(i)
        if i == 2:
            return          # 函数在此立即结束
    print("循环后输出内容")   # 永远不会执行

show()
```

【为什么？】
return 和 print 的区别是"给机器用"和"给人看"的区别。print 把结果丢到屏幕上就没了，调用者拿不到。return 把结果交给调用者，调用者可以继续处理。

这是一个初学 Python 最容易养成的坏习惯——用 print 替代 return。测试中这是致命的：你不能对 print 的结果做断言。

【必须掌握】
- return 返回结果给调用者
- return 立即结束函数，后面的代码不执行
- 不要用 print 替代 return
- 没有 return 的函数默认返回 None

【企业场景】
你在写一个数据校验函数，发现数据不合法立即 return 错误信息：
```python
def validate_user(user):
    if not user.get("name"):
        return False, "姓名不能为空"   # 提前 return，后面代码不跑
    if not user.get("age"):
        return False, "年龄不能为空"
    return True, "校验通过"

ok, msg = validate_user({"name": "Tom"})
```
提前 return 避免了深层嵌套 if-else，这是一种"卫语句"模式。

【面试考察】
面试官："return 除了返回值还有什么作用？"

参考回答框架：
1. return 立即结束函数执行
2. 常用于"守卫条件"——校验不通过提前退出
3. 避免深层嵌套 if-else

【易错点】

| 常见错误              | 错误原因                | 正确做法                        |
| ----------------- | ------------------- | --------------------------- |
| 用 print 替代 return | 把输出当返回              | 函数返回结果用 return，展示结果才用 print |
| return 后面还写代码     | 那些代码永远不会执行          | IDE 会标灰提醒                   |
| 忘记 return 就用返回值   | 没 return 的函数返回 None | 检查函数是否有 return 语句           |

### 知识点 4：多个返回值 = 组包

【课程原话/定义】
一个函数只能返回一个值。`return a, b` 看起来返回了两个值，实际上 Python 自动把 `a, b` **组包**成一个元组返回。

```python
def getTwoNum():
    a = int(input("请输入第一个数字："))
    b = int(input("请输入第二个数字："))
    return a, b        # 自动组包为 (a, b) 元组

result = getTwoNum()
print(result)          # (3, 5)  一个元组
print(type(result))    # <class 'tuple'>
```

【为什么？】
Python 不能破坏"一个函数一个返回值"的语义，但又想让多返回值写起来方便。于是它做了个折中：语法上允许你写 `return a, b`，底层自动组包成元组。

接收时你既可以：
- `result = func()` → result 是元组
- `m, n = func()` → 自动解包到两个变量

这不是"返回了两个值"，是"返回一个元组，你解包了它"。面试官很爱问这个。

【必须掌握】
- `return a, b` 实际返回 1 个元组 `(a, b)`
- 接收时 `m, n = func()` 是解包操作
- 用 `type()` 验证返回值类型

【企业场景】
测试函数返回执行结果和详细信息：
```python
def run_test_case(case_id):
    # ... 执行测试 ...
    return passed, error_msg, duration

# 解包接收
ok, err, time_cost = run_test_case("TC001")
if not ok:
    log(f"失败: {err}, 耗时: {time_cost}s")
```

【面试考察】
面试官："`return a, b` 返回了几个值？"

参考回答框架：
1. 返回了 1 个值：元组 `(a, b)`
2. Python 做了自动组包
3. 接收时 `x, y = func()` 是自动解包
4. 可以验证：`type(func())` 是 tuple

【易错点】

| 常见错误           | 错误原因    | 正确做法                             |
| -------------- | ------- | -------------------------------- |
| 认为 return 了多个值 | 没理解组包机制 | 记：底层始终返回 1 个值                    |
| 解包时变量数不等于元组元素数 | 忘了数元素个数 | `len(result)` 检查，或用 `*rest` 接收剩余 |

### 知识点 5：组包与解包

【课程原话/定义】
- **组包**：多个值赋给一个变量时，Python 自动将多个值打包成元组。
- **解包**：一个容器（元组/列表等）赋给多个变量时，Python 将容器中元素依次取出赋值。

```python
# 组包
nums = 1, 2, 3, 4, 5
print(nums)       # (1, 2, 3, 4, 5)
print(type(nums)) # <class 'tuple'>

# 解包
a, b, c, d, e = nums
print(a, b, c, d, e)  # 1 2 3 4 5
```

【为什么？】
组包和解包是 Python 简洁性的核心体现。没有组包你就得写 `nums = (1, 2, 3, 4, 5)`，没有解包你就得写 `a=nums[0]; b=nums[1]...`。

这两个特性在测试中无处不在：unittest 的参数化测试、Pytest 的 fixture 传参、返回多个测试结果，背后都是组包解包。

【必须掌握】
- 组包：`a = 1, 2, 3` → a 是元组
- 解包：`x, y, z = (1, 2, 3)` → x=1, y=2, z=3
- 解包的元素数必须和变量数一致
- Python 3 支持 `a, *b, c = (1, 2, 3, 4, 5)` → a=1, c=5, b=[2,3,4]

【企业场景】
交换两个变量的值，Python 一行搞定：
```python
a, b = b, a    # 右边组包为 (b, a)，左边解包给 a, b
```
这比传统语言的临时变量法简洁得多。

从函数返回的测试结果中提取数据：
```python
test_id, *metrics, status = run_test()
# test_id = "TC001"
# status = "PASS"
# metrics = [response_time, memory_used, cpu_used]
```

【面试考察】
面试官："`a, b = b, a` 背后发生了什么？"

参考回答框架：
1. 右边 `b, a` 组包为元组
2. 左边 `a, b` 解包元组
3. 这是 Python 交换变量值的标准写法

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 解包变量和元素数量不匹配 | 忘了数元素个数 | 用 `*middle` 接收可变部分 |
| 以为 `a = 1, 2, 3` 是列表 | 逗号默认组包成元组 | `type(a)` 验证 |

【我的理解】
> （用组包解包实现：不用临时变量交换两个变量的值。然后用 `*` 解包接收不确定数量的中间元素）

### 知识点 6：多个 return 语句

【课程原话/定义】
一个函数中可以有多个 return 语句，在不同条件下返回不同值。但同一时刻只有一个 return 会执行——第一个被执行到的 return 立即结束函数。

```python
def multiReturn():
    return 1    # 函数在此结束
    return 2    # 永远不会执行
    return 3    # 永远不会执行

print(multiReturn())  # 永远输出 1
```

【为什么？】
多个 return 是给不同分支准备不同的出口。这是"卫语句"（Guard Clause）模式——把异常情况先处理掉，return 提前退出，让正常逻辑不被 if-else 层层嵌套包裹。

```python
# 不用卫语句：深层嵌套
def process(data):
    if data:
        if data.is_valid():
            if data.has_permission():
                return data.result()

# 用卫语句：扁平清晰
def process(data):
    if not data:
        return None
    if not data.is_valid():
        return None
    if not data.has_permission():
        return None
    return data.result()
```

【必须掌握】
- 多个 return 合法，但只有第一个被执行到的生效
- 常用于卫语句模式：先 return 掉异常情况
- 不是 return 越多越好——太多 return 也可能降低可读性

【企业场景】
测试用例的断言函数，不同失败原因返回不同错误：
```python
def check_response(resp):
    if resp.status_code != 200:
        return False, f"状态码错误: {resp.status_code}"
    if "data" not in resp.json():
        return False, "响应缺少 data 字段"
    if len(resp.json()["data"]) == 0:
        return False, "data 为空"
    return True, "通过"
```

【面试考察】
面试官："一个函数里有 5 个 return，会返回哪个？"

参考回答框架：
1. 返回第一个被执行到的 return
2. 后面的 return 不会执行
3. 这是卫语句模式，用于提前处理异常情况

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为所有 return 都会执行 | 不理解 return 终止函数的机制 | 记：return = 函数结束 |
| 在 if-else 里漏了某个分支的 return | 有些路径返回 None | 确保所有分支都有 return 或最后的兜底 return |

【我的理解】
> （写一个自己的多 return 函数，用"卫语句"风格：先检查三个异常情况并 return，最后 return 正常结果）

## 三、参数传递

### 知识点 7：实参与形参

【课程原话/定义】
- **形式参数（形参）**：定义函数时括号里的变量名，是占位符。
- **实际参数（实参）**：调用函数时括号里传入的具体值。
- 调用时，实参会依次传递给形参。

```python
# name, age, gender 为形参
def info(name, age, gender):
    print(f"我叫{name}, 年龄{age}岁，性别{gender}")

# "Tom", 22, "男" 为实参
info("Tom", 22, "男")
```

【为什么？】
形参和实参的区分解释了"为什么函数能复用"：形参是"规则"，实参是"具体数据"。同一个规则（函数体），填入不同数据（实参），得到不同结果。

就像出租车——形参是"出发地"和"目的地"这两个概念，实参是"北京西站"和"天安门"这两个具体地址。

【必须掌握】
- 形参 = 定义时的变量（占位符）
- 实参 = 调用时的值
- 实参按顺序传递给形参

### 知识点 8：位置参数

【课程原话/定义】
位置参数（必备参数）要求调用时**数量**和**位置**必须与定义时一致。数量不对抛 TypeError，位置不对可能抛异常或结果与预期不符。

```python
def printMsg(n, msg):
    for i in range(n):
        print(f'第{i+1}次输出{msg}')

printMsg(5, "Hogwarts")         # 正确
printMsg("Hogwarts", 5)         # 错误：字符串传给了 n，int 传给了 msg
```

【为什么？】
位置参数是函数调用的"默认协议"——调用者不需要记参数名，只需要按顺序传。简单直观，但脆弱：一旦记错顺序，bug 悄悄产生且不报错（如果类型碰巧兼容）。

【必须掌握】
- 实参数量和位置必须与形参一致
- 数量不对 → TypeError
- 位置不对 → 可能不报错但逻辑错误（更难排查）

【企业场景】
你调测试框架的断言函数，位置参数居多：
```python
assertEqual(actual, expected, "登录失败时应返回401")
#                位置1     位置2         位置3
```
记错位置 → 断言信息出现在预期值参数里 → 测试结果完全错乱。

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 把顺序传反 | 靠记忆不靠参数名 | 参数超过 2 个时用关键字参数 |
| 忘了某个参数 | 定义时 3 个形参，调用时只传 2 个 | 检查函数签名 |

### 知识点 9：关键字参数

【课程原话/定义】
关键字参数通过形参名指定传入的值，不再依赖位置。避免记忆参数顺序的麻烦。

```python
def printMsg(n, msg):
    for i in range(n):
        print(f'第{i+1}次输出{msg}')

printMsg(n=5, msg="Hogwarts")        # 关键字参数
printMsg(msg="Hogwarts", n=5)        # 顺序无所谓
```

【为什么？】
关键字参数解决了位置参数的"魔法数字"问题。当你看到 `create_user("Tom", 25, "Beijing", True, None)` 时，`True` 和 `None` 各是什么意思？只能去翻函数定义。而 `create_user(name="Tom", age=25, city="Beijing", is_vip=True, avatar=None)` 一眼就懂。

**【关键规则】位置参数必须在关键字参数之前**。`func(1, b=2)` 对，`func(a=1, 2)` 错。原因很简单：Python 需要先按位置把未命名的参数对号入座，才能处理关键字参数。

【必须掌握】
- `func(参数名=值)` 不依赖位置
- 位置参数必须写在关键字参数前面
- 参数超过 2 个时推荐用关键字参数提高可读性
- 调用第三方库函数时，关键字参数是自文档化的最佳实践

【企业场景】
调用 Selenium 的元素定位函数：
```python
# 位置参数：不清不楚
driver.find_element("id", "login-btn")

# 关键字参数：一目了然
driver.find_element(by="id", value="login-btn")
```

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| `func(a=1, 2)` | 位置参数不能在关键字参数后面 | `func(2, a=1)` 或 `func(a=1, b=2)` |
| 关键字参数名写错 | 拼写错误 | 检查函数定义中的形参名 |

【我的理解】
> （写一个参数较多的函数调用，演示：位置参数和关键字参数可以混用，但位置参数必须在前面）

### 知识点 10：默认值参数

【课程原话/定义】
定义函数时，形参可以赋默认值。调用时如果传了该参数就用传入值，没传就用默认值。

**默认值参数必须放在所有非默认值参数的后面**，否则语法错误。

```python
def my_power(m, n=2):
    return m ** n

print(my_power(2, 3))   # 8, n=3
print(my_power(2))      # 4, n 用默认值 2
```

【为什么？】
默认值参数的设计出发点是"让常用场景少写参数"。你写 `sorted(data)` 时不需要每次都指定 `reverse=False`——因为默认就是 False。

但默认值参数有一个著名的陷阱：**默认值在函数定义时只计算一次**。如果默认值是可变对象（列表、字典），每次调用可能共享同一个对象：

```python
# 陷阱！
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))  # [1]
print(add_item(2))  # [1, 2]  ← 不是 [2]！lst 是同一个列表
```

【必须掌握】
- 默认值参数必须在非默认值参数之后
- 默认值在函数定义时计算一次（不是每次调用重新计算）
- 默认值不要用可变对象（用 None + 函数内判断替代）
- 调用时可以用关键字参数覆盖默认值

【企业场景】
封装一个 HTTP 请求函数，给常用参数设默认值：
```python
def api_get(endpoint, timeout=10, retries=3, headers=None):
    if headers is None:        # 避免可变默认值陷阱
        headers = {"Content-Type": "application/json"}
    # ...
```
`timeout` 和 `retries` 有合理默认值，省去每次调用都写。

【面试考察】
面试官："`def f(lst=[])` 有什么问题？为什么？"

参考回答框架：
1. 默认值在定义时计算一次，lst 是同一个列表对象
2. 多次调用会累积数据
3. 正确做法：`def f(lst=None): if lst is None: lst = []`

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 默认值参数放在非默认值参数前面 | Python 语法不允许 | 非默认值在前，默认值在后 |
| 默认值用 `[]` 或 `{}` | 可变默认值被共享 | 用 None + 函数内初始化 |
| 以为默认值每次调用重新计算 | 理解错计算时机 | 默认值只在 def 时算一次 |

【我的理解】
> （写代码验证：定义一个默认值为空列表的函数，多次调用，观察列表是否累积。然后用 None 改写正确版本）

### 知识点 11：可变参数 `*args`

【课程原话/定义】
`*args` 接收任意数量的**位置参数**，将它们打包成一个**元组**。用于参数个数不确定的场景。

```python
def my_sum(*args):
    print(args)       # (1, 2, 3)  元组
    print(type(args)) # <class 'tuple'>
    s = 0
    for i in args:
        s += i
    print(s)

my_sum(1, 2, 3)       # 传 3 个
my_sum(1, 2, 3, 4, 5) # 传 5 个
```

【为什么？】
`*args` 解决了"不知道调用者会传几个参数"的问题。`len()` 只能测一个对象，但 `print()` 能接收任意多个参数——`print(a, b, c, d)` 全合法，底层就是 `*args`。

命名 `args` 是约定（arguments 的缩写），实际 `*任何名字` 都可以，但社区统一用 `*args`，方便别人一眼看懂。

【必须掌握】
- `*args` 接收任意数量的位置参数，存成元组
- 名字不一定是 args，但约定俗成
- `*args` 后面的参数只能用关键字方式传递
- `*` 在函数调用时可以做解包：`func(*[1, 2, 3])` 展开为位置参数

【企业场景】
写一个测试日志函数，接收不定数量的消息：
```python
def test_log(*messages):
    for msg in messages:
        print(f"[TEST LOG] {msg}")

test_log("开始测试", "初始化数据库", "清理缓存")
# [TEST LOG] 开始测试
# [TEST LOG] 初始化数据库
# [TEST LOG] 清理缓存
```

【面试考察】
面试官："`*args` 是什么？为什么叫 args？存成什么数据结构？"

参考回答框架：
1. `*args` 接收任意数量的位置参数
2. args 是约定名，可换成其他名字
3. 存成元组（tuple）
4. 常见用途：不确定参数个数时（如 print、sum 等）

【易错点】

| 常见错误              | 错误原因                           | 正确做法                   |
| ----------------- | ------------------------------ | ---------------------- |
| 以为 `*args` 是列表    | `*args` 内部是元组                  | `type(args)` 验证        |
| 把 `*args` 当关键字参数用 | `*args` 只接收位置参数                | 关键字参数用 `**kwargs`      |
| `*args` 放错位置      | 必须放在位置参数之后、默认值参数/`**kwargs` 之前 | `def f(a, *args, b=1)` |

【我的理解】
> （写一个 `*args` 函数，传入不同数量的参数，验证 args 的类型和内容）

### 知识点 12：可变关键字参数 `**kwargs`

【课程原话/定义】
`**kwargs` 接收任意数量的**关键字参数**，打包成一个**字典**。

```python
def print_info(**kwargs):
    print(kwargs)       # {'Tom': 18, 'Jim': 20}
    print(type(kwargs)) # <class 'dict'>
    for k, v in kwargs.items():
        print(k, v)

print_info(Tom=18, Jim=20, Lily=12)
print_info(name="tom", age=22, gender="male", address="BeiJing")
```

【为什么？】
`**kwargs` 和 `*args` 是搭档——一个收位置参数，一个收关键字参数。两者组合 `def f(*args, **kwargs)` 能接收"任何形式的参数"，这是设计通用装饰器、代理函数、调用转发的基础。

`kwargs` 是 keyword arguments 的缩写。为什么存成字典？因为关键字参数天然是 key-value 对，字典是最自然的容器。

【必须掌握】
- `**kwargs` 接收任意数量的关键字参数，存成字典
- 名字约定为 kwargs
- `**kwargs` 只能放在参数列表最后
- `**` 在函数调用时可以做字典解包：`func(**{"a": 1, "b": 2})`

【企业场景】
封装一个灵活的测试配置函数：
```python
def run_test_with_config(test_name, **config):
    timeout = config.get("timeout", 30)
    retries = config.get("retries", 3)
    env = config.get("env", "staging")
    print(f"运行 {test_name} | 超时={timeout}s | 重试={retries} | 环境={env}")

run_test_with_config("登录测试", timeout=60, env="production")
# 运行 登录测试 | 超时=60s | 重试=3 | 环境=production
```

【面试考察】
面试官："`**kwargs` 是什么？和 `*args` 有什么区别？"

参考回答框架：
1. `*args` 接收任意数量的位置参数 → 元组
2. `**kwargs` 接收任意数量的关键字参数 → 字典
3. `*args` 写前面，`**kwargs` 写最后
4. 组合 `def f(*args, **kwargs)` 能接收任何形式的参数

【易错点】

| 常见错误                     | 错误原因          | 正确做法                             |
| ------------------------ | ------------- | -------------------------------- |
| `**kwargs` 放在 `*args` 前面 | 顺序错，语法错误      | `*args` 必须在 `**kwargs` 之前        |
| 用位置参数方式传 `**kwargs`      | `**` 只接收关键字参数 | `func(a=1, b=2)` 不是 `func(1, 2)` |
| 把 `**kwargs` 当列表遍历       | 它是字典          | 用 `.items()` 或 `.keys()`         |

【我的理解】
> （写一个 `**kwargs` 函数，接收并打印任意关键字参数，验证 kwargs 的类型是 dict）

### 知识点 13：混合参数的正确顺序

【课程原话/定义】
当函数同时包含多种参数类型时，必须遵守以下定义顺序：

```
def func(位置参数, *args, 默认值参数, **kwargs):
    pass
```

简化形式（接收任意参数）：
```python
def func(*args, **kwargs):
    pass
```

```python
def info(name1, name2, *args, age1=18, age2=21, **kwargs):
    print("name1:", name1)
    print("name2:", name2)
    print("args:", args)
    print("age1:", age1)
    print("age2:", age2)
    print("kwargs:", kwargs)

info("Alice", "Bob", "Charlie", "Dave", age2=30, occupation="Engineer", city="New York")
# name1=Alice, name2=Bob, args=('Charlie','Dave'), age1=18(默认), age2=30(传入), kwargs={'occupation':'Engineer','city':'New York'}
```

【为什么？】
这个顺序不是随意规定的——它由 Python 的参数解析逻辑决定：
1. 先匹配位置参数（按顺序填）
2. 多余的位置参数进 `*args`
3. 关键字参数匹配到对应的形参名（包括有默认值的）
4. 多余的关键字参数进 `**kwargs`

如果 `*args` 放在默认值参数后面，Python 就没法区分"这个位置参数是要进 *args 还是给默认值参数"。

【必须掌握】
- 顺序：位置 → `*args` → 默认值 → `**kwargs`
- 调用时：位置参数必须在关键字参数前面
- `func(*args, **kwargs)` 是通用参数签名
- 理解每一类参数"捕获"了什么

【企业场景】
设计一个通用测试用例执行函数：
```python
def execute_test(test_id, *prerequisites, timeout=30, retries=3, **options):
    # test_id: 必传
    # prerequisites: 前置依赖项
    # timeout/retries: 有默认值的配置
    # options: 其他可选配置
    for dep in prerequisites:
        setup_dependency(dep)
    run(test_id, timeout=timeout, retries=retries, **options)
```

【面试考察】
面试官："`def f(a, *args, b=1, **kwargs)` 中，调用 `f(1, 2, 3, b=4, c=5)` 各参数分别是什么？"

参考回答框架：
1. a=1（位置参数）
2. args=(2, 3)（多余位置参数入队）
3. b=4（关键字参数覆盖默认值）
4. kwargs={'c': 5}（多余关键字参数入队）

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| `def f(*args, a)` | 位置参数不能放在 `*args` 后面 | `def f(a, *args)` |
| `def f(**kwargs, a)` | `**kwargs` 必须在最后 | `def f(a, **kwargs)` |
| `def f(a, *args, b, **kwargs)` 但 b 没设默认值 | `*args` 后面的参数必须用关键字传 | 给 b 设默认值或放 `*args` 前面 |

【我的理解】
