## 第 2 段（60 分钟）动手：最小可用脚本（每日总结任务 11）

照抄即可：

1. **确认 JDK**：终端执行 `java -version`（≥ Java 8，推荐 11/17）
2. **装 JMeter**：官网下 `apache-jmeter-5.6.x.zip` → 解压到 `D:\apache-jmeter-5.6.3`（你的大文件盘）→ 把 `bin` 目录加进 PATH → **新开一个终端**执行 `jmeter -v`，能出版本号即成功
3. **起一个被压服务**：任意目录执行 `python -m http.server 8000`（本地就有了一个被测服务）
4. **建脚本**：测试计划 → 添加 → 线程（用户）→ 线程组（5 线程 / Ramp-up 5 / 循环 2）→ 右键线程组：添加 → 取样器 → HTTP 请求（服务器 `127.0.0.1`、端口 `8000`、路径 `/`）→ 添加 → 监听器 → **察看结果树** + **聚合报告**
5. **运行**（工具栏三角按钮）→ 结果树里确认响应码 200 → 聚合报告里看这 4 列：`Samples`、`Average`、`90% Line`、`Error %`、`Throughput`

**交付物**（明天发我）：
- 脚本结构截图（能看到 测试计划 → 线程组 → HTTP 请求 → 两个监听器）
- 聚合报告截图
- 三个数字：Samples ／ Average ／ Throughput

## 第 3 段（20 分钟）自测 + 卡点排查

**自测 3 问：**
1. 我这条脚本里，哪些元件属于"八大组件"？它们分别属于哪一类？
2. 聚合报告里 `Throughput` 的单位是什么？它和 RT 一起看你得出了什么？
3. 察看结果树 和 聚合报告 的分工分别是什么？（提示：一个看"单条细节"，一个看"整体统计"）

**常见卡点（先看这里，别卡 20 分钟）：**

| 现象 | 排查方向 |
|------|----------|
| `jmeter -v` 提示找不到命令 | PATH 没生效 → 关掉终端重开；或用绝对路径 `D:\apache-jmeter-5.6.3\bin\jmeter.bat` |
| 双击 jmeter.bat 闪退 | JDK 未装 / JAVA_HOME 未配 / 版本过高（JMeter 5.6 配 Java 8~17 最稳） |
| 界面中文乱码 | 改 `bin/jmeter.properties` 的 `sampleresult.default.encoding=UTF-8`，或系统字体缺失（改语言为英文最省事） |
| 端口 8000 被占用 | 换端口 `python -m http.server 8888`；HTTP 请求里的端口同步改 |
| 结果树全是 404 | 请求路径不对（`http.server` 的根目录里没有对应文件）→ 路径填 `/` |
| Ramp-up 理解偏差 | 记忆点：**第一线程立即启动，最后一个线程在第 (线程数/Ramp-up × (线程数-1)) 秒附近启动** |
