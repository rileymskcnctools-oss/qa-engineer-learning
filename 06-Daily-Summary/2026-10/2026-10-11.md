### 任务 2：验证 UDV 的一次性求值（30 分钟）
在上一个脚本里做两个对照实验：① 在 UDV 里写一个 `${__Random(1,100)}`，跑 3 个线程 × 3 轮，看 Debug Sampler 里这个值是否**始终相同**；② 把同样的随机值改成 Random Variable 元件 / 请求参数里直接写 `${__Random(1,100)}`，再看是否每轮都变。目的：用实验证明"求值时机决定用途"，而不是背结论。（Ch32 知识点2）

### 任务 3：跨线程传参的两种写法对照（45 分钟）
① 错误写法：在 setUp 线程组登录并把 token 存成**变量**，主线程组的请求头写 `${token}` —— 观察 Debug Sampler 里是否为 `${token}` 字面量；② 正确写法：setUp 里用 `${__setProperty(token,${token})}` 写属性，主线程组写 `token: ${__P(token)}` —— 观察是否正常取到。目的：亲手复现"静默失败"，这是本节最值钱的一次实验。（Ch32 知识点4）

## 面试可能怎么问

Q1：JMeter 里变量和属性有什么区别？多线程之间怎么传值？
→ 参照 Ch32 知识点4：官方定义（变量线程私有、属性全 JVM 共享且必须用 `${__P()}` 引用）→ 因此"变量跨线程传参"不成立（课程原文此处写错）→ 跨线程正道是 `${__setProperty(名,值)}` 写 + `${__P(名)}` 读 → 典型用法"setUp 登录一次写属性、主线程组全员复用" → 加分边界：属性是 JVM 级（可能读到上次运行的旧值）、分布式下要 `-G` 传。

Q2：用户定义的变量（UDV）什么时候生效？能不能在里面用函数？
→ 参照 Ch32 知识点2：配置元件；测试计划开始时**一次性**处理（与摆放位置无关）；结果**复制给每个线程**；不能引用运行期变量；函数只保存**第一次调用**结果（`__Random` 不可用、`__P` 可用）；要做逐轮变化要用 CSV / Random Variable / User Parameters。

Q3：JMeter 里引用一个不存在的变量会怎样？怎么发现？
→ 参照 Ch32 知识点3：**不报错、不打日志、原样输出 `${foo}`**（官方原文）→ 症状是"HTTP 200 但业务全错" → 发现手段：Debug Sampler 看值、View Results Tree 看请求里是否替换、再加断言看业务 → 三者是"值 / 引用 / 业务"三层不同的检查。

## 企业真实场景

> 这个知识点在企业里什么时候会用到？

- **多环境跑同一套脚本**：dev / test / pre / prod 的域名、账号、商户号全部变量化，脚本只有一份，用 `${__P(host,localhost)}` + 命令行 `-Jhost=pre.example.com` 切换环境——这是"能交付给同事和 CI 用"的前提。
- **压测数据不撞车**：500 个虚拟用户要有各自的账号 / 商品 / 订单号，靠 CSV 账号池 + `${__threadNum}` / `${__counter}` 造唯一值；用 UDV 写"随机"值是典型事故（所有线程拿到同一个数）。
- **防爆破 / 省开销的登录**：登录接口有限制时，setUp 线程组只登录 1 次 → `${__setProperty(token,...)}` → 主线程组 `${__P(token)}`，一次登录全员复用。
- **脚本交付自检**：小样本（1 线程 1 轮）调通 → Debug Sampler 看值 → View Results Tree 看请求 → 加断言 → **删掉调试元件**再放大并发。这条流程是"压测数据可信"的最低标准。

## 收获

1. **变量与属性是本模块的分水岭**：变量是**线程私有**的（UDV 也只是"测试开始时把变量集复制给每个线程"），属性才是**全 JVM 共享**的（`${__setProperty()}` 写 / `${__P()}` 读）。课程原文"变量可以跨线程传参"是错的，这是面试最爱追问的点。
2. **求值时机决定用途**：UDV 测试开始一次（不能放 `${__Random}`、不能引用运行期变量）→ CSV 每迭代一行 → 函数 / 随机元件每次调用 → 提取器每次响应后。选型口诀：**"值变不变、什么时候变"**。
3. **引用失败是静默的**：`${未定义变量}` 不报错、原样发出，HTTP 可以照样 200——所以"取到值 / 引用生效 / 业务成功"必须用三种手段分别验证（Debug Sampler / View Results Tree / 断言），且正式压测前要删掉前两个调试元件。
