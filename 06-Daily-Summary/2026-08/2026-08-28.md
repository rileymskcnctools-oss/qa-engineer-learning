## 企业真实场景

1. **夜间构建 flaky 治理**：loading 遮罩导致 `ElementClickInterceptedException`，隐式等待放行 → 显式等待遮罩消失再点，偶发失败归零。
2. **框架基线配置**：`conftest.py` 统一 `implicitly_wait(5)` 兜底 + 关键交互显式等待。
3. **review 新人代码**：满屏 sleep → 算账 + 带改一条用数据说话。
4. **clear() 失效**：number/日期/autocomplete 组件值在内部状态 → Ctrl+A+Delete 或 JS。
5. **定位契约化**：推动研发加 `data-test-id`，改版只改 PO 层一处。
6. **综合实战交付**：Ch10 的搜索用例 = 五要素落地 + driver 生命周期管理 + 断言，是团队自动化验收的"标准模板"。

## 收获

1. **等待三句话**：强制"死等时间"、隐式"全局找元素"、显式"精确等条件"；"元素在 DOM ≠ 可交互"是最高频考点。
2. **两个单位陷阱 + 一个传参陷阱**：`time.sleep` 秒 / `Thread.sleep` 毫秒；`until` 传条件对象不是结果。
3. **控件交互是"基本动作库"**：click/send_keys/clear 走流程，.text/get_attribute 做断言。
4. **定位策略 = 方法 + 规则**：七条选型原则 + 特殊场景（alert/日期/上传），特殊场景共同点是"不在常规 DOM 交互模型里"。
5. **CSS 吃属性、XPath 吃文本**：CSS 不能按文本、不能向上找父级；XPath 补齐这两点。`//li[1]`（每个父下第一个）vs `(//li)[1]`（全局第一个）是 XPath 最大陷阱。
6. **综合实战是检验标准**：Ch10 把产品分析→用例→脚本→前置后置→断言串起来，证明"能写一条完整、可判定、可维护的用例"。
