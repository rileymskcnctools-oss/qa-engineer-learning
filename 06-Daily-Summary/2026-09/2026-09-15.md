## 企业真实场景

1. **前后端并行开发**：前端 mock、后端写接口，接口是两边"对接标准"，你测接口就是验这个契约。（Ch07）
2. **发版回归**：新版本上线前，把接口用例存进 Collection 点 Run，几十条一次跑完看通过率。（Ch09/Ch10）
3. **接口文档不全/过期**：用 Charles 抓包，从真实流量还原接口的真实参数和返回。（Ch08/Ch11）
4. **资金类接口**：订单/支付接口专门测幂等，防用户重复点击扣两次钱。（Ch08）
5. **秒杀/抢购**：压测工具模拟高并发，断言库存不为负、无超卖。（Ch08）
6. **故障演练**：配合开发停掉 Redis/数据库，验证接口能否降级、不雪崩。（Ch08）
7. **多环境切换**：baseURL 放 Environment，切 test/stage 环境，一套用例复用。（Ch09/Ch10）
8. **接口间数据关联**：新增宠物返回的 id 存进 Collection 变量，删除接口 `{{petId}}` 引用，实现增删联动。（Ch10）
9. **移动端接口测试**：手机连 Charles 代理抓 App 真实请求，看 url/参数对不对、返回对不对。（Ch12/Ch13）
10. **传参排错**：前端能过、脚本不能过，抓包对比发现脚本漏了 `X-Client-Type` 头，补上即通。（Ch13）
11. **token 自包含**：把"登录拿 token"放进 Pre-request Script，每次跑测试集自动登录，token 不过期、用例自包含。（Ch14）
12. **数据驱动回归**：搜索接口一个请求 + 断言，CSV 放多组关键词，Run 一次跑出多组用例。（Ch14）

## 收获

1. **接口 = 契约**：后端预定义的函数，约定输入输出；接口测试验的是"通信与数据交换"是否准确可靠。
2. **分层测试金字塔（马丁福勒）**：单元→接口→UI，越往上发现 bug 越晚、成本越高，所以测试重心要下沉到接口层。
3. **接口测试早介入**：需求分析完就能测，不依赖 UI，这是它比 UI 测试更快更便宜的根本原因。
4. **用例设计六维度**：边界值/特殊字符/类型/必填/组合（输入域）+ 排重/幂等 + 并发/分布式 + 故障注入，是接口特有于功能测试的部分。
5. **幂等防重复副作用**：多次执行=一次执行的"副作用"，资金系统必测；实现靠唯一请求号/状态机/唯一索引。
6. **故障注入测健壮性**：故意制造 Redis/DB/接口故障，验证降级、多活、重试，防止线上雪崩。
7. **Postman 四种 body**：form-data（键值对+文件）、urlencoded（纯表单）、raw（JSON 最常用）、binary（纯二进制），必须和 Content-Type 匹配。
8. **断言让测试可回归**：pm.test + status/include/eql/header/below，预期 vs 实际自动化比较，PASS/FAIL 一目了然。
9. **变量作用域 + 优先级**：Data→Environment→Collection→Global→Local，用于参数化（复用值）和关联（接口间传值）。
10. **常见的接口协议 = Ch01**：本次"常见的接口协议"一节与 Ch01-接口协议基础 完全重合，未重复造章。
11. **抓包 = 中间人代理**：流量经过 Charles 才能看/改/重发；抓 HTTPS 必须"装证书 + 开 SSL Proxying"两件套。
12. **改包四件套**：过滤（Focus）、重发（Repeat/Repeat Advanced）、改请求（Compose）、断点（请求/响应断点）——断点改响应 = 轻量 mock。
13. **token 关联是接口自动化核心**：登录拿 token → 存集合变量 → {{token}} 复用；Pre-request Script 让用例自包含、token 不过期。
14. **数据驱动分离逻辑与数据**：一份请求 + 断言，CSV/JSON 喂多组数据，`data.xxx` 引用，覆盖等价类/边界。

## 反思
> Ch07 是接口测试的"世界观"——最容易被当成"背概念"带过，但真正的抓手是"为什么要分层、为什么 UI 测试不够了"。要能把"后端复杂 + 快速迭代 → 传统测试跟不上 → 分层 + 自动化"这条因果链用自己的话讲出来，测试金字塔才不是一张死图。Ch08 是本章最重的一章，幂等（知识点 5）、并发/秒杀（知识点 6）、故障注入（知识点 7）是接口测试区别于功能测试的"特有维度"，面试必问，别只停留在"知道名词"，要能说清"怎么测、为什么测"。Ch09-Ch10 是工具落地，最容易学浅的是只点按钮不写断言——Postman 的价值在"断言 + Collection Run + 变量关联"这三个工程化能力，单个 Send 只是调试。
>
> Ch11-Ch14 是"抓包 + 实战"的完整链，真正的抓手是一条主线：**Ch11 工具（中间人原理）→ Ch12 证书（HTTPS 解密）→ Ch13 抓包实战（过滤/重发/改包/断点）→ Ch14 端到端（har → 数据驱动 → token 关联 → 导出代码）**。Ch12 的"装证书 + 开 SSL Proxying"和"Android6+/iOS10+ 信任"是实操最容易卡住的地方，务必亲手走一遍（任务 7/8）。Ch14 价值最高，务必跑一遍（任务 10）：它把前面所有知识点——抓包、断言、数据驱动、变量、鉴权——串成一条可写进简历的"接口测试实战链路"。面试时"描述你怎么做接口测试"这类问题，答案就是 Ch08 用例设计 + Ch10/Ch14 的 Postman 实战 + Ch11-Ch13 的抓包，别背概念，要能说清"从哪抓包、怎么设计用例、怎么数据驱动、怎么处理 token 关联"。
