## 学习任务

### 任务 1：亲手跑 logging 的三个默认值（30 分钟）
写脚本：①先不设 level 直接 `logging.info('...')`，观察为什么不输出；②加 `level=logging.DEBUG` 再跑，确认 DEBUG/INFO 都出来；③`filemode='w'` 和 `filemode='a'` 各跑两次，打开文件看是覆盖还是追加。目的：把"默认 WARNING / filemode 默认 'a' / 不设 filename 走控制台"三个默认值变成肌肉记忆。

### 任务 2：一个 logger 挂两个 handler（30 分钟）
用 `logging.getLogger()` 建一个 logger，`addHandler` 一个 `StreamHandler`（控制台）+ 一个 `FileHandler`（文件），各配一个 `Formatter`（格式可以不同）。跑一条日志，确认"一份日志同时打控制台 + 写文件"。目的：真正理解四大组件的流水线分工。

### 任务 3：默写日志格式串（15 分钟）

## 企业真实场景

1. **测试框架入口统一配置日志**：`logging.basicConfig(filename="logs/run.log", filemode="w", format=fmt, level=logging.INFO)` 一行统一所有用例的日志格式，失败后按时间戳+行号翻日志定位。（Ch05）
2. **日志分级防磁盘打满**：开发环境 `level=DEBUG` 全量记录，上线前改 `level=INFO/WARNING`，避免海量 DEBUG 日志写满磁盘。（Ch05）
3. **一个 logger 多 handler**：控制台 handler 实时看 + 文件 handler 留档 + 网络/邮件 handler 失败告警，跑用例时"边跑边看 + 事后翻档"两不误。（Ch05）
4. **回归成本可量化**：原来 3 人 2 天做一轮全量回归，接上 Appium 后 2 小时跑完还每天在 CI 自动跑——这是自动化价值最有说服力的数字。（Ch06）
5. **什么该自动化**：Appium 落地最稳的是"登录、下单、支付"这类稳定核心主流程；改版页、营销活动页先手工，等稳定了再补自动化。（Ch06）

## 收获

1. **logging 四层知识**：等级（阈值语义，默认 WARNING）、组件（logger/handler/filter/formatter 流水线）、basicConfig（filename/filemode/format/level 默认值）、format（五个格式符）。
2. **logging vs print 四大差异**：可留档、可分级、可带元信息（时间戳/行号/级别）、可多目的地。
3. **三大易错默认值**：默认 level=WARNING（不设时 info/debug 不输出）、filemode 默认 'a'（追加非覆盖）、不设 filename 走控制台。
4. **App 自动化的驱动力**：迭代加速（月发版→小时发版）+ 多平台×多机型×多版本组合爆炸，手工回归跟不上。
5. **Appium 定位一句话**：跨平台（Android+iOS）跨语言（Java/Python/JS...），代价是稳定性"一般"；Uiautomator2/XCUITest 是单平台原生工具（快而稳但只测一个平台）。
6. **选型本质**：约束条件（平台、语言）决定可选集，工具名气靠后。
7. **自动化适用边界**：稳定流程 + 高频回归 + 核心场景适合自动化；UI/流程频繁改动先手工后自动化。
