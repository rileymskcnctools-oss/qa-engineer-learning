## 企业真实场景

1. **新电脑装环境排错**：Server 起不来查 Node，连不上设备查 adb/SDK，元素定位不了查 Inspector——七件套职责记牢，排错快一倍。（Ch08）
2. **1.x→2.x 迁移清单**：URL 去 /wd/hub、capability 加 appium: 前缀、驱动单独装，三点就是迁移清单。（Ch08）
3. **看 Server 日志定位问题在哪一层**：卡在端口映射说明 UIAutomator2 没起来，卡在推 settings apk 说明 adb 有问题——日志每一段对应一个环节。（Ch09）
4. **换被测 App 只改两个 capability**：appPackage + appActivity，deviceName 真机填真机 id（adb devices 看）、模拟器填模拟器名。（Ch10）
5. **框架化标准姿势**：setup_method 建 driver → 测试方法做操作 + 断言 → teardown_method 关 driver；断言是测试和演示脚本的分水岭。（Ch10）

## 收获

1. **Appium 一句话定位**：开源 + 跨平台（iOS/Android/Windows/Mac）+ 跨语言（Java/Python/JS...）+ WebDriver 协议，是"移动端的 Selenium"。
2. **两大默认引擎**：Android = UiAutomator2、iOS = XCUITest（底层 WebDriverAgent）；通过 automationName 指定。
3. **2.x 三大变化**：默认路径 /（不再用 /wd/hub）、驱动拆出单独装、非标准 capability 加 appium: 前缀。
4. **三模块架构**：Client（发起）/ Server（中转）/ 移动端（执行），单一职责；Server 中转是"跨语言跨平台"能成立的关键。
5. **一次 session 流程**：POST /session → 匹配 driver → adb 启动 → 推 settings apk → 端口映射 8200→6790 → 装/启 UIAutomator2 server → am start。
6. **写脚本三件套**：五个核心 capability + setup/teardown + 断言，是"能跑"到"能测"的分水岭。
