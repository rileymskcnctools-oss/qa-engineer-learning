## 企业真实场景

1. **换被测 App 只改 capability**：appPackage + appActivity 两行，就能让同一套脚本测另一个 App；capability 抽成 caps.py 配置文件，环境切换只改一个文件。（Ch11）
2. **回归测试的稳定性参数**：noReset=True 保留登录态连续跑、dontStopAppOnReset 首启不停 App、skipDeviceInitialization 跳过重复安装提速——三个参数就是"回归要快又要稳"的答案。（Ch11）
3. **测 App 跳转第三方**：activate_app 切到浏览器/地图/支付，terminate_app 回收，对应"分享/唤起/支付"类跨 App 用例。（Ch12）
4. **定位失败先看 Inspector**：定位不到别猜，回到页面源码树确认属性到底叫什么；定位不唯一用多属性 XPath 组合。（Ch13）
5. **用例稳定的八成靠等待**：setup 里设隐式等待兜底，关键交互处用显式等待等 element_to_be_clickable，少用 sleep。（Ch14）
6. **测自定义控件**：进度条/滑动条/图表没有可点元素，用 location + size 算坐标再 tap，是处理自定义控件的通用套路。（Ch15）

## 收获

1. **Capability 是"启动前告诉服务器测什么"的唯一入口**：键值对 JSON，非标准键加 appium: 前缀，automationName 是唯一必填。
2. **启动/关闭各分两种**：Remote 建会话 vs activate_app 切前台；terminate_app 关进程 vs quit 关会话——"建会话/切前台/关进程/关会话"四个动作别混。
3. **定位优先级**：ID > Accessibility ID > Class name > XPath；跨平台优先 Accessibility ID（content-desc = accessibility-id）。
4. **等待三兄弟**：强制=sleep 固定睡、隐式=全局找元素兜底、显式=精确等条件；核心认知是"元素在 DOM ≠ 可交互"。
5. **交互三件套**：操作（click/tap/send_keys/clear）+ 状态判断（is_displayed/is_enabled/is_selected）+ 取属性（get_attribute/text/location/size）。
6. **tap 点坐标是自定义控件杀手锏**：location + size 算中心点，比 click 更精细。
