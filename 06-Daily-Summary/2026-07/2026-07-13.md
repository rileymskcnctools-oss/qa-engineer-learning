## 企业真实场景

> 今天 10 章，分两线推进：
>
> **Python 线（Ch01-Ch05）— 编程入门的 5 块基石：**
> 1. PyCharm 快捷键 → 每天 6 小时在 IDE 里，省的不是每次 2 秒，是一天几百次重复操作
> 2. PEP8 → 代码被读的次数远多于被写的次数。你写的脚本 3 个月后自己都看不懂
> 3. input/print → 交互式脚本和调试的基础。后续 Pytest 用 assert 替代 print 做验证
> 4. 函数 → 测试脚本的核心单元：每个测试用例是一个函数，公共操作封装成函数
> 5. 变量+布尔 → 断言 `assert 2+2==4` 的底层，测试自动化就靠它判断 Pass/Fail
>
> **功能测试线（Ch07-Ch11）— Web 测试实战全流程：**
> 1. DevTools → 测试工程师的"CT 机"：Console 看报错、Network 看请求、Elements 看 DOM、Application 看存储
> 2. Web 测试流程 → 从需求到上线的完整链路，面试官问"你们怎么测的"你就按这个流程答
> 3. 设计思路 → 不是所有功能都测一样的深度——核心流程全测、次要功能主路径、边缘场景快速过
> 4. 常见 Bug → 新人最怕"发现不了 Bug"，这个清单就是你的检查清单
> 5. 兼容策略 → 不是所有浏览器都同等重要——看数据做决策

## 收获

1. Python 5 章 = 编程入门的全部基础：环境（Ch01）→ 规范（Ch02）→ 交互（Ch03）→ 封装（Ch04）→ 数据（Ch05）
2. `Python之禅`核心：代码被读的次数远多于被写的次数——这解释了为什么编码规范不是"加分项"而是"必需品"
3. F12 DevTools 四面板分工：Elements(DOM) / Console(JS) / Network(请求) / Application(存储)——四板斧
4. Web 测试流程 = 测试左移（需求评审提前介入）+ 测试右移（上线监控+用户反馈）——不只是"中间测一下"
5. 兼容测试优先级公式：用户占有率 × 核心功能覆盖 = 排期依据
