## 企业真实场景

> 今天 8 章覆盖 Python 从"能写"到"写好"再到"写稳"的三个阶梯：
>
> **第三阶梯 — 工具与技巧（Ch15-Ch17）：**
> 1. range + random → 造测试数据的基础工具：批量生成用户名、随机选测试样本、打乱数据顺序
> 2. 循环嵌套 → 遍历多维数据（Excel 行列、JSON 嵌套结构）的底层能力
> 3. 推导式 → 测试中一行代码完成"过滤+转换"：`[r for r in responses if r.status != 200]` 找出所有失败请求
>
> **第四阶梯 — 函数进阶（Ch18-Ch19）：**
> 4. 函数返回值 → 测试脚本中每个工具函数都返回结果：`def login(username, password): return session_token`
> 5. 变量作用域 → 大脚本中最隐蔽的 Bug 来源：全局变量在函数里被意外修改。LEGB 规则就是你的排查路径
>
> **第五阶梯 — 健壮性（Ch20-Ch22）：**
> 6. 错误分析 → 不是"代码报错了"就结束，而是"看 Traceback→定位行号→分析原因"——这是调试的基本功
> 7. 异常处理 → 自动化测试脚本不能因为一个用例报错就全停——try-except 让脚本"容错"
> 8. 面向对象入门 → Page Object 模式的底层。你把"登录页"封装成一个类，属性和方法都是自然映射

## 收获

1. `range(start, stop, step)` 生成的序列不包含 stop——这是初学者最容易犯的边界错误
2. 推导式 = 更快 + 更 Pythonic，但不要超过一层嵌套——可读性 > 炫技
3. break 只跳出最近一层循环——多层嵌套时想全跳需要额外的标志变量
4. 函数参数优先级：位置参数(必填) → 默认参数(可选) → *args(不定长位置) → **kwargs(不定长关键字)
5. LEGB = Local → Enclosing → Global → Built-in，从内到外四层作用域查找链
6. try-except-else-finally：try 无异常走 else，finally 无论如何都执行——即使 try 里有 return
7. `self` 不是关键字，是约定——它把实例自身传给方法，让你能访问同一个对象的其他属性和方法
8. 面向对象 = 把数据和行为绑在一起。测试脚本中：一个页面 = 一个类，页面元素 = 属性，页面操作 = 方法
