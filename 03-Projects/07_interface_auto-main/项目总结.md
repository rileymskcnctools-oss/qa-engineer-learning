# 企业微信接口自动化测试框架 — 项目总结

> 用于课程学习重点把握与后续复习。

---

## 项目总览

**企业微信接口自动化测试框架**，用 Python + pytest + requests + Allure + uv 管理。

**核心目标**：用分层架构封装企业微信 API，实现部门管理的增删改查自动化测试。

---

## 一、分层架构（必考重点）

```
tests（用例层）
  ↓ 依赖
apis（接口对象层）
  ↓ 依赖
base（基础层）
  ↓ 依赖
utils（工具层）
```

**设计原则**：每层只依赖下层，不跨层、不反向依赖。

| 层次 | 文件 | 作用 |
|------|------|------|
| utils | file_util.py / log_util.py / util.py | 路径处理、YAML读写、日志配置、数据库查询 |
| base | base_api.py | 对 requests 二次封装，统一 `send_api()` 方法 |
| apis | wework.py / departments.py | 按业务封装接口对象 |
| tests | test_departments.py | 编写用例，调用 apis 层 |

## 二、核心知识点

### 1. BaseApi — requests 统一封装

`base_api.py` 的 `send_api(req)` 方法：
- 接收一个 dict：`{"method": "post", "url": "...", "json": {...}}`
- 内部调用 `requests.request(**req)` 解包发送
- 自动记录请求/响应日志
- **面试考点**：为什么要封装？→ 统一日志、统一异常处理、方便后续加重试/断言

### 2. Wework — Token 获取与缓存机制（重点）

`wework.py` 的 `get_access_token()` 实现：
- **缓存策略**：token 缓存在 `config/token_cache.yaml`，用 `corpid_corpsecret` 作为 key
- **提前刷新**：`REFRESH_BEFORE_EXPIRE = 600`，过期前 600 秒就刷新
- **缓存结构**：`{corpid_secret: {token, obtained_at, expires_in, expires_at}}`
- **面试考点**：
  - 企微 token 有效期 7200 秒（2小时），为什么不能每个用例都重新获取？→ 有频率限制，会被封
  - 为什么用文件缓存而不是内存缓存？→ 多进程场景下内存不共享，文件缓存更可靠

### 3. Department — 接口 CRUD 封装

`departments.py` 继承 Wework，提供：
- `create(data)` — POST 创建部门
- `update(data)` — POST 更新部门
- `delete(id)` — GET 删除部门
- `list()` — GET 获取部门列表
- `clear()` — 清理所有部门（遍历删除，跳过 id=1 的根部门）
- 用 `jsonpath` 提取响应中的 id 列表

### 4. 测试用例 — 两种写法

`test_departments.py` 是主用例，展示了两个测试场景：

**场景一：部门增删改查全流程**
```
创建 → 查询验证 → 更新 → 数据库断言 → 删除 → 查询验证
```
- 用 `allure.step()` 标记步骤
- 用 `jsonpath(r.json(), "$..id")` 提取所有 id
- 用 `Utils.query_db()` 查数据库验证更新结果

**场景二：参数化创建部门**
```python
@pytest.mark.parametrize("depart_data", get_yaml_data(...))
def test_create_departments_by_datas(self, depart_data):
```
- 数据驱动：YAML 文件提供多组测试数据
- 每组数据包含 `name, name_en, parentid, order, id, expect`
- 断言 `errcode == expect`（0 表示成功，非 0 表示预期失败）

### 5. 测试数据 YAML 设计

`departments_data.yaml` 包含**正常 + 异常**用例：
- 正常创建：name="技术部", expect=0
- 空 name：expect=40058（参数无效）
- 超长 name_en：expect=60009（非法字符）
- 父部门不存在：expect=40058
- 重复 id：expect=60008
- 父部门 id=1（根部门）：expect=60123（不可操作）
- **面试考点**：为什么测试数据放 YAML 而不是代码里？→ 数据与代码分离，不用改代码就能加用例

### 6. 工具层

| 工具 | 作用 |
|------|------|
| `get_path()` | 用 `Path(__file__).resolve().parent.parent` 定位项目根目录 |
| `get_yaml_data()` / `write_yaml_data()` | YAML 读写 |
| `log_util.py` | loguru 双输出（控制台+文件），1MB 轮转，保留 10 份 |
| `Utils.query_db()` | pymysql 数据库查询，DictCursor 返回字典 |

## 三、企业微信 API 关键信息

| 接口 | URL | 方法 |
|------|-----|------|
| 获取 token | `{base_url}/cgi-bin/gettoken?corpid=xxx&corpsecret=xxx` | GET |
| 创建部门 | `{base_url}/cgi-bin/department/create?access_token=*** | POST |
| 更新部门 | `{base_url}/cgi-bin/department/update?access_token=*** | POST |
| 删除部门 | `{base_url}/cgi-bin/department/delete?access_token=*** | GET |
| 部门列表 | `{base_url}/cgi-bin/department/simplelist?access_token=*** | GET |

## 四、高频面试题

1. **分层架构各层职责是什么？为什么这样分层？**
   - 参考回答框架：分层是为了职责分离、可维护、可复用。utils 提供通用能力，base 统一 HTTP 封装，apis 按业务封装，tests 只关心断言不关心实现细节。

2. **Token 缓存策略怎么设计的？为什么提前 600 秒刷新？**
   - 参考回答框架：用文件缓存避免重复请求，提前刷新防止边界情况（网络延迟导致刚好过期）。

3. **数据驱动测试怎么实现的？YAML 数据格式怎么设计？**
   - 参考回答框架：`@pytest.mark.parametrize` + `get_yaml_data()` 读取，每组数据包含正常和异常场景，expect 字段表示预期 errcode。

4. **jsonpath 的 `$..id` 是什么意思？**
   - 递归查找所有 id 字段，不管嵌套多深。

5. **为什么 Department 要继承 Wework？**
   - 复用 token 获取能力，避免重复代码。

## 五、看课程时的重点

1. **分层思想** — 每层只依赖下层，这是企业级框架的核心
2. **Token 缓存** — 文件缓存 + 提前刷新，面试必问
3. **数据驱动** — YAML 数据 + pytest 参数化，一条数据一条用例
4. **jsonpath 提取** — 从嵌套 JSON 中灵活取值
5. **Allure 报告** — `@allure.feature`、`@allure.story`、`allure.step()` 的使用
6. **数据库断言** — 接口返回成功 ≠ 数据真正写入，DB 验证是加分项
