## 企业真实场景

> 今天 6 章是 Python 的"数据处理 + 流程控制"双核心：
>
> **数据结构（Ch09-Ch11）：**
> 1. 列表 → 测试中最常用的容器：存测试用例列表、存 API 返回的数组、存断言用的期望值
> 2. 字典 → JSON 的本质就是字典嵌套。API 返回的 response.json() 就是 dict，你每天都要从里面取字段
> 3. 深拷贝 vs 浅拷贝 → 测试造数据时最容易踩的坑：你以为复制了一份独立的数据，其实两个变量指向同一块内存，改一个另一个也变了
>
> **控制流（Ch12-Ch14）：**
> 1. if-elif-else → 测试逻辑的骨架：判断响应码、判断字段存在性、判断值范围——全部基于 if
> 2. while → 轮询用：等一个异步任务完成、等一个文件生成——"没完成就继续等"
> 3. for-in → 批量处理用：遍历 100 条测试数据、遍历 API 返回的列表校验每个元素——for-in + assert 是自动化测试基本公式

## 收获

1. 列表 list = 有序可变的序列容器；字典 dict = 无序的键值对容器 —— 定位原则：需要顺序/去重用 list，需要快速查找/关联数据用 dict
2. `list.sort()` 原地修改，`sorted(list)` 返回新列表——函数式 vs 破坏式的经典区别
3. 浅拷贝只复制第一层，嵌套子对象共享引用。深拷贝 `copy.deepcopy()` 递归复制所有层——"一改全改"的 Bug 就来自这里
4. if-elif 是互斥的：第一个 True 被执行，后面的 elif 跳过——顺序决定了逻辑优先级
5. while 的致命陷阱：忘记更新循环变量 = 死循环。每一次 while 循环都必须确保有"退出路径"
6. for-in 是 Python 最"Pythonic"的循环方式——只要对象可迭代，就能用 for-in

## 反思

> 今天 6 章每章都绑定企业场景和面试考点——不再是"入门"而是"内功"级别的内容。数据结构（Ch09-Ch11）和控制流（Ch12-Ch14）是后续自动化测试代码的地基——没有这些，你写的测试脚本只是"能跑"，有了这些，你的脚本是"健壮的"。
>
> 深拷贝 vs 浅拷贝是 Python 面试的必考题，也是测试造数据时最容易踩的坑。建议自己动手验证——不实际跑代码，光看文字解释永远记不住"为什么嵌套结构不能只用 copy()"。
>
> 控制流三章中最容易忽视的是"选择 while 还是 for-in"——这本质上是一个"已知循环次数 vs 未知循环次数"的判断。数据量已知用 for-in，等待条件满足用 while。这个区别面试官不会直接问，但会在你的代码中看出来。
