## 完整操作过程（6 步）

### 背景

从 GitHub 拉取 PytestProject 后，代码能跑通但环境不规范：pytest 装在系统 Python 3.14 下，用绝对路径运行。目标是建一个项目级虚拟环境，让代码具有可移植性。

### 步骤 1：进入项目目录

```bash
cd PytestProject/
```

### 步骤 2：选择 Python 版本并创建虚拟环境

**思考过程：** 系统有三个 Python 版本（3.11 Hermes venv、3.12 PyCharm 默认、3.14 系统安装）。选择了 3.14，理由：
- `requirements.txt` 里 `pytest>=7.0` 三个版本都支持
- 3.14 向后兼容，团队成员用 3.11/3.12 也能跑
- **原则：选最低版本保证最大兼容性，但 3.14 已经装好 pytest 依赖，用 3.14 最省事**

```bash
C:\Users\riley\AppData\Local\Programs\Python\Python314\python -m venv .venv
```

**关键认知：** `.venv/` 放在项目根目录下，IDE 自动识别，不进 git，每人自己建。

### 步骤 3：激活虚拟环境

```bash
.venv\Scripts\activate   # Windows
```

成功后终端前面出现 `(.venv)` 标记，此时 `python` 和 `pip` 都指向 `.venv/` 内的 3.14。

### 步骤 4：安装依赖

```bash
pip install -r requirements.txt
```

### 步骤 5：发现依赖声明不全

运行 `pytest` 报错：`ModuleNotFoundError: No module named 'yaml'`

**排查：** 用 `grep -h "^import|^from" tests/*.py` 扫描所有测试文件的 import，逐一判断哪个是第三方库：

| import | 类型 | 需要进入 requirements.txt？ |
|--------|------|---------------------------|
| `import yaml` | 第三方库 PyYAML | ✅ |
| `import os` | 标准库 | ❌ |
| `from time import sleep` | 标准库 | ❌ |

**修复：** 在 `requirements.txt` 补上 `pyyaml`，重新 `pip install -r requirements.txt`。

**核心教训：** 依赖声明不全 = 换台电脑就炸。每次 `pip install xxx` 后立刻更新 `requirements.txt`。

### 步骤 6：验证

```bash
pytest   # 直接敲，不需要 python -m 或绝对路径
```

结果：17 passed, 1 failed（`[1+9=2]` 是 YAML 数据里故意放的错误用例，正常）

### 额外：.gitignore 确认

- 仓库根目录 `.gitignore` 已经有 `.venv/`，自动忽略所有子目录的虚拟环境
- **一个仓库一个根 `.gitignore` 即可，子目录不需要重复**
- PytestProject 下的 `.gitignore` 有前导空格 bug，已修复

## 我的理解（最重要）

> 项目可移植性的核心不是"把环境带过去"，而是"把环境的**配方**带过去，让每个人按配方重建"。`.venv/` 是厨房，`requirements.txt` 是菜谱。厨房不进 git，菜谱进。任何人 clone 下来，两条命令（创建 venv + pip install）就能复现完全相同的环境。今天踩的坑（pyyaml 没写进 requirements.txt）就是典型：菜谱漏了食材，换厨房就做不出菜。

## 企业真实场景

> 新人第一天入职，从 GitLab clone 项目代码。README 里写了两条命令：`python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`，5 分钟后环境跑通，开始读代码。如果 requirements.txt 不全，新人第一天的体验就是痛苦的 import error 排查 — 这就是为什么依赖声明完整性在工程化里是第一道门。

## 收获

1. 项目虚拟环境的标准做法：`.venv/` 放项目根目录，`requirements.txt` 声明依赖，`.gitignore` 排除 `.venv/`
2. 依赖声明不全的诊断方法：grep 所有 import → 区分标准库和第三方库 → 补全 requirements.txt
3. 一个 git 仓库只需要一个根目录 `.gitignore`，子目录不需要重复
