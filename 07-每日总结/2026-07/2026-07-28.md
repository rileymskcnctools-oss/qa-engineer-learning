## 我的理解（最重要）

> Flask 路由的本质是 URL → 函数的映射表。`@app.route("/xxx")` 装饰器做的事就是往这张表里注册一条记录："当用户访问 /xxx 时，调用下面这个函数"。动态路由 `<变量>` 让一个路由规则匹配一类 URL（比如 `/user/1`、`/user/99` 共用一条规则），类型限定 `<int:id>` 在路由层就做了参数校验——传错的直接 404，不会进到视图函数里报 500。请求方法通过 `methods=["GET","POST"]` 控制，默认只有 GET——这意味着如果有人 POST 你的 GET 接口，Flask 直接返回 405。

## 企业真实场景

> Mock 接口时，你需要根据不同的 URL 返回不同的假数据。比如前端请求 `/api/user/1` 返回用户 1 的信息，请求 `/api/user/2` 返回用户 2 的信息——这就是动态路由 `<int:uid>` 的典型场景。而类型限定 `<int:uid>` 比 `<uid>` 更好，因为前端如果传了 `/api/user/abc`，你能直接返回 404 而不是让代码 `int("abc")` 崩溃。

## 收获

1. Flask 的路由装饰器 `@app.route()` 是 URL 和函数的绑定机制——理解了这个就理解了后端 Web 框架的核心
2. 动态路由 + 类型限定 = 一组 URL 的匹配规则 + 自动参数校验
3. `methods` 参数让同一个 URL 在不同 HTTP 方法下执行不同逻辑（RESTful 的基石）
