## 一、OpenAI 与 ChatGPT

### 知识点 1：OpenAI 是什么

【课程原话/定义】

OpenAI 是一个美国人工智能研究实验室，由非营利组织 OpenAI Inc 和营利组织子公司 OpenAI LP 组成，2015 年成立于旧金山。微软先后投资百亿美元，用于独家授权使用 GPT-4。

【为什么？】

理解 OpenAI 的"非营利 + 营利"双层结构很重要：非营利组织掌控方向（确保 AI 安全），营利子公司负责商业化。这也是为什么它叫"Open"却并未完全开源所有模型——开源的是理念，商业的是产品。

【必须掌握】

- OpenAI 2015 年成立，总部旧金山
- 微软是主要投资方，独家授权 GPT-4
- 核心产品线：GPT（文本）、DALL·E（图像）、Whisper（语音识别）、Sora（视频）

【我的理解】

> OpenAI 为什么要设计"非营利 + 营利"的双层结构？这反映了 AI 行业的什么矛盾？

---

### 知识点 2：ChatGPT 是什么

【课程原话/定义】

ChatGPT 全称 Chat Generative Pre-trained Transformer（聊天生成预训练转换器），是 OpenAI 开发的人工智能聊天机器人，2022 年 12 月推出。基于 GPT-3.5、GPT-4、GPT-4o 架构，用强化学习训练，能自动生成文本、问答、摘要、编写和调试程序。

【为什么？】

拆解名字的三个关键词：
- **Chat**：针对对话场景优化
- **Generative**：生成式，不是检索式——它"创造"内容而非"查找"内容
- **Pre-trained**：先在海量数据上预训练，学到通用语言能力，再针对任务微调

【面试考察】

> 面试官："GPT 的全称是什么？'预训练'是什么意思？"

**参考回答框架：**

1. GPT = Generative Pre-trained Transformer
2. 预训练（Pre-training）指：先在无标注的海量文本上做"预测下一个词"的自监督学习，让模型学会语言规律
3. 之后再用少量标注数据微调（Fine-tuning），让模型适应具体任务
4. 好处：预训练阶段不需要人工标注，成本低、数据量大，这是大模型能"涌现"能力的关键

【易错点】

| 易混淆 | 正确理解 |
|--------|---------|
| ChatGPT = GPT | ChatGPT 是产品（聊天机器人），GPT 是底层模型 |
| GPT 是搜索引擎 | GPT 是生成式，会"编造"内容，检索是另一条技术路线（RAG） |
| 预训练 = 微调 | 预训练学通用能力，微调学具体任务，是两阶段 |

## 二、GPT 模型系列

### 知识点 3：GPT-3.5 / GPT-4 / GPT-4o / GPT-4o mini

【课程原话/定义】

| 模型 | 定位 |
|------|------|
| GPT-3.5 Turbo | 上一代，聊天优化，2024年7月起建议用 gpt-4o-mini 替代 |
| GPT-4 | 大型多模态（文本+图像输入→文本输出），推理能力更强 |
| GPT-4o | "o"=omni（全能），多模态，速度快2倍、便宜50% |
| GPT-4o mini | 小型类别最先进，最便宜，多模态 |

【为什么？】

模型命名里的 "o" 代表 omni（全能/全模态）。GPT-4o 和 GPT-4o mini 的关系：同一个架构，mini 是参数规模更小的版本——用更少的参数换取更低的价格和更快的速度，适合"不需要最强推理"的日常任务。

【必须掌握】

- GPT-4o = 全能多模态（文本/图像/音频理解）
- GPT-4o mini = 便宜快速的小模型，日常任务首选
- GPT-4 Turbo = GPT-4 的加速版本
- GPT-3.5 已过时，官方建议用 4o-mini 替代

【企业场景】

> 你所在团队要接入 LLM 做自动化测试断言（判断接口返回是否符合预期）。CTO 问：选哪个模型？
>
> 分析：断言是高频、低难度任务，对推理要求不高，但对成本和速度敏感。选 **gpt-4o-mini**——便宜（$0.15/1M tokens）、够用、快。只有当需要复杂推理（如生成测试用例设计、分析复杂日志）时才升级到 gpt-4o。

【面试考察】

> 面试官："GPT-4o 和 GPT-4o mini 有什么区别？什么时候用哪个？"

**参考回答框架：**

1. 两者架构相同，mini 是参数更小的版本
2. 区别：mini 更便宜（价格低一个数量级）、更快，但推理能力弱于完整版
3. 选型原则：日常任务（分类、简单问答、格式转换）用 mini；复杂推理（代码生成、多步逻辑）用完整版

### 知识点 4：文本生成模型价格对比

【课程原话/定义】

| 模型 | 价格（输入/输出 $/1M tokens） | 特点 |
|------|------|------|
| gpt-4o-mini | $0.15 / $0.6 | 加速廉价版，日常任务推荐 |
| gpt-3.5-turbo | $3 / $1.5 | 上一代，廉价替代 |
| gpt-4o | $5 / $15 | 速度快，能力略弱于 gpt-4 |
| gpt-4-turbo | $10 / $30 | gpt-4 加速版 |
| gpt-4 | $30 / $60 | 推理最强，训练数据规模大 |

【为什么？】

注意一个反直觉的点：**价格 ≠ 能力排序**。gpt-4（$30/$60）比 gpt-4o（$5/$15）贵很多，但 4o 是"能力接近、速度更快"的新架构。gpt-3.5-turbo（$3/$1.5）反而比 gpt-4o-mini（$0.15/$0.6）贵——因为 4o-mini 是更高效的新架构，所以"新一代小模型 > 老一代大模型"。

【易错点】

| 误区 | 事实 |
|------|------|
| 越贵越强 | 新旧架构差异大，新小模型可能比老大模型既强又便宜 |
| 输入输出同价 | 输出通常比输入贵（生成比读取费算力） |

【我的理解】

> 为什么输出 token 的价格通常是输入 token 的数倍？从计算角度解释。

## 三、OpenAI 多模态产品线

### 知识点 5：DALL·E / TTS / Whisper / Sora / Embeddings

【课程原话/定义】

| 产品 | 能力 |
|------|------|
| DALL·E | 文本 → 图像（DALL·E 3 支持指定尺寸生成；DALL·E 2 支持编辑/变体） |
| TTS | 文本 → 语音（tts-1 实时优化，tts-1-hd 质量优化） |
| Whisper | 语音 → 文本（通用语音识别，多语言、翻译、语言识别） |
| Embeddings | 文本 → 向量（衡量文本相关性，用于搜索/聚类/推荐） |
| Sora | 文本 → 视频（生成现实且富有想象力的场景） |

【为什么？】

这些产品背后是同一个核心思想：**把不同模态（文字、图像、语音、视频）统一映射到数字向量空间**。Embeddings 是关键基础——它把文本变成向量，向量之间可以算距离，于是"搜索"就变成了"找距离最近的向量"。RAG（检索增强生成）正是基于 Embeddings：先把知识库向量化，用户提问时检索最相关的片段，再喂给 GPT 生成答案。

【必须掌握】

- Embeddings：文本的数字表示，用于衡量相关性
- RAG = 检索（Retrieval）+ 增强（Augmented）+ 生成（Generation）
- Whisper 的 API 版本与开源版本模型一致，但 API 推理更快

【企业场景】

> 公司有大量历史 Bug 记录和测试文档，你想做一个"智能问答助手"让新人快速查资料。
>
> 方案：用 Embeddings 把文档向量化存进向量库 → 用户提问时检索最相关的 Top-K 片段 → 把这些片段拼进 prompt 喂给 GPT 生成答案。这就是 RAG 架构，比直接微调 GPT 便宜得多，也更容易更新。

【面试考察】

> 面试官："什么是 RAG？和微调（Fine-tuning）有什么区别？"

**参考回答框架：**

1. RAG：检索增强生成，不改变模型，而是在提问时检索外部知识库，把相关文档作为上下文喂给模型
2. 微调：用标注数据继续训练模型，改变模型权重
3. 区别：RAG 便宜、易更新、可溯源；微调贵、需要数据、不可溯源但能改变模型行为
4. 选型：知识会频繁更新 → RAG；需要模型学会特定风格/格式 → 微调

## 四、ChatGPT 使用方式

### 知识点 6：四种调用方式

【课程原话/定义】

1. **命令行**：`openai api chat.completions.create -m gpt-4o-mini -g user "..."`（需 `pip install openai`）
2. **编程语言 Library**：
```python
from openai import OpenAI
client = OpenAI()
chat_completion = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Hello world"}]
)
```
3. **Langchain 等框架**：
```python
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-4o")
ai_msg = llm.invoke(messages)
```
4. **学社提供的 AI 服务**（如 Dify 平台）

【为什么？】

四种方式本质是同一个 API 的不同封装层级：
- 命令行：最底层，适合快速验证
- OpenAI SDK：官方库，最直接
- Langchain：框架，抽象了"链式调用、记忆、工具"等高级能力，方便切换模型供应商
- 平台（Dify）：可视化，适合非程序员或快速搭建原型

【易错点】

| 方式 | 适用 | 局限 |
|------|------|------|
| 命令行 | 快速验证 | 无法集成业务逻辑 |
| SDK | 直接控制 | 需自己处理多轮对话、工具 |
| Langchain | 复杂应用 | 抽象层厚，学习成本高 |
| Dify | 快速原型 | 灵活性受限 |

【我的理解】

> 为什么有了官方 SDK，还需要 Langchain 这类框架？框架解决了什么 SDK 没有解决的问题？

## 五、ChatGPT 助理（Assistants）

### 知识点 7：Assistants / 工具 / Function calling

【课程原话/定义】

Assistants 由 GPT-4 等大模型支持，能执行任务，基于上下文窗口中的指令操作，可使用工具（运行代码、检索文件）完成更复杂任务。

内置工具：文件搜索（File Search）、代码解释器（Code Interpreter）、函数调用（Function calling）。

【为什么？】

Function calling（函数调用）是大模型落地企业场景的关键：模型本身不能执行操作（如查数据库、调接口），但可以"智能地决定该调用哪个函数、传什么参数"。于是分工变成：
- **模型**负责理解意图 + 生成结构化调用参数
- **你的代码**负责真正执行函数并返回结果

这就是"AI 大脑 + 代码手脚"的协作模式，也是 AI Agent 的基础。

【必须掌握】

- Assistants 三种内置工具：文件搜索、代码解释器、函数调用
- Function calling 流程：模型返回函数名+参数 → 代码执行 → 结果回传给模型

【企业场景】

> 你要做一个"语音控制测试执行"的助手：用户说"帮我跑一下登录接口的回归测试"，助手应该调用你写的 `run_regression_test()` 函数。
>
> 实现：用 Function calling 定义 `run_regression_test` 函数的描述和参数 schema，用户输入后模型返回 `{"name": "run_regression_test", "arguments": {...}}`，你的代码收到后真正执行 pytest，再把结果回传给模型生成人类可读的报告。

【面试考察】

> 面试官："Function calling 的原理是什么？模型会真的执行函数吗？"

**参考回答框架：**

1. 不会。模型只返回"该调哪个函数 + 参数 JSON"，不执行任何代码
2. 流程：定义函数 schema → 模型返回调用意图 → 开发者代码执行 → 结果回传模型 → 模型生成最终回答
3. 这是 AI Agent 的核心机制：模型负责决策，代码负责执行

## 六、ChatGPT 微调（Fine-tuning）

### 知识点 8：微调与使用建议

【课程原话/定义】

微调通过训练超出提示范围的更多示例来改进小样本学习，让模型在大量任务上取得更好结果。微调后不需要在提示中提供那么多示例，节省成本、降低延迟。

官方建议微调前先尝试：
1. 提示工程（Prompt engineering）
2. 提示链（Prompt chaining）
3. 函数调用（Function calling）

【为什么？】

微调是"重武器"，成本和门槛高，所以官方建议先穷尽提示层面的手段。核心原因：**提示迭代的反馈循环快**（改几个字就能重试），而微调需要准备数据集 + 跑训练任务，反馈慢且贵。只有当"提示怎么改都达不到效果"时才考虑微调。

微调数据格式（JSONL）：
```json
{"messages": [{"role": "system", "content": "Marv 是一个既真实又讽刺的聊天机器人。"},
              {"role": "user", "content": "谁写了'罗密欧与朱丽叶'？"},
              {"role": "assistant", "content": "哦，只是一个叫威廉·莎士比亚的人，听说过他吗？"}]}
```

工具调用微调则额外包含 `tools` 字段，教模型在什么情况下调用哪个函数。

【必须掌握】

- 微调前先试：提示工程 → 提示链 → 函数调用
- 微调数据是 JSONL 格式，每行一个 `messages` 对话
- 微调后模型名格式：`ft:gpt-4o-mini:my-org:custom_suffix:id`

【易错点】

| 场景 | 正确选择 |
|------|---------|
| 知识需要频繁更新 | RAG（不是微调） |
| 模型需要学会固定输出格式 | 可先试提示工程，不行再微调 |
| 想省 token/降延迟 | 微调（把示例固化进模型权重） |
| 想让模型懂内部文档 | RAG（微调不适合"注入知识"） |

【我的理解】

> 为什么"微调不适合用来注入新知识"？如果公司文档天天更新，微调会遇到什么问题？
