# 测试开发岗位 · AI 能力要求与掌握程度

> 覆盖 [[README|AI大模型]] 五个章节（Ch01~Ch05），面向测试开发岗位的掌握标准。

## 一、核心结论

**测试开发的 AI 能力 ≠ 会用 ChatGPT，而是"把 LLM 能力工程化进测试流程"。**

5 个部分不是平级的，价值排序和掌握深度差异很大。判断你"是否到位"的唯一标准是：**能不能写代码把 AI 能力落地到测试里**，而不是"能不能聊 AI"。

分水岭 = 会不会写代码落地（Ch05 是分水岭，Ch02 是最实用的先手）。

## 二、四级掌握梯度

| 梯度 | 标准 | 一句话 |
|------|------|--------|
| L0 了解 | 能说清概念、原理、区别，面试不丢分 | "知道是什么、为什么" |
| L1 会用 | 能动手用工具提效 | "打开工具能干活" |
| L2 会写 | 能写代码把 AI 能力工程化落地 | "写代码把 AI 接进测试"（测试开发核心壁垒） |
| L3 会设计 | 能设计整套智能测试方案并落地平台 | "主导方案，别人照着搭" |

**测试开发岗位的及格线 = L2；竞争力 = L3。**

## 三、逐章拆解

### Ch01 大模型认知 —— 目标 L1→L2

培养：模型选型、四种调用方式、RAG vs 微调、Function calling。

| 能力点 | 程度 | 说明 |
|--------|------|------|
| 模型选型（4o-mini vs 4o） | L1 会用 | 企业会问"断言用哪个模型省钱"，要能说清"日常任务用 mini，复杂推理用完整版" |
| 调用模型（SDK / init_chat_model） | L2 会写 | 至少能写 `client.chat.completions.create` 或 `llm.invoke()` 真正调一次 |
| Function calling 原理 | L1 会用 | **必须吃透**——它是 Agent 的基石，面试高频 |
| RAG vs 微调选型 | L1 会用 | 要能说清"知识更新→RAG，改行为/风格→微调" |

**到此为止，别深挖**：DALL·E / Sora / Whisper 生成类产品了解即可（测试岗用不到）；微调训练不用动手做（准备数据集 + 跑训练，测试岗基本碰不到）。

---

### Ch02 提示词工程 —— 目标 L2（最该先精通）

培养：五大原则、few-shot、结构化输出、系统测试。

| 能力点 | 程度 | 说明 |
|--------|------|------|
| 工业级用例生成提示词 | L2 会写 | 能写出"角色扮演 + 定界符 + few-shot + 拆分"的完整提示词，产出可用用例 |
| 结构化输出（JSON Schema） | L2 会写 | **必须会**——否则生成结果无法被程序解析，无法工程化 |
| 系统测试提示词 | L2 会写 | 像改代码一样版本化迭代提示词，每次只改一个变量 |

**为什么最该先精通**：这是唯一"今天学了明天就能提效"的技能，且 5 个章节全部依赖它（工作流、Agent 都要写提示词）。

**到此为止，别深挖**：不用背提示词模板大全，掌握五大原则 + 会迭代即可。

---

### Ch03 Dify 工作流 —— 目标 L1→L2

培养：节点编排、变量、逻辑控制、异常、structured output。

| 能力点 | 程度 | 说明 |
|--------|------|------|
| 搭"测试用例批量生成"工作流 | L2 会写 | 能独立搭通"拆解→迭代→合并 + JSON Schema"这条主链路 |
| 节点/变量/逻辑控制 | L1 会用 | 理解大模型节点、迭代 vs 循环、三类变量即可 |

**到此为止，别深挖**：Dify 是低代码工具，不必深挖内部实现。定位是"快速原型 + 给非技术团队用"，测试开发要会用，但不必是 Dify 专家。

---

### Ch04 Agent 概念 —— 目标 L1

培养：ReAct、Plan-and-Execute、结构化输出、记忆、五大核心元素。

| 能力点 | 程度 | 说明 |
|--------|------|------|
| ReAct 循环 / 五大元素 | L1 会用 | **面试高频**，必须能脱稿讲清 Thought-Action-Observation 循环和 `LLM+Planning+Parser+Tools+Memory` |

**到此为止，别深挖**：概念吃透即可，具体实现靠 Ch05 落地，不要在 Ch04 重复记两遍。

---

### Ch05 LangChain —— 目标 L2→L3（分水岭）

培养：生态、模型调用、create_agent、@tool、MCP、RAG、向量、多智能体。

| 能力点 | 程度 | 说明 |
|--------|------|------|
| create_agent + @tool | L2 会写 | 能手写最小 Agent，知道 docstring 决定工具调用准确率 |
| MCP 接入 | L2 会写 | 能手写 `MultiServerMCPClient` 接 stdio/streamable_http |
| RAG 管线 | L2 会写 | 能手写 loader→splitter→embedding→vector→retriever 全链路 |
| 接口自动化测试智能体 | L3 入门 | **必做至少一个**：把测试执行引擎封装成工具/MCP，Agent 自然语言驱动执行 |

**到此为止，别深挖**：多智能体、知识图谱是 L3 加分项，有余力再做；LangChain 底层源码不用读。

## 四、量化标准（"能做什么" = 掌握到位）

| 章节 | 掌握到位的可检验标准 |
|------|---------------------|
| Ch01 | 说出"断言选 4o-mini"的理由；写代码调一次模型；讲清 Function calling 流程 |
| Ch02 | 产出一份能直接导入 TestRail/Excel 的结构化用例（JSON Schema 约束） |
| Ch03 | 独立搭通"拆解→迭代→合并"的用例生成工作流并跑出结果 |
| Ch04 | 脱稿画出 ReAct 循环图，背出五大元素 |
| Ch05 | 跑通一个"接口测试智能体"demo：自然语言输入 → Agent 调 MCP 工具 → 返回测试结果 |

## 五、优先级与建议学习顺序

按"性价比 × 面试权重"排序：

1. **Ch02 提示词** —— 马上提效，性价比最高，先精通
2. **Ch05 LangChain** —— 工程壁垒，决定你是不是"真测试开发"
3. **Ch01 模型选型 + Function calling** —— 面试高频，补认知
4. **Ch04 Agent 概念** —— 面试基础，吃透即可
5. **Ch03 Dify** —— 快速原型，辅助加分

## 六、面试最可能被问的 3 个 AI 问题（测试开发岗）

1. **RAG 和微调有什么区别？什么场景用哪个？**（Ch01 必考）
2. **Function calling 的原理？模型会真的执行函数吗？**（Ch01/Ch04 必考）
3. **怎么用 Agent/LLM 改造传统自动化测试？**（Ch05 必考，你的杀手锏）

> 这 3 个问题能答出"原理 + 自己动手做过的 demo"，测试开发岗的 AI 部分基本就过关了。
