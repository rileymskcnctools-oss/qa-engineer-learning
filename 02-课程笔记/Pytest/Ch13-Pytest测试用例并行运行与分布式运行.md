## 一、为什么需要并行与分布式

### 知识点1：两种使用场景

【课程原话/定义】
- **场景1（加速）**：1000 条用例，单条 1 分钟，串行执行需要 1000 分钟。10 个核心同时跑只需要 100 分钟。
- **场景2（并发模拟）**：报名系统同时修改数据，需要模拟多用户并发请求的场景。

【为什么？】
场景1 解决的是**时间问题**——用硬件资源换反馈速度。场景2 解决的是**真实性问题**——生产环境是并发的，串行测试发现不了竞态条件（race condition）。两个场景对应 pytest-xdist 的两种用法：`-n auto`（加速）和分布式 worker（并发模拟）。

【必须掌握】
- pytest-xdist 的两大使用场景：加速执行 vs 并发模拟
- `-n auto`：自动根据 CPU 核心数分配 worker
- `-n 4`：手动指定 4 个 worker
- 核心原理：多进程并行，每个 worker 独立运行一部分用例

【企业场景】
你们的 CI 流水线中测试环节原本需要 45 分钟。开发提交代码后等 45 分钟才能知道结果，反馈太慢。你引入 pytest-xdist：`pytest -n 4`，4 核并行，时间降到 15 分钟。后来升级到 `-n 8`，降到 8 分钟。开发从"提交后去喝咖啡"变成"提交后刷新一下页面就能看结果"——这就是 CI 反馈速度对开发体验的影响。

【面试考察】
面试官："1000 条用例要 1 小时跑完，你有哪些优化手段？"
参考回答框架：① 并行执行（pytest-xdist `-n auto`）② 分层执行（冒烟 5 分钟 + 全量晚上）③ 减少 fixture 开销（scope=session 替代 function）④ 只跑变更相关的用例（pytest-testmon 或自定义 marker + `-m`）⑤ 数据驱动优化（减少冗余的 parametrize 组合）

【易错点】

| 误区 | 正解 |
|------|------|
| 只有一个 CPU 核心用 `-n auto` 也会加速 | 不会，`-n auto` 最多等于核心数；单核 CPU 并行无收益 |
| 并发越多越好 | 超过 CPU 核心数后，上下文切换开销反而降低效率 |
| 用例有共享状态还开并发 | 会导致数据竞争、用例间互相影响、结果不稳定 |

## 二、pytest-xdist 使用

### 知识点2：安装与运行

【课程原话/定义】
- 安装：`pip install pytest-xdist`
- 运行：`pytest -n auto`（自动检测 CPU 核心数）
- 或 `pytest -n 4`（手动指定 4 个进程）
- 支持与 allure 报告配合使用

【为什么？】
`-n auto` 比 `-n 4` 更推荐——不同 CI 机器的核心数不同，`auto` 自动适配，不需要为每台机器定制命令。pytest-xdist 底层用的是 Python 的 `multiprocessing` 模块，将用例列表分发给多个子进程执行，最后汇总结果。

【必须掌握】
- `pytest -n auto`：自动分配（推荐）
- `pytest -n 4`：手动指定进程数
- `pytest -n auto --dist loadscope`：按模块分配（同一模块的用例在同一进程，减少 fixture 冲突）
- 注意事项：用例多时效果明显，用例少时进程启动开销可能大于并行收益

【企业场景】
你的 CI 配置了 `pytest -n auto --dist loadscope --timeout=60`：
- `-n auto`：自动利用所有核心
- `--dist loadscope`：按测试模块分组分配，同一模块的用例在同一进程跑（避免模块级 fixture 冲突）
- `--timeout=60`：防止某个 worker 卡死

你发现不加 `--dist loadscope` 时，某些用例偶尔失败——因为 module 级别的 fixture 被分到不同进程，各进程各自初始化了一次，导致了资源冲突。加上 `--dist loadscope` 后稳定了。

【面试考察】
面试官："`pytest -n auto` 底层原理是什么？有什么注意事项？"
参考回答框架：① 底层用 Python multiprocessing，fork 多个子进程 ② 主进程收集所有用例 → 分发给子进程 → 子进程独立执行 → 汇总结果 ③ 注意事项：用例必须独立（无共享状态）；module/session 级别的 fixture 在每个进程中独立创建 ④ `--dist loadscope` 确保同一模块的用例在同一进程，避免 fixture 冲突

【易错点】

| 常见错误               | 原因/后果                       | 正确做法                          |
| ------------------ | --------------------------- | ----------------------------- |
| 用例写文件到同一路径，并发时互相覆盖 | 多进程同时写入同一文件                 | 用唯一文件名（如加时间戳/进程ID）            |
| 依赖全局变量在用例间传递数据     | 每个进程有独立内存空间，全局变量不共享         | 数据传递用 fixture 或外部存储（DB/Redis） |
| 以为 `-n 0` 是不并行     | `-n 0` = 自动检测，等价于 `-n auto` |                               |
| 少量用例（比如 5 条）也开并发   | 进程创建开销 > 并行收益               | 用例数 < 20 时不建议用 xdist          |

【扩展知识】
`--dist` 的三种分配模式：

| 模式                 | 含义                    | 适用场景                       |
| ------------------ | --------------------- | -------------------------- |
| `--dist load`      | 按用例动态分配给空闲 worker（默认） | 用例执行时间不均时                  |
| `--dist loadscope` | 按模块分配给 worker         | 有 module 级 fixture 时（避免冲突） |
| `--dist loadfile`  | 按文件分配给 worker         | 有文件级资源依赖时                  |
