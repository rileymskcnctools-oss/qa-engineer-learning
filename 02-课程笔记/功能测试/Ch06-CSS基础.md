## 一、CSS 是什么

### 【课程定义】

> CSS（Cascading Style Sheets，层叠样式表）定义如何显示 HTML 元素。样式通常存储在样式表中，目的是解决内容与表现分离的问题，让同一页面在不同浏览器中呈现相同样式。

### 【为什么？】

回顾三件套的分工：

```
HTML  →  有什么  （内容/结构）
CSS   →  长什么样（样式/布局）
JS    →  能干什么（行为/交互）
```

CSS 对测试的核心意义：

| 测试场景 | 需要 CSS 知识的点 |
|---------|-----------------|
| UI 测试 | 判断样式 Bug 是 CSS 问题还是 HTML 问题 |
| 兼容性测试 | 同一 CSS 在不同浏览器渲染可能不同 |
| 自动化定位 | CSS Selector 是元素定位最强大的方式 |
| 布局测试 | 元素位置、重叠、遮挡问题根因分析 |

### 【必须掌握】

- CSS 的作用：控制 HTML 元素的显示样式
- "层叠"的含义：多个样式可以叠加，按优先级生效
- 内容与表现分离的设计思想

### 【易错点】

| 误区 | 正解 |
|------|------|
| CSS 只是"好看" | CSS 影响可读性、可访问性、交互体验，Bug 也分功能 Bug 和样式 Bug |
| 样式问题不是 Bug | 按钮被遮挡导致用户点不了 → 这是功能性 Bug，根因在 CSS |

## 二、CSS 语法与选择器

### 【课程定义】

```css
选择器 {
  属性: 值;
  属性: 值;
}
```

四种基础选择器：

| 选择器 | 语法 | 匹配 | 测试定位场景 |
|--------|------|------|------------|
| 元素选择器 | `tag {}` | 所有该标签 | 找所有按钮 `button` |
| id 选择器 | `#id {}` | id 匹配的元素 | 定位唯一元素 `#submitBtn` |
| class 选择器 | `.class {}` | class 匹配的元素 | 定位一组元素 `.btn-primary` |
| 属性选择器 | `[属性] {}` | 有该属性的元素 | 定位 `[data-testid]`、`[name="email"]` |

### 【为什么？】

**CSS 选择器是自动化测试中元素定位的最强武器。** 它比 `getElementsByClassName` 灵活得多：

```javascript
// CSS Selector 的组合玩法（都能在 querySelector 中用）：
document.querySelector('#login-form input[type="email"]')  // 层级+属性组合
document.querySelectorAll('.btn:not(.disabled)')            // 排除禁用按钮
document.querySelector('[data-testid="submit"]')            // 测试专用属性定位
document.querySelector('div > p')                           // 直接子元素
```

### 【选择器的测试实战价值】

| 选择器类型 | 适用场景 | 鲁棒性 |
|-----------|---------|--------|
| `#id` | id 稳定不变时 | ★★★★★ |
| `[data-testid]` | 开发配合加测试标识 | ★★★★★ |
| `[name="xxx"]` | 表单元素 | ★★★★ |
| `.class` | 语义化 class 时 | ★★★ |
| `tag` | 页面唯一标签时 | ★★ |
| 哈希类名 `.a8x3k` | 不靠谱 | ★（随时变） |

### 【必须掌握】

- 四种基础选择器的写法
- 选择器可以组合使用（层级、属性、伪类）
- 在 F12 Console 用 `querySelector` / `querySelectorAll` 验证选择器

### 【面试考察】

> 面试官：CSS 选择器和 XPath 哪个更好用？

参考回答框架：
1. CSS Selector 更简洁、可读性好，大多数场景够用
2. XPath 能做文本匹配（`//button[text()="提交"]`）和轴定位（找父元素/兄弟元素）
3. 实际项目：优先 CSS Selector，复杂场景用 XPath
4. 性能上 CSS Selector 略快

## 三、CSS 的三种引入方式

### 【课程定义】

| 方式 | 写法 | 优先级 |
|------|------|--------|
| 内联样式 | `<p style="color:red">` | 最高 |
| 内部样式表 | `<style>p{color:red}</style>` | 中 |
| 外部样式表 | `<link rel="stylesheet" href="mystyle.css">` | 最低（可被覆盖） |

### 【为什么？】

三种方式对应三种测试关注点：

| 方式 | 测试关注点 |
|------|-----------|
| 内联样式 | 优先级最高，JS 动态插入的 style 会覆盖 CSS 文件 |
| 内部样式 | 测试环境临时改样式常用 |
| 外部样式 | 404 加载失败时页面无样式（常见 Bug） |

### 【企业场景】

> 用户反馈"页面突然变得很丑，没有样式"。你打开 F12 Network 面板，发现 `style.css` 返回 404——CDN 上文件丢了或者路径配错了。这就是外部样式表加载失败导致的经典 Bug。如果你不知道 CSS 有外部引用这回事，看到白板页面根本不知道从哪查起。

### 【易错点】

| 误区 | 正解 |
|------|------|
| 三种方式一样 | 优先级不同：内联 > 内部 > 外部，导致样式"改不动"时往上一级查 |
| 样式优先级只看书写顺序 | 实际上内联 > ID > Class > 标签，和书写顺序是两回事 |

## 四、CSS 常用属性速查

> 以下按测试频率排列，不需要背，但看到要知道是干什么的。

### 4.1 背景 (background)

| 属性 | 作用 | 测试场景 |
|------|------|---------|
| `background-color` | 背景色 | 颜色是否正确 |
| `background-image` | 背景图 | 图片是否加载 |
| `background-repeat` | 是否重复 | 背景填充效果 |
| `background-position` | 起始位置 | 背景图偏移 |

### 4.2 文本 (text)

| 属性 | 作用 | 测试场景 |
|------|------|---------|
| `color` | 文本颜色 | 链接色、警告色、品牌色是否正确 |
| `text-align` | 对齐（left/center/right） | 对齐是否符合设计稿 |
| `text-decoration` | 修饰线（下划线/删除线） | 链接是否有下划线 |
| `text-indent` | 首行缩进 | 长文本段落格式 |

### 4.3 字体 (font)

| 属性 | 作用 | 测试场景 |
|------|------|---------|
| `font-family` | 字体系列 | 中英文混排时字体是否统一 |
| `font-size` | 字体大小 | 层级是否清晰（h1 > h2 > p） |
| `font-weight` | 粗细（bold/normal） | 加粗是否正确 |
| `font-style` | 斜体 | 引用、强调文本 |

### 4.4 表格 (table)

| 属性 | 作用 |
|------|------|
| `border` | 表格边框 |
| `border-collapse` | 边框合并（单线 vs 双线） |
| `padding` | 单元格内边距 |

### 4.5 列表 (list)

| 属性 | 作用 |
|------|------|
| `list-style-type` | 列表标记类型（圆点/数字/无） |
| `list-style-image` | 用图片做标记 |

## 五、定位 (position)

### 【课程定义】

| 值 | 含义 | 参照物 |
|----|------|--------|
| `static` | 默认，正常文档流 | 无 |
| `relative` | 相对定位 | 自身原位置 |
| `absolute` | 绝对定位 | 最近的有定位的父元素 |
| `fixed` | 固定定位 | 浏览器窗口 |
| `sticky` | 粘性定位 | 滚动位置 |

### 【为什么？】

定位是 CSS 中最容易出 Bug 的领域，也是测试高频发现的问题：

| 测试场景 | 可能原因 |
|---------|---------|
| 弹窗不在屏幕中央 | absolute/fixed 定位计算错误 |
| 下拉菜单被遮挡 | z-index + 定位问题 |
| 页面滚动时元素跟着跑 | 该用 absolute 却用了 fixed |
| 固定导航栏与内容重叠 | fixed 元素未预留空间 |
| 元素消失了 | absolute 定位跑到了屏幕外 |

### 【必须掌握】

- 5 种定位的区别
- fixed 和 absolute 最容易混淆
- 能在 F12 中查看元素的 position 属性

### 【易错点】

| 易混淆 | 辨析 |
|--------|------|
| absolute vs fixed | absolute 相对父元素，fixed 相对浏览器窗口（滚动不变） |
| relative vs absolute | relative 占原位置（不脱离文档流），absolute 不占（脱离文档流） |
| sticky 是啥？ | 滚动到一定位置后"粘"住，常用于吸顶导航 |

### 【企业场景】

> 你测一个电商详情页，加购按钮在 iPhone 上被底部导航栏挡住了。F12 一看，按钮是 `position: fixed; bottom: 0`，但没考虑 iPhone 底部有安全区域（safe area）。这就是 fixed 定位在不同设备上的兼容问题。

## 六、盒子模型 (Box Model)

### 【课程定义】

```
┌──────────────────────────┐
│       Margin (外边距)     │  ← 透明，元素与元素之间的距离
│  ┌────────────────────┐  │
│  │   Border (边框)     │  │  ← 可见边框
│  │  ┌──────────────┐  │  │
│  │  │ Padding(内边距)│  │  │  ← 透明，内容到边框的距离
│  │  │  ┌────────┐  │  │  │
│  │  │  │Content │  │  │  │  ← 实际内容（文字/图片）
│  │  │  └────────┘  │  │  │
│  │  └──────────────┘  │  │
│  └────────────────────┘  │
└──────────────────────────┘
```

**一个元素的真实宽度 = content + padding + border + margin**

### 【为什么？】

盒子模型是所有布局 Bug 的根因分析工具：

| 现象 | 根因可能在 |
|------|----------|
| 两个元素之间间距不对 | margin 冲突（外边距合并） |
| 元素比预期宽 | padding/border 没算在 width 里 |
| 内容被裁剪 | overflow + 盒子太小 |
| 点击区域太小 | padding 不够 |
| border-box vs content-box | `box-sizing` 属性决定宽度计算方式 |

### 【必须掌握】

- 四层结构：content → padding → border → margin
- 能在 F12 的 Computed 面板查看元素的盒子模型
- `box-sizing: border-box` 让宽度包含 padding 和 border（更直观）

### 【企业场景】

> 设计稿要求按钮宽 200px，开发写 `width: 200px; padding: 10px; border: 2px`，你发现按钮实际宽度 224px（200 + 10×2 + 2×2）。因为默认 `box-sizing: content-box`（width 只算 content）。这就是经典"按钮对不齐"Bug 的根因。

## 七、网页布局

### 【基本概念】

CSS 布局方式决定了页面元素怎么排列。常见布局方案：

| 布局方式 | 关键词 | 测试关注点 |
|---------|--------|-----------|
| 普通流 | 默认从上到下 | — |
| 浮动 | `float: left/right` | 浮动元素是否撑开父容器、是否重叠 |
| 弹性布局 | `display: flex` | 响应式换行、元素对齐 |
| 网格布局 | `display: grid` | 复杂多列布局 |

### 【测试关注点】

布局测试的核心问题：

1. **响应式**：不同屏幕宽度下布局是否正常？
2. **元素重叠**：浮动/定位导致元素叠在一起？
3. **溢出**：内容超出容器是否被截断？
4. **对齐**：多列内容是否对齐？
