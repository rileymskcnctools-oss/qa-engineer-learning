## 一、什么是字符串

### 【课程原话/定义】

> 字符串是由引号包裹的任意字符组成的不可变序列，用于表示文本类型数据。

### 【为什么？】

测试工作中，你处理的 90% 的数据都是字符串——接口返回的 JSON、页面上的文本、Excel 里的用例数据、日志文件里的每一行。字符串操作能力直接决定你能多快地从一堆文本里提取出你要验证的那一行。**字符串不可变**意味着每次操作（替换、切割）都产生新字符串——这个特性看似"浪费内存"，实则保证了数据安全（不会意外改坏原始数据）。

### 【必须掌握】

- 三种引号定义方式及适用场景
- 不可变序列的含义（每次操作产生新对象）
- 下标访问和切片（最常用的两个操作）

### 【企业场景】

> 接口返回 `{"error": "密码不能少于6位"}`，你要断言错误提示文案是否正确——第一步是从 JSON 里取出字符串，第二步可能要做 `strip()` 去掉多余空格，第三步可能用 `in` 判断关键词是否存在。一个简单的文本断言背后是 3 种字符串操作的组合。

### 【面试考察】

> "Python 字符串是不可变的，这意味着什么？操作字符串时发生了什么？"

> 参考回答：不可变意味着字符串创建后就不能修改其中的某个字符。所有"修改"操作（replace、upper、strip 等）实际是创建并返回一个新字符串，原字符串不变。这样做的好处：① 线程安全（不会被意外修改）；② 可作为字典的 key；③ 字符串常量可以被 intern（缓存复用）。

### 【易错点】

| 易混淆 | 区别 |
|--------|------|
| 字符串不可变 ≠ 变量不能重新赋值 | `s = "a"; s = "b"` 合法——变量重新指向了新字符串，但 `"a"` 这个字符串对象本身没变 |
| 单引号/双引号/三引号 | 单双引号功能等价（方便字符串内含另一种引号）；三引号用于多行文本 |

## 二、字符串定义

### 【课程原话/定义】

> 使用单引号 `'...'`、双引号 `"..."` 或三引号 `"""..."""` 定义。

### 【为什么？】

三种引号解决一个实际问题：字符串内容本身可能包含引号。`"It's fine"` 不需要转义，因为外层双引号、内层单引号不会冲突。三引号解决多行文本——SQL 语句、HTML 模板、接口返回的 JSON，一行写不完。

### 【必须掌握】

```python
name = 'Alice'                    # 单引号
message = "Hello, world!"         # 双引号
sql = """select * from user
         where name='tom';"""     # 三引号（多行）
```

### 【易错点】

| 写法        | 结果                                     |
| --------- | -------------------------------------- |
| `'It's'`  | ❌ SyntaxError — 第一个 `'` 在 `'It'` 处就闭合了 |
| `"It's"`  | ✅ 外层双引号，内层单引号不冲突                       |
| `'It\'s'` | ✅ 转义单引号                                |

### 【我的理解】

## 三、转义字符

### 【课程原话/定义】

> 转义字符用于表示无法直接输入的特殊字符：`\n` 换行、`\t` 制表符、`\"` 双引号、`\\` 反斜杠。

### 【为什么？】

两个场景：① 你需要在字符串里放"不能直接打出来"的字符（换行、Tab）；② 你需要在字符串里放引号本身，但它和字符串边界冲突了。转义字符就是"告诉 Python：下一个字符有特殊含义"。

### 【必须掌握】

| 转义        | 含义    | 测试场景                        |
| --------- | ----- | --------------------------- |
| `\n`      | 换行    | 验证接口返回的多行文本格式               |
| `\t`      | Tab   | 解析 TSV/制表符分隔的测试数据           |
| `\\`      | 反斜杠本身 | Windows 路径 `C:\\Users\\...` |
| `\"` `\'` | 引号    | 构造含引号的 SQL/JSON 测试数据        |

### 【面试考察】

> "Windows 路径 `C:\Users\test` 在 Python 中怎么写？"

> 参考回答：要么用 `\\` 转义：`"C:\\Users\\test"`，要么用 raw string：`r"C:\Users\test"`。后者更常用于文件路径。

## 四、字符串下标（索引）

### 【课程原话/定义】

> 下标是从 0 开始的数字编号，通过 `字符串[下标]` 获取对应位置的字符。

### 【为什么？】

索引是"精准定位"的基础——你要取 URL 的第 5 个字符判断是不是 `s`（`https://`），你要取错误码的第 1 位判断是什么类型的错误。没有索引，你只能"知道字符串里有什么"，不能"拿到字符串里某个位置的东西"。

### 【必须掌握】

```python
s = "hello"
s[0]    # 'h' — 第一个字符
s[-1]   # 'o' — 最后一个字符（负索引从右数）
s[5]    # IndexError — 下标越界
```

### 【企业场景】

> 接口返回的订单号格式是 `ORD-20260714-001`，你要提取中间日期部分做时效性验证。`order_id[4:12]` 直接拿到 `20260714`——下标+切片是提取子串的核心手段。

### 【易错点】

| 错误                   | 原因                     |
| -------------------- | ---------------------- |
| `s[5]` 对 5 个字符的字符串报错 | 索引从 0 开始，5 个字符的下标是 0~4 |
| `s[1.0]` 报错          | 索引必须是整数，不能是浮点数         |

## 五、字符串操作速查总表

> 【必须掌握】所有操作都不改变原字符串，返回新字符串。

---

### 5.1 统计查找替换类

| 方法                         | 作用         | 找不到时             | 测试场景                  |
| -------------------------- | ---------- | ---------------- | --------------------- |
| `len(s)`                   | 字符个数       | —                | 验证返回数据长度（如手机号 11 位）   |
| `s.count(sub)`             | sub 出现次数   | 返回 0             | 统计接口返回中某个关键词出现次数      |
| `s.find(sub)`              | 返回第一次出现的索引 | 返回 **-1**        | 检查错误信息中是否包含某个关键词      |
| `s.index(sub)`             | 同 find     | 抛 **ValueError** | 需要明确报错的场景（数据必须含某值）    |
| `s.rfind(sub)`             | 从右侧查找      | 返回 -1            | 取文件扩展名：`s.rfind(".")` |
| `s.rindex(sub)`            | 从右侧查找      | 抛 ValueError     | 同上，但需要报错              |
| `s.replace(old, new, max)` | 替换         | 不匹配则不变           | 清理测试数据（把空格替换为下划线）     |

#### 【为什么 find 返回 -1 而 index 抛异常？】

两种设计哲学：`find` 是"问问看，没有就算了"（适合条件判断 `if s.find("error") != -1`）；`index` 是"我认为它一定在，不在就是数据有问题"（适合数据校验，尽早暴露异常）。测试中根据场景选——不确定有没有用 `find`，一定有但没找到说明被测系统有 Bug 用 `index`。

#### 【企业场景】

> 接口返回一段 HTML，你要判断登录按钮是否存在：`if html.find('<button id="login">') != -1: 点击登录`。

#### 【易错点】

| 方法 | 易错 |
|------|------|
| `find` vs `index` | 混用两个的返回值——`find` 找不到返回 -1，`if s.find("x")` 判断要写 `!= -1`，不能直接 `if s.find("x")`（因为找到在下标 0 时也会被当 False） |
| `replace` | 忘记赋值——`s.replace("a","b")` 不改变 s，要 `s = s.replace("a","b")` |

### 5.2 字符串判断类

| 方法 | 判断内容 | True 条件 | 测试场景 |
|------|---------|-----------|----------|
| `s.startswith(pre)` | 以 pre 开头 | 完全匹配开头 | 验证 URL 协议：`url.startswith("https://")` |
| `s.endswith(suf)` | 以 suf 结尾 | 完全匹配结尾 | 验证文件扩展名：`file.endswith(".json")` |
| `s.isalpha()` | 全字母 | 至少 1 字符且全是字母 | 验证姓名字段不包含数字 |
| `s.isdigit()` | 全数字 | 至少 1 字符且全是数字 | 验证手机号/验证码字段全是数字 |
| `s.isalnum()` | 全字母或数字 | 至少 1 字符且全是字母或数字 | 验证用户名（允许字母+数字） |
| `s.isspace()` | 全空白 | 至少 1 字符且全是空白 | 验证输入是否全是空格（无效输入） |
| `s.isupper()` | 全大写 | 至少 1 字母且都大写 | 验证状态码字段格式 |
| `s.islower()` | 全小写 | 至少 1 字母且都小写 | 验证 email 格式（通常全小写） |
| `s.istitle()` | 标题化 | 每个单词首字母大写 | 验证名字格式："John Smith" |

#### 【为什么？】

判断方法的命名很直白——但注意它们的返回边界。`"".isalpha()` 返回 `False`（空字符串不算"全字母"），`"abc123".isalpha()` 也返回 `False`（含数字）。这些细节是测试断言里的常见坑——你以为"空字符串"没字母所以"全字母"，但 Python 说"至少一个字符"。

#### 【企业场景】

> 注册接口测试：用户名要求"6-20位字母数字组合"。断言：`len(username) >= 6 and len(username) <= 20 and username.isalnum()`。但请注意——`isalnum()` 不排斥纯数字，如果要求"必须含字母"，需要额外判断：`not username.isdigit()`。

#### 【易错点】

| 代码 | 结果 | 为什么 |
|------|------|--------|
| `"".isalpha()` | `False` | 空字符串返回 False（所有 isxxx 都这样） |
| `"123".isalpha()` | `False` | 含数字 |
| `"abc123".isdigit()` | `False` | 含字母 |
| `" ".isspace()` | `True` | 空格是空白字符 |
| `"".isspace()` | `False` | 空字符串 |

### 【我的理解】

>

### 5.5 字符串去除空白类

| 方法 | 作用 | 测试场景 |
|------|------|----------|
| `s.strip()` | 去左右空白 | 接口返回数据清理（接口常带多余空格/换行） |

#### 【企业场景】

> 接口返回 `"  success  "`，你直接断言 `== "success"` 会失败——先 `response.strip()` 再比较。带 `chars` 参数时可以去掉指定字符：`s.strip("cba")` 从两端去掉 c/b/a 任意组合。

#### 【面试考察】

> "`strip()` 和 `replace(" ", "")` 有什么区别？"

> 参考回答：`strip()` 只去两端，中间的空白保留；`replace(" ", "")` 去所有空格。另外 `strip()` 不带参数时去掉的是空白字符（空格、`\t`、`\n`、`\r`），比替换空格更全面。

### 5.6 字符串分割类

| 方法 | 作用 | 测试场景 |
|------|------|----------|
| `s.split(sep, max)` | 按分隔符拆成列表 | **最常用**——解析 CSV、URL 参数、日志行 |
| `s.splitlines()` | 按换行符拆 | 解析多行文本（接口返回的文本块） |
| `s.partition(sep)` | 拆成 (前, 分隔符, 后) 三元组 | 精确拆分——只拆第一次出现的位置 |
| `s.rpartition(sep)` | 从右侧开始 partition | 取文件扩展名、"最后一个"分隔 |

#### 【为什么？】

`split` 返回列表，`partition` 返回三元组——选哪个取决于"你会不会丢掉分隔符"。拆分 URL `"https://test.com/api/v1"` 时，用 `split("/")` 你会失去 `/`，用 `partition("/")` 只会拆出第一段 `("https:", "/", "/test.com/api/v1")`。实际测试中 `split` 占 90%，`partition` 用于需要精确保留分隔符的场景。

#### 【企业场景】

> 接口返回 CSV 格式 `"id,name,age\n1,Alice,25\n2,Bob,30"`，先 `splitlines()` 拆行，再逐行 `split(",")` 拆字段。这是数据驱动测试的日常操作。

#### 【易错点】

| 代码 | 结果 | 注意 |
|------|------|------|
| `"a--b".split("-")` | `['a', '', 'b']` | 连续分隔符产生空字符串 |
| `"a-b".split("-+")` | `['a-b']` | 分隔符不匹配时，整个字符串作为唯一元素返回 |
| `"a b c".split()` | `['a','b','c']` | 不带参数时按任意空白分割且自动去空 |

### 【我的理解】

### 5.7 字符串连接类

| 方法 | 语法 | 说明 |
|------|------|------|
| `+` | `"a" + "b"` → `"ab"` | 两侧必须都是字符串 |
| `*` | `"-" * 10` → `"----------"` | 重复 N 次 |
| `join()` | `"-".join(["a","b"])` → `"a-b"` | **最常用**——用分隔符拼接可迭代对象 |

#### 【为什么？】

`join()` 比 `+` 效率高很多——`+` 每次创建新对象（字符串不可变），拼接 10000 次就是 10000 个临时对象。`join()` 一次性分配好内存。测试数据构造时：`",".join(user_list)` 生成 CSV 行，`"/".join(path_parts)` 拼接 URL。

#### 【企业场景】

> 构造测试 URL：`base_url = "https://api.test.com"`，`endpoint = "/users"`，`user_id = "123"`——`f"{base_url}{endpoint}/{user_id}"` 或 `"/".join([base_url, endpoint, user_id])`。

#### 【面试考察】

> "`+` 拼接 vs `join()` 拼接，性能差异大吗？为什么？"

> 参考回答：循环中用 `+` 拼接每次创建新字符串对象，O(n²) 复杂度；`join()` 预先计算总长度，一次分配内存，O(n)。少量拼接没区别，循环内拼接必须用 `join()`。

### 【我的理解】

>

## 六、切片操作

### 【课程原话/定义】

> 对字符串按指定范围截取，得到子字符串。格式：`str[start:end:step]`，不包含 end。

### 【为什么？】

切片是字符串操作中使用频率最高的技能——没有之一。取文件名去扩展名、取 URL 去掉协议前缀、取日志行的前 10 个字符、逆序输出字符串。**切片和索引一样，只定位不修改**。

### 【必须掌握】

```python
s = "abcdefg"

s[0:2]     # 'ab' — 下标 0~1，不含 2
s[:2]      # 'ab' — 省略 start = 从 0 开始
s[2:]      # 'cdefg' — 省略 end = 到末尾
s[:]       # 'abcdefg' — 完整拷贝
s[::2]     # 'aceg' — step=2，隔一个取一个
s[::-1]    # 'gfedcba' — 逆序（面试高频）
s[-3:-1]   # 'ef' — 负索引：从 -3 到 -2
s[-1:-3:-1]  # 'gf' — 负步长向右→左
```

### 【企业场景】

> 接口返回时间戳 `"2026-07-14T15:30:00"`，你要取日期部分断言：`timestamp[:10]` → `"2026-07-14"`。这是接口测试里最常写的切片——一行代码就够，不用 import datetime。

### 【面试考察】

> "如何用切片逆序一个字符串？`s[::-1]` 的原理是什么？"

> 参考回答：`[::-1]` 等价于 `[0:len(s):-1]`，step 为负表示从右向左遍历。`[::-1]` 是最简洁的字符串逆序写法，面试常考。

### 【易错点】

| 代码 | 结果 | 注意 |
|------|------|------|
| `s[0:5]` | 下标 0~4 的字符 | end 不包含——很多人忘记 |
| `s[5:0]` | `""` 空字符串 | start > end 且 step 为正 → 空 |
| `s[5:0:-1]` | 下标 5,4,3,2,1 | step 为负时 start > end 才有输出 |
| `s[0:100]` | 全部字符 | 越界不报错，自动截断到末尾 |

### 【我的理解】

## 七、字符串格式化

### 【课程原话/定义】

> 字符串格式化是将变量或值插入字符串的过程。Python 提供 `format()` 和 f-string 两种方式。

### 【为什么？】

测试中需要动态构造大量消息——断言失败的报错信息（"期望 200，实际 {}"）、用例标题（"test_login_{}_{}"）、请求参数模板。硬编码 = 每次改都要重写；格式化 = 把不变的部分写成模板，变的部分传参数。

### 【必须掌握】

```python
name, age = "Alice", 25

# format() — 传统方式
"{} is {} years old".format(name, age)        # 位置参数
"{0} is {1} years old".format(name, age)      # 索引参数
"{n} is {a} years old".format(n=name, a=age)  # 关键字参数

# f-string — 推荐方式 (Python 3.6+)
f"{name} is {age} years old"
f"PI={3.14159:.2f}"              # 保留两位小数
f"{'hello':>10}"                  # 右对齐，宽度10
f"{'PASS' if age>18 else 'FAIL'}"  # 表达式
f"{name.upper()}"                 # 函数调用
```

### 【为什么 f-string 优于 format()？】

可读性完胜——变量名直接出现在花括号里，不用去 format() 末尾对参数顺序。性能也更好（编译时优化，比 format() 快约 30%）。测试代码里无脑用 f-string。

### 【企业场景】

> 测试失败时的报错信息：`assert actual == expected, f"状态码错误：期望 {expected}，实际 {actual}，URL={url}"`。用 f-string 一行搞定，调试时一眼看出哪个用例、哪个参数出问题。

### 【面试考察】

> "Python 有哪些字符串格式化方式？你用什么？为什么？"

> 参考回答：① `%` 格式化（旧式，不推荐）；② `str.format()`（3.0 引入）；③ f-string（3.6 引入，推荐）。f-string 可读性最好、性能最优、支持表达式和函数调用。唯一限制是需要 Python 3.6+。

### 【格式化选项速查】

| 选项 | 示例 | 输出 |
|------|------|------|
| 宽度 | `f"{'ab':5}"` | `'ab   '` |
| 左对齐 | `f"{'ab':<5}"` | `'ab   '` |
| 右对齐 | `f"{'ab':>5}"` | `'   ab'` |
| 居中 | `f"{'ab':^5}"` | `' ab  '` |
| 小数精度 | `f"{3.14159:.2f}"` | `'3.14'` |
| 百分比 | `f"{0.85:.1%}"` | `'85.0%'` |
| 千位分隔 | `f"{10000:,}"` | `'10,000'` |
