## 一、两种编程范式

### 知识点 1：面向过程 vs 面向对象

【课程原话/定义】

| | 面向过程 | 面向对象 |
|------|------|------|
| **核心** | 过程/函数（做什么） | 对象（谁来做） |
| **数据与行为** | 分离——函数操作独立的数据 | 封装——数据和行为绑在一起 |
| **复用方式** | 封装函数 | 继承 + 多态 |
| **代表语言** | C、Fortran、Pascal | Java、C++、Python |
| **适用** | 简单任务、小项目 | 复杂系统、大项目 |

面向对象四大特性：封装、继承、多态、抽象。

【为什么？】
面向过程不是"落后"，面向对象不是"高级"——它们是解决不同类型问题的不同思维模式。写一个 50 行的小脚本，面向过程干净利落；写一个 5000 行的测试框架，面向对象帮你管理复杂度。

关键差异通过一个类比理解：
- 面向过程 = 写菜谱：步骤 1 洗菜、步骤 2 切菜、步骤 3 炒菜……
- 面向对象 = 分工合作：厨师负责炒菜、帮厨负责切菜、洗碗工负责清理

测试框架为什么都是面向对象的？因为测试用例有共性（都需要 setUp/tearDown/assert），用继承提取共性，每个用例只写差异部分——复用率极高。

【必须掌握】
- 面向过程：围绕"步骤和函数"
- 面向对象：围绕"对象和数据"
- 四大特性：封装、继承、多态、抽象
- 选型原则：小脚本→面向过程；大项目/框架→面向对象

【企业场景】
你刚开始学自动化测试时写的脚本（面向过程）：
```python
# 面向过程：一步步写操作
driver = webdriver.Chrome()
driver.get("https://example.com/login")
driver.find_element("id", "username").send_keys("admin")
driver.find_element("id", "password").send_keys("123456")
driver.find_element("id", "login-btn").click()
assert "Welcome" in driver.page_source
driver.quit()
```

学了 Pytest 之后（面向对象）：
```python
class TestLogin:
    def setup_method(self):
        self.driver = webdriver.Chrome()

    def test_valid_login(self):
        self.driver.get("https://example.com/login")
        # ... 操作
        assert "Welcome" in self.driver.page_source

    def teardown_method(self):
        self.driver.quit()
```
setUp/tearDown 自动复用——这就是面向对象的实际价值。

【面试考察】
面试官："面向过程和面向对象有什么区别？各适合什么场景？"

参考回答框架：
1. 面向过程 = 围绕"步骤/函数"组织代码，数据与函数分离
2. 面向对象 = 围绕"对象"组织代码，数据与方法绑定
3. 面向过程适合简单脚本和计算密集型任务
4. 面向对象适合复杂系统、测试框架、GUI 应用
5. 测试框架就是面向对象的典型案例（用例继承、共性复用）

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 认为 OOP 一定比面向过程好 | 盲目崇拜 OOP | 工具无优劣，场景决定选择 |
| 为了 OOP 而 OOP，写了一堆空类 | 不理解 OOP 解决什么问题 | 先有复用/封装需求，再引入类 |
| 学了 OOP 就把之前的函数全改成类 | 过度工程化 | 简单的工具函数不需要类 |

> （用自己的话解释面向过程和面向对象的区别，用你熟悉的日常生活中"分工合作"的例子类比）

## 二、类与对象

### 知识点 2：类是什么

【课程原话/定义】
类（Class）是定义现实事物属性和方法的**蓝图/模板**。类描述了事物的特征（属性）和行为（方法）。类是抽象的，不是具体存在的。

类由 **属性**（成员变量）和 **方法**（成员函数）组成。

Python 使用 `class` 关键字定义类：
```python
class ClassName:
    pass

# 或显式继承 object
class ClassName(object):
    pass
```

【为什么？】
类和对象的关系是"模具和产品"的关系。为什么需要模具？因为你要做 100 个相同结构的产品，没有模具你得手工一个个捏——慢且不一致。类就是代码世界的模具：

- `list` 是类，`[1, 2, 3]` 是对象
- `str` 是类，`"hello"` 是对象
- `dict` 是类，`{"a": 1}` 是对象

你早就在用类了，只是没意识到——你用的 `"hello".upper()` 就是在调用 str 类的方法。

【必须掌握】
- 类 = 模板/蓝图，对象 = 具体实例
- `class 类名:` 定义类，类名通常用大驼峰（PascalCase）
- 类包含属性（数据）和方法（函数）
- Python 所有类默认继承自 `object`

【企业场景】
测试框架中定义一个测试用例类：
```python
class TestCase:
    """测试用例模板"""
    def __init__(self, name):
        self.name = name
        self.result = None

    def run(self):
        """子类重写这个方法"""
        pass

    def report(self):
        return f"{self.name}: {self.result}"
```
所有具体的测试用例都继承这个模板，自动获得 `report()` 方法。

【面试考察】
面试官："类和对象的关系是什么？用生活中的例子说明。"

参考回答框架：
1. 类 = 模具/蓝图，对象 = 用模具生产出来的具体产品
2. 类定义"有什么属性、能做什么"，对象是"具体的值"
3. 一辆车的设计图纸（类） vs 停车场里的那辆红色宝马（对象）

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 把类和对象混为一谈 | 没理解抽象 vs 具体的区别 | 类 = 图纸，对象 = 实物 |
| 类名用小写 | 不符合 Python 规范 | 类名用 PascalCase：`TestLogin` |
| 在类定义时就想着"这跟函数有啥区别" | 拿面向过程的思维套 OOP | 从"数据+行为绑定"的角度重新理解 |

【我的理解】
> （用自己的语言定义"类"和"对象"，各举一个你已经用过的 Python 内置类和它的对象例子）

### 知识点 3：类的定义与实例化

【课程原话/定义】
定义类用 `class` 关键字。类中的函数叫**方法**，第一个参数必须是 `self`（约定名），指向调用该方法的实例对象。

实例化 = 用类创建对象：`对象名 = 类名()`

```python
class Plane(object):
    def flying(self, hour):
        print(f"飞机已飞行{hour} 小时。。。")

# 实例化两个对象
airPlane1 = Plane()
airPlane2 = Plane()

# 不同对象调用同一个方法
airPlane1.flying(3)    # 飞机已飞行3 小时。。。
airPlane1.flying(5)    # 飞机已飞行5 小时。。。
airPlane2.flying(3)    # 飞机已飞行3 小时。。。
```

【为什么？】
`self` 是理解面向对象的第一道坎。为什么方法里要写 `self`？

因为同一个类可以有多个对象。当你写 `airPlane1.flying(3)` 时，Python 背后做了 `Plane.flying(airPlane1, 3)`——`self` 就是 `airPlane1`。`self` 让方法知道"是哪个对象在调用我"。

没有 `self`，方法里的代码无法区分 `airPlane1` 还是 `airPlane2` 调用了它。

类比：你在餐厅点菜，服务员（方法）需要知道是哪桌（self）点的——"给我来份牛排"不够，需要"3 号桌来份牛排"。

【必须掌握】
- `class 类名:` 定义类
- 类中方法的第一个参数是 `self`
- `self` 指向调用该方法的实例对象
- 实例化：`对象 = 类名()`
- 调用方法：`对象.方法(参数)`，不需要传 self，Python 自动传

【企业场景】
测试中定义多个浏览器实例：
```python
class Browser:
    def __init__(self, name):
        self.name = name

    def open(self, url):
        print(f"{self.name} 浏览器打开 {url}")

chrome = Browser("Chrome")
firefox = Browser("Firefox")

chrome.open("https://test.com")     # Chrome 浏览器打开 https://test.com
firefox.open("https://test.com")    # Firefox 浏览器打开 https://test.com
```
两个独立的对象，各有各的 `name`，调用同一个 `open` 方法——self 自动区分。

【面试考察】
面试官："类方法里的 `self` 是什么？为什么每个方法都要写？"

参考回答框架：
1. `self` 指向调用方法的实例对象本身
2. 必须写是因为同一个类的不同对象调用方法时，需要通过 self 区分
3. Python 自动传递 self，调用时不需要手动传
4. `self` 是约定名，不是关键字（但不要改）

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 方法定义时忘记写 self | 不理解 self 的作用 | 类中方法第一个参数永远是 self |
| 调用时手动传了 self | 以为需要显式传 | 只需 `obj.method(arg)`，Python 自动传 self |
| 类定义后忘记括号：`obj = Plane` | 这是把类赋值给变量，不是实例化 | 必须加括号：`obj = Plane()` |
