## 一、什么是分支语句

### 知识点 1：为什么程序需要分支

【课程原话/定义】
程序中的选择语句，也称为条件语句，即按照条件选择执行不同的代码片段。Python 中有 3 种形式：`if`、`if...else`、`if...elif...else`。

【为什么？】
程序如果没有分支，就只能从头到尾直线执行——这叫"脚本"，不叫"程序"。测试中你需要的"如果登录成功则继续，否则报错"、"如果是 200 则解析 JSON，如果是 500 则重试"，这些都是分支。分支是程序"智能"的最小单位——根据输入做出不同反应。

【必须掌握】
- 三种形式：`if`（可选执行）、`if...else`（二选一）、`if...elif...else`（多选一）
- 所有分支依赖条件表达式的布尔值（True/False）

【企业场景】
> 接口自动化中，每个断言都是隐式的分支——框架内部就是 `if actual != expected: raise AssertionError`。你写的 `if response.status_code == 200: parse() else: log_error()` 也是分支。没有分支就没有测试逻辑。

【面试考察】
> 面试官："Python 中条件语句有哪几种？各适用于什么场景？"
> 参考回答：三种。`if` 适用于"满足条件才执行"（可选操作）；`if...else` 适用于二选一；`if...elif...else` 适用于多选一（如 HTTP 状态码处理：200/301/404/500 不同处理）。

【我的理解】

## 二、if 条件判断

### 知识点 2：if 语句

【课程原话/定义】

```python
if 表达式:
    语句块
```

如果表达式为真，执行语句块；为假则跳过。相当于汉语的"如果……就……"。

【为什么？】
`if` 是最简分支——只关心"条件满足时做什么"，不满足就什么都不做。Python 使用缩进而非花括号来界定语句块范围，这迫使代码视觉上统一、减少"悬挂 else"类 Bug。冒号 `:` 是语法要求——告诉解释器"下面是一个新的代码块"。

【必须掌握】
- 表达式后面必须有冒号 `:`
- 语句块必须缩进（4 个空格，PEP 8 标准）
- 条件为假时，语句块被完全跳过

【企业场景】
> 测试脚本中：`if not response.ok: print(f"警告：接口返回 {response.status_code}")`——只记录异常不中断执行。或者环境检查：`if not os.path.exists("config.yaml"): raise FileNotFoundError("配置文件缺失")`。

【面试考察】
> 面试官："Python 中 if 语句的缩进可以用 2 个空格吗？"
> 参考回答：语法上可以（只要同一块内一致），但 PEP 8 强制推荐 4 个空格。团队协作中缩进不一致会导致 `IndentationError` 或更可怕的逻辑错误（看起来在 if 里面，实际在外面）。

【易错点】

| 写法                      | 结果                             |
| ----------------------- | ------------------------------ |
| `if x == 1 print("ok")` | `SyntaxError`：缺少冒号             |
| `if x == 1:` 下一行没缩进     | `IndentationError`             |
| `if x = 1:`             | `SyntaxError`：`=` 是赋值，`==` 是比较 |

## 三、if...else 判断语句

### 知识点 3：if...else

【课程原话/定义】

```python
if 表达式:
    语句块1
else:
    语句块2
```

满足条件执行语句块1，否则执行语句块2。相当于汉语的"如果……否则……"。二选一，必走其中一个。

【为什么？】
`if...else` 保证"必然执行一个分支"——这在测试中断言场景非常重要：要么通过要么失败，没有第三种可能。`else` 是兜底逻辑，即使你没预料到的情况也会被捕获（好事也是坏事——可能掩盖意外情况，所以后面有 `elif`）。

【必须掌握】
- `else` 后面也有冒号
- `else` 不能单独使用，必须跟在 `if` 后面
- 两个分支必然执行一个

【企业场景】
> 登录测试：`if response.status_code == 200: print("登录成功") else: print(f"登录失败：{response.text}")`。断言判断：`if actual == expected: test_result = "PASS" else: test_result = "FAIL"`。

【面试考察】
> 面试官："`else` 可以省略吗？什么时候省略？"
> 参考回答：可以省略——`else` 不是必须的。当"不满足条件时什么都不做"是合理行为时就省略。比如 `if debug: print(response.text)`，非 debug 模式不需要 else 分支。

## 四、if...elif...else 多重条件

### 知识点 4：if...elif...else

【课程原话/定义】

```python
if 表达式1:
    语句块1
elif 表达式2:
    语句块2
elif 表达式3:
    语句块3
else:
    语句块n
```

从上到下依次检查每个表达式，第一个为真的被执行，后续跳过。所有都为假时执行 else（如果有）。相当于"如果……否则如果……否则……"。

【为什么？】
多分支用 `elif` 而不是多个独立的 `if`，核心原因是**互斥**——多个 `if` 会每个都检查（可能执行多次），`if...elif` 只执行第一个匹配的（执行完就跳出整个结构）。测试中处理状态码这种互斥场景，必须用 `elif`。如果用多个 `if`，`code == 200` 和 `code >= 200` 都会匹配，产生重复处理。

【必须掌握】
- `elif` 可以有任意多个
- 只有一个分支会被执行（第一个为真的）
- `else` 可选，兜底所有未匹配的情况
- `elif` 不能单独出现，必须在 `if` 之后

【企业场景】
> HTTP 状态码分流处理：
> ```python
> if code == 200:
>     parse_response()
> elif code == 301:
>     follow_redirect()
> elif code == 401:
>     refresh_token()
> elif code == 500:
>     retry_or_fail()
> else:
>     log_unexpected(code)
> ```

> 测试用例优先级分流：
> ```python
> if priority == "P0":
>     run_immediately()
> elif priority == "P1":
>     add_to_queue()
> elif priority == "P2":
>     schedule_later()
> else:
>     skip()
> ```

【面试考察】
> 面试官："多个 `elif` 和多个 `if` 有什么区别？什么时候不能互换？"
> 参考回答：多个 `if` 是独立判断，每个都执行条件检查，可能多个块都被执行；`if...elif` 是互斥的，只执行第一个匹配的。处理互斥条件（如状态码、错误类型）时必须用 `elif`。比如 `if x > 0: ... if x > 10: ...` 中 x=20 两个都会执行，而 `if x > 0: ... elif x > 10: ...` 中 x=20 只执行第一个。

【易错点】

| 写法 | x=5 时的结果 | 问题 |
|------|------------|------|
| 三个独立的 `if` | | |
| `if...elif...else` | | |

```python
# 动手验证这两个的区别：
x = 20

# 写法A：多个独立的 if
if x > 0:
    print("正数")
if x > 10:
    print("大于10")
if x > 100:
    print("大于100")
# 输出几行？

# 写法B：if...elif
if x > 0:
    print("正数")
elif x > 10:
    print("大于10")
elif x > 100:
    print("大于100")
# 输出几行？
```

## 五、分支嵌套

### 知识点 5：分支嵌套

【课程原话/定义】
三种 if 语句可以互相嵌套。可以在 if、else、elif 内部再嵌套任意形式的分支。关键是控制好缩进层级。

【为什么？】
单层分支解决简单的"是/否"问题，现实中的测试逻辑往往是多层的：先判断环境（是否有网络），再判断操作（登录是否成功），再判断结果（数据是否正确）。嵌套分支让代码能表达复杂决策树。但嵌套太深（超过 3 层）是代码坏味道——通常意味着应该拆成函数。

【必须掌握】
- 每层缩进 4 个空格，层级清晰
- 嵌套不超过 3 层为宜（超过则考虑提取函数）
- 嵌套的 `else` 属于最近的 `if`（"悬挂 else"问题）

【企业场景】
> 接口测试中的多级判断：
> ```python
> if response.status_code == 200:
>     data = response.json()
>     if data.get("code") == 0:
>         if len(data["data"]["items"]) > 0:
>             verify_items(data["data"]["items"])
>         else:
>             print("返回数据为空")
>     else:
>         print(f"业务错误：{data.get('message')}")
> else:
>     print(f"HTTP错误：{response.status_code}")
> ```

> 这是测试中最典型的嵌套模式：外层判断 HTTP 状态 → 中层判断业务状态码 → 内层判断数据内容。

【面试考察】
> 面试官："Python 中 else 属于哪个 if？怎么避免歧义？"
> 参考回答：`else` 属于最近的、同缩进级别的 `if`。Python 用缩进消除歧义（不像 C 语言有"悬挂 else"问题需要花括号）。但嵌套深了仍然容易看错——建议超过 3 层就提取函数。

【易错点】

| 问题 | 怎么避免 |
|------|---------|
| 缩进层级太多，眼睛看花 | IDE 显示缩进线，超过 3 层提取函数 |
| `else` 对错了 `if` | 看缩进对齐的 if |
| 忘记写 `else` 导致无兜底 | 关键的判断留一个 else 打日志"未预期的分支" |
| `elif` 和 `else` 混在嵌套中分不清层级 | 每个分支哪怕只有一行也写完整缩进结构 |

## 六、综合对比

### 知识点 6：三种分支形式对比

| 形式 | 分支数 | 是否必须执行某个分支 | 典型测试场景 |
|------|--------|-------------------|-------------|
| `if` | 0 或 1 | 否 | 条件日志、环境检查、debug 模式 |
| `if...else` | 必执行 1 个 | 是 | 断言通过/失败、登录成功/失败 |
| `if...elif...else` | 必执行 1 个（有 else 时） | 是 | HTTP 状态码分流、错误类型处理 |
