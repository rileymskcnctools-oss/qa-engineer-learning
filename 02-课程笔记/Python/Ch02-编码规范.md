# Ch02 - 编码规范

## 1. 知识点理解

> 一句话解释：PEP8 是 Python 官方代码风格指南，让所有人写的 Python 代码看起来像同一个人写的。

| 维度          | 说明                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| **一句话解释**   | 缩进、注释、命名的统一规则，让代码易读易维护                                                                                |
| **为什么需要**   | Guido 的核心洞察：代码被**读**的次数远多于被**写**的次数。你写的测试脚本 3 个月后自己都看不懂，更别说同事接手                                       |
| **在测试中的作用** | 测试脚本通常是"写完就跑，偶尔改"。命名清晰 + 注释到位 = 下次改参数时不用从头读代码。而且 Pytest 通过函数名发现测试用例——`test_login` 能被识别，`TestLogin` 不能 |

## 2. Python 语法

### 2.1 缩进

#### 语法格式

```python
# Python 用缩进（不是大括号）定义代码块
# 同一级代码块缩进量必须一致
# 推荐：4 个空格（或 Tab 键）
```

#### 示例代码

```python
class Student:
    def __init__(self, name, age):   # ← 4空格缩进
        self.name = name              # ← 8空格缩进
        self.age = age

    def info(self):                   # ← 4空格缩进（和 __init__ 同级）
        print(f"Name: {self.name}")   # ← 8空格缩进
        if self.age >= 18:            # ← 8空格缩进
            print("已成年")            # ← 12空格缩进
        else:                         # ← 8空格缩进（和 if 同级）
            print("未成年")            # ← 12空格缩进
```

#### 代码解释

| 行 | 作用 |
|----|------|
| `class Student:` | 顶格，类定义 |
| `def __init__` | 缩进 4 格，类的方法 |
| `self.name = ...` | 缩进 8 格，方法内的语句 |
| `if/else` | 缩进 8 格（和 `self.age` 同级） |
| `print("已成年")` | 缩进 12 格（if 内的语句） |

#### 测试中怎么看缩进

```python
# 一个测试用例的缩进层次
def test_login_success():              # 0 缩进
    response = login("admin", "123")   # 4 缩进
    assert response["code"] == 200     # 4 缩进
    if response["data"]:               # 4 缩进
        assert response["data"]["name"] == "admin"  # 8 缩进
```

### 2.2 注释

#### 语法格式

```python
# 1. 单行注释：用 #
# 2. 多行注释：用三个引号 ''' 或 """
# 3. 文档注释：函数/类下面的 """..."""（也叫 docstring）
```

#### 示例代码

```python
# 单行注释：这是一条单行注释

"""
多行注释：用三引号包裹
可以写多行
Python 解释器会忽略这些内容
"""

def login(username, password):
    """
    用户登录函数

    Args:
        username: 用户名
        password: 密码

    Returns:
        dict: {"code": 200, "msg": "success"}
    """
    return {"code": 200, "msg": "success"}
```

#### 代码解释

| 行 | 作用 |
|----|------|
| `# 单行注释` | 单行，`#` 后跟一个空格再写内容（PEP8 建议） |
| `"""..."""` | 多行注释或 docstring，不会被解释器执行 |
| `def login(...):` 下的 `"""..."""` | 文档注释，解释函数做什么、参数是什么、返回什么 |

### 2.3 命名规范

#### 语法格式

| 类型 | 规则 | 示例 |
|------|------|------|
| 包名 | 全小写，短，不推荐下划线 | `testutils` |
| 模块名 | 全小写，可用下划线 | `test_login.py` |
| 类名 | Pascal（每个单词首字母大写） | `TestLogin`, `HttpClient` |
| 常量 | 全大写 + 下划线 | `BASE_URL`, `MAX_RETRY` |
| 变量/函数 | 全小写 + 下划线 | `test_login()`, `user_name` |
| 受保护 | 单下划线 `_` 开头 | `_internal_helper()` |
| 私有 | 双下划线 `__` 开头 | `__private_method()` |

#### 示例代码

```python
# 常量：全大写
BASE_URL = "http://api.example.com"
MAX_TIMEOUT = 30

# 变量：小写 + 下划线
user_name = "admin"
login_count = 0

# 函数：小写 + 下划线
def test_login_success():
    pass

def get_user_info(user_id):
    pass

# 类：Pascal
class TestLogin:
    def test_with_valid_user(self):
        pass

# 受保护（单下划线）：别从外部调
def _generate_token():
    pass

# 私有（双下划线）：类内部专用
class Database:
    def __connect(self):
        pass
```

#### 代码解释

| 行 | 规则 | 为什么这样命名 |
|----|------|-------------|
| `BASE_URL` | 常量，全大写 | 一眼看出这是配置，不是变量 |
| `test_login_success` | 函数，小写+下划线 | Pytest 识别 `test_` 前缀自动发现用例 |
| `TestLogin` | 类，Pascal | Pytest 中类名以 `Test` 开头才会被执行 |
| `_generate_token` | 受保护 | 提示"这是内部函数，外部调用后果自负" |
| `__connect` | 私有 | 只有类自己能用，防止外部误调用 |

## 3. 测试应用场景

| 场景 | 怎么用 | 对应阶段 |
|------|--------|---------|
| 测试用例 | 函数命名用 `test_` 前缀（Pytest 发现规则）；常量用大写（BASE_URL 一眼识别） | 目前 |
| 自动化脚本 | 文档注释写清楚每个函数的输入输出，换人维护时不费劲 | 后续 |
| Pytest 集成 | Pytest 靠命名发现用例：`test_` 函数 + `Test` 类 + `test_` 方法，命名不规范 = 用例不执行 | 后续 |

> 说明：目前只需要关注「测试用例」列，自动化/Pytest 是后续学习内容，此处先建立印象。

## 4. 易错点

| 常见错误 | 错误原因 | 解决方法 |
|---------|---------|---------|
| 缩进混用空格和 Tab | 有的行用 Tab，有的行用 4 空格，Python 报 `IndentationError` | PyCharm: `Ctrl+Alt+L` 一键统一 |
| 缩进层级不对 | `if` 后面的 `print` 没缩进，或缩进多了 | 看到 `IndentationError: expected an indented block` 就是这事 |
| 忘了写注释 | "代码就是最好的注释"——3 个月后自己不这么想 | 每个函数至少写一行 docstring |
| `#` 和注释内容之间没空格 | `#注释` 不符合 PEP8 | PyCharm 会灰线提示，写 `# 注释` |
| 函数命名用驼峰 | `testLogin()` 不是 Python 风格 | 用 `test_login()`，Pytest 也推荐这种格式 |
| 常量用小写 | `base_url = "..."` 看起来像普通变量 | 常量用 `BASE_URL`，一眼识别 |

## 6. 自动化关联

| 关联框架 | 关系说明 | 学到时会怎么用 |
|---------|---------|--------------|
| **Pytest** | Pytest 靠命名发现用例（`test_` 函数、`Test` 类），命名不规范直接不执行 | 写 `def test_login():` 而不是 `def loginTest():` |
| **Selenium** | Selenium 脚本通常较长，docstring 和行注释是救命稻草 | 几百行浏览器操作脚本，没注释 = 天书 |
| **Playwright** | Playwright 自动生成代码，但生产脚本要自己整理成 PEP8 风格 | `playwright codegen` 生成的代码格式可能乱，需要 `Ctrl+Alt+L` |

## 7. 面试输出

> 30 秒能说完的回答。

**问题：说说你对 PEP8 的理解，工作中怎么遵守？**

**回答：** PEP8 是 Python 官方代码风格指南，核心是可读性。我主要关注三点：① 缩进统一用 4 空格，同级代码对齐；② 命名规范——函数/变量用 `snake_case`，类用 `PascalCase`，常量全大写；③ 函数加 docstring 说明输入输出。PyCharm 的 `Ctrl+Alt+L` 一键格式化 + PEP8 实时检查灰线提示，基本不会写出风格违规的代码。
