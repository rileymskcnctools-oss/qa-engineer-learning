## 一、LEGB 规则

### 知识点 1：变量查找的四层作用域

【课程原话/定义】
Python 变量的访问权限取决于变量在哪里赋值。作用域分为 4 层，从内到外查找：

| 层级  | 缩写            | 含义            | 示例                    |
| --- | ------------- | ------------- | --------------------- |
| 最内层 | L (Local)     | 函数内部定义的变量     | `def f(): x=1`        |
| 第二层 | E (Enclosing) | 外层函数的局部变量（闭包） | 嵌套函数中内层访问外层           |
| 第三层 | G (Global)    | 模块级全局变量       | 文件顶层 `x = 1`          |
| 最外层 | B (Built-in)  | Python 内置的名字  | `print`、`len`、`range` |

查找顺序：**L → E → G → B**。在任意一层找到就停止，全找不到就报 `NameError`。

【为什么？】
LEGB 规则不是 Python 拍脑袋定的——它解决了"同名变量该用哪个"的经典问题。内层优先，意味着函数的局部变量不会意外被外层同名变量覆盖，这是**封装**的基础。如果反过来（外层优先），那你写的每个函数都要担心有没有人在外面定义过相同的变量名——函数也就不再是独立单元了。

另一层深意：B（Built-in）在最外层。这意味着你可以在函数内直接写 `print(x)` 而不需要导入任何东西——Python 帮你兜底查到最后。

【必须掌握】
- 4 层：Local → Enclosing → Global → Built-in
- 内层优先，找到即停
- 全找不到 → NameError
- Built-in 层包含 `print`、`len`、`range` 等，你写的代码可以覆盖它们（不推荐）

【企业场景】
你在调试测试脚本时，发现函数内的 `print` 行为异常——原来有人在前面定义了一个局部变量也叫 `print`：
```python
def test():
    print = "debug mode"    # 局部变量 print 覆盖了 built-in print
    print("hello")          # TypeError: 'str' object is not callable
```
这就是 LEGB 规则的实际影响——局部 `print` 比 Built-in `print` 先被找到，导致内置函数被"影子遮蔽"（shadowing）。

【面试考察】
面试官："Python 的 LEGB 规则是什么？"

参考回答框架：
1. L=Local（函数内）、E=Enclosing（外层函数）、G=Global（模块级）、B=Built-in（内置）
2. 查找顺序：L → E → G → B，内层优先
3. 举例：函数内 `x=1`（L），模块顶层 `x=2`（G），函数内用 1
4. 找不到报 NameError

【易错点】

| 常见错误            | 错误原因                      | 正确做法                |
| --------------- | ------------------------- | ------------------- |
| 以为全局变量一定比局部优先级高 | 不理解 LEGB 内层优先原则           | 记口诀：L→E→G→B，越往里越优先  |
| 误覆盖 Built-in 名字 | 定义了叫 `list`、`print` 的局部变量 | 避免用 Python 内置名做变量名  |
| 忘记 Enclosing 层  | 只记得 L、G、B 三层              | 嵌套函数场景才用到 E，但面试要能说出 |

## 二、局部变量

### 知识点 2：局部变量的生命周期

【课程原话/定义】
局部变量在函数内部定义，只在函数内部有效。函数被调用时创建，函数执行结束后销毁。函数外部无法访问。

```python
def show():
    a = 10          # 局部变量：show() 被调用时创建
    print(a)        # 函数内部可以访问

show()              # 输出 10
# print(a)          # NameError: name 'a' is not defined
```

【为什么？】
局部变量的"用完即毁"是保护机制，不是限制。如果函数执行完后变量一直留着，那：
- 调用 1000 次函数就会留下 1000 份数据，内存爆炸
- 不同函数之间的变量可能互相干扰

Python 用"调用时创建、返回时销毁"保证了函数是自清洁的——你来过，你走了，什么都不留下。这让测试变得可靠：每次调用函数都是干净的开始。

【必须掌握】
- 局部变量只在函数内部有效
- 函数调用时创建，执行结束销毁
- 函数外访问 → NameError
- 不同函数可以有同名局部变量，互不影响

【企业场景】
你在写测试用例，每个测试函数有自己独立的测试数据：
```python
def test_login():
    username = "test_user_001"    # test_login 的局部变量
    password = "pass123"
    # 执行登录测试...

def test_order():
    username = "test_user_002"    # test_order 的局部变量，和上面互不影响
    # 执行订单测试...
```
两个函数都有 `username`，但因为都是局部变量，在各自的作用域内独立存在，不会互相覆盖。

【面试考察】
面试官："局部变量什么时候被创建？什么时候被销毁？"

参考回答框架：
1. 创建：函数被调用时，进入函数体
2. 销毁：函数执行结束（return 或异常退出）
3. 设计目的：封装 + 内存管理

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 函数外访问局部变量 | 以为函数执行完变量还在 | 需要外部用的值用 return 返回 |
| 不同函数用同名局部变量以为会冲突 | 不理解作用域隔离 | 放心用——各自独立 |
| 函数内修改全局变量不声明 global | 以为赋值就能改全局 | 见下节 global 关键字 |

【我的理解】
> （写一个函数，内部创建局部变量并 return。然后用 return 的值在外面使用。验证直接访问局部变量报 NameError）

## 三、全局变量

### 知识点 3：全局变量的定义和使用

【课程原话/定义】
定义在函数外部的变量为全局变量，可以在当前程序文件的任何位置访问（读写）。

```python
m = 20          # 全局变量

def show1():
    print("show1:", m)   # 读取全局变量 ✓

def show2():
    print("show2:", m)   # 读取全局变量 ✓

print(m)        # 20
show1()         # show1: 20
show2()         # show2: 20
```

【为什么？】
全局变量解决的问题是"多个函数都需要同一个数据"。比如 API 的基础 URL、数据库连接配置、当前登录用户——这些数据如果每个函数都作为参数传来传去，代码会非常啰嗦。

但代价也很明显：全局变量让函数不再"自给自足"。一个函数偷偷改了全局变量，另一个函数的行为就变了——而且排查困难。这就是为什么"尽量少用全局变量"是编程界的共识。

【必须掌握】
- 全局变量：定义在函数外部，全文件可访问
- 函数内**读取**全局变量：直接读
- 函数内**修改**全局变量：必须用 `global` 声明
- 不用 `global` 直接赋值 → 创建同名局部变量（屏蔽全局）

【企业场景】
测试框架中的全局配置：
```python
BASE_URL = "https://api.example.com"
API_VERSION = "v2"
TIMEOUT = 30

def test_login():
    url = f"{BASE_URL}/{API_VERSION}/login"  # 读取全局配置
    # ...

def test_search():
    url = f"{BASE_URL}/{API_VERSION}/search" # 同样使用
    # ...
```
这里用全局变量是合理的——配置是所有测试共享的、不会在运行时被修改的常量。

【面试考察】
面试官："函数内部能修改全局变量吗？怎么修改？"

参考回答框架：
1. 直接 `x = 值` 不会修改全局变量，会创建同名局部变量
2. 必须 `global x` 声明后才能修改
3. 这是 Python 的保护机制，防止意外修改全局变量
4. 尽量少用 global，改用参数传递

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 函数内 `m = new_value` 以为改了全局 | 没声明 global，创建了同名局部变量 | 加 `global m` |
| 过度使用全局变量 | 图方便，到处共享 | 能用参数传递就用参数传递 |
| 多个函数修改同一个全局变量 | 执行顺序决定结果，难以调试 | 全局变量只放"常量"，不放"可变状态" |

【我的理解】
> （写代码演示：函数内不声明 global 直接对全局变量赋值，对比声明 global 后赋值，用 print 展示全局变量的值是否变了）

### 知识点 4：同名变量屏蔽

【课程原话/定义】
当全局变量和局部变量同名时，根据 LEGB 规则，内部局部变量会**屏蔽**外部全局变量。

```python
m = 10           # 全局变量

def show():
    m = "ABC"    # 创建局部变量 m，屏蔽全局 m
    print("show:", m)  # 用局部 m

print(m)          # 10（全局）
show()            # show: ABC（局部屏蔽全局）
print(m)          # 10（全局未被修改）
```

【为什么？】
"屏蔽"是 LEGB 规则的自然结果——内层先找到就停。这不是 bug，是设计决定。好处是：你在函数内部定义变量时，不用纠结外面有没有同名的——Python 保证你会用你刚定义的那个。

但这也意味着：如果你想修改全局变量，直接赋值 `m = "ABC"` 达不到目的——你只是创建了同名局部变量。这时必须用 `global`。

【必须掌握】
- 同名时：函数内部用局部变量，外部用全局变量
- 函数内 `m = 值` → 创建局部 m，不是修改全局 m
- 函数内 `print(m)` → 先找局部 m，没有才找全局 m
- `m = 值` 和 读取 `m` 的不同：赋值创建局部，读取沿 LEGB 查找

【企业场景】
测试中一个常见 bug：
```python
test_count = 0

def run_test():
    test_count = test_count + 1   # UnboundLocalError!
    # ...
```
你以为是"读取全局 test_count + 1 再赋值"，但 Python 看到函数内有 `test_count =` 的赋值，就把整个函数内的 `test_count` 当作局部变量。然后 `test_count + 1` 时局部变量还没赋值 → 报错。

正确做法是 `global test_count` 声明。

【面试考察】
面试官："全局变量和局部变量同名时，函数内部用哪个？怎么修改全局变量？"

参考回答框架：
1. 函数内部优先使用局部变量（LEGB 内层优先）
2. 读取：没局部找全局
3. 赋值：直接赋值创建局部变量；要修改全局必须 `global`
4. 演示屏蔽现象：同名时内外互不影响

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为 `m = 新值` 能修改全局 m | 不理解赋值=创建局部变量的机制 | 加 `global m` |
| `print(m)` 能读全局，但 `m += 1` 报错 | `+=` 包含赋值，触发了局部变量规则 | 需要修改全局时统一声明 global |
| 函数内部 `m = m + 1` 报 UnboundLocalError | Python 看到赋值就把 m 当局部变量 | `global m` 或在外部传参 |

【我的理解】
> （写代码演示"屏蔽"：同名变量在函数内外各有不同值。然后修改为用 global 的版本，对比结果差异）

### 知识点 5：global 关键字

【课程原话/定义】
`global` 关键字用于在函数内部声明"这个变量是全局变量"，之后对该变量的赋值会直接修改全局变量。

```python
m = 10

def show():
    global m          # 声明 m 是全局变量
    m = "ABC"         # 修改全局 m
    print("show:", m)

print(m)              # 10
show()                # show: ABC
print(m)              # ABC（全局被修改了！）
```

【为什么？】
Python 的设计哲学是"默认安全"：函数内部的赋值默认创建局部变量，防止不小心破坏全局状态。如果你明确要改全局变量，必须显式声明 `global`——相当于你对 Python 说"我知道我在做什么"。

这个设计在测试中很有用：它迫使你思考"真的要改全局吗？"——通常更好的方式是传参 + return。`global` 存在的意义是给少数合理场景（如全局计数器、配置热更新）一条路，而不是鼓励你滥用。

【必须掌握】
- `global 变量名` 声明该变量是全局变量
- 声明后，函数内对该变量的赋值直接作用于全局
- 不加 global 直接赋值 → 创建局部变量
- 可以一次声明多个：`global a, b, c`
- global 应尽量少用

【企业场景】
维护一个测试执行计数器：
```python
passed = 0
failed = 0

def run_and_count(test_case):
    global passed, failed
    result = execute(test_case)
    if result == "PASS":
        passed += 1
    else:
        failed += 1

for case in test_suite:
    run_and_count(case)

print(f"通过: {passed}, 失败: {failed}")
```
这是一个有限合理的使用场景——多个测试共用两个计数器，用 global 比传参 + 返回更简洁。但更优雅的做法是用类封装状态（面向对象），这是后续学习的内容。

【面试考察】
面试官："不用 global 能不能修改全局变量？为什么要有 global？"

参考回答框架：
1. 不声明 global 的赋值 = 创建局部变量，改不了全局
2. 可变对象（列表、字典）可以直接修改内容（`.append()` 等），但不能重新赋值
3. global 是 Python 安全设计的一部分——默认保护全局变量
4. 但这不意味着鼓励用 global——是"给你工具，但慎用"

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为不用 global 也能改全局 | 混淆了"读取全局"和"赋值给全局" | 记：读不需要 global，改（赋值）需要 |
| 全局的列表/字典用 `.append()` 改内容，以为是 global 的效果 | 修改可变对象内容不算"重新赋值" | 这不叫改了全局变量，这叫改了变量指向的对象 |
| 在多个函数里用 global 改同一个变量 | 代码耦合度高，难维护 | 考虑用类封装或传参 |

【我的理解】
> （手写一个使用 global 的程序：全局计数器，函数每次调用 +1。然后思考：如果不用 global，还能怎么实现同样的效果？）

## 四、全局变量与局部变量对比

### 知识点 6：优缺点与选型

【课程原话/定义】

| | 全局变量 | 局部变量 |
|------|------|------|
| **作用范围** | 整个程序 | 函数内部 |
| **生命周期** | 程序启动到结束 | 函数调用到返回 |
| **优点** | 方便跨函数共享数据 | 安全隔离，不污染外部；自动回收内存 |
| **缺点** | 易被误修改；命名冲突；调试困难；占内存 | 作用范围有限，不能直接跨函数共享 |

【为什么？】
这个对比表不是要你选"哪个更好"，而是帮你理解"什么时候该用哪个"。原则简单：

- 数据只在函数内部用 → 局部变量（90%的情况）
- 数据是整个模块的常量 → 全局（用大写命名，如 `BASE_URL`）
- 数据需要跨函数共享且可变 → 考虑传参，而不是全局

【必须掌握】
- 默认用局部变量，需要共享时用参数传递
- 全局变量用于模块级常量（通常对变量）——大写命名约定
- 尽量不用 global，用 return + 参数传递替代

【企业场景】
一个反例——测试框架中过度使用全局变量：
```python
# 糟糕的设计
current_user = None
current_page = None
test_data = []

def setup():
    global current_user, test_data
    current_user = "admin"
    test_data = load_csv()

def test_1():
    # 依赖 setup() 已经执行过...
    assert current_user == "admin"

# 好的设计
def setup():
    user = "admin"
    data = load_csv()
    return user, data

def test_1(user, data):
    assert user == "admin"
```
好的设计中，test_1 不依赖任何外部状态，可以单独运行、单独调试。

【我的理解】
> （总结：什么时候用全局变量，什么时候用局部变量？你学到的最重要的一条原则是什么？）

## 今日课程总结

| 模块 | 核心内容 | 面试权重 |
|------|----------|----------|
| LEGB 规则 | Local→Enclosing→Global→Built-in，内层优先 | ★★★★★ |
| 局部变量 | 函数内部有效，调用创建、返回销毁 | ★★★★☆ |
| 全局变量 | 模块级，读取直接、修改需 global | ★★★★☆ |

| global 关键字 | 在函数内声明使用全局变量，慎用 | ★★★★☆ |
| 全局 vs 局部选型 | 默认局部，常量用全局大写，慎用 global | ★★★☆☆ |
