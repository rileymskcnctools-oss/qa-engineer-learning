## 一、封装（Encapsulation）

### 知识点 1：封装的概念

【课程原话/定义】
封装是面向对象三大特性之一，将数据（属性）和操作数据的方法打包在一起形成类。目的是**隐藏内部实现细节**，提供安全且易于使用的接口。

封装包含三个层面：
- **数据隐藏**：属性设为私有/受保护，防止外部直接篡改
- **方法封装**：通过方法访问/修改数据，而不是直接操作
- **接口定义**：对外暴露公共方法，使用者无需了解内部实现

【为什么？】
不用封装 → 数据裸奔，谁都能改。测试中 `driver.url = "http://evil.com"` 一行就能让所有测试跑偏。

封装的本质是**约定优于强制**。Python 没有真正的 private，靠的是"下划线警告 + 程序员自觉"。

类比：银行账户。余额是私有属性（`__balance`），你不能直接 `account.__balance = 1000000`，必须通过 `deposit()` / `withdraw()` 方法——方法里可以做校验（余额不足拒绝交易）。

【必须掌握】
- 封装 = 数据 + 方法打包，隐藏内部实现
- 三个目的：数据安全、模块化、简化接口
- Python 的封装是"约定"，不是强制

【企业场景】
测试框架中封装浏览器操作：

```python
class Browser:
    def __init__(self):
        self.__driver = None       # 私有：外部不能直接拿 driver 乱操作

    def start(self):
        self.__driver = webdriver.Chrome()

    def goto(self, url):
        if self.__driver is None:
            raise RuntimeError("浏览器未启动")
        self.__driver.get(url)

    def quit(self):
        if self.__driver:
            self.__driver.quit()
```

外部只能通过 `goto()` / `quit()` 操作浏览器，不能直接 `browser.__driver.get("http://evil.com")`。

【面试考察】
面试官："封装解决了什么问题？Python 如何实现封装？"

参考回答框架：
1. 封装将数据和方法绑定，隐藏内部实现，对外暴露接口
2. 解决：数据安全（防止篡改）、降低耦合、简化使用
3. Python 通过命名约定实现：`_` 保护、`__` 私有（名称改写）
4. Python 的封装是约定而非强制——仍然可以访问，但不应访问

【我的理解】
> （用自己的话解释封装，用日常生活中的一个例子类比。为什么"隐藏实现细节"对团队协作很重要？）

### 知识点 2：三种访问权限

【课程原话/定义】
Python 没有 `public`/`protected`/`private` 关键字，通过下划线命名约定实现三种权限：

| 权限  | 写法       | 类内访问 | 子类访问 | 类外访问   | 对应其他语言    |
| --- | -------- | ---- | ---- | ------ | --------- |
| 公有  | `name`   | ✅    | ✅    | ✅      | public    |
| 保护  | `_name`  | ✅    | ✅    | ⚠️ 不推荐 | protected |
| 私有  | `__name` | ✅    | ❌    | ❌      | private   |

```python
class A:
    def __init__(self):
        self.a = 10         # 公有
        self._b = 20        # 保护
        self.__c = 30       # 私有

    def show(self):
        print(self.a)       # ✅ 类内可访问
        print(self._b)      # ✅ 类内可访问
        print(self.__c)     # ✅ 类内可访问

obj = A()
print(obj.a)       # ✅ 10
print(obj._b)      # ⚠️ 20（能用，但 IDE 警告，不建议）
# print(obj.__c)   # ❌ AttributeError
```

私有属性的原理：**名称改写（Name Mangling）**——Python 把 `__c` 改成了 `_A__c`，所以外部 `obj.__c` 找不到，但 `obj._A__c` 仍然可以访问（强烈不建议）。

【为什么？】
为什么 Python 不实现真正的 private？

Python 的设计哲学："我们都是成年人了"（We're all consenting adults）。相信程序员知道自己在做什么，不强制约束。

`__` 双下划线的真实用途：**防止子类意外覆盖父类的关键属性**。名称改写让 `__attr` 变成 `_类名__attr`，子类定义一个同名 `__attr` 不会覆盖父类的。

不要为了"安全"把所有属性都加 `__`——过度私有化让代码难以调试和测试。实践中 `_` 单下划线最常用。

【必须掌握】
- `name` → 公有，任何地方访问
- `_name` → 保护，"不要碰，但你需要的时候可以碰"
- `__name` → 私有，名称改写为 `_类名__name`
- 双下划线前后都有（`__init__`）→ 魔法方法，Python 系统调用
- 实践中：公开 API 用公有，内部实现用 `_` 保护，防子类覆盖用 `__`

【企业场景】
测试用例基类的设计：

```python
class BaseTest:
    def __init__(self):
        self.test_name = ""          # 公有：子类可以直接设置
        self._result = "NOT_RUN"     # 保护：通过方法修改
        self.__internal_id = 0       # 私有：子类不应该碰

    def set_result(self, status):
        if status in ("PASS", "FAIL", "SKIP"):
            self._result = status    # 方法内修改保护属性
```

子类可以自由设置 `test_name`，通过 `set_result()` 修改结果，但不能直接碰 `__internal_id`。

【面试考察】
面试官："`_var`、`__var`、`__var__` 三者的区别？"

参考回答框架：
1. `_var`：约定为保护属性，类外可访问但不建议，子类可访问
2. `__var`：触发名称改写 → `_类名__var`，类外无法直接访问，子类也不可访问（防止覆盖）
3. `__var__`：魔法方法/属性，Python 系统使用（`__init__`、`__str__`），不要自定义

【易错点】

| 常见错误                | 错误原因              | 正确做法                        |
| ------------------- | ----------------- | --------------------------- |
| 以为 `__var` 真的不可访问   | 不了解名称改写机制         | 知道 `_类名__var` 能访问，但不应该用     |
| 所有属性都加 `__`         | 过度私有化             | 绝大多数场景 `_` 够用，`__` 仅用于防子类覆盖 |
| 自定义 `__xxx__` 格式的属性 | 可能与 Python 未来版本冲突 | 避免使用双下划线前后缀                 |

【我的理解】
> （写一个 BankAccount 类，用 `__balance` 私有属性存余额，提供 `deposit()` / `withdraw()` 公有方法。解释为什么不能直接 `account.__balance = 1000`？）

## 二、计算属性：`@property`

### 知识点 3：从 Getter/Setter 到 `@property`

【课程原话/定义】
私有属性不能在类外直接访问，需要提供 getter（访问器）和 setter（修改器）方法。传统写法 `get_xxx()` / `set_xxx()` 啰嗦。`@property` 装饰器让方法像属性一样使用：

```python
class Person:
    def __init__(self, name):
        self._name = name

    @property
    def username(self):              # getter —— 像属性一样读
        return self._name

    @username.setter
    def username(self, name):        # setter —— 像属性一样写
        if name.isalpha():
            self._name = name

tom = Person("tom")
print(tom.username)        # tom —— 像属性一样访问，实际调用了 getter
tom.username = "Tom"       # 像属性一样赋值，实际调用了 setter
print(tom.username)        # Tom
```

规则：
- 必须先定义 `@property`（getter），才能定义 setter
- getter 和 setter 方法名相同
- setter 装饰器格式：`@属性名.setter`

【为什么？】
传统 `get_name()` / `set_name()` 的痛点：
- `tom.get_name()` 是方法调用，`tom.name` 是属性访问——语法不统一
- 别人用你的类时要查文档才知道是用属性还是方法

`@property` 的价值：
- **优雅**：`tom.username = "Tom"` 比 `tom.set_username("Tom")` 自然
- **兼容**：最开始可以用公有属性，后来需要加校验时改成 @property——调用方代码一行不用改
- **可读**：看起来像属性，实际是方法

三个优势：隐藏实现细节、访问控制、数据验证——都在不改变调用方式的前提下完成。

【必须掌握】
- `@property` → getter：`obj.attr` 时调用
- `@attr.setter` → setter：`obj.attr = value` 时调用
- 必须先定义 getter，才能定义 setter
- 可以在 setter 中做数据校验

【企业场景】
Page Object 模式中的元素定位：

```python
class LoginPage:
    def __init__(self, driver):
        self._driver = driver

    @property
    def username_input(self):
        """每次访问都重新定位，避免 StaleElementException"""
        return self._driver.find_element(By.ID, "username")

    @property
    def url(self):
        return self._driver.current_url

# 使用
login_page = LoginPage(driver)
login_page.username_input.send_keys("admin")   # 像属性一样自然
print(login_page.url)
```

不用 `@property` 就得写 `login_page.get_username_input().send_keys()`——啰嗦。

【面试考察】
面试官："`@property` 是什么？它和直接暴露公有属性相比，有什么优势？"

参考回答框架：
1. `@property` 让方法像属性一样访问
2. 优势：可以加校验（setter 中）、可以隐藏实现、不改变外部调用方式
3. 先有公有属性，后来需要加逻辑 → 改成 @property，调用代码零改动
4. Pytest fixtures、Selenium Page Object 大量使用

【易错点】

| 常见错误                   | 错误原因               | 正确做法                     |
| ---------------------- | ------------------ | ------------------------ |
| 只写了 setter 没写 getter   | @property 必须先定义    | 先写 `@property` 定义 getter |
| getter 和 setter 方法名不一致 | 误解了 property 机制    | 必须同名                     |
| setter 中忘记做数据校验        | 以为 @property 会自动校验 | setter 中手动写校验逻辑          |

【我的理解】
> （定义一个 Circle 类，用 `_radius` 私有属性存半径，用 `@property` 实现 `diameter` 计算属性和 `area` 计算属性（`3.14 * r²`），并给 `radius` 加 setter 校验半径必须 > 0。解释为什么 diameter 只需要 getter 不需要 setter？）

## 三、继承（Inheritance）

### 知识点 4：单继承

【课程原话/定义】
子类（派生类）继承父类（基类），获得父类的属性和方法，并可以扩展或重写。

```python
class A:                        # 等价于 class A(object):
    def show(self):
        print("父类A的方法")

class B(A):                     # B 继承自 A
    def display(self):
        print("子类B的方法")

b = B()
b.display()    # 自己的方法
b.show()       # 继承自父类的方法
```

Python 3 所有类默认继承自 `object`（新式类）。

【为什么？】
继承解决的核心问题：**代码复用**。

不用继承 → 每个类都把公共代码写一遍（复制粘贴地狱）。用继承 → 公共代码放父类，子类自动拥有。

测试框架中，你写了 100 个测试用例，每个都 `driver = webdriver.Chrome()` → 把这一步提取到父类 `setUp()` 里，100 个子类自动继承。

继承形成层次结构：`object` → `TestCase` → `LoginTest`，越往上越通用，越往下越具体。

【必须掌握】
- `class 子类(父类):` 实现单继承
- 子类自动拥有父类所有公有和保护属性/方法
- 私有属性（`__xxx`）不继承（名称改写 `_父类名__xxx`）
- Python 所有类最终继承自 `object`

【企业场景】
Pytest 风格的测试用例继承：

```python
class BaseTest:
    def setup(self):
        self.driver = webdriver.Chrome()
        self.driver.implicitly_wait(10)

    def teardown(self):
        self.driver.quit()

class TestLogin(BaseTest):               # 继承 BaseTest
    def test_valid(self):
        self.driver.get("https://...")   # 直接用父类的 driver
        # ... 测试逻辑
```

`setup()` 和 `teardown()` 写在父类一次，所有测试子类自动复用。

【面试考察】
面试官："继承解决了什么问题？Python 中所有类最终继承自什么？"

参考回答框架：
1. 继承解决代码复用——子类自动拥有父类的属性和方法
2. 还实现了"is-a"关系建模（猫 is-a 动物）
3. Python 3 所有类默认继承 `object`（新式类）
4. 私有属性 `__xxx` 不会被继承（名称改写导致）

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 忘记继承 object | Python 2 习惯 | Python 3 自动继承，不写也行 |
| 以为私有属性能继承 | 不了解名称改写 | `__attr` → `_父类名__attr`，子类不继承 |
| 过度使用继承 | 继承层次太深 | 优先组合，继承最多 3 层 |

【我的理解】
> （创建一个 Vehicle 父类（brand, speed），创建 Car 子类和 Bike 子类，各自添加独特属性。说明哪些代码可以复用？）

### 知识点 5：方法重写与 super()

【课程原话/定义】
子类可以重写父类的方法。使用 `super()` 在重写时调用父类版本：

```python
class A:
    def show(self):
        print("父类A的方法")

class B(A):
    def show(self):              # 重写父类方法
        super().show()           # 调用父类的 show()
        print("子类B的方法")

b = B()
b.show()
# 父类A的方法
# 子类B的方法
```

子类 `__init__` 中也需要 `super().__init__()` 初始化父类属性：

```python
class A:
    def __init__(self, a):
        self.a = a

class B(A):
    def __init__(self, a, b):
        super().__init__(a)      # 父类负责初始化 a
        self.b = b               # 子类负责初始化 b
```

【为什么？】
方法重写的精髓：**"变的部分放子类，不变的部分放父类，用 super() 串联"**。

`super()` 不直接写 `A.show(self)` 的好处：
- 不硬编码父类名——父类改名或换继承关系时不用改代码
- 多继承时按 MRO 自动找下一个——手写父类名做不到

一个原则：**父类的活让父类干**。子类 `__init__` 不要手动 `self.a = a` 去初始化父类的属性——调 `super().__init__(a)` 让父类自己初始化。

【必须掌握】
- 子类定义同名方法 → 覆盖父类方法（重写 override）
- `super().方法()` 调用父类版本
- `super().__init__(参数)` 初始化父类属性
- 原则：父类工作父类做，子类只负责扩展

【企业场景】
测试用例的 setUp/tearDown 重写：

```python
class BaseTest:
    def setup(self):
        self.driver = webdriver.Chrome()

    def teardown(self):
        self.driver.quit()

class TestLogin(BaseTest):
    def setup(self):
        super().setup()                      # 复用父类的 driver 初始化
        self.login_data = self.load_data()   # 子类额外的准备工作

    def teardown(self):
        self.save_results()                  # 子类先处理自己的事
        super().teardown()                   # 父类清理 driver
```

`super()` 让你在保留父类行为的同时添加自己的逻辑。

【面试考察】
面试官："`super()` 的作用是什么？为什么不直接写父类名调用？"

参考回答框架：
1. `super()` 返回父类代理对象，用于调用父类方法
2. 不硬编码父类名：父类改名或换继承关系时不用改代码
3. 多继承时按 MRO 顺序自动查找——手写父类名无法实现
4. 典型用法：`super().__init__()`、`super().method()`

【易错点】

| 常见错误                                  | 错误原因        | 正确做法                   |
| ------------------------------------- | ----------- | ---------------------- |
| 子类 `__init__` 不调 `super().__init__()` | 以为写了属性就行    | 必须调，父类可能有初始化逻辑         |
| `super()` 写成 `super(子类名, self)`       | Python 2 写法 | Python 3 直接用 `super()` |
| 重写方法时忘了调 `super()`                    | 不记得保留父类行为   | 先想清楚：父类的逻辑还要不要？        |

【我的理解】
> （创建一个 Employee 父类（name, salary），创建 Manager 子类（额外 bonus 属性）。重写 `__init__` 和 `__str__`，用 `super()` 串联父子逻辑。manager 的年收入 = salary + bonus，而 employee 只算 salary——如何设计？）

### 知识点 6：多继承

【课程原话/定义】
一个子类同时继承多个父类：

```python
class FA:
    def fa_show(self):
        print("FA Show")

class FB:
    def fb_show(self):
        print("FB Show")

class S(FA, FB):            # 同时继承 FA 和 FB
    def s_show(self):
        print("S Show")

s = S()
s.fa_show()   # ✅
s.fb_show()   # ✅
```

同名方法查找顺序 → MRO（Method Resolution Order），使用 C3 算法。大致按继承书写顺序从左到右：

```python
class FA:
    def show(self):
        print("FA")

class FB:
    def show(self):
        print("FB")

class S(FB, FA):     # FB 在左，优先查找
    pass

s = S()
s.show()             # "FB" —— 按书写顺序，FB 优先
```

多继承初始化：`super()` 只能引用 MRO 链上的第一个父类，其他父类需直接指定类名调用：

```python
class S(FB, FA):
    def __init__(self, a, b, c):
        FA.__init__(self, a)     # 直接指定父类名
        FB.__init__(self, b)
        self.c = c
```

【为什么？】
多继承是把双刃剑——强大但危险。

为什么需要它？现实世界中一个对象可能有多种身份。比如"一个既是老师又是运动员的人"——同时继承 Teacher 和 Athlete。

但多继承最著名的问题："菱形继承"（两个父类继承自同一个祖父类）——同名方法到底用哪个？Python 的 MRO/C3 算法解决了这个问题，但代码可读性急剧下降。

核心原则：**能用组合就别用多继承**。Python 的 Mixin 模式（小功能片段）是多继承的最佳实践，但日常开发中单继承 + 组合就够用了。

【必须掌握】
- `class S(A, B):` 多继承语法
- 同名方法按 MRO 顺序查找（大致 = 继承书写顺序从左到右）
- 多继承初始化：非第一个父类需直接 `父类名.__init__(self, ...)`
- 能用组合 + 单继承就不要用多继承

【企业场景】
测试中较少直接用多继承，但了解它有助于理解 Pytest 的 fixture 机制（背后有类似思路）。实际中使用 Mixin 模式更常见：

```python
class LogMixin:
    def log(self, msg):
        print(f"[LOG] {msg}")

class DBHelper:
    def query(self, sql):
        return f"执行: {sql}"

class TestCase(LogMixin, DBHelper):   # 同时获得日志和数据库能力
    def run(self):
        self.log("测试开始")
        result = self.query("SELECT * FROM users")
        self.log(f"结果: {result}")
```

【面试考察】
面试官："Python 多继承的同名方法查找顺序是什么？MRO 是什么？"

参考回答框架：
1. MRO = Method Resolution Order（方法解析顺序）
2. Python 使用 C3 线性化算法计算 MRO
3. 大致规则：按继承书写顺序从左到右，深度优先但不重复
4. `类名.__mro__` 或 `类名.mro()` 可查看
5. 实践中尽量避免多继承，用 Mixin 或组合替代

【易错点】

| 常见错误                        | 错误原因                  | 正确做法                            |
| --------------------------- | --------------------- | ------------------------------- |
| 多继承中只用 `super().__init__()` | super() 只覆盖 MRO 第一个父类 | 其他父类用 `父类名.__init__(self, ...)` |
| 菱形继承时搞不清楚调用顺序               | 不了解 MRO               | 用 `类名.__mro__` 查看顺序             |
| 随意使用多继承                     | 过度设计                  | 优先用 Mixin 或组合                   |

【我的理解】
> （设计一个场景：SmartPhone 同时继承 Phone 和 Camera 两个类。Phone 有 call()，Camera 有 take_photo()。如果两个父类都有 power_on()，子类 `SmartPhone(FB, FA)` 调用 power_on() 输出什么？跟 `SmartPhone(FA, FB)` 有什么区别？）

## 四、多态（Polymorphism）

### 知识点 7：多态与鸭子类型

【课程原话/定义】
**多态**：不同的对象对同一消息做出不同响应。同一方法名在不同类中有不同实现，调用方不需要知道具体是哪个类的对象。

```python
class Father:
    def cure(self):
        print("使用中医方法治疗。。。")

class Son(Father):
    def cure(self):
        print("使用西医方法治疗。。。")

class Patient:
    def needDoctor(self, doctor):
        doctor.cure()               # 不管什么医生，都调 cure()

patient = Patient()
patient.needDoctor(Father())        # 使用中医方法治疗。。。
patient.needDoctor(Son())           # 使用西医方法治疗。。。
```

**鸭子类型（Duck Typing）**：Python 特有的多态实现——不要求继承同一个父类，只要对象有同名方法就可以互换。

```python
class AnimalDoctor:                  # 没有继承 Father！
    def cure(self):
        print("使用兽医方法治疗。。。")

patient.needDoctor(AnimalDoctor())   # 使用兽医方法治疗。。。
                                       # ✅ 也能用！因为有 cure() 方法
```

"走路像鸭子、叫声像鸭子、看起来像鸭子，那么它就是鸭子。"

【为什么？】
传统多态（Java/C++）要求：继承同一个父类 → 重写方法 → 父类引用指向子类对象。Python 的鸭子类型把这个约束拿掉了——**只看行为，不看类型**。

鸭子类型的优势：
- 不需要预先设计继承体系
- 第三方类只要实现了相同方法就能无缝接入
- 非常灵活，符合 Python "协议"哲学

风险：编译期没有类型检查，传错对象到运行时才报错。

【必须掌握】
- 多态 = 同一方法名，不同类不同实现
- 传统多态：继承 + 方法重写
- 鸭子类型：有同名方法就行，不要求继承关系
- `isinstance(obj, type)` → 检查 obj 是否是 type 或其子类的实例
- `issubclass(Type1, Type2)` → 检查 Type1 是否是 Type2 的子类

【企业场景】
测试报告的多态：

```python
class HTMLReporter:
    def generate(self, results):
        return f"<html>...{results}...</html>"

class JSONReporter:
    def generate(self, results):
        import json
        return json.dumps(results)

class TestRunner:
    def run_and_report(self, reporter):     # reporter 可以是任何有 generate() 的对象
        results = self.execute_tests()
        return reporter.generate(results)

runner = TestRunner()
print(runner.run_and_report(HTMLReporter()))  # HTML 格式
print(runner.run_and_report(JSONReporter()))  # JSON 格式
```

`TestRunner` 不关心 reporter 是谁——只要有 `generate()` 方法就能用。哪天要加 XMLReporter，新建类实现 `generate()` 就行，`TestRunner` 一行不改。

【面试考察】
面试官："多态是什么？Python 的鸭子类型和传统多态有什么不同？"

参考回答框架：
1. 多态 = 不同对象响应同一消息，有不同的行为
2. 传统多态需要继承同一个父类/接口
3. 鸭子类型：只看行为（有没有某个方法），不看类型（继承关系）
4. Python 中鸭子类型更灵活，不需要显式继承
5. 风险：没有编译期类型检查，可能运行时出错

面试官追问："`isinstance()` 和 `issubclass()` 的区别？"

参考回答：
- `isinstance(obj, Type)`：obj 是这个类型或其子类的实例吗？
- `issubclass(Sub, Parent)`：Sub 是 Parent 的子类吗？（包括自己）
- `isinstance()` 检查对象，`issubclass()` 检查类

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为 Python 多态必须继承 | 受 Java/C++ 思维影响 | Python 鸭子类型，不继承也能多态 |
| `isinstance(obj, Father)` 对子类返回 False（预期 True） | 误解了 isinstance 语义 | isinstance 对子类实例也返回 True |
| 鸭子类型传错对象，运行时才报错 | 没有类型约束 | 关键路径用 isinstance() 防御 |

【我的理解】
> （设计一个支付场景：WeChatPay、AliPay、BankCard 三个类，都实现 pay(amount) 方法但逻辑不同。一个 checkout(payment_method, amount) 函数接收任意支付对象。解释这里多态如何让 checkout 不需要修改就能支持新增支付方式？鸭子类型体现在哪里？）

## 五、类型检查

### 知识点 8：isinstance() 和 issubclass()

【课程原话/定义】

```python
# isinstance：检查对象是否是某类型的实例
isinstance(littleDoctor, Father)      # True（子类实例也是父类实例）
isinstance(littleDoctor, Son)         # True
isinstance(littleDoctor, AnimalDoctor) # False

# issubclass：检查类之间的继承关系
issubclass(Father, Father)            # True（自己也算子类）
issubclass(Son, Father)              # True
issubclass(AnimalDoctor, Father)     # False
```

用途：结合鸭子类型做防御性检查：

```python
class Patient:
    def needDoctor(self, doctor):
        if isinstance(doctor, Father):       # 类型守卫
            doctor.cure()
        else:
            print("此大夫医疗方法不适用病人。。。")
```

【为什么？】
Python 把类型检查留给了运行时。`isinstance()` 是鸭子类型的"防护栏"——大部分时候不需要，但关键路径加一下避免翻车。

测试中典型场景：Mock 对象校验。`assert isinstance(mock.call_args[0][0], dict)` 验证被测代码传入了正确的参数类型。

但有一派 Python 观点认为：`isinstance()` 是破坏鸭子类型的反模式。务实做法：对外接口加 isinstance 防御，内部代码相信调用方。

【必须掌握】
- `isinstance(对象, 类)` → bool
- `issubclass(子类, 父类)` → bool（自己也是自己的子类）
- `obj.__class__` 获取对象的类

【我的理解】
> （为什么 `issubclass(Father, Father)` 返回 True？这个设计合理吗？`isinstance()` 和 `type() ==` 有什么区别？）
