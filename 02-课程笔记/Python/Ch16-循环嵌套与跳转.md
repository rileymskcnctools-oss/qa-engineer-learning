## 一、循环嵌套

### 知识点 1：嵌套循环的执行规则

【课程原话/定义】
在一个循环的循环体中嵌入另一个循环，称为嵌套循环。循环嵌套不局限于某种循环形式，for-in 和 while 可以任意相互嵌套。

核心规则：**外层循环执行一次，内层循环执行完整的一轮。**

```python
# for-in 嵌套遍历二维列表
data = [
    [1, 2, 3, 4, 5, 6, 7, 8, 9],
    ["A", "B", "C", "D", "E"],
    ["Hello", "World", "Python", "Hogwarts"]
]
for item in data:      # 外层：遍历每一行
    for el in item:    # 内层：遍历当前行的每个元素
        print(el)

# while 嵌套遍历二维列表
l1 = len(data)
i = 0
while i < l1:
    item = data[i]
    l2 = len(item)
    j = 0
    while j < l2:
        el = item[j]
        print(el)
        j += 1
    i += 1
```

【为什么？】
嵌套循环的本质是**笛卡尔积式的遍历**——外层的每一个状态，都要和内层的所有状态组合一遍。你可以把它想象成电子表格：外层是"行号"，内层是"列号"，遍历时先锁定第 0 行，把第 0 行的每一列走完，再切到第 1 行。

为什么允许 for 和 while 混用？因为场景决定选择：外层"已知有多少行"用 for-in 最安全，内层"不确定有几个元素"或"需要条件判断跳出"用 while 更灵活。Python 不限制组合方式，正是因为它相信程序员应该按场景选工具。

【必须掌握】
- 执行顺序：外层 1 次 → 内层完整一轮 → 外层下一次
- for-in 嵌套：外层用 `for row in data`，内层用 `for cell in row`
- while 嵌套：外层和内层各自维护独立的计数器（i 和 j），各自负责自增
- for + while / while + for 任意混搭皆可

【企业场景】
你在做数据驱动测试，Excel 里有 50 条测试用例，每条用例有 8 个参数字段：
```python
test_cases = load_excel("cases.xlsx")  # 50 行 × 8 列
for case in test_cases:           # 外层：遍历每条用例
    for field in case:            # 内层：校验每个字段非空
        assert field != "", f"用例{case[0]}有空字段"
```
外层 for 保证不漏用例，内层 for 保证每个字段都检查到。

你在做接口自动化，需要分页拉取 10 页数据，每页 20 条：
```python
for page in range(1, 11):                  # 外层：第几页
    response = api.get_page(page)
    for item in response["data"]:          # 内层：遍历当前页的每条记录
        results.append(item["id"])
```

【面试考察】
面试官："`for i in range(3): for j in range(2): print(i, j)` 会输出什么？"

参考回答框架：
1. 先说出输出：(0,0) (0,1) (1,0) (1,1) (2,0) (2,1)
2. 解释规律：外层 i 固定时，内层 j 走完 [0, 1] 才进入下一个 i
3. 总分：3 × 2 = 6 次 print

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 内外层用同一个变量名 | 内层覆盖外层变量，逻辑错乱 | 外层 i、内层 j（或 row/col） |
| while 嵌套忘写内层自增 `j += 1` | 内层 j 永远是 0，死循环 | while 写完后立刻补自增语句 |
| `for el in data` 把子列表当成单个元素 | 忘记 data 是二维列表 | 需要两层 for：先取子列表，再取元素 |
| 九九乘法表内层写成 `range(1, 10)` | 每行都打印了 9 列，不是三角形 | 内层应该是 `range(1, i+1)` |

【扩展知识】
- 三层及以上嵌套尽量避免——三层嵌套如果有 10 个元素每层，就是 1000 次迭代，可读性和性能都差
- 可以用 itertools.product() 扁平化多层嵌套，代码更清晰
- 列表推导式也可以嵌套：`[x*y for x in range(1,10) for y in range(1,10)]`

### 知识点 2：九九乘法表

【课程原话/定义】
九九乘法表是嵌套循环的经典练习。外层控制行（乘数 i），内层控制列（被乘数 j），每行的列数等于当前行号。

```python
# 标准格式：1*1=1   1*2=2   2*2=4   ...
for i in range(1, 10):
    for j in range(1, i + 1):
        print(f"{j}*{i}={i*j}", end="\t")
    print()
```

【为什么？】
为什么 `range(1, i+1)`？因为第 i 行应该有 i 个乘法式子，如第 3 行有 1×3, 2×3, 3×3。`range(1, i+1)` 生成 1 到 i，恰好 i 个值。

这是面试中最常被要求手写的代码之一。面试官通过这道题同时考察：嵌套循环理解、range 边界处理、print 的 end 参数、格式化输出。一行代码暴露基本功。

【必须掌握】
- 外层 `range(1, 10)` 控制 1~9 行
- 内层 `range(1, i+1)` 控制当前行的列数
- `print(i*j, end=" ")` 不换行，`print()` 换行
- 标准格式用 `f"{j}*{i}={i*j}"` 而不是 `f"{i}*{j}={i*j}"`

【企业场景】
你在写测试报告生成工具时，需要在 console 输出格式化表格：
```python
# 输出测试结果矩阵：行=模块，列=测试类型
modules = ["登录", "订单", "支付"]
types = ["功能", "性能", "安全"]
for module in modules:
    for test_type in types:
        print(f"{module}-{test_type}", end="\t")
    print()
```
这和九九乘法表的结构完全一样——外层决定行数，内层决定每行列数。

【面试考察】
面试官："请手写九九乘法表，`1*1=1` 格式。"

参考回答框架：
1. 两层 for 循环，i 从 1 到 9，j 从 1 到 i
2. 注意是 `j*i` 不是 `i*j`——标准格式 j 在前
3. `end="\t"` 对齐，`print()` 换行

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 写成 `i*j` 而不是 `j*i` | 标准格式是小的在前 | 看清格式：`j*i` |
| `range(1, i)` 漏了 `i*1` | range 不含 stop | `range(1, i+1)` |
| `print(i*j)` 每行只有一个数竖着排 | 忘写 `end=" "` | 内层 print 用 end，外层用空 print 换行 |

## 二、循环跳转

### 知识点 3：死循环 `while True`

【课程原话/定义】
死循环是指循环条件恒为真，循环会一直执行下去。这不是语法错误，在不确定循环次数的情况下可以合理使用。如 Web 服务器监听客户端连接、持续等待用户输入。

```python
# 持续输入直到用户输入 bye
data = []
while True:
    d = input("请输入数据：")
    if d == "bye":
        break
    data.append(d)
    print(data)
```

【为什么？】
死循环不是 bug，而是一种"我先开着门，你告诉我要关我才关"的设计模式。它的哲学是：**我不知道什么时候结束，所以先不设结束条件，让循环体内部决定退出时机**。

Web 服务器从启动到关闭，中间的请求处理就是一个巨大的 `while True`。测试中的"轮询等待元素出现"也是同一个模式——你没法事先知道等 3 秒还是 30 秒。

【必须掌握】
- `while True` 是标准死循环写法
- 死循环必须配合 `break` 退出，否则真的死循环
- 适用场景：循环次数不确定，由运行时条件决定退出

【企业场景】
你在做 UI 自动化测试，点击按钮后需要等待弹窗出现，但不知道等多久：
```python
from time import sleep
max_wait = 30
elapsed = 0
while True:
    if driver.find_element(...):
        break
    sleep(1)
    elapsed += 1
    if elapsed >= max_wait:
        raise TimeoutError("元素未出现")
```
这就是"不确定次数"的典型场景——弹窗可能 0.5 秒出，也可能 10 秒出。

【面试考察】
面试官："`while True` 什么时候用？它和 `for i in range(N)` 的区别是什么？"

参考回答框架：
1. `while True`：不知道循环次数，靠内部条件 break
2. `for i in range(N)`：明确知道循环 N 次
3. 举例：轮询等待用 while True；遍历列表用 for-in

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| `while True` 忘写 break | 真的死循环，程序卡死 | 写完 while True 立刻写退出条件 |
| 把 `while True` 用在明确次数的地方 | 过度设计 | 知道次数直接用 for-in + range |

### 知识点 4：break 语句

【课程原话/定义】
`break` 可以立即终止当前的 while 或 for-in 循环，无论循环还有多少次没执行，都无条件结束，跳到循环后的语句继续执行。

**在嵌套循环中，break 只跳出它所在的那一层循环，外层不受影响。**

```python
# 内层 break 演示
for i in range(2):
    for j in range(5):
        print("Hello", j)
        if j == 2:
            break   # 只跳出内层 for j，外层 for i 继续
# 输出：j=0,1,2 后内层结束，外层进入 i=1，内层又从 j=0 开始
```

【为什么？】
break 设计的语义是"结束当前循环"，不是"结束所有循环"。这个设计是合理的——大多数场景你只是想在当前这个维度停止，而不是炸掉整个程序。如果需要在深层嵌套中跳出所有循环，Python 的做法是用一个标志变量 + 外层检查，或者把代码封装成函数后 return。

生活中：你在逛商场（外层），进每家店逛（内层），逛到第 3 家店时看到喜欢的就买了走人（内层 break），但你不会因此离开商场（外层继续），你继续进下一家店。

【必须掌握】
- break 终止当前所在循环，不跳外层
- 嵌套中要跳出所有层：设置 `found = False`，内层 break 后外层检查
- break 后循环的 else 子句不执行

【企业场景】
你在遍历 100 个测试用例，第 1 个就发现严重 bug，想立即停止：
```python
for case in test_cases:
    result = run_test(case)
    if result == "CRITICAL_FAIL":
        print(f"严重失败：{case['name']}，停止测试")
        break  # 不再执行后续用例
```

嵌套场景：在多个页面查找一个元素：
```python
found = False
for page in pages:
    for element in page.elements:
        if element.id == target_id:
            click(element)
            found = True
            break     # 跳出内层
    if found:
        break         # 跳出外层
```

【面试考察】
面试官："嵌套循环中内层的 break 会影响外层吗？如果我要跳出所有循环，怎么做？"

参考回答框架：
1. 内层 break 只跳内层，外层继续
2. 跳出所有层的方法：flag 变量 + 外层再 break；或者封装函数 return
3. 说出实际场景：查找元素，找到就全停

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为内层 break 会终止外层 | 不理解 break 的作用范围 | 记口诀：break 只管自己这层 |
| 嵌套中只用了一个 break | 内层停了，外层继续白跑 | 加标记变量，外层检测后也 break |
| break 和 return 混用 | 在函数中 return 直接退出整个函数 | 函数内需要全退出用 return，循环退出用 break |

【我的理解】

### 知识点 5：continue 语句

【课程原话/定义】
`continue` 的作用是中止本次循环，跳过循环体中后续未执行的代码，直接进入下一次循环。

大多数情况下，可以通过改变条件的方式避免使用 continue，代码会更简洁。

```python
# 使用 continue
for i in range(10):
    print("*" * 10)
    print("i=", i)
    if i % 3 == 0:
        continue      # 跳过 print("i*10=...")
    print("i*10= ", i * 10)

# 等价改写：用条件反转替代 continue
for i in range(10):
    print("*" * 10)
    print("i=", i)
    if i % 3 != 0:    # 条件取反
        print("i*10= ", i * 10)
```

【为什么？】
continue 解决的问题是"有些数据我不想处理，但不是错误，我想跳过"。它的本质是**提前短路本次迭代**。

Python 社区偏好"正向条件"而非 continue——因为 `if condition: do_something()` 的阅读路径是直线向下的，而 `if condition: continue` 需要读者在脑中跳转。但 continue 在某些场景确实更清晰，比如数据校验层：`if invalid: continue` 比 `if valid: 嵌套一大段代码` 减少了缩进层级。

【必须掌握】
- continue 跳过本次循环剩余代码，进入下一次迭代
- 可以用条件取反替代 continue
- continue 不影响循环的 else 子句

【企业场景】
你在处理一批测试数据，需要跳过空行和注释行：
```python
test_data = open("data.csv").readlines()
for line in test_data:
    line = line.strip()
    if not line or line.startswith("#"):
        continue  # 跳过空行和注释
    run_test(line)
```
这里用 continue 很自然——"不符合条件就跳过"比"符合条件才执行一大段"更清晰。

【面试考察】
面试官："break 和 continue 的区别是什么？各写一个场景。"

参考回答框架：
1. break：结束整个循环，跳出去
2. continue：结束本次迭代，进入下一次
3. 类比：break = 下班回家；continue = 这页文件跳过看下一页
4. 测试场景：break 是"找到目标元素，停止搜索"；continue 是"跳过空行，继续处理下一行"

【易错点】

| 常见错误                    | 错误原因               | 正确做法                         |
| ----------------------- | ------------------ | ---------------------------- |
| continue 后写代码           | continue 后的代码永远不执行 | IDE 通常会有警告                   |
| 把 continue 和 break 混为一谈 | 不记本质区别             | break = 终止循环，continue = 跳过本次 |
| 滥用 continue 让代码难读       | 逻辑跳跃过多             | 优先考虑条件取反改写                   |

### 知识点 6：loop-else 子句

【课程原话/定义】
Python 的循环语句（for-in 和 while）都可以使用 `else` 子句。当循环**没有被 break 中断而正常结束**时，执行 else 后的代码块。

```python
# 正常结束 → 执行 else
for i in range(5):
    print(i)
else:
    print("Over")  # 会执行

# 被 break 中断 → 不执行 else
for i in range(5):
    print(i)
    if i == 2:
        break
else:
    print("Over")  # 不会执行
```

实用示例：在列表中查找元素
```python
names = ["tom", "jack", "rose", "tony"]
inName = input("请输入要查找的姓名：")

# 方法1：标记变量法
flag = False
for name in names:
    if name == inName:
        print("找到了")
        flag = True
        break
if not flag:
    print("没找到")

# 方法2：loop-else 法（更 Pythonic）
for name in names:
    if name == inName:
        print("找到了")
        break
else:
    print("没找到")
```

【为什么？】
loop-else 是 Python 最被误解的语法之一。很多人第一次看到觉得"else 不是和 if 配对吗？"实际上这里的 else 语义是 **"no break"**——循环没有被 break 打断，就执行 else。

为什么需要它？因为它消除了"标记变量"的样板代码。看上面的找元素例子：方法 1 需要一个 `flag` 变量来记录"有没有找到"，多了 3 行代码和一个变量污染；方法 2 直接用 else 表达"没找到"的语义，干净利落。

这个设计灵感来自：如果你在循环中找东西，找到了就 break，没找到自然走到 else。语义是"找完所有没找到 → 执行备选逻辑"。

【必须掌握】
- else 在循环正常结束时执行（没有被 break 打断）
- else 在下列情况执行：循环完所有迭代、range 为空序列、while 条件一开始就为 False
- else 在下列情况不执行：循环内遇到 break
- 能用 loop-else 替代标记变量的场景，优先用 loop-else

【企业场景】
你在做回归测试，检查所有测试结果中是否有失败项：
```python
for test_result in test_results:
    if test_result.status == "FAILED":
        send_alert(f"测试{test_result.name}失败！")
        break
else:
    print("所有测试通过，可以发布")

# 等价的不使用 else 的写法需要标记变量
all_pass = True
for test_result in test_results:
    if test_result.status == "FAILED":
        send_alert(f"测试{test_result.name}失败！")
        all_pass = False
        break
if all_pass:
    print("所有测试通过，可以发布")
```
loop-else 版本少了 3 行样板代码，语义更直接："全跑完没失败 → 通过"。

【面试考察】
面试官："Python 循环的 else 子句在什么条件下执行？写一个遍历列表查找元素的例子。"

参考回答框架：
1. 循环没有被 break 中断时执行 else
2. 展示查找元素的两个版本（标记变量 vs loop-else）
3. 说明 loop-else 的语义：no break
4. 加分项：承认这个语法名不好，"nobreak" 可能更好理解

【易错点】

| 常见错误 | 错误原因 | 正确做法 |
|---------|---------|---------|
| 以为 else 在循环结束后一定执行 | 忽略了 break 会跳过 else | 记口诀：正常结束才 else，break 打断就不 else |
| `for i in range(0): else: print("x")` 以为不执行 | range(0) 是空序列，也算"正常结束" | 空循环也是正常结束，else 会执行 |
| 在不需要的场景硬用 else | 过度使用降低可读性 | else 最适合的场景是"查找-找到/没找到"模式 |
