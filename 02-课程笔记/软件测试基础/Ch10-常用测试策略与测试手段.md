## 一、策略 vs 手段

### 【课程定义】

| 概念   | 定义           | 通俗理解                       |
| ---- | ------------ | -------------------------- |
| 测试策略 | 测试活动的整体方法和方针 | **"仗怎么打"** — 测什么、先测什么、测多深  |
| 测试手段 | 具体实施策略的方法和技术 | **"用什么武器"** — 黑盒/白盒/自动化/手工 |

### 【为什么策略比手段更重要？】

面试中常被问："你们的测试策略是什么？"

新手回答："我们用黑盒测试、自动化测试。" → 这是在说手段，不是策略。

策略回答："新功能全量测试，回归用自动化覆盖核心链路，高风险的支付模块加专项安全测试。" → 这是策略。

### 【必须掌握】四大价值

| 价值 | 对你意味着什么 |
|------|--------------|
| 提高软件质量 | 策略决定测什么、测多深 |
| 提高工作效率 | 策略决定先测什么后测什么，时间花在刀刃上 |
| 降低风险 | 策略基于风险分析，高风险模块重点保障 |
| 增强团队协作 | 策略让所有人知道测试在做什么、为什么这么做 |

## 二、测试策略五要素

### 【必须掌握】制定策略时回答五个问题

| 要素 | 问题 | 举例 |
|------|------|------|
| 目标 | 测到什么程度算够？ | "核心链路零Bug，边缘功能允许P3级遗留" |
| 风险 | 哪里最可能出问题？ | "支付模块改动多、逻辑复杂，风险最高" |
| 范围 | 测哪些？不测哪些？ | "本期测登录+支付+订单，商品模块不动" |
| 安排 | 怎么安排测试活动？ | "第一周功能测试，第二周性能+安全" |
| 评价 | 怎么判断测到位了？ | "用例执行率100%，严重Bug全部关闭" |

#### 【面试考察】

> 面试官："一个新版本，你怎么制定测试策略？"

**参考回答框架：** 先看风险——改了什么、改了多少、哪些模块关联影响。再看目标——这个版本是紧急修复还是大版本发布？紧急修复缩小范围只测改动的核心链路；大版本发布全面测试。第三看资源——几个测试、几天时间。最后根据风险等级分配测试深度：高风险模块全量+专项，低风险模块做冒烟+回归。上线前做质量评估——严重Bug清零了没有、遗留问题有没有卡控。

## 三、测试策略实例（完整流程）

> 课程展示了一个完整项目的测试策略文档结构。以下按实际工作流程拆解。

### 【策略文档全景图】

```
总体测试策略
  → 第一个版本测试策略
    → 跟踪测试执行
      → 版本质量评估
        → 后续版本测试策略
          → 发布质量评估
```

### 3.1 总体测试策略

#### 1.1 明确产品质量目标

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702154529.png]]

| 质量维度 | 目标 | 怎么测 |
|---------|------|--------|
| 功能正确性 | 核心功能100%通过 | 全量功能测试 |
| 性能指标 | 页面加载<2秒，并发500 | 性能压测 |
| 兼容性 | iOS 14+，Android 10+，Chrome/Safari | 兼容性矩阵测试 |
| 安全性 | 无高危漏洞 | 安全扫描+手工渗透 |

#### 1.2 功能分类测试策略

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702154549.png]]

| 功能等级 | 定义 | 测试深度 | 举例 |
|---------|------|---------|------|
| 核心功能 | 产品赖以生存的功能 | 全量+专项+自动化 | 支付、登录 |
| 重要功能 | 用户常用但不致命 | 全量功能测试 | 地址管理、优惠券 |
| 一般功能 | 辅助功能 | 主流程+冒烟 | 帮助中心、关于页 |

#### 1.3 风险分析

>![[02-课程笔记/软件测试基础/images/Pasted image 20260702154627.png]]
![[02-课程笔记/软件测试基础/images/Pasted image 20260702154633.png]]

| 风险类型 | 识别方法 | 应对策略 |
|---------|---------|---------|
| 技术风险 | 新框架、新数据库、复杂算法 | 加专项测试（性能/安全） |
| 业务风险 | 核心链路改动、金额计算 | 加回归+数据校验 |
| 资源风险 | 测试时间不够、环境不稳定 | 提前预警，缩小范围 |
| 依赖风险 | 外部接口不稳定 | Mock测试+契约测试 |

#### 1.4 总体测试安排

>![[02-课程笔记/软件测试基础/images/Pasted image 20260702154659.png]]

| 阶段 | 时间 | 测试内容 |
|------|------|---------|
| 需求阶段 | D-7 ~ D-1 | 需求评审、风险评估 |
| 开发阶段 | D-Day ~ D+7 | 用例编写、自动化准备 |
| 提测 | D+8 ~ D+12 | 功能测试、Bug提交 |
| 回归 | D+13 ~ D+14 | 回归验证、性能/安全测试 |
| 发布 | D+15 | 线上验证、监控 |

### 3.2 第一个版本测试策略

#### 2.1 测试范围

>![[02-课程笔记/软件测试基础/images/Pasted image 20260702154720.png]]

#### 2.2 测试目标

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702154738.png]]

|---------|------|
| 质量目标 | "P0/P1 Bug全部关闭，P2<=3个" |

### 3.4 版本质量评估

#### 4.1 需求与实现的偏差

>![[02-课程笔记/软件测试基础/images/Pasted image 20260702155057.png]]

对比需求文档和实际交付：开发有没有多做（镀金）、有没有少做（遗漏）、有没有做错。

#### 4.2 测试过程评估

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155113.png]]

| 评估项 | 问题 |
|--------|------|
| 用例执行率 | 计划内的用例都跑完了吗？ |
| 阻塞时间 | 有没有因为环境/Bug导致测试中断？ |
| 测试效率 | 每天发现了多少Bug？效率正常吗？ |

#### 4.3 缺陷分析

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155131.png]]

分析Bug的根因：是需求理解不一致？开发粗心？还是架构问题？

### 3.5 后续版本测试策略

#### 5.1 回归测试策略

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155152.png]]
![[02-课程笔记/软件测试基础/images/Pasted image 20260702155239.png]]

| 策略 | 做法 | 适用场景 |
|------|------|---------|
| 全量回归 | 所有用例重跑一遍 | 大版本、核心架构改动 |
| 选择性回归 | 只跑改动的+关联影响的 | 小版本迭代 |
| 自动化回归 | 脚本自动跑核心链路 | 每次发版都跑 |

#### 5.2 探索式测试策略

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155258.png]]

| 探索方向 | 方法 |
|---------|------|
| 新手视角 | 第一次用这个功能的人会怎么操作 |
| 恶意用户视角 | 故意做错操作，看系统怎么处理 |
| 边界场景 | 极端数据、边界时间、极限操作 |
| 组合场景 | 多个功能交叉操作 |

### 3.6 发布质量评估

#### 6.1 确认质量目标

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155333.png]]

对照总体策略里的质量目标，逐条确认。

#### 6.2 遗留缺陷分析

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155345.png]]

| 遗留Bug处理 | 方式 |
|------------|------|
| 严重Bug | 不能遗留，必须修 |
| 一般Bug | PM确认可以遗留的，记录在已知问题列表 |
| 优化建议 | 排到后续版本 |

#### 6.3 暂挂Bug的处理

> ![[02-课程笔记/软件测试基础/images/Pasted image 20260702155403.png]]

暂挂（Suspended）的Bug是谁暂挂的、什么原因、什么时候处理——必须记录清楚，不能丢了。

## 四、测试手段速查

> 以下在 Ch04 已详细展开，此处做策略视角下的速查。

| 手段 | 策略中怎么用 | 适用场景 |
|------|------------|---------|
| 黑盒测试 | 新功能、系统测试 | 不了解代码，关注功能 |
| 白盒测试 | 单元测试、代码审计 | 开发自测阶段 |
| 动态测试 | 执行功能测试、性能测试 | 有可运行的版本 |
| 静态测试 | 需求评审、代码审查 | 还没代码的阶段 |
| 手工测试 | 新功能、探索式测试 | 第一次测、复杂场景 |
| 自动化测试 | 回归测试、CI流水线 | 重复执行的核心链路 |
